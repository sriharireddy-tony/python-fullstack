How to use these pages

Every page has a Run button on each code block. Press it and the code executes in your browser, right there on the page, and prints what it prints. Nothing to install, no editor to set up.

Do not read a page top to bottom in one go. The order below is deliberate:

  1. Read the problem and stop. Try to solve it in your head, badly. Badly is fine.
  2. Read think first and check whether your bad idea matches the one on the page. It usually will — that is the point. Everyone starts there.
  3. Read why it is slow and press Run on the timing demo. Seeing 269 ms next to 2 ms teaches more than the phrase “O(n²)” ever will.
  4. Read the better idea, then close the page and try to write the code yourself. You will get it wrong. Come back, read the dry run, try again.
The one habit that matters

Never memorise a solution. Memorised solutions collapse the moment an interviewer changes one detail. What survives is the trade each solution makes — almost always “I will use extra memory so that I can stop repeating work”. Learn the trade and you can rebuild the code from nothing.

Why two versions of everything

The from-scratch version exists because arr.includes(x) looks like one instruction but is secretly a loop — and if you do not know that, you will write an O(n²) solution and believe it is O(n). The built-in version exists because that is the code you write at your job, and an interviewer who sees only hand-rolled loops wonders whether you know the language.

Big-O without the maths

Big-O answers one question: if the input gets ten times bigger, what happens to the running time? That is all. Read the table as sentences.

O(1)constantsame timereading arr[5], map.get(k)
O(log n)logarithmicbarely slowerbinary search — halving each step
O(n)linear10× slowerone loop over the array

The line that hides a loop

arr.includes(x), arr.indexOf(x) and arr.find(...) each read as a single step but scan the whole array. Put one inside a for loop and you have written O(n²) in code that looks like O(n). This single misunderstanding is behind most “my solution timed out” moments, which is exactly why every page here writes the loop out by hand first.

Sequential loops add; nested loops multiply

Two loops one after the other is n + n = 2n, which is still O(n). Ten passes over an array is still O(n). It is only nesting that squares the work. Beginners lose marks for calling a two-pass solution quadratic — and lose more for calling a sliding window quadratic because it has a while inside a for.
