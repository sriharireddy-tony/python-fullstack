Strings · Problem 08

Check if Strings Are Rotations

The answer is one line: (a + a).includes(b). Interviewers ask this problem precisely to see whether you can explain that line. So this page derives it rather than handing it to you.

Step 1

The problem

Is string b a rotation of string a? A rotation means cutting a at some point and swapping the two pieces.

abRotation?Cut point
"waterbottle""erbottlewat"trueafter "wat"
"abcde""cdeab"trueafter "ab"
"abcde""abced"falsenot a rotation, just scrambled
"abc""abc"truecut at 0 — a zero rotation counts
"aa""aaa"falsedifferent lengths

Row three is the important one. "abced" has exactly the same letters as "abcde", so it is an anagram — but it is not a rotation. A rotation preserves the cyclic order; an anagram does not.

  a = "abcde"

  cut after 0:  "" + "abcde"   =  "abcde"
  cut after 1:  "a" + "bcde"   ->  "bcdea"
  cut after 2:  "ab" + "cde"   ->  "cdeab"
  cut after 3:  "abc" + "de"   ->  "deabc"
  cut after 4:  "abcd" + "e"   ->  "eabcd"

  those five strings are the ONLY rotations of "abcde".
  "abced" is not among them.
Step 2

Think first — try every cut

There are only n possible rotations. Generate each one and compare.

Version 0 — try all n rotations
function isRotationBrute(a, b) {
  if (a.length !== b.length) return false;
  if (a.length === 0) return true;

  for (let cut = 0; cut < a.length; cut++) {
    const rotated = a.slice(cut) + a.slice(0, cut);
    if (rotated === b) return true;
  }

  return false;
}

console.log(isRotationBrute('waterbottle', 'erbottlewat'));   // true
console.log(isRotationBrute('abcde', 'cdeab'));               // true
console.log(isRotationBrute('abcde', 'abced'));               // false
console.log(isRotationBrute('abc', 'abc'));                   // true
console.log(isRotationBrute('aa', 'aaa'));                    // false
console.log(isRotationBrute('', ''));                         // true

Completely correct and easy to explain. It builds n strings of length n and compares each: O(n²) time and O(n) space per attempt.

Step 3

Why it does more work than it needs to

Every cut allocates a whole new string. For a 100,000-character string that is 100,000 allocations of 100,000 characters each — ten billion characters copied.

Press Run below. The honest result may surprise you: on this adversarial input the two are about the same speed, because both are O(n²) in the worst case and JavaScript’s string concatenation is lazier than it looks. What the doubled version really buys is one allocation instead of n, and a native search routine instead of a hand-written comparison loop — which matters enormously on typical inputs and not at all on this one.

That is worth internalising: an elegant one-liner is not automatically a faster one-liner.

Timing demo
// A long run of identical characters is the worst case: every
// candidate rotation agrees with the target for thousands of
// characters before finally disagreeing.
const N = 40000;
const a = 'a'.repeat(N - 1) + 'b';
const cut = Math.floor(N / 2);
const b = a.slice(cut) + a.slice(0, cut);

function brute(x, y) {
  if (x.length !== y.length) return false;
  for (let c = 0; c < x.length; c++) {
    if (x.slice(c) + x.slice(0, c) === y) return true;
  }
  return false;
}

function doubled(x, y) {
  if (x.length !== y.length) return false;
  return (x + x).includes(y);
}

let t = performance.now();
const r1 = brute(a, b);
const bruteMs = performance.now() - t;

t = performance.now();
const r2 = doubled(a, b);
const fastMs = performance.now() - t;

console.log('try every cut :', r1, 'in', bruteMs.toFixed(1) + ' ms');
console.log('doubled string:', r2, 'in', fastMs.toFixed(2) + ' ms');
console.log('speed-up:', Math.round(bruteMs / Math.max(fastMs, 0.01)) + 'x');
console.log('');
console.log('Note: both are O(n^2) in the worst case. The win here is');
console.log('that the doubled version allocates ONE extra string and');
console.log('hands the search to a heavily optimised native routine,');
console.log('instead of building n separate rotations.');
Step 4

The better idea — write it twice

Think of the string as written around a circle. A rotation is just choosing a different starting point on the same circle — the letters and their cyclic order never change.

Now: how do you lay a circle out flat so that every starting point is visible? Write it twice.

  a = "abcde"

  a + a  =  "abcdeabcde"
             |||||
             abcde        cut 0
              |||||
              bcdea       cut 1
               |||||
               cdeab      cut 2
                |||||
                deabc     cut 3
                 |||||
                 eabcd    cut 4

  Every rotation of "abcde" is a window of length 5 inside
  "abcdeabcde". So "is b a rotation of a?" becomes
  "does b appear inside a + a?"
The unlock

(a + a).includes(b)

Doubling the string lays out every rotation, side by side, in one place. A substring search then checks all n of them at once.

Why the length check is not optional

The doubled trick alone is wrong without it:

  a = "abcde"     b = "abc"

  a + a  =  "abcdeabcde"
  does it contain "abc"?   YES, at position 0.

  But "abc" is obviously not a rotation of "abcde" -- it is not even
  the same length. `includes` finds any substring, not just the
  full-length windows we care about.

  So:  a.length === b.length  AND  (a + a).includes(b)

The length equality is what restricts includes to exactly the n windows of length n — which are precisely the rotations. That is the full proof, and it is what an interviewer is fishing for.

function rotationExplained(a, b) {
  console.log('a = "' + a + '"   b = "' + b + '"');

  if (a.length !== b.length) {
    console.log('lengths differ (' + a.length + ' vs ' + b.length + ') -> FALSE');
    console.log('');
    return false;
  }

  const doubled = a + a;
  console.log('a + a = "' + doubled + '"');
  console.log('looking for "' + b + '":');

  for (let pos = 0; pos < a.length; pos++) {
    const window = doubled.slice(pos, pos + b.length);
    const hit = window === b;
    console.log('  position ' + pos + ': "' + window + '"   ' + (hit ? 'MATCH' : 'no'));
    if (hit) {
      console.log('  -> b is a rotated left by ' + pos);
      console.log('');
      return true;
    }
  }

  console.log('  not found -> FALSE');
  console.log('');
  return false;
}

Step 6

Version 1 — without built-in methods

No includes, no slice, no + on whole strings. Instead: compare b against the doubled string using modular indexing, which avoids building the doubled string at all.

Version 1 — modular indexing, no allocation
function isRotationManual(a, b) {
  if (a.length !== b.length) return false;
  if (a.length === 0) return true;

  const n = a.length;

  // try every possible starting offset in a
  for (let offset = 0; offset < n; offset++) {

    let matches = true;

    for (let i = 0; i < n; i++) {
      // (offset + i) % n walks around the circle -- this IS the
      // doubled string, without building it
      if (a[(offset + i) % n] !== b[i]) {
        matches = false;
        break;
      }
    }

    if (matches) return true;
  }

  return false;
}

console.log(isRotationManual('waterbottle', 'erbottlewat'));   // true
console.log(isRotationManual('abcde', 'cdeab'));               // true
console.log(isRotationManual('abcde', 'abced'));               // false
console.log(isRotationManual('abc', 'abc'));                   // true
console.log(isRotationManual('aa', 'aaa'));                    // false
console.log(isRotationManual('', ''));                         // true
console.log(isRotationManual('aab', 'aba'));                   // true
console.log(isRotationManual('aab', 'baa'));                   // true
console.log(isRotationManual('abab', 'abab'));                 // true

(offset + i) % n is the same wrap-around modulo from Rotate Array. It makes the circle idea literal: index past the end and you come back to the start. This version is O(1) extra space — better than the one-liner on memory, worse on elegance.

and the one that also tells you the offset
function rotationOffset(a, b) {
  if (a.length !== b.length) return -1;
  if (a.length === 0) return 0;

  const n = a.length;

  for (let offset = 0; offset < n; offset++) {
    let ok = true;
    for (let i = 0; i < n; i++) {
      if (a[(offset + i) % n] !== b[i]) { ok = false; break; }
    }
    if (ok) return offset;
  }

  return -1;
}

console.log(rotationOffset('waterbottle', 'erbottlewat'));   // 3
console.log(rotationOffset('abcde', 'cdeab'));               // 2
console.log(rotationOffset('abcde', 'abcde'));               // 0
console.log(rotationOffset('abcde', 'abced'));               // -1

// A useful check: rebuilding a with that offset must give b.
const off = rotationOffset('abcde', 'cdeab');
console.log('rebuilt:', 'abcde'.slice(off) + 'abcde'.slice(0, off));   // 'cdeab'
Step 7

Version 2 — with built-in methods

Version 2 — the one-liner, with its guard
function isRotation(a, b) {
  return a.length === b.length && (a + a).includes(b);
}

console.log(isRotation('waterbottle', 'erbottlewat'));   // true
console.log(isRotation('abcde', 'cdeab'));               // true
console.log(isRotation('abcde', 'abced'));               // false
console.log(isRotation('abc', 'abc'));                   // true
console.log(isRotation('abcde', 'abc'));                 // false  -- the guard earns its keep
console.log(isRotation('', ''));                         // true
console.log(isRotation('a', 'a'));                       // true
console.log(isRotation('ab', 'ba'));                     // true

the array version, and the number version
// The same idea works on arrays.
function isArrayRotation(a, b) {
  if (a.length !== b.length) return false;
  const doubled = [...a, ...a];
  // find b inside doubled
  outer:
  for (let start = 0; start < a.length; start++) {
    for (let i = 0; i < b.length; i++) {
      if (doubled[start + i] !== b[i]) continue outer;
    }
    return true;
  }
  return false;
}

console.log(isArrayRotation([1,2,3,4,5], [3,4,5,1,2]));   // true
console.log(isArrayRotation([1,2,3,4,5], [3,4,5,2,1]));   // false
console.log(isArrayRotation([1,1,2], [1,2,1]));           // true

// And on numbers, via their digits:
function isDigitRotation(x, y) {
  const a = String(x), b = String(y);
  return a.length === b.length && (a + a).includes(b);
}

console.log(isDigitRotation(12345, 34512));   // true
console.log(isDigitRotation(12345, 34521));   // false
What includes costs

(a + a).includes(b) reads like O(n) but substring search is O(n·m) in the naive case — here O(n²), the same as trying every cut. In practice JavaScript engines use a fast search (Boyer–Moore-style) so it is dramatically quicker in real terms, as the Step 3 demo shows. If an interviewer asks for a guaranteed O(n), the answer is KMP — a linear-time substring search — applied to the doubled string. Naming it is usually enough.

O(n) for real: KMP on the doubled string
// Knuth-Morris-Pratt: find pattern inside text in O(text + pattern).
// The "failure table" says, after a mismatch, how far back in the
// PATTERN we can resume without re-reading the text.
function buildFailure(pattern) {
  const fail = new Array(pattern.length).fill(0);
  let len = 0;

  for (let i = 1; i < pattern.length; ) {
    if (pattern[i] === pattern[len]) {
      len++;
      fail[i] = len;
      i++;
    } else if (len > 0) {
      len = fail[len - 1];         // fall back, do not restart
    } else {
      fail[i] = 0;
      i++;
    }
  }

  return fail;
}

function kmpContains(text, pattern) {
  if (pattern.length === 0) return true;
  const fail = buildFailure(pattern);
  let j = 0;

  for (let i = 0; i < text.length; i++) {
    while (j > 0 && text[i] !== pattern[j]) j = fail[j - 1];
    if (text[i] === pattern[j]) j++;
    if (j === pattern.length) return true;
  }

  return false;
}

function isRotationKMP(a, b) {
  return a.length === b.length && kmpContains(a + a, b);
}

console.log(buildFailure('abcabd'));                     // [0,0,0,1,2,0]
console.log(isRotationKMP('waterbottle', 'erbottlewat'));// true
console.log(isRotationKMP('abcde', 'cdeab'));            // true
console.log(isRotationKMP('abcde', 'abced'));            // false
console.log(isRotationKMP('abcde', 'abc'));              // false

// Genuinely O(n) -- the text pointer i never moves backwards.
// Worth being able to name; rarely worth writing under time pressure.
Step 8

Complexity, in sentences

SolutionTimeSpace
Build every rotationO(n²)O(n)
Modular indexingO(n²)O(1)
(a+a).includes(b)O(n²) worst, fast in practiceO(n)
KMP on the doubled stringO(n)O(n)

The honest summary: the one-liner is not asymptotically better than trying every cut. What it avoids is allocating n strings, and it hands the search to a heavily optimised native routine. That is why it wins by orders of magnitude in the demo while having the same worst-case Big-O.

The modular-indexing version is the memory winner — O(1) extra space, no doubled string, no allocations at all.

Say this in the interview

“Every rotation of a appears as a window of length n inside a + a, because doubling lays the circle out flat. So b is a rotation exactly when the lengths match and a + a contains b. The length check is essential — without it any substring, like "abc" in "abcde", passes. Substring search is O(n²) worst case; with KMP it is O(n).”

Step 9

Mistakes people actually make

1. The one-liner without the length check

Broken — any substring passes
const broken = (a, b) => (a + a).includes(b);

console.log(broken('waterbottle', 'erbottlewat'));   // true   fine
console.log(broken('abcde', 'cdeab'));               // true   fine
console.log(broken('abcde', 'abc'));                 // TRUE   WRONG
console.log(broken('abcde', 'de'));                  // TRUE   WRONG
console.log(broken('abcde', ''));                    // TRUE   WRONG
console.log(broken('abcde', 'ea'));                  // TRUE   WRONG -- spans the join

// includes finds ANY substring. The length equality is what limits
// it to the n full-length windows, which are the rotations.

2. Confusing rotation with anagram

Broken — sorting checks the wrong thing
function broken(a, b) {
  return [...a].sort().join('') === [...b].sort().join('');
}

console.log(broken('abcde', 'cdeab'));   // true   -- correct, it IS a rotation
console.log(broken('abcde', 'abced'));   // TRUE   -- WRONG, that is only an anagram
console.log(broken('abc', 'cba'));       // TRUE   -- WRONG, 'cba' is not a rotation of 'abc'

// Every rotation is an anagram, but not every anagram is a rotation.
// Sorting throws away order, and order is the whole question here.
// Rotations of "abc" are exactly: "abc", "bca", "cab".

3. Only checking one specific cut

Broken — assumes where the cut is
function broken(a, b) {
  if (a.length !== b.length) return false;
  // guess the cut point from where a[0] appears in b
  const cut = b.indexOf(a[0]);
  if (cut === -1) return false;
  return b.slice(cut) + b.slice(0, cut) === a;
}

console.log(broken('abcde', 'cdeab'));   // true   fine
console.log(broken('aab', 'aba'));       // false  WRONG, should be true

// With "aab" and "aba": a[0] is 'a', and indexOf finds the FIRST 'a'
// in "aba" at index 0. Rotating by 0 gives "aba" !== "aab", so it
// reports false. The correct cut was index 2.
// Repeated characters make "find the cut" ambiguous -- you would
// have to try every occurrence, which is the brute force again.

4. Forgetting that a zero rotation counts

isRotation("abc", "abc") is true — cutting at position 0 is a valid rotation. The one-liner gets this right for free ("abcabc" contains "abc"). A hand-written loop that starts at offset = 1 does not. Confirm the expected answer if the problem statement is ambiguous.

5. Building the doubled string inside a loop

correct but wasteful
const N = 30000;
let a = '';
for (let i = 0; i < N; i++) a += String.fromCharCode(97 + (i % 26));
const b = a.slice(1000) + a.slice(0, 1000);

function insideLoop(x, y) {
  if (x.length !== y.length) return false;
  for (let i = 0; i < x.length; i++) {
    const doubled = x + x;              // rebuilt every iteration -- bug
    if (doubled.slice(i, i + y.length) === y) return true;
  }
  return false;
}

function outsideLoop(x, y) {
  if (x.length !== y.length) return false;
  const doubled = x + x;                // built once
  for (let i = 0; i < x.length; i++) {
    if (doubled.slice(i, i + y.length) === y) return true;
  }
  return false;
}

let t = performance.now();
const r1 = insideLoop(a, b);
const inMs = performance.now() - t;

t = performance.now();
const r2 = outsideLoop(a, b);
const outMs = performance.now() - t;

console.log('doubled inside the loop  :', r1, 'in', inMs.toFixed(1) + ' ms');
console.log('doubled once, outside    :', r2, 'in', outMs.toFixed(1) + ' ms');

// Anything that does not change between iterations belongs OUTSIDE
// the loop. This is not a rotation-specific lesson.
Step 10

Practice before you move on

  1. Say the proof out loud in two sentences: why doubling exposes every rotation, and why the length check is required. That is the entire interview answer.
  2. Return the rotation offset rather than a boolean. It is in Step 6 — write it from memory, and check it on a string with repeated characters.
  3. Rotate a string by k. Combine with Rotate Array: which is s.slice(k) + s.slice(0, k), and take k % n first.
  4. Search in a rotated sorted array. A different problem with the same circular idea, and it appears in the searching topic in this collection.
  5. The smallest rotation. Which rotation of a string is alphabetically first? Brute force is O(n²); Booth’s algorithm does it in O(n). Try the brute force, then look up why the fast version is hard.
What to carry forward

Doubling turns a circular problem into a linear one. Whenever something wraps around — rotations, circular arrays, ring buffers, a round table — concatenating the structure with itself lets you use ordinary linear tools on it. Circular Maximum Subarray, circular queues and cyclic string matching all use the same move. The companion trick, when you cannot afford the copy, is modular indexing: (i + offset) % n walks the circle without building it.
