Strings · Problem 04

Longest Palindromic Substring

Stop looking for palindromes and start growing them. Stand at each possible centre and push outwards while the characters match. The only genuinely tricky part is realising there are 2n−1 centres, not n.

Step 1

The problem

Find the longest contiguous stretch of the string that reads the same forwards and backwards.

InputAnswerNote
"babad""bab""aba" is equally valid
"cbbd""bb"even length
"a""a"one character is a palindrome
"ac""a"or "c" — no pair matches
"forgeeksskeegfor""geeksskeeg"hidden in the middle

Two facts that are easy to skate past and both matter:

  • Every single character is a palindrome of length 1. So the answer is never empty unless the string is.
  • Palindromes come in two shapes: odd length, with a character at the centre ("aba"), and even length, with the centre falling between two characters ("abba"). Handling only one shape is the classic half-solution.
Substring, not subsequence — again

In "character" the letters c, a, r, a, c form a palindrome but they are scattered. The answer must be one solid run. "carac" is not a substring of "character".

Step 2

Think first — the obvious answer

Generate every substring, test each one, keep the longest palindrome.

Version 0 — every substring
function isPalindrome(s) {
  let lo = 0, hi = s.length - 1;
  while (lo < hi) {
    if (s[lo] !== s[hi]) return false;
    lo++;
    hi--;
  }
  return true;
}

function longestPalindromeBrute(s) {
  let best = '';

  for (let start = 0; start < s.length; start++) {
    for (let end = start; end < s.length; end++) {
      const piece = s.slice(start, end + 1);

      if (piece.length > best.length && isPalindrome(piece)) {
        best = piece;
      }
    }
  }

  return best;
}

console.log(longestPalindromeBrute('babad'));            // 'bab'
console.log(longestPalindromeBrute('cbbd'));             // 'bb'
console.log(longestPalindromeBrute('a'));                // 'a'
console.log(longestPalindromeBrute('ac'));               // 'a'
console.log(longestPalindromeBrute('forgeeksskeegfor')); // 'geeksskeeg'
console.log(longestPalindromeBrute(''));                 // ''

The isPalindrome helper is two pointers walking towards each other — the same shape as reversing an array in place, just comparing instead of swapping. Note the piece.length > best.length check comes first: there is no point testing a substring that could not beat what you already have.

Step 3

Why it is slow

There are about n²/2 substrings, and checking each one walks up to n characters: O(n³). A 1,000-character string is a billion operations.

And the waste is easy to see. Testing "abcba" compares the outer a’s, then the b’s, then the middle. Testing "bcb" a moment later re-compares the b’s and the middle — work already done.

Timing demo
// The worst case for checking every substring: a string where EVERY
// substring is a palindrome, so no check can ever exit early.
const N = 800;
let s = '';
for (let i = 0; i < N; i++) s += 'a';

function isPal(str, lo, hi) {
  while (lo < hi) { if (str[lo] !== str[hi]) return false; lo++; hi--; }
  return true;
}

function brute(str) {
  let bs = 0, bl = 0;
  for (let i = 0; i < str.length; i++)
    for (let j = i; j < str.length; j++)
      if (isPal(str, i, j) && j - i + 1 > bl) { bs = i; bl = j - i + 1; }
  return str.slice(bs, bs + bl);
}

function expand(str) {
  let bs = 0, bl = 1;
  const grow = (lo, hi) => {
    while (lo >= 0 && hi < str.length && str[lo] === str[hi]) { lo--; hi++; }
    return [lo + 1, hi - lo - 1];
  };
  for (let i = 0; i < str.length; i++) {
    const [s1, l1] = grow(i, i);
    if (l1 > bl) { bs = s1; bl = l1; }
    const [s2, l2] = grow(i, i + 1);
    if (l2 > bl) { bs = s2; bl = l2; }
  }
  return str.slice(bs, bs + bl);
}

const a = brute(s);
const bruteMs = performance.now() - t;

t = performance.now();
const b = expand(s);
const fastMs = performance.now() - t;

console.log('speed-up:', Math.round(bruteMs / Math.max(fastMs, 0.01)) + 'x');
Step 4

The better idea — grow from the middle

A palindrome is symmetric about its centre. So instead of picking two ends and checking whether what is between them happens to be symmetric, pick the centre and push outwards while the characters match.

The unlock

Stand at a centre. Compare the characters immediately left and right. If they match, step both pointers outwards and compare again. Stop when they differ or you run off an end. Whatever you walked over is the longest palindrome with that centre.

  s = "babad",  centre at index 1 (the 'a')

     b  a  b  a  d
        ^
     lo=1 hi=1        "a"           match trivially, expand
     lo=0 hi=2        b == b        "bab"    expand
     lo=-1 hi=3       off the left end -> stop

  longest palindrome centred at index 1 is "bab", length 3

Why 2n−1 centres

Here is the part people miss. An odd-length palindrome is centred on a character. An even-length one is centred between two characters. So the centres are:

   s =    b   a   b   a   d
        ^ | ^ | ^ | ^ | ^ |
          0   1   2   3   4      <- 5 character centres  (odd lengths)
            ^   ^   ^   ^
           0|1 1|2 2|3 3|4       <- 4 gap centres        (even lengths)

   total: 5 + 4 = 9 = 2n - 1

In code that is two expansions per index: one starting at (i, i) for odd, one at (i, i + 1) for even. The even one immediately fails when s[i] !== s[i+1], which costs nothing.

Missing the even centres

Solutions that only expand from (i, i) return "b" for "cbbd" instead of "bb", and "a" for "aa". Test on an even-length palindrome every single time.

the algorithm, narrating itself
function longestExplained(s) {
  if (s.length === 0) return '';

  let bestStart = 0, bestLen = 1;

  function expand(lo, hi, label) {
    const startLo = lo, startHi = hi;
    while (lo >= 0 && hi < s.length && s[lo] === s[hi]) { lo--; hi++; }
    lo++; hi--;                       // step back onto the last match
    const len = hi - lo + 1;
    const text = len > 0 ? s.slice(lo, hi + 1) : '';
    console.log('  ' + label + ' (' + startLo + ',' + startHi + ')  ->  "' +
                text + '"  length ' + len);
    return [lo, len];
  }

  console.log('s = "' + s + '"');
  console.log('');

  for (let i = 0; i < s.length; i++) {
    console.log('centre index ' + i + ':');

    const [oddStart, oddLen] = expand(i, i, 'odd ');
    if (oddLen > bestLen) {
      bestStart = oddStart; bestLen = oddLen;
      console.log('        NEW BEST "' + s.slice(bestStart, bestStart + bestLen) + '"');
    }

    const [evenStart, evenLen] = expand(i, i + 1, 'even');
    if (evenLen > bestLen) {
      bestStart = evenStart; bestLen = evenLen;
      console.log('        NEW BEST "' + s.slice(bestStart, bestStart + bestLen) + '"');
    }
  }

  console.log('');
  return s.slice(bestStart, bestStart + bestLen);
}

Step 6

Version 1 — without built-in methods

Version 1 — expand around centre, loops only
function longestPalindromeManual(s) {
  if (s.length === 0) return '';

  let bestStart = 0;
  let bestLength = 1;         // a single character always works

  for (let i = 0; i < s.length; i++) {

    // ---- odd length: centre ON character i ----
    let lo = i;
    let hi = i;
    while (lo >= 0 && hi < s.length && s[lo] === s[hi]) {
      lo--;
      hi++;
    }
    // the loop overshot by one on both sides
    let length = (hi - 1) - (lo + 1) + 1;
    if (length > bestLength) {
      bestLength = length;
      bestStart = lo + 1;
    }

    // ---- even length: centre BETWEEN i and i+1 ----
    lo = i;
    hi = i + 1;
    while (lo >= 0 && hi < s.length && s[lo] === s[hi]) {
      lo--;
      hi++;
    }
    length = (hi - 1) - (lo + 1) + 1;
    if (length > bestLength) {
      bestLength = length;
      bestStart = lo + 1;
    }
  }

  // build the answer without slice
  let result = '';
  for (let k = bestStart; k < bestStart + bestLength; k++) {
    result = result + s[k];
  }
  return result;
}

console.log(longestPalindromeManual('babad'));             // 'bab'
console.log(longestPalindromeManual('cbbd'));              // 'bb'
console.log(longestPalindromeManual('a'));                 // 'a'
console.log(longestPalindromeManual('ac'));                // 'a'
console.log(longestPalindromeManual('aa'));                // 'aa'
console.log(longestPalindromeManual('racecar'));           // 'racecar'
console.log(longestPalindromeManual('forgeeksskeegfor'));  // 'geeksskeeg'
console.log(longestPalindromeManual(''));                  // ''
console.log(longestPalindromeManual('abcde'));             // 'a'
The overshoot — the most common bug on this page

When the while loop ends, lo and hi have already moved past the last matching pair — either onto a mismatch or off the end. So the palindrome actually runs from lo + 1 to hi - 1, and its length is hi - lo - 1.

Check it on "aba" centred at index 1: the loop ends with lo = -1, hi = 3. Length is 3 - (-1) - 1 = 3. Correct. Writing hi - lo + 1 gives 5, which is longer than the whole string.

Version 2 — with built-in methods

Version 2 — the interview answer
function longestPalindrome(s) {
  if (s.length < 2) return s;

  let start = 0;
  let maxLength = 1;

  // returns [start, length] of the palindrome grown from this centre
  function expand(lo, hi) {
    while (lo >= 0 && hi < s.length && s[lo] === s[hi]) {
      lo--;
      hi++;
    }
    return [lo + 1, hi - lo - 1];      // step back in, then measure
  }

  for (let i = 0; i < s.length; i++) {
    const [oddStart,  oddLen]  = expand(i, i);       // odd centre
    const [evenStart, evenLen] = expand(i, i + 1);   // even centre

    if (oddLen > maxLength)  { start = oddStart;  maxLength = oddLen; }
    if (evenLen > maxLength) { start = evenStart; maxLength = evenLen; }
  }

  return s.slice(start, start + maxLength);
}

the related helpers you will actually write
// Is a string a palindrome? Two pointers, no allocation.
function isPalindrome(s) {
  let lo = 0, hi = s.length - 1;
  while (lo < hi) {
    if (s[lo] !== s[hi]) return false;
    lo++; hi--;
  }
  return true;
}

console.log(isPalindrome('racecar'));   // true
console.log(isPalindrome('abba'));      // true
console.log(isPalindrome('abc'));       // false

// The one-liner people reach for -- correct, but allocates two
// whole new strings and is measurably slower on long input.
const isPalReverse = s => s === [...s].reverse().join('');
console.log(isPalReverse('racecar'));   // true

// Count ALL palindromic substrings -- same expansion, count instead
// of measuring. This is a common follow-up.
function countPalindromes(s) {
  let count = 0;
  const expand = (lo, hi) => {
    while (lo >= 0 && hi < s.length && s[lo] === s[hi]) { count++; lo--; hi++; }
  };
  for (let i = 0; i < s.length; i++) { expand(i, i); expand(i, i + 1); }
  return count;
}

console.log(countPalindromes('abc'));    // 3   a, b, c
console.log(countPalindromes('aaa'));    // 6   a,a,a, aa,aa, aaa
console.log(countPalindromes('aba'));    // 4   a,b,a, aba
the dynamic-programming version, for completeness
// dp[i][j] = "is s[i..j] a palindrome?"
// Build it up by length, because a longer palindrome depends on the
// shorter one inside it.
function longestPalindromeDP(s) {
  const n = s.length;
  if (n < 2) return s;

  const dp = Array.from({ length: n }, () => new Array(n).fill(false));
  let start = 0, maxLen = 1;

  for (let i = 0; i < n; i++) dp[i][i] = true;               // length 1

  for (let i = 0; i < n - 1; i++) {                          // length 2
    if (s[i] === s[i + 1]) { dp[i][i + 1] = true; start = i; maxLen = 2; }
  }

  for (let len = 3; len <= n; len++) {                       // length 3 and up
    for (let i = 0; i + len - 1 < n; i++) {
      const j = i + len - 1;
      // ends match AND the inside is already known to be a palindrome
      if (s[i] === s[j] && dp[i + 1][j - 1]) {
        dp[i][j] = true;
        start = i;
        maxLen = len;
      }
    }
  }

  return s.slice(start, start + maxLen);
}

console.log(longestPalindromeDP('babad'));             // 'bab' or 'aba'
console.log(longestPalindromeDP('cbbd'));              // 'bb'
console.log(longestPalindromeDP('forgeeksskeegfor'));  // 'geeksskeeg'

// Same O(n^2) time as expansion, but O(n^2) SPACE for the table.
// Expansion is strictly better here. Know the DP version because
// interviewers ask "can you do it with DP?" -- then say why you
// would not.
Step 8

Complexity, in sentences

SolutionTimeSpace
Every substringO(n³)O(n)
Dynamic programmingO(n²)O(n²)
Expand around centreO(n²)O(1)
Manacher’s algorithmO(n)O(n)

Why expansion is O(n²) and not O(n). There are 2n−1 centres, and each expansion can walk up to n/2 steps in each direction. So the worst case — a string like "aaaaaaaa", where every expansion runs to the ends — is about n²/2 comparisons.

O(1) space is the win over the DP version: you hold two indexes and a best-so-far, never a table. Same time complexity, dramatically less memory, and simpler code.

Manacher’s algorithm gets it to O(n) by reusing information from palindromes already found — if you are inside a known palindrome, its mirror tells you a lower bound for free. It is genuinely intricate and almost never expected. Mention that it exists; do not attempt it under time pressure.

Say this in the interview

“Checking every substring is O(n³). Instead, every palindrome has a centre, so I expand outwards from each of the 2n−1 centres — n character centres for odd lengths and n−1 gap centres for even — keeping the longest. O(n²) time, O(1) space. There is a DP formulation with the same time but O(n²) space, and Manacher’s gets it to O(n) if you need it.”

Step 9

Mistakes people actually make

1. Only handling odd-length palindromes

Broken — no even centres
function broken(s) {
  if (s.length < 2) return s;
  let start = 0, maxLen = 1;
  for (let i = 0; i < s.length; i++) {
    let lo = i, hi = i;                 // only odd centres -- bug
    while (lo >= 0 && hi < s.length && s[lo] === s[hi]) { lo--; hi++; }
    const len = hi - lo - 1;
    if (len > maxLen) { maxLen = len; start = lo + 1; }
  }
  return s.slice(start, start + maxLen);
}

3. Slicing strings inside the loop

correct but wasteful
const N = 4000;
let s = '';
for (let i = 0; i < N; i++) s += 'a';

function withSlicing(str) {
  let best = '';
  const expand = (lo, hi) => {
    while (lo >= 0 && hi < str.length && str[lo] === str[hi]) {
      const piece = str.slice(lo, hi + 1);      // new string every step
      if (piece.length > best.length) best = piece;
      lo--; hi++;
    }
  };
  for (let i = 0; i < str.length; i++) { expand(i, i); expand(i, i + 1); }
  return best;
}

function withIndexes(str) {
  let start = 0, maxLen = str.length ? 1 : 0;
  const expand = (lo, hi) => {
    while (lo >= 0 && hi < str.length && str[lo] === str[hi]) { lo--; hi++; }
    const len = hi - lo - 1;
    if (len > maxLen) { maxLen = len; start = lo + 1; }
  };
  for (let i = 0; i < str.length; i++) { expand(i, i); expand(i, i + 1); }
  return str.slice(start, start + maxLen);
}

4. Returning the length instead of the string

The question asks for the substring. maxLength is what you tracked; the answer is s.slice(start, start + maxLength). Read the return type before you write the last line.

5. Not handling the empty string or a single character

"" should give "", and "a" should give "a". Initialising maxLength = 1 unconditionally is wrong for the empty string — you would slice a character that is not there. Guard with if (s.length < 2) return s;, which handles both at once.

Step 10

Practice before you move on

  1. Write the expand function from memory, then verify the overshoot arithmetic by hand on "aba". That one check catches the most common bug on this page.
  2. Count all palindromic substrings. It is in Step 7 — cover it and rewrite it. The only change is counting inside the loop instead of measuring after it.
  3. Longest palindromic subsequence. Letters may be skipped now, so expansion no longer applies — this one genuinely needs DP. Doing both makes the difference between substring and subsequence permanent.
  4. Shortest palindrome. Add the fewest characters to the front to make the whole string a palindrome. Hint: find the longest palindromic prefix.
  5. Palindrome Partitioning. Split the string so every piece is a palindrome. Backtracking, using the palindrome check from this page — and it sits in the recursion topic later in this collection.
What to carry forward

Build the thing you are looking for instead of testing candidates. Checking every substring asks “is this one a palindrome?” n² times. Expanding from centres asks “how far does the palindrome here reach?” 2n−1 times, and every comparison contributes to an answer. When a structure has a defining property — a centre, a peak, a root — enumerating those is usually cheaper than enumerating candidates and filtering.
