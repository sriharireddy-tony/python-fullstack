Strings · Problem 02

Group Anagrams

The whole problem is one question: what could I compute from a word that is identical for all its anagrams and different for everything else? Find that, and the grouping is a four-line loop. This idea is called a canonical key.

Step 1

The problem

Given a list of words, group together the ones that are anagrams of each other — same letters, same counts, different order.

InputAnswer
["eat","tea","tan","ate","nat","bat"][["eat","tea","ate"], ["tan","nat"], ["bat"]]
[""][[""]]
["a"][["a"]]
["abc","cba","xyz"][["abc","cba"], ["xyz"]]

A word with no anagram partner still forms a group of one — "bat" above. The order of the groups usually does not matter, and neither does the order within a group, but ask if you are unsure.

What makes two words anagrams

Exactly one thing: the multiset of characters is equal. "eat" and "tea" both have one e, one a, one t. Length must match too, but that follows automatically from the counts matching.

Step 2

Think first — the obvious answer

Take the first word, scan the rest for its anagrams, pull them into a group, repeat with what is left.

Version 0 — compare every pair
function isAnagram(a, b) {
  if (a.length !== b.length) return false;
  const counts = {};
  for (const ch of a) counts[ch] = (counts[ch] || 0) + 1;
  for (const ch of b) {
    if (!counts[ch]) return false;
    counts[ch]--;
  }
  return true;
}

function groupAnagramsBrute(words) {
  const used = new Array(words.length).fill(false);
  const groups = [];

  for (let i = 0; i < words.length; i++) {
    if (used[i]) continue;

    const group = [words[i]];
    used[i] = true;

    for (let j = i + 1; j < words.length; j++) {
      if (!used[j] && isAnagram(words[i], words[j])) {
        group.push(words[j]);
        used[j] = true;
      }
    }

    groups.push(group);
  }

  return groups;
}

console.log(groupAnagramsBrute(["eat","tea","tan","ate","nat","bat"]));
// [["eat","tea","ate"], ["tan","nat"], ["bat"]]
console.log(groupAnagramsBrute(["abc","cba","xyz"]));
console.log(groupAnagramsBrute([""]));

The isAnagram helper is worth reading on its own: count the letters of the first word, then spend them against the second. If you ever need a letter that is not in the budget, they are not anagrams. That is the whole of the next problem on this list.

Step 3

Why it is slow

Every word is compared against every other word, and each comparison walks both words. With n words of average length k that is O(n² · k). Ten thousand words means fifty million comparisons, each doing real work.

Timing demo
// 6,000 words, each a shuffle of one of 300 base words
const bases = [];
for (let i = 0; i < 300; i++) {
  let w = '';
  for (let k = 0; k < 8; k++) w += String.fromCharCode(97 + ((i * 7 + k * 3) % 26));
  bases.push(w);
}
const words = [];
for (let i = 0; i < 6000; i++) {
  const chars = [...bases[i % bases.length]];
  for (let j = chars.length - 1; j > 0; j--) {
    const k = Math.floor(Math.random() * (j + 1));
    [chars[j], chars[k]] = [chars[k], chars[j]];
  }
  words.push(chars.join(''));
}

function same(a, b) {
  if (a.length !== b.length) return false;
  const c = {};
  for (const ch of a) c[ch] = (c[ch] || 0) + 1;
  for (const ch of b) { if (!c[ch]) return false; c[ch]--; }
  return true;
}

function brute(list) {
  const used = new Array(list.length).fill(false);
  const groups = [];
  for (let i = 0; i < list.length; i++) {
    if (used[i]) continue;
    const g = [list[i]]; used[i] = true;
    for (let j = i + 1; j < list.length; j++)
      if (!used[j] && same(list[i], list[j])) { g.push(list[j]); used[j] = true; }
    groups.push(g);
  }
  return groups;
}

function byKey(list) {
  const map = new Map();
  for (const w of list) {
    const key = [...w].sort().join('');
    if (!map.has(key)) map.set(key, []);
    map.get(key).push(w);
  }
  return [...map.values()];
}

let t = performance.now();
const a = brute(words);
const bruteMs = performance.now() - t;

t = performance.now();
const b = byKey(words);
const fastMs = performance.now() - t;

console.log('all pairs   :', a.length, 'groups in', bruteMs.toFixed(1) + ' ms');
console.log('canonical key:', b.length, 'groups in', fastMs.toFixed(1) + ' ms');
console.log('same grouping:', a.length === b.length);
console.log('speed-up:', Math.round(bruteMs / Math.max(fastMs, 0.01)) + 'x');
Step 4

The better idea — a canonical key

Comparing everything to everything is the shape of a problem that should be a hash map. But a hash map needs a key, and words that are anagrams are all different strings. So invent a key they share.

The unlock

Compute something from each word that is identical for all its anagrams. The simplest such thing: sort its letters.

"eat", "tea" and "ate" all sort to "aet". "tan" and "nat" both sort to "ant". Now just bucket the words by that key.

  word    sorted key    bucket

  eat  ->   aet         aet: [eat]
  tea  ->   aet         aet: [eat, tea]
  tan  ->   ant         ant: [tan]
  ate  ->   aet         aet: [eat, tea, ate]
  nat  ->   ant         ant: [tan, nat]
  bat  ->   abt         abt: [bat]

  answer = the bucket values

One pass over the words, and each word is touched once. The comparison between words has vanished entirely — that is what a good key buys you.

A second key: the letter counts

Sorting a word of length k costs k log k. You can do better with a count signature — how many of each letter, written as a string:

two keys for the same word
"eat"   sorted key:  "aet"
        count key:   "1#0#0#0#1#0#...#1#0#0#0#0#0#0"
                      a b c d e         t
                      one a, one e, one t, zero everywhere else

Building that is O(k) instead of O(k log k). For short words it does not matter; for long ones, or a restricted alphabet, it does. Both are legitimate answers — mention both and say which you would pick.

Why the separator in the count key matters

Without one, a word with 11 a’s and a word with 1 a and 1 b would both produce "11...". Joining the counts with # or , keeps them apart. This is a real bug that only shows up on inputs with repeated letters — exactly the kind that never makes it into a hand-written test.

The groups come out in the order their first member appeared, because JavaScript’s Map preserves insertion order. That is a genuinely useful property and one reason to prefer Map over a plain object here.

the algorithm, narrating itself
function groupExplained(words) {

  console.log('words =', words);

Step 6

Version 1 — without built-in methods

No sort, no split, no Map. The count-signature key, built by hand, which conveniently avoids needing a sort at all.

Version 1 — count signature, plain object
function groupAnagramsManual(words) {
  const buckets = {};      // key -> array of words
  const keyOrder = [];     // remember insertion order ourselves

  for (let i = 0; i < words.length; i++) {
    const word = words[i];

    // count the 26 lowercase letters
    const counts = [];
    for (let k = 0; k < 26; k++) counts[k] = 0;

    for (let c = 0; c < word.length; c++) {
      const code = word.charCodeAt(c) - 97;    // 'a' is 97
      counts[code] = counts[code] + 1;
    }

    // turn the counts into a string, with separators
    let key = '';
    for (let k = 0; k < 26; k++) {
      key = key + counts[k] + '#';
    }

    if (!Object.prototype.hasOwnProperty.call(buckets, key)) {
      buckets[key] = [];
      keyOrder[keyOrder.length] = key;
    }

    buckets[key][buckets[key].length] = word;
  }

  // collect the buckets in the order the keys first appeared
  const result = [];
  for (let i = 0; i < keyOrder.length; i++) {
    result[i] = buckets[keyOrder[i]];
  }

  return result;
}

console.log(groupAnagramsManual(["eat","tea","tan","ate","nat","bat"]));
// [["eat","tea","ate"], ["tan","nat"], ["bat"]]
console.log(groupAnagramsManual(["abc","cba","xyz"]));
console.log(groupAnagramsManual([""]));            // [[""]]
console.log(groupAnagramsManual(["a"]));           // [["a"]]
console.log(groupAnagramsManual(["aab","aba","baa","ab"]));
// [["aab","aba","baa"], ["ab"]]
Why keyOrder exists

A plain object does not reliably preserve insertion order: keys that look like non-negative integers get sorted numerically and listed first. Our keys start with digits, so this is a real risk. Tracking the order in a separate array removes the doubt entirely — or use a Map, which guarantees insertion order for every key type.

see the object key-order surprise
const o = {};
o['banana'] = 1;

console.log(Object.keys(o));     // ['1','2','banana','apple']  -- digits first!

const m = new Map();

m.set('2', 2);
m.set('apple', 3);
m.set('1', 4);
console.log([...m.keys()]);      // ['banana','2','apple','1']  -- as inserted
Step 7

Version 2 — with built-in methods

Version 2a — sorted key, the interview answer
function groupAnagrams(words) {
  const map = new Map();

  for (const word of words) {
    const key = [...word].sort().join('');    // canonical form

    if (!map.has(key)) map.set(key, []);
    map.get(key).push(word);
  }

  return [...map.values()];
}

console.log(groupAnagrams(["eat","tea","tan","ate","nat","bat"]));
console.log(groupAnagrams(["listen","silent","enlist","inlets","google"]));
console.log(groupAnagrams([""]));
console.log(groupAnagrams(["a"]));
word.sort() does not exist

Strings have no sort method — they are immutable. You must explode the string into an array first ([...word] or word.split('')), sort that, and join it back. Prefer [...word]: it iterates by code point, so it handles emoji and other non-BMP characters correctly, where split('') would cut them in half.

Version 2b — count key, avoids the sort
function groupAnagramsCounts(words) {
  const map = new Map();

  for (const word of words) {
    const counts = new Array(26).fill(0);
    for (const ch of word) counts[ch.charCodeAt(0) - 97]++;
    const key = counts.join('#');            // separators matter

    if (!map.has(key)) map.set(key, []);
    map.get(key).push(word);
  }

  return [...map.values()];
}

console.log(groupAnagramsCounts(["eat","tea","tan","ate","nat","bat"]));
console.log(groupAnagramsCounts(["aab","aba","baa","ab"]));

// O(n*k) instead of O(n*k log k). Only works for a known alphabet
// though -- here, lowercase a-z. For arbitrary characters, use a Map
// of counts and sort its entries, or just sort the string.
Version 2c — reduce, and a general key function
// The pattern extracted: group anything by any key.
function groupBy(items, keyOf) {
  return items.reduce((map, item) => {
    const key = keyOf(item);
    if (!map.has(key)) map.set(key, []);
    map.get(key).push(item);
    return map;
  }, new Map());
}

const words = ["eat","tea","tan","ate","nat","bat"];
console.log([...groupBy(words, w => [...w].sort().join('')).values()]);

// the same helper, different key -- this is the point
console.log([...groupBy(words, w => w.length).entries()]);
console.log([...groupBy(words, w => w[0]).entries()]);

const people = [
  { name: 'ana', team: 'red' }, { name: 'bo', team: 'blue' },
  { name: 'cy', team: 'red' }
];
console.log([...groupBy(people, p => p.team).entries()]);

// Object.groupBy exists in newer runtimes and does exactly this:
if (typeof Object.groupBy === 'function') {
  console.log(Object.groupBy(words, w => [...w].sort().join('')));
}

That groupBy helper is the real prize. Group Anagrams is one instance of it, and “group an array of objects by a key” is a Tier 4 problem on this same list — the same six lines.

Step 8

Complexity, in sentences

SolutionTimeSpace
Compare every pairO(n² · k)O(n)
Sorted keyO(n · k log k)O(n · k)
Count keyO(n · k)O(n · k)

where n is the number of words and k the length of the longest one.

The sorted key does n sorts of k characters: n · k log k. The count key does n passes of k characters plus building a fixed-size key: n · k. Both store every word once plus a key per group, so O(n·k) space.

In practice, for typical English words (k under 15), the sorted key is faster — join('#') over 26 counters costs more than sorting 8 characters. Say that. Knowing when the asymptotically-better option loses on real inputs is a senior-sounding observation.

Say this in the interview

“Comparing every pair is O(n²k). Instead I compute a canonical key that is the same for all anagrams — the sorted letters — and bucket the words in a Map by that key. One pass, O(n·k log k). If the alphabet is fixed I can use a 26-element count signature instead of sorting, which drops it to O(n·k); I would separate the counts so 11 and 1,1 do not collide.”

Step 9

Mistakes people actually make

1. A count key with no separators

Broken — keys collide
function broken(words) {
  const map = new Map();
  for (const word of words) {
    const counts = new Array(26).fill(0);
    for (const ch of word) counts[ch.charCodeAt(0) - 97]++;
    const key = counts.join('');          // no separator -- bug
    if (!map.has(key)) map.set(key, []);
    map.get(key).push(word);
  }
  return [...map.values()];
}

// 'a' repeated 11 times vs 1 'a' and 1 'b':
const a11 = 'aaaaaaaaaaa';
const ab  = 'ab';
console.log(broken([a11, ab]));
// [["aaaaaaaaaaa","ab"]]   WRONG -- grouped together

// a11 gives counts [11,0,0,...]  ->  "1100000..."
// ab  gives counts [1,1,0,...]   ->  "1100000..."
// identical strings, different words.

3. Sorting with the default comparator on numbers

Not an issue for letters — the default string comparison is exactly what you want here. It is an issue if you ever build a key from numeric values. The rule from Three Sum still applies: numbers need (a, b) => a - b.

4. Overwriting the bucket instead of appending

Broken — keeps only the last word
function broken(words) {
  const map = new Map();
  for (const word of words) {
    const key = [...word].sort().join('');
    map.set(key, word);         // set, not push -- bug
  }
  return [...map.values()];
}

console.log(broken(["eat","tea","tan","ate","nat","bat"]));
// ["ate","nat","bat"]   WRONG -- one word per group, the last seen

// The map value must be an ARRAY you append to, not the word itself.

5. Assuming lowercase ASCII

The 26-element count key breaks on uppercase, digits, spaces and accents — 'A'.charCodeAt(0) - 97 is -32, which writes to a negative array index and silently produces a broken key. If the input is not guaranteed lowercase a–z, use the sorted key, or a Map of character counts whose entries you sort.

a key that works on any characters
function anyCharKey(word) {
  const counts = new Map();
  for (const ch of word) counts.set(ch, (counts.get(ch) || 0) + 1);
  return [...counts.entries()]
    .sort((a, b) => a[0] < b[0] ? -1 : a[0] > b[0] ? 1 : 0)
    .map(([ch, n]) => ch + n)
    .join('|');
}

console.log(anyCharKey('Eat!'));    // '!1|E1|a1|t1'
console.log(anyCharKey('at!E'));    // '!1|E1|a1|t1'  -- same key
console.log(anyCharKey('aab'));     // 'a2|b1'
console.log(anyCharKey('ab'));      // 'a1|b1'  -- no collision
Step 10

Practice before you move on

  1. Write the six-line Map version from memory, then say out loud what “canonical key” means in one sentence.
  2. Valid Anagram. Just two words — the next page. You have already written the helper in Step 2.
  3. Find all anagrams of a pattern inside a string. A sliding window carrying a count signature, compared against the pattern’s signature at each step. It combines this page with the previous one.
  4. Group by any rule. Reuse the groupBy helper to group words by length, by first letter, and by “set of distinct letters”. Notice that only the key function changes.
  5. Group numbers that are permutations of each other’s digits. 123 and 321 together. What is the canonical key for a number?
What to carry forward

When a problem asks you to find things that are “the same” under some transformation, do not compare them — compute a canonical form and bucket by it. Anagrams sort to the same string; shifted strings normalise to the same offset pattern; isomorphic strings map to the same numbering. Finding the right key turns an O(n²) comparison problem into an O(n) grouping problem, every time.
