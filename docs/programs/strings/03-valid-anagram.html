Strings · Problem 03

Valid Anagram

A short problem carrying one durable habit: count, then spend. Build a budget of characters from the first string and pay it down with the second. If the budget ever goes negative, the answer is no.

Step 1

The problem

Given two strings, decide whether the second is an anagram of the first — same characters, same counts, any order.

stAnswerWhy
"anagram""nagaram"true3 a’s, 1 n, 1 g, 1 r, 1 m in both
"rat""car"falset against c
"a""ab"falsedifferent lengths
""""truetrivially
"aacc""ccac"falsesame letters, different counts
The row that catches half-solutions

"aacc" and "ccac" use exactly the same set of characters — a and c — and are the same length. They are still not anagrams, because "aacc" has two a’s and "ccac" has one. Any solution built on Set rather than counts gets this wrong.

And before anything else: if the lengths differ, return false immediately. It is one line, it is always correct, and it saves the whole rest of the work on most negative cases.

Step 2

Think first — the obvious answers

Version 0a — sort both and compare
function isAnagramSort(s, t) {
  if (s.length !== t.length) return false;
  return [...s].sort().join('') === [...t].sort().join('');
}

console.log(isAnagramSort('anagram', 'nagaram'));   // true
console.log(isAnagramSort('rat', 'car'));           // false
console.log(isAnagramSort('aacc', 'ccac'));         // false
console.log(isAnagramSort('', ''));                 // true

// One line of real work, obviously correct, O(n log n).
// Say this out loud first -- it buys you thinking time.
Version 0b — the tempting wrong one
function withSets(s, t) {
  if (s.length !== t.length) return false;
  const a = new Set(s), b = new Set(t);
  if (a.size !== b.size) return false;
  for (const ch of a) if (!b.has(ch)) return false;
  return true;
}

console.log(withSets('anagram', 'nagaram'));   // true
console.log(withSets('rat', 'car'));           // false
console.log(withSets('aacc', 'ccac'));         // TRUE -- WRONG

// A Set throws away how MANY of each character there are, which is
// exactly the information the problem is about.
Step 3

Why sorting is more work than needed

Sorting arranges the characters into a total order. But the question does not care about order at all — it only cares how many of each character there are. Sorting computes far more information than the question needs, and pays n log n for it.

Timing demo
// two long anagrams -- the worst case, since we cannot exit early
const N = 400000;
let s = '';
for (let i = 0; i < N; i++) s += String.fromCharCode(97 + (i % 26));
const t = [...s].reverse().join('');

function bySorting(a, b) {
  if (a.length !== b.length) return false;
  return [...a].sort().join('') === [...b].sort().join('');
}

function byCounting(a, b) {
  if (a.length !== b.length) return false;
  const counts = new Map();
  for (const ch of a) counts.set(ch, (counts.get(ch) || 0) + 1);
  for (const ch of b) {
    const left = counts.get(ch);
    if (!left) return false;
    counts.set(ch, left - 1);
  }
  return true;
}

let x = performance.now();
const r1 = bySorting(s, t);
const sortMs = performance.now() - x;

x = performance.now();
const r2 = byCounting(s, t);
const countMs = performance.now() - x;

console.log('sorting  :', r1, 'in', sortMs.toFixed(1) + ' ms');
console.log('counting :', r2, 'in', countMs.toFixed(1) + ' ms');
console.log('speed-up:', Math.round(sortMs / Math.max(countMs, 0.01)) + 'x');
Step 4

The better idea — a budget you spend

The unlock

Walk the first string and build a budget: how many of each character you have. Then walk the second string and spend it: subtract one for each character. If you ever need a character with nothing left in the budget, they are not anagrams.

And because the lengths are equal (you checked that first), spending exactly n characters from a budget of exactly n means the budget must land precisely at zero. You do not need a final check that everything is zero — it is guaranteed.

That is a genuinely nice piece of reasoning and worth saying out loud:

budget total  = length of s   = n
amount spent  = length of t   = n        (we checked they are equal)

if we never overdrew, then we spent exactly what we had,
so every counter is exactly zero at the end.

The one-pass variant

You can even merge the two walks: add for s[i] and subtract for t[i] in the same loop. But then a counter can dip negative and come back, so you do need the final all-zeros check. Two clean passes are easier to reason about; one pass with a final check is slightly fewer iterations. Both are fine — know which one you are writing and why.

the algorithm, narrating itself
function isAnagramExplained(s, t) {
  console.log('s = "' + s + '"   t = "' + t + '"');

  if (s.length !== t.length) {
    console.log('lengths differ (' + s.length + ' vs ' + t.length + ') -> FALSE');
    console.log('');
    return false;
  }

  const budget = new Map();

  console.log('PASS 1 -- build the budget from s');
  for (const ch of s) {
    budget.set(ch, (budget.get(ch) || 0) + 1);
    console.log("  '" + ch + "'  ->  " + JSON.stringify([...budget]));
  }

  console.log('PASS 2 -- spend it with t');
  for (const ch of t) {
    const left = budget.get(ch) || 0;
    if (left === 0) {
      console.log("  '" + ch + "'  budget has 0  ->  OVERDRAWN, FALSE");
      console.log('');
      return false;
    }
    budget.set(ch, left - 1);
    console.log("  '" + ch + "'  had " + left + ", spend one  ->  " + JSON.stringify([...budget]));
  }

  console.log('never overdrew -> TRUE');
  console.log('');
  return true;
}

Step 6

Version 1 — without built-in methods

Version 1a — a 26-slot counter array
function isAnagramManual(s, t) {
  if (s.length !== t.length) return false;

  // one counter per lowercase letter
  const counts = [];
  for (let i = 0; i < 26; i++) counts[i] = 0;

  // PASS 1: build the budget from s
  for (let i = 0; i < s.length; i++) {
    const idx = s.charCodeAt(i) - 97;      // 'a' is 97
    counts[idx] = counts[idx] + 1;
  }

  // PASS 2: spend it with t
  for (let i = 0; i < t.length; i++) {
    const idx = t.charCodeAt(i) - 97;

    if (counts[idx] === 0) {
      return false;                        // overdrawn
    }

    counts[idx] = counts[idx] - 1;
  }

  // lengths matched, so the budget must be exactly spent
  return true;
}

console.log(isAnagramManual('anagram', 'nagaram'));   // true
console.log(isAnagramManual('rat', 'car'));           // false
console.log(isAnagramManual('aacc', 'ccac'));         // false
console.log(isAnagramManual('', ''));                 // true
console.log(isAnagramManual('a', 'a'));               // true
console.log(isAnagramManual('ab', 'ba'));             // true
console.log(isAnagramManual('listen', 'silent'));     // true
Version 1b — one pass, add and subtract
function isAnagramOnePass(s, t) {
  if (s.length !== t.length) return false;

  const counts = [];
  for (let i = 0; i < 26; i++) counts[i] = 0;

  // walk BOTH strings together: +1 for s, -1 for t
  for (let i = 0; i < s.length; i++) {
    counts[s.charCodeAt(i) - 97]++;
    counts[t.charCodeAt(i) - 97]--;
  }

  // now every counter MUST be zero -- and here we really do have
  // to check, because a counter can go negative and come back
  for (let i = 0; i < 26; i++) {
    if (counts[i] !== 0) return false;
  }

  return true;
}

console.log(isAnagramOnePass('anagram', 'nagaram'));   // true
console.log(isAnagramOnePass('rat', 'car'));           // false
console.log(isAnagramOnePass('aacc', 'ccac'));         // false
console.log(isAnagramOnePass('ab', 'ba'));             // true

// Why the final check is unavoidable here:
// with s = "ab", t = "ba", after i = 0 the counters are a:+1, b:-1.
// A negative counter mid-loop means nothing -- only the end state
// tells you the answer.
charCodeAt, plainly

Every character has a numeric code. 'a' is 97, 'b' is 98, up to 'z' at 122. Subtracting 97 maps them onto 0–25, which are array indexes. That is the whole trick behind every 26-element counter array you will ever see, and it is why those solutions break the moment a capital letter or a space appears.

Step 7

Version 2 — with built-in methods

Version 2 — Map, works on any characters
function isAnagram(s, t) {
  if (s.length !== t.length) return false;

  const budget = new Map();
  for (const ch of s) budget.set(ch, (budget.get(ch) || 0) + 1);

  for (const ch of t) {
    const left = budget.get(ch);
    if (!left) return false;          // undefined or 0 -- overdrawn either way
    budget.set(ch, left - 1);
  }

  return true;
}

console.log(isAnagram('anagram', 'nagaram'));   // true
console.log(isAnagram('rat', 'car'));           // false
console.log(isAnagram('aacc', 'ccac'));         // false
console.log(isAnagram('Hello!', '!olleH'));     // true  -- any characters
console.log(isAnagram('a b', 'b a'));           // true  -- spaces count
console.log(isAnagram('', ''));                 // true

if (!left) handles both cases at once: undefined (character never seen) and 0 (budget exhausted) are both falsy. That is one of the few places where relying on falsiness is genuinely clean rather than risky — because 0 and undefined mean the same thing here.

the realistic variations
// Case-insensitive, ignoring spaces and punctuation
function isAnagramLoose(s, t) {
  const clean = str => [...str.toLowerCase()].filter(c => /[a-z0-9]/.test(c));
  const a = clean(s), b = clean(t);
  if (a.length !== b.length) return false;

  const budget = new Map();
  for (const ch of a) budget.set(ch, (budget.get(ch) || 0) + 1);
  for (const ch of b) {
    const left = budget.get(ch);
    if (!left) return false;
    budget.set(ch, left - 1);
  }
  return true;
}

console.log(isAnagramLoose('Dormitory', 'Dirty Room'));      // true
console.log(isAnagramLoose('Astronomer', 'Moon starer'));    // true
console.log(isAnagramLoose('Listen!', 'Silent'));            // true
console.log(isAnagramLoose('hello', 'world'));               // false

// Word-level anagrams: same words, different order
function isWordAnagram(s, t) {
  const key = str => str.toLowerCase().split(/\s+/).filter(Boolean).sort().join(' ');
  return key(s) === key(t);
}

console.log(isWordAnagram('the quick fox', 'fox the quick'));   // true
console.log(isWordAnagram('the quick fox', 'the quick dog'));   // false
Unicode: .length lies

JavaScript string length counts UTF-16 code units, not characters. A single emoji has .length === 2. So the early length check can reject a genuine anagram of emoji-containing strings, and s[i] can hand you half a character. Iterating with for...of or [...s] walks whole code points; comparing [...s].length instead of s.length fixes the guard. For interview inputs this never matters. For real user text, it does.

the unicode-safe version
function isAnagramUnicode(s, t) {
  const a = [...s], b = [...t];              // whole code points
  if (a.length !== b.length) return false;

  const budget = new Map();
  for (const ch of a) budget.set(ch, (budget.get(ch) || 0) + 1);
  for (const ch of b) {
    const left = budget.get(ch);
    if (!left) return false;
    budget.set(ch, left - 1);
  }
  return true;
}

console.log('naive length of "a😀":', 'a😀'.length);        // 3
console.log('code-point length   :', [...'a😀'].length);   // 2

console.log(isAnagramUnicode('a😀b', 'b😀a'));   // true
console.log(isAnagramUnicode('a😀b', 'ab😀'));   // true
console.log(isAnagramUnicode('a😀b', 'abc'));    // false
Step 8

Complexity, in sentences

SolutionTimeSpace
Sort bothO(n log n)O(n)
Count with a MapO(n)O(k)
26-slot arrayO(n)O(1)

where k is the number of distinct characters.

The array version is O(1) space in a meaningful sense: 26 slots, whatever the input size. The Map version is O(k), which for a bounded alphabet is also effectively constant — but say “O(k) where k is the alphabet size” rather than claiming O(1) for arbitrary Unicode, where k can be large.

Two passes over the string is still O(n). Sequential passes add.

Say this in the interview

“Sorting both strings works and is O(n log n), but the question only depends on character counts, not order. So: if the lengths differ, false. Otherwise build a frequency map from the first string and decrement it with the second, returning false the moment a count would go negative. Because the lengths are equal, no final zero-check is needed. O(n) time, O(k) space for the alphabet — or a fixed 26-element array if the input is lowercase a–z.”

Step 9

Mistakes people actually make

1. Using a Set and losing the counts

Shown in Step 2. "aacc" versus "ccac" is the input that exposes it, and it is the first thing a good interviewer will try.

2. Skipping the length check

Broken — no length guard
function broken(s, t) {
  const budget = new Map();
  for (const ch of s) budget.set(ch, (budget.get(ch) || 0) + 1);
  for (const ch of t) {
    const left = budget.get(ch);
    if (!left) return false;
    budget.set(ch, left - 1);
  }
  return true;                 // no length check anywhere
}

console.log(broken('anagram', 'nagaram'));   // true   fine
console.log(broken('aabb', 'ab'));           // TRUE   WRONG
console.log(broken('ab', 'aabb'));           // false  right, by accident

// "ab" spends only part of the budget built from "aabb" and never
// overdraws, so it passes. Either check the lengths up front, or
// verify that every counter is zero at the end. The length check
// is one line and also short-circuits most negative cases.

3. One pass without the final zero-check

Broken — bailing on a negative counter
function broken(s, t) {
  if (s.length !== t.length) return false;
  const counts = new Array(26).fill(0);
  for (let i = 0; i < s.length; i++) {
    counts[s.charCodeAt(i) - 97]++;
    counts[t.charCodeAt(i) - 97]--;
    if (counts[t.charCodeAt(i) - 97] < 0) return false;   // bail early -- bug
  }
  return true;
}

console.log(broken('anagram', 'nagaram'));   // false  WRONG, should be true
console.log(broken('ab', 'ba'));             // false  WRONG, should be true

// In the merged loop, counters legitimately go negative and come
// back. Only the state AFTER the whole loop means anything.
// Early bail-out belongs to the two-pass version, not this one.

4. Comparing sorted strings without joining

Broken — comparing arrays with ===
function broken(s, t) {
  return [...s].sort() === [...t].sort();
}
console.log(broken('abc', 'cba'));   // false -- always false

// === on two arrays compares OBJECT IDENTITY, not contents.
// Two different arrays are never ===, however equal they look.
console.log([1,2] === [1,2]);        // false
console.log([1,2].join() === [1,2].join());   // true

// So join them into strings first:
console.log([...'abc'].sort().join('') === [...'cba'].sort().join(''));   // true

5. Assuming lowercase ASCII when the input is not

'A'.charCodeAt(0) - 97 is -32. Writing counts[-32]++ does not throw — JavaScript quietly adds a "-32" property to the array — so the bug is silent and the answer is wrong. If the input might contain anything other than a–z, use the Map version.

Step 10

Practice before you move on

  1. Write the Map version from memory, then explain why no final zero-check is needed when the lengths match.
  2. Ransom Note. Can you build string a using the letters of string b? Identical budget-and-spend, except the lengths do not have to match, so you drop the length check — and now leftover budget is fine. It is a Tier 1 problem on this list.
  3. Find all anagram start indexes. Given a string and a pattern, return every index where an anagram of the pattern begins. Sliding window plus a count comparison — this page combined with the sliding-window page.
  4. Count how many characters must change to make the strings anagrams. Sum the positive differences between the two count maps.
  5. Anagram of a palindrome. Can the string be rearranged into a palindrome? Count the characters; at most one may have an odd count. Two lines once you have the counts.
What to carry forward

The frequency map is the single most reused tool in string problems. Build one, then either compare two of them, spend one down, or slide a window and keep it in sync. And notice the general lesson from Step 3: sorting computes an ordering you often do not need. Before you sort, ask whether counting would answer the question — it is usually a whole complexity class cheaper.
