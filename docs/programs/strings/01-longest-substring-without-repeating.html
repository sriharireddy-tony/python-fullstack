Strings · Problem 01

Longest Substring Without Repeating Characters

This is where you learn the sliding window — a stretchy range that grows on the right and shrinks on the left. Once you can see it, roughly a dozen other interview problems become the same problem.

Step 1

The problem

Given a string, find the longest run of characters, side by side, in which no character repeats. Return its length.

InputAnswerThe winning run
"abcabcbb"3"abc"
"bbbbb"1"b"
"pwwkew"3"wke"
""0nothing
"dvdf"3"vdf"
Substring, not subsequence

In "pwwkew" the answer is "wke" and not "pwke". "pwke" has four distinct characters, but they are not side by side — you had to jump over a w. That makes it a subsequence, which this problem does not allow. Say “contiguous” to yourself before you start.

Watch the last row, "dvdf". It looks harmless and it is the input that breaks most first attempts. Come back to it after Step 9.

Step 2

Think first — the obvious answer

Try every possible substring, check whether it has duplicates, keep the longest clean one. Two loops to pick the start and end, and a set to check for repeats.

Version 0 — brute force
function lengthOfLongestBrute(s) {
  let best = 0;

  for (let start = 0; start < s.length; start++) {
    const seen = new Set();

    for (let end = start; end < s.length; end++) {
      if (seen.has(s[end])) {
        break;              // this substring is spoiled -- no point extending it
      }
      seen.add(s[end]);

      const length = end - start + 1;
      if (length > best) best = length;
    }
  }

  return best;
}

console.log(lengthOfLongestBrute('abcabcbb'));   // 3
console.log(lengthOfLongestBrute('bbbbb'));      // 1
console.log(lengthOfLongestBrute('pwwkew'));     // 3
console.log(lengthOfLongestBrute('dvdf'));       // 3
console.log(lengthOfLongestBrute(''));           // 0

Note end - start + 1. The length of a range that includes both ends is “last minus first, plus one”. From index 2 to index 4 is 3 characters, not 2. Forgetting the + 1 is the most common off-by-one in the whole of this subject.

Step 3

Why it is slow

O(n²) in the worst case: for each of n starting points, walk forward. And again the waste is the interesting part. Take "abcdefX" where X is a repeat of a:

start at 0:  a b c d e f  -- reads 6 characters, hits the repeat, gives up
start at 1:    b c d e f  -- reads 5 characters. But we ALREADY KNEW
                             b c d e f had no duplicates in it.
start at 2:      c d e f  -- ditto
start at 3:        d e f  -- ditto

Every restart re-verifies a stretch it has already verified. The window we found is thrown away and rebuilt from one place further along. That is the work we are going to eliminate.

Timing demo
// A long string with only a few distinct characters forces
// lots of restarts in the brute force.
const alphabet = 'abcdefghijklmnopqrstuvwxyz';
let s = '';
for (let i = 0; i < 20000; i++) s += alphabet[i % 26];

function brute(s) {
  let best = 0;
  for (let i = 0; i < s.length; i++) {
    const seen = new Set();
    for (let j = i; j < s.length; j++) {
      if (seen.has(s[j])) break;
      seen.add(s[j]);
      if (j - i + 1 > best) best = j - i + 1;
    }
  }
  return best;
}

function window(s) {
  const last = new Map();
  let left = 0, best = 0;
  for (let right = 0; right < s.length; right++) {
    const c = s[right];
    if (last.has(c) && last.get(c) >= left) left = last.get(c) + 1;
    last.set(c, right);
    if (right - left + 1 > best) best = right - left + 1;
  }
  return best;
}

let t = performance.now();
const a = brute(s);
const bruteMs = performance.now() - t;

t = performance.now();
const b = window(s);
const fastMs = performance.now() - t;

console.log('brute force   :', a, 'in', bruteMs.toFixed(1) + ' ms');
console.log('sliding window:', b, 'in', fastMs.toFixed(2) + ' ms');
console.log('speed-up:', Math.round(bruteMs / Math.max(fastMs, 0.01)) + 'x');
Step 4

The better idea — the sliding window

Instead of throwing the window away and rebuilding it, keep one window and adjust its two ends. Picture two fingers on the string:

        a  b  c  a  b  c  b  b
        ^        ^
      left     right

   the window is everything from left to right, inclusive

The rule for moving them:

  • right always moves forward, one step per loop iteration. It is reading new characters into the window.
  • left only moves when the window becomes invalid — that is, when the character right just read is already inside the window. Then left jumps forward far enough to kick the earlier copy out.
The unlock

Neither finger ever moves backwards. Each of them travels the length of the string once. Two fingers each walking n steps is 2n steps in total — which is O(n), not O(n²), even though the code has a loop inside a loop shape.

How far does left jump?

This is the only genuinely subtle part. When right lands on a character we have seen before at index p, we need that copy gone. So left must move to p + 1 — one past the old copy.

But only if p is actually inside the current window. And that is exactly the trap in "dvdf":

  d  v  d  f
  0  1  2  3

At right = 2 we see 'd', last seen at index 0.
   left jumps to 0 + 1 = 1.        window is now "vd"

At right = 3 we see 'f' -- never seen. Window grows to "vdf", length 3.  CORRECT

Now imagine we had NOT checked whether the old copy was still in the window.
Suppose later we meet 'd' again at index 9, with left already at 5.
The map still says "d was at 2". Jumping left to 3 would move it BACKWARDS,
re-admitting characters we had already thrown out, and the answer inflates.

That is why the condition is:
        if (lastSeen.has(c) AND lastSeen.get(c) >= left)

The >= left guard says: only react to a duplicate that is still inside my window. A duplicate that fell out of the window long ago is not a duplicate any more. Leave that guard out and the code passes "abcabcbb" and fails on inputs like "abba".

Step 5

Dry run — trace the window

s = "abcabcbb". The map holds the last index each character was seen at.

left = 0   best = 0   lastSeen = {}

right=0  'a'  not in window        lastSeen={a:0}   window "a"     len 1   best=1
right=1  'b'  not in window        lastSeen={a:0,b:1}  window "ab"  len 2  best=2
right=2  'c'  not in window        lastSeen={a:0,b:1,c:2}  window "abc" len 3  best=3
right=3  'a'  seen at 0, and 0 >= left(0)  ->  left = 1
                                   lastSeen={a:3,...}  window "bca" len 3  best=3
right=4  'b'  seen at 1, and 1 >= left(1)  ->  left = 2
                                   lastSeen={b:4,...}  window "cab" len 3  best=3
right=5  'c'  seen at 2, and 2 >= left(2)  ->  left = 3
                                   lastSeen={c:5,...}  window "abc" len 3  best=3
right=6  'b'  seen at 4, and 4 >= left(3)  ->  left = 5
                                   lastSeen={b:6,...}  window "cb"  len 2  best=3
right=7  'b'  seen at 6, and 6 >= left(5)  ->  left = 7
                                   lastSeen={b:7,...}  window "b"   len 1  best=3

answer: 3

Watch left across those eight rows: 0, 0, 0, 1, 2, 3, 5, 7. It only ever goes up. That is the proof that this is O(n).

Now the tricky one, s = "abba", which is the input the >= left guard exists for:

left = 0   best = 0   lastSeen = {}

right=0  'a'  new                       lastSeen={a:0}      window "a"   best=1
right=1  'b'  new                       lastSeen={a:0,b:1}  window "ab"  best=2
right=2  'b'  seen at 1, 1 >= left(0)   ->  left = 2
                                        lastSeen={a:0,b:2}  window "b"   best=2
right=3  'a'  seen at 0 ... but 0 >= left(2)?  NO.
              The old 'a' is already outside the window. Do NOT move left.
                                        lastSeen={a:3,b:2}  window "ba"  best=2

answer: 2       (without the guard, left would jump BACK to 1 and the
                 window would be "bba" -- length 3, and wrong)
the algorithm, narrating itself
function longestExplained(s) {
  const lastSeen = new Map();
  let left = 0, best = 0;

  console.log('s = "' + s + '"');
  console.log('');

  for (let right = 0; right < s.length; right++) {
    const c = s[right];

    if (lastSeen.has(c) && lastSeen.get(c) >= left) {
      const old = lastSeen.get(c);
      left = old + 1;
      console.log('right=' + right + " '" + c + "'  duplicate inside window (at " + old +
                  ') -> left jumps to ' + left);
    } else if (lastSeen.has(c)) {
      console.log('right=' + right + " '" + c + "'  seen at " + lastSeen.get(c) +
                  ', but that is left of the window -- ignore it');
    } else {
      console.log('right=' + right + " '" + c + "'  new character");
    }

    lastSeen.set(c, right);

    const len = right - left + 1;
    if (len > best) best = len;

    console.log('           window "' + s.slice(left, right + 1) + '"  len=' + len + '  best=' + best);
  }

  console.log('');
  return best;
}

Step 6

Version 1 — without built-in methods

No Set, no Map, no slice. A plain object as the lookup table, and charAt-style indexing.

Version 1a — plain object, jumping left
function longestManual(s) {
  const lastSeen = {};    // character -> the last index it appeared at
  let left = 0;
  let best = 0;

  for (let right = 0; right < s.length; right++) {
    const c = s[right];

    // has this character been seen, AND is that copy still in the window?
    if (Object.prototype.hasOwnProperty.call(lastSeen, c) && lastSeen[c] >= left) {
      left = lastSeen[c] + 1;      // jump past the old copy
    }

    lastSeen[c] = right;           // record where this copy is

    const length = right - left + 1;
    if (length > best) {
      best = length;
    }
  }

  return best;
}

console.log(longestManual('abcabcbb'));   // 3
console.log(longestManual('bbbbb'));      // 1
console.log(longestManual('pwwkew'));     // 3
console.log(longestManual('dvdf'));       // 3
console.log(longestManual('abba'));       // 2
console.log(longestManual(''));           // 0
console.log(longestManual('au'));         // 2

The other shape: shrink one step at a time

There is a second way to write every sliding window, and it is worth knowing both. Instead of jumping left straight to its new home, you can walk it forward one character at a time until the window is valid again. It needs a count of what is in the window rather than last-seen indexes.

Version 1b — shrink with a while loop
function longestShrink(s) {
  const inWindow = {};   // character -> is it currently inside the window?
  let left = 0;
  let best = 0;

  for (let right = 0; right < s.length; right++) {
    const c = s[right];

    // while the new character is already in the window, drop characters
    // from the left until it is not
    while (inWindow[c] === true) {
      inWindow[s[left]] = false;
      left++;
    }

    inWindow[c] = true;

    const length = right - left + 1;
    if (length > best) best = length;
  }

  return best;
}

console.log(longestShrink('abcabcbb'));   // 3
console.log(longestShrink('pwwkew'));     // 3
console.log(longestShrink('dvdf'));       // 3
console.log(longestShrink('abba'));       // 2

// "A while loop inside a for loop -- surely that is O(n squared)?"
// No. The while loop can only ever move `left` forward, and `left`
// can only travel the length of the string once in total across
// the WHOLE run. Total work is at most 2n. This is the single most
// important thing to understand about sliding windows.
Which shape should you use?

The jump version (1a) is shorter and is what most people write for this exact problem. The shrink version (1b) generalises much better: the moment the rule becomes “at most K distinct characters” or “sum at most X”, jumping is no longer possible and you must walk. Learn 1b properly — it is the shape you will reuse.

Step 7

Version 2 — with built-in methods

Version 2a — Map
function lengthOfLongestSubstring(s) {
  const lastSeen = new Map();
  let left = 0;
  let best = 0;

  for (let right = 0; right < s.length; right++) {
    const c = s[right];

    if (lastSeen.has(c) && lastSeen.get(c) >= left) {
      left = lastSeen.get(c) + 1;
    }

    lastSeen.set(c, right);
    best = Math.max(best, right - left + 1);
  }

  return best;
}

console.log(lengthOfLongestSubstring('abcabcbb'));   // 3
console.log(lengthOfLongestSubstring('bbbbb'));      // 1
console.log(lengthOfLongestSubstring('pwwkew'));     // 3
console.log(lengthOfLongestSubstring('dvdf'));       // 3
console.log(lengthOfLongestSubstring(' '));          // 1  a space is a character
console.log(lengthOfLongestSubstring('!@#!'));       // 3
Version 2b — Set, shrink shape
function lengthOfLongestSet(s) {
  const window = new Set();
  let left = 0, best = 0;

  for (const c of s) {              // for...of walks the characters
    while (window.has(c)) {
      window.delete(s[left]);
      left++;
    }
    window.add(c);
    best = Math.max(best, window.size);   // the Set's own size IS the length
  }

  return best;
}

console.log(lengthOfLongestSet('abcabcbb'));   // 3
console.log(lengthOfLongestSet('pwwkew'));     // 3
console.log(lengthOfLongestSet('abba'));       // 2

// Neat detail: because the Set contains exactly the window's
// characters and they are all distinct, `window.size` is the window
// length. No arithmetic, no off-by-one to get wrong.

Returning the substring, not just its length

variation — return the actual text
function longestSubstring(s) {
  const lastSeen = new Map();
  let left = 0, best = 0, bestStart = 0;

  for (let right = 0; right < s.length; right++) {
    const c = s[right];
    if (lastSeen.has(c) && lastSeen.get(c) >= left) left = lastSeen.get(c) + 1;
    lastSeen.set(c, right);

    if (right - left + 1 > best) {
      best = right - left + 1;
      bestStart = left;             // freeze where the winner starts
    }
  }

  return s.slice(bestStart, bestStart + best);
}

console.log(longestSubstring('abcabcbb'));   // "abc"
console.log(longestSubstring('pwwkew'));     // "wke"
console.log(longestSubstring('dvdf'));       // "vdf"
console.log(longestSubstring('abba'));       // "ab"

Same trick as in Kadane’s: record the winning start only at the moment a new best is confirmed, never on every move of left.

Step 8

Complexity, in sentences

SolutionTimeSpaceIn words
Brute forceO(n²)O(min(n, k))Every start, walked forward until it breaks.
Sliding windowO(n)O(min(n, k))Each pointer crosses the string once.

Why O(n) despite the nested loop. This is the sentence to have ready. The inner while does not restart for each right — it continues from wherever left already was. Across the entire run, left advances at most n times and right advances exactly n times. Total 2n moves, so O(n). Counting the loops visually and saying “two loops means n²” is the mistake this problem is designed to expose.

Space O(min(n, k)), where k is the alphabet size. The map can never hold more distinct characters than exist in the string, and never more than the alphabet allows. For plain ASCII that is at most 128 entries no matter how long the input is — effectively O(1).

Say this in the interview

“I keep a window of distinct characters and a map from character to its last index. The right pointer always advances; when it reads a character whose last position is inside the window, I move the left pointer past that position. Both pointers only move forward, so it is O(n) time and O(min(n, alphabet)) space. The subtlety is checking that the previous occurrence is still inside the window — otherwise the left pointer can move backwards on inputs like abba.”

Step 9

Mistakes people actually make

1. Letting left move backwards

Broken — missing the >= left guard
function broken(s) {
  const lastSeen = new Map();
  let left = 0, best = 0;
  for (let right = 0; right < s.length; right++) {
    const c = s[right];
    if (lastSeen.has(c)) left = lastSeen.get(c) + 1;   // no window check -- bug
    lastSeen.set(c, right);
    best = Math.max(best, right - left + 1);
  }
  return best;
}

console.log(broken('abcabcbb'));   // 3   fine
console.log(broken('pwwkew'));     // 3   fine
console.log(broken('abba'));       // 3   WRONG, should be 2
console.log(broken('tmmzuxt'));    // 6   WRONG, should be 5

// On "abba": at right=3 we see 'a', last at index 0, so left jumps
// BACK from 2 to 1 -- silently re-admitting the 'b' we had removed.
// The window becomes "bba", which contains a duplicate.

2. Resetting the window on a duplicate

Broken — starts over instead of shrinking
function broken(s) {
  let best = 0, current = 0;
  const seen = new Set();
  for (const c of s) {
    if (seen.has(c)) {
      seen.clear();       // throwing the whole window away -- bug
      current = 0;
    }
    seen.add(c);
    current++;
    best = Math.max(best, current);
  }
  return best;
}

console.log(broken('abcabcbb'));   // 3   right, but only by luck
console.log(broken('dvdf'));       // 2   WRONG, should be 3

// Clearing everything discards characters that were still valid.
// On "dvdf", the repeated 'd' at index 2 throws away the 'v' as well
// -- but 'v' was never a duplicate. The answer "vdf" is now
// unreachable because we deleted part of it.
// A duplicate does not invalidate the whole window -- only the
// part up to and including the earlier copy.

3. The + 1 in the length

right - left is the gap between the pointers; right - left + 1 is the count of characters. If your answers are consistently one too small, this is why. A quick check: when left === right the window holds exactly one character, and right - left + 1 gives 1 while right - left gives 0.

4. Assuming lowercase letters only

The input can contain spaces, digits, punctuation, uppercase. " " answers 1. A fixed-size array of 26 counters breaks on all of these — use a map, or size the array for the full character set if you must use one.

5. Non-ASCII characters and s[i]

worth knowing
const emoji = 'ab😀c';

console.log('length via .length :', emoji.length);        // 5, not 4
console.log('emoji[2] :', JSON.stringify(emoji[2]));      // half of the emoji
console.log('spread   :', [...emoji]);                    // ['a','b','😀','c']

// JavaScript strings are UTF-16 code units. Characters outside the
// basic range (emoji, some scripts) take TWO slots, so s[i] can hand
// you half a character.
//
// For interview inputs this never comes up. For real production code
// that touches user text, iterate with [...s] or for...of, both of
// which walk whole characters.
console.log('safe length:', [...emoji].length);           // 4
Step 10

Practice before you move on

  1. Write version 1b (the shrink shape) from memory. Then explain out loud why a while inside a for is still O(n). If you can do that, you own the pattern.
  2. Longest substring with at most K distinct characters. The window rule becomes “shrink while the map has more than K keys”. You need counts now, not just presence, so you can tell when a character has fully left the window.
  3. Longest substring with at most two distinct characters. The same problem with K fixed at 2. Do this one first if the general version feels heavy.
  4. Minimum window substring. The hard sibling: find the shortest window of s that contains every character of t. Same two pointers, opposite goal — grow until valid, then shrink while still valid.
  5. Longest repeating character replacement. You may change up to K characters. It is in this collection under sliding window — try it before reading it.
What to carry forward

The sliding window applies whenever a problem asks for the best contiguous stretch that satisfies some rule, and the rule gets worse as the window grows. Grow on the right unconditionally; shrink on the left only while the rule is broken. Whenever you catch yourself writing a nested loop over substrings, ask whether the window from the previous step could have been repaired instead of rebuilt.
