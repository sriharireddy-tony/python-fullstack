Strings · Problem 06

String Compression

Run-length encoding — "aabbbcc" becomes "a2b3c2". Straightforward until the in-place version, where the read and write pointers from Move Zeroes come back, and a count of 10 or more needs several slots.

Step 1

The problem

Replace each run of repeated characters with the character followed by the length of the run. A run of length 1 keeps just the character — no "1".

InputCompressedNote
"aabbbcc""a2b3c2"
"abc""abc"no run is longer than 1
"aaa""a3"
"aaaaaaaaaaaa""a12"the count takes two characters
"aabaa""a2ba2"runs are contiguous only
""""

Two details that decide whether your solution is right:

  • A count of 1 is omitted. "abc" compresses to "abc", not "a1b1c1". Which means compression can make the string longer in general — but with the 1 omitted it never does.
  • Runs must be adjacent. In "aabaa" the four a’s are two separate runs of two, because a b sits between them.
The count that does not fit in one slot

A run of 12 becomes "a12" — the character plus two digits. Every solution that assumes the count is a single character breaks at 10. This is the bug this problem exists to find, and it never shows up in small hand-written tests.

Step 2

Think first — building a new string

Walk the string, count how long the current run is, and append the character and count to a result.

Version 0 — build a new string
function compressSimple(s) {
  if (s.length === 0) return '';

  let result = '';
  let runChar = s[0];
  let runLength = 1;

  for (let i = 1; i <= s.length; i++) {
    // i === s.length is a deliberate extra step so the LAST run
    // gets flushed without duplicating the code below
    if (i < s.length && s[i] === runChar) {
      runLength++;
    } else {
      result += runChar;
      if (runLength > 1) result += runLength;   // omit a count of 1
      runChar = s[i];
      runLength = 1;
    }
  }

  return result;
}

console.log(compressSimple('aabbbcc'));         // 'a2b3c2'
console.log(compressSimple('abc'));             // 'abc'
console.log(compressSimple('aaa'));             // 'a3'
console.log(compressSimple('aaaaaaaaaaaa'));    // 'a12'
console.log(compressSimple('aabaa'));           // 'a2ba2'
console.log(compressSimple(''));                // ''
console.log(compressSimple('a'));               // 'a'
The one-past-the-end trick

The loop runs to i <= s.length, one step beyond the string. That extra iteration can never match runChar (s[s.length] is undefined), so it always takes the else branch and flushes the final run. Without it you need a duplicate copy of the flush code after the loop — and forgetting that copy is a genuinely common bug. This trick is worth stealing for any “group consecutive items” loop.

Step 3

Why the in-place version exists

Version 0 is O(n) time and completely fine — except for result += .... In JavaScript strings are immutable, so += can mean building a brand-new string each time. Modern engines optimise this heavily with ropes, so it is usually fine; on other platforms, or with a very large input, it is O(n²).

The classic form of this problem hands you a character array and asks you to compress it in place, returning the new length. That is where the read/write pointers come in.

Timing demo — naive concatenation vs an array buffer
// 300,000 characters in runs of 3
const N = 300000;
let s = '';
for (let i = 0; i < N / 3; i++) s += 'abc'[i % 3].repeat(3);

function byConcat(str) {
  let out = '';
  let ch = str[0], n = 1;
  for (let i = 1; i <= str.length; i++) {
    if (i < str.length && str[i] === ch) n++;
    else { out += ch; if (n > 1) out += n; ch = str[i]; n = 1; }
  }
  return out;
}

function byParts(str) {
  const parts = [];
  let ch = str[0], n = 1;
  for (let i = 1; i <= str.length; i++) {
    if (i < str.length && str[i] === ch) n++;
    else { parts.push(ch); if (n > 1) parts.push(n); ch = str[i]; n = 1; }
  }
  return parts.join('');
}

let t = performance.now();
const a = byConcat(s);
const concatMs = performance.now() - t;

t = performance.now();
const b = byParts(s);
const partsMs = performance.now() - t;

console.log('string +=      : ' + a.length + ' chars in ' + concatMs.toFixed(1) + ' ms');
console.log('array + join   : ' + b.length + ' chars in ' + partsMs.toFixed(1) + ' ms');
console.log('same answer:', a === b);

// On a modern engine these are close, because += on strings is
// heavily optimised. Push to an array and join once anyway: it is
// the habit that stays correct when the engine cannot help you.
Step 4

The better idea — read and write pointers

Exactly the shape from Move Zeroes: one pointer reads the original, a slower pointer writes the compressed form into the same array.

The unlock

read scans runs. write marks where the next compressed character goes. Because the compressed form is never longer than the original, write can never overtake read — so overwriting as you go is safe.

Why is it never longer? A run of length 1 writes 1 character. A run of length 2 writes 2 ("a2"). A run of length k writes 1 + digits(k), and for k ≥ 2 that is always at most k:

Run lengthWrittenCharacters used
1a1
2a22
3a32
9a92
12a123
100a1004

That is the safety proof for writing in place, and it is exactly the kind of thing an interviewer will ask you to justify.

Writing a multi-digit count

The count is a number; the array holds characters. So convert it to a string and write its digits one at a time:

writing the count
for (const digit of String(runLength)) {
  chars[write] = digit;
  write++;
}

// String(12) is "12", so this writes '1' then '2' -- two slots.
// Writing chars[write] = runLength would put the NUMBER 12 into a
// character array, which is a different type and breaks join().

function compressExplained(chars) {
  console.log('start: [' + chars.join(',') + ']');
  console.log('');

  let write = 0;
  let read = 0;

  while (read < chars.length) {
    const runChar = chars[read];
    let runLength = 0;

    // how long is this run?
    while (read < chars.length && chars[read] === runChar) {
      read++;
      runLength++;
    }

    console.log("run of '" + runChar + "' length " + runLength +
                '   (read is now ' + read + ')');

    chars[write] = runChar;
    write++;
    console.log('   wrote the character   [' + chars.join(',') +
                ']   write=' + write);

    if (runLength > 1) {
      for (const digit of String(runLength)) {
        chars[write] = digit;
        write++;
      }
      console.log('   wrote the count "' + runLength + '"  [' + chars.join(',') +
                  ']   write=' + write);
    } else {
      console.log('   length 1, no count written');
    }
  }

  console.log('');
  console.log('new length = ' + write + '   result = "' +
              chars.slice(0, write).join('') + '"');
  console.log('');
  return write;
}

Step 6

Version 1 — without built-in methods

Version 1 — in place, loops only
function compressManual(chars) {
  let write = 0;      // where the next compressed character goes
  let read = 0;       // where we are reading from

  while (read < chars.length) {
    const runChar = chars[read];
    let runLength = 0;

    // measure the run
    while (read < chars.length && chars[read] === runChar) {
      read = read + 1;
      runLength = runLength + 1;
    }

    // write the character
    chars[write] = runChar;
    write = write + 1;

    // write the count, one digit at a time, only if it is 2 or more
    if (runLength > 1) {
      // turn the number into its digits without using String()
      const digits = [];
      let n = runLength;
      let count = 0;
      while (n > 0) {
        digits[count] = n % 10;      // last digit first
        n = Math.floor(n / 10);
        count = count + 1;
      }
      // digits came out backwards, so write them in reverse
      for (let d = count - 1; d >= 0; d--) {
        chars[write] = '' + digits[d];
        write = write + 1;
      }
    }
  }

  return write;
}

function run(arr) {
  const copy = [...arr];
  const len = compressManual(copy);
  return { length: len, result: copy.slice(0, len).join('') };
}

console.log(run(['a','a','b','b','b','c','c']));   // 6,  'a2b3c2'
console.log(run(['a','b','c']));                   // 3,  'abc'
console.log(run(['a','a','a']));                   // 2,  'a3'
console.log(run(Array(12).fill('a')));             // 3,  'a12'
console.log(run(Array(100).fill('x')));            // 4,  'x100'
console.log(run(['a','a','b','a','a']));           // 5,  'a2ba2'
console.log(run(['a']));                           // 1,  'a'
console.log(run([]));                              // 0,  ''

The digit extraction is worth reading closely. n % 10 gives the last digit; Math.floor(n / 10) chops it off. Repeating that pulls the digits out backwards, which is why the write loop runs in reverse. That is how every number-to-string conversion works underneath.

Step 7

Version 2 — with built-in methods

Version 2a — in place, the interview answer
function compress(chars) {
  let write = 0;
  let read = 0;

  while (read < chars.length) {
    const runChar = chars[read];
    let runLength = 0;

    while (read < chars.length && chars[read] === runChar) {
      read++;
      runLength++;
    }

    chars[write++] = runChar;

    if (runLength > 1) {
      for (const digit of String(runLength)) chars[write++] = digit;
    }
  }

  return write;
}

const a = ['a','a','b','b','b','c','c'];
console.log(compress(a), a.slice(0, 6).join(''));      // 6 'a2b3c2'

const b = Array(12).fill('a');
console.log(compress(b), b.slice(0, 3).join(''));      // 3 'a12'

const c = ['a','b','c'];
console.log(compress(c), c.slice(0, 3).join(''));      // 3 'abc'
Version 2b — string in, string out
function compressString(s) {
  if (!s) return '';

  const parts = [];
  let i = 0;

  while (i < s.length) {
    const ch = s[i];
    let j = i;
    while (j < s.length && s[j] === ch) j++;

    const runLength = j - i;
    parts.push(ch);
    if (runLength > 1) parts.push(String(runLength));

    i = j;
  }

  return parts.join('');
}

console.log(compressString('aabbbcc'));        // 'a2b3c2'
console.log(compressString('abc'));            // 'abc'
console.log(compressString('aaaaaaaaaaaa'));   // 'a12'
console.log(compressString('aabaa'));          // 'a2ba2'
console.log(compressString(''));               // ''

// A regex does the run-finding for you, if you like it:
function compressRegex(s) {
  return s.replace(/(.)\1*/g, m => m.length > 1 ? m[0] + m.length : m[0]);
}

console.log(compressRegex('aabbbcc'));         // 'a2b3c2'
console.log(compressRegex('aaaaaaaaaaaa'));    // 'a12'
console.log(compressRegex('abc'));             // 'abc'

// (.)\1*  means "any character, then that same character repeated".
// \1 is a backreference to the first group. Short, and much harder
// to explain on a whiteboard -- know it, but write the loop.
and the decompression, which is the useful half
function decompress(s) {
  const parts = [];
  let i = 0;

  while (i < s.length) {
    const ch = s[i];
    i++;

    // read the digits that follow, if any
    let digits = '';
    while (i < s.length && s[i] >= '0' && s[i] <= '9') {
      digits += s[i];
      i++;
    }

    const count = digits === '' ? 1 : parseInt(digits, 10);
    parts.push(ch.repeat(count));
  }

  return parts.join('');
}

console.log(decompress('a2b3c2'));     // 'aabbbcc'
console.log(decompress('abc'));        // 'abc'
console.log(decompress('a12'));        // 'aaaaaaaaaaaa'
console.log(decompress('x100'));       // 100 x's

// compress again here so this block stands on its own
function compressAgain(str) {
  if (!str) return '';
  const parts = [];
  let i = 0;
  while (i < str.length) {
    const ch = str[i];
    let j = i;
    while (j < str.length && str[j] === ch) j++;
    parts.push(ch);
    if (j - i > 1) parts.push(String(j - i));
    i = j;
  }
  return parts.join('');
}

const original = 'aaabbbbccd';
console.log('compressed  :', compressAgain(original));      // 'a3b4c2d'
console.log('round trip works:', decompress(compressAgain(original)) === original);

// Note the multi-digit read: you must consume ALL the digits, not
// just one, or 'a12' decompresses to 'a' repeated once then '2'.
// Same trap as the compression side, from the other direction.
Run-length encoding breaks on digits in the input

If the string can contain digits, "a2" is ambiguous — is it a run of two a’s, or the literal characters a and 2? Real formats solve this with an escape character or by always writing the count. Worth raising as a clarifying question: “can the input contain digits?” is exactly the kind of thing interviewers reward.

Step 8

Complexity, in sentences

SolutionTimeExtra space
String +=O(n) to O(n²)O(n)
Array of parts + joinO(n)O(n)
In placeO(n)O(1)

Why O(n) despite the nested while. Same argument as the sliding window: the inner loop advances read, and read only ever moves forward, crossing the array exactly once in total. The outer loop does not restart it.

O(1) space for the in-place version — two indexes and a run counter, whatever the input size. The digits of the count are written straight into the array, not buffered. (Version 1’s hand-rolled digit array holds at most 10 entries for any realistic count, which is constant.)

Say this in the interview

“I use a read pointer to measure each run and a write pointer for the compressed output. Because a run of length k compresses to 1 + digits(k) characters, which is never more than k, the write pointer can never overtake the read pointer — so writing in place is safe. A count of 10 or more needs several slots, so I write String(count) digit by digit. O(n) time, O(1) space, and I return the new length rather than a string.”

Step 9

Mistakes people actually make

1. Assuming the count is one character

Broken — a number in a character array
function broken(chars) {
  let write = 0, read = 0;
  while (read < chars.length) {
    const ch = chars[read];
    let n = 0;
    while (read < chars.length && chars[read] === ch) { read++; n++; }
    chars[write++] = ch;
    if (n > 1) chars[write++] = n;      // the NUMBER, in one slot -- bug
  }
  return write;
}

const a = Array(12).fill('a');
const len = broken(a);
console.log('length reported:', len);              // 2 -- should be 3
console.log('slots:', a.slice(0, len));            // ['a', 12]
console.log('types:', a.slice(0, len).map(x => typeof x));   // ['string','number']
console.log('joined:', a.slice(0, len).join(''));  // 'a12' -- looks fine!

// join() stringifies, so the output LOOKS correct. But the array
// contains a number where a character belongs, and the returned
// length is wrong. Any caller that trusts the length gets 'a1'.

2. Forgetting to flush the last run

Broken — the final run is lost
function broken(s) {
  let out = '';
  let ch = s[0], n = 1;
  for (let i = 1; i < s.length; i++) {      // stops AT length -- bug
    if (s[i] === ch) n++;
    else { out += ch; if (n > 1) out += n; ch = s[i]; n = 1; }
  }
  return out;                               // last run never written
}

console.log(broken('aabbbcc'));   // 'a2b3'   WRONG, the 'c2' is missing
console.log(broken('abc'));       // 'ab'     WRONG, the 'c' is missing
console.log(broken('aaa'));       // ''       WRONG, nothing at all

// The run is only written when a DIFFERENT character arrives, and
// after the last character none ever does. Either loop to
// i <= s.length (see Step 2) or flush once more after the loop.

3. Writing "1" for a single character

Broken — and now it can grow
function broken(s) {
  const parts = [];
  let i = 0;
  while (i < s.length) {
    const ch = s[i];
    let j = i;
    while (j < s.length && s[j] === ch) j++;
    parts.push(ch, String(j - i));      // always writes the count -- bug
    i = j;
  }
  return parts.join('');
}

console.log(broken('abc'));       // 'a1b1c1'  -- longer than the input
console.log(broken('aabbbcc'));   // 'a2b3c2'  -- fine

// Beyond being the wrong answer, this breaks the in-place version's
// safety proof: the output can now be twice the input, so the write
// pointer WOULD overtake the read pointer.

4. Returning the array instead of the length

The in-place signature returns a number. The caller reads only the first k slots and ignores the rest — which still contain leftover characters. Returning chars or chars.join('') misreads the contract.

5. Comparing with the next character instead of tracking the run

Broken — look-ahead off the end
function broken(s) {
  let out = '', n = 1;
  for (let i = 0; i < s.length; i++) {
    if (s[i] === s[i + 1]) {          // s[length] is undefined -- fine
      n++;
    } else {
      out += s[i] + (n > 1 ? n : '');
      n = 1;
    }
  }
  return out;
}

console.log(broken('aabbbcc'));   // 'a2b3c2'   correct
console.log(broken('abc'));       // 'abc'      correct
console.log(broken(''));          // ''         correct

// This one actually WORKS -- s[i+1] being undefined at the end
// conveniently forces the final flush. It is fine, but it relies on
// out-of-range indexing returning undefined rather than throwing.
// That is true in JavaScript and NOT true in most other languages,
// so it is a habit that does not travel. Prefer tracking the run.
Step 10

Practice before you move on

  1. Write the in-place version from memory, then test it on twelve identical characters. If it returns 2 instead of 3, you have the single-digit bug.
  2. Write the decompressor. It is in Step 7 — cover it and rewrite it, paying attention to reading all the digits.
  3. Only compress if it helps. Return the original string when the compressed form is not shorter. (With the count-of-1 omitted it never is longer, but the always-write-the-count variant needs this check.)
  4. Case-insensitive runs. "aAaBb" becomes "a3b2". One comparison changes.
  5. Encode and decode a list of strings. The real version of this problem: join a list into one string so it can be split back unambiguously, even when the strings contain the separator. Hint: prefix each string with its length. It is the same “count then payload” idea, and it is how real network protocols do it.
What to carry forward

Two things. The read/write pointer pair is now the third time you have seen it — Move Zeroes, in-place filtering, and here. And the one-past-the-end loop is a small trick worth keeping: when you are grouping consecutive items and need to flush the final group, running one step beyond the array removes the duplicated flush code and the bug that comes with forgetting it.
