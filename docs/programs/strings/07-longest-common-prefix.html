Strings · Problem 07

Longest Common Prefix

An easy problem with a nice reframe. Instead of comparing words to each other horizontally, line them up and read down each column. The first column where anything disagrees is where the answer ends.

Step 1

The problem

Find the longest string that every word in the list starts with. If there is none, return the empty string.

InputAnswerWhy
["flower","flow","flight"]"fl"all three start "fl", then they differ
["dog","racecar","car"]""nothing in common
["interspecies","interstellar","interstate"]"inters"
["abc"]"abc"one word is its own prefix
["abc",""]""an empty word kills everything
[]""no words at all
Two facts that bound the answer before you start

The answer can never be longer than the shortest word — a prefix of a 4-letter word is at most 4 characters. And it can never be longer than the common prefix of the first two words. Either observation gives you a cheap early exit.

Step 2

Think first — horizontal scanning

Take the first word as a candidate prefix. Compare it with the second word and trim it down to whatever they share. Compare that with the third. Keep shrinking.

Version 0 — shrink the candidate
function longestCommonPrefixHorizontal(words) {
  if (words.length === 0) return '';

  let prefix = words[0];

  for (let i = 1; i < words.length; i++) {
    // trim the prefix until words[i] actually starts with it
    while (words[i].indexOf(prefix) !== 0) {
      prefix = prefix.slice(0, prefix.length - 1);
      if (prefix === '') return '';        // nothing left in common
    }
  }

  return prefix;
}

console.log(longestCommonPrefixHorizontal(["flower","flow","flight"]));   // 'fl'
console.log(longestCommonPrefixHorizontal(["dog","racecar","car"]));      // ''
console.log(longestCommonPrefixHorizontal(["abc"]));                      // 'abc'
console.log(longestCommonPrefixHorizontal(["abc",""]));                   // ''
console.log(longestCommonPrefixHorizontal([]));                           // ''

Correct, and it is the answer most people give. The indexOf(prefix) !== 0 test asks “does this word begin with the prefix?”, which startsWith now says more clearly. Both scan the prefix each time.

Step 3

Why it does more work than needed

Both approaches are O(total characters) in the worst case, so this is not a complexity story — it is a wasted work story.

Horizontal scanning starts with the whole of the first word as the candidate. If the first word is long and the answer is short, it repeatedly re-checks and trims a candidate that was never plausible:

words = ["aaaaaaaaaaaaaaaaaaaa", "b"]

prefix starts as the 20-character word.
Compare with "b": no match. Trim to 19. No match. Trim to 18. ...
Twenty trims, twenty comparisons, to discover the answer is "".

Vertical scanning compares column 0 -- 'a' vs 'b' -- and stops.
One comparison.
Timing demo
// 2,000 long words that share nothing after the first character
const words = [];
for (let i = 0; i < 2000; i++) {
  words.push(String.fromCharCode(97 + (i % 26)) + 'x'.repeat(3000));
}

function horizontal(list) {
  if (!list.length) return '';
  let prefix = list[0];
  for (let i = 1; i < list.length; i++) {
    while (list[i].indexOf(prefix) !== 0) {
      prefix = prefix.slice(0, -1);
      if (!prefix) return '';
    }
  }
  return prefix;
}

function vertical(list) {
  if (!list.length) return '';
  for (let col = 0; col < list[0].length; col++) {
    const ch = list[0][col];
    for (let w = 1; w < list.length; w++) {
      if (col === list[w].length || list[w][col] !== ch) {
        return list[0].slice(0, col);
      }
    }
  }
  return list[0];
}

let t = performance.now();
const a = horizontal(words);
const hMs = performance.now() - t;

t = performance.now();
const b = vertical(words);
const vMs = performance.now() - t;

console.log('horizontal : "' + a + '" in ' + hMs.toFixed(1) + ' ms');
console.log('vertical   : "' + b + '" in ' + vMs.toFixed(2) + ' ms');
console.log('same answer:', a === b);
console.log('speed-up:', Math.round(hMs / Math.max(vMs, 0.01)) + 'x');
Step 4

The better idea — read down the columns

Write the words one under the other and read vertically:

        col:  0  1  2  3  4  5

  flower       f  l  o  w  e  r
  flow         f  l  o  w
  flight       f  l  i  g  h  t
               -  -  ^
               |  |  |
             all all  'o' vs 'o' vs 'i'  ->  DISAGREEMENT
              f   l

  answer: columns 0 and 1  ->  "fl"
The unlock

Walk column by column. At column c, take the character from the first word and check every other word has the same one. The moment any word disagrees — or runs out of characters — the answer is everything before this column.

Why this is better: it stops as soon as possible. It never looks past the answer, never builds a candidate it will discard, and it reads at most (length of answer + 1) × number of words characters.

The check people forget

col === words[w].length — the word has ended. Reading words[w][col] past the end gives undefined, which never equals a real character, so in JavaScript it happens to behave correctly by accident. Write the check explicitly anyway: it states the intent, and in most other languages the same code would crash.

Step 5

Dry run — trace it by hand

Without the length check, "flo"[3] is undefined, which is not 'w',

Step 6

Version 1 — without built-in methods

Version 1 — vertical scan, loops only
function longestCommonPrefixManual(words) {
  if (words.length === 0) return '';

  const first = words[0];
  let matched = 0;          // how many columns have agreed so far

  // walk the columns of the first word
  for (let col = 0; col < first.length; col++) {
    const ch = first[col];

    // does every other word have this character at this column?
    let allAgree = true;

    for (let w = 1; w < words.length; w++) {
      if (col >= words[w].length || words[w][col] !== ch) {
        allAgree = false;
        break;
      }
    }

    if (!allAgree) break;
    matched = matched + 1;
  }

  // build the prefix without slice
  let prefix = '';
  for (let k = 0; k < matched; k++) {
    prefix = prefix + first[k];
  }
  return prefix;
}

console.log(longestCommonPrefixManual(["flower","flow","flight"]));   // 'fl'
console.log(longestCommonPrefixManual(["dog","racecar","car"]));      // ''
console.log(longestCommonPrefixManual(["interspecies","interstellar","interstate"]));  // 'inters'
console.log(longestCommonPrefixManual(["abc"]));                      // 'abc'
console.log(longestCommonPrefixManual(["abc",""]));                   // ''
console.log(longestCommonPrefixManual([]));                           // ''
console.log(longestCommonPrefixManual(["a","a","a"]));                // 'a'
console.log(longestCommonPrefixManual(["flow","flower","flo"]));      // 'flo'
console.log(longestCommonPrefixManual(["ab","abc","abcd"]));          // 'ab'
Why the first word is a safe reference

Any common prefix must be a prefix of every word, including the first one. So comparing everything against words[0] loses nothing. You could use the shortest word as the reference instead — it caps the loop sooner — but finding it costs a pass, and the length check inside the loop already handles running out.

Step 7

Version 2 — with built-in methods

Version 2a — vertical, the interview answer
function longestCommonPrefix(words) {
  if (words.length === 0) return '';

  const first = words[0];

  for (let col = 0; col < first.length; col++) {
    const ch = first[col];

    for (let w = 1; w < words.length; w++) {
      if (col === words[w].length || words[w][col] !== ch) {
        return first.slice(0, col);
      }
    }
  }

  return first;
}

console.log(longestCommonPrefix(["flower","flow","flight"]));   // 'fl'
console.log(longestCommonPrefix(["dog","racecar","car"]));      // ''
console.log(longestCommonPrefix(["interspecies","interstellar","interstate"]));
console.log(longestCommonPrefix([]));                           // ''
console.log(longestCommonPrefix(["abc",""]));                   // ''
Version 2b — horizontal with reduce
function longestCommonPrefixReduce(words) {
  if (words.length === 0) return '';

  return words.reduce((prefix, word) => {
    let i = 0;
    while (i < prefix.length && i < word.length && prefix[i] === word[i]) i++;
    return prefix.slice(0, i);
  });
}

console.log(longestCommonPrefixReduce(["flower","flow","flight"]));   // 'fl'
console.log(longestCommonPrefixReduce(["dog","racecar","car"]));      // ''
console.log(longestCommonPrefixReduce(["abc"]));                      // 'abc'

// reduce with NO initial value uses the first element as the seed,
// which is exactly what we want here. Note it throws on an empty
// array -- hence the guard.
Version 2c — the sorting trick
// Sort the words. The common prefix of the WHOLE list is then just
// the common prefix of the first and last -- because sorting puts
// the two most dissimilar words at the ends.
function longestCommonPrefixSorted(words) {
  if (words.length === 0) return '';

  const sorted = [...words].sort();
  const first = sorted[0];
  const last = sorted[sorted.length - 1];

  let i = 0;
  while (i < first.length && first[i] === last[i]) i++;

  return first.slice(0, i);
}

console.log(longestCommonPrefixSorted(["flower","flow","flight"]));   // 'fl'
console.log(longestCommonPrefixSorted(["dog","racecar","car"]));      // ''
console.log(longestCommonPrefixSorted(["interspecies","interstellar","interstate"]));

// O(n*k log n) because of the sort -- worse than vertical scanning.
// But it is a genuinely clever observation and a good thing to
// mention: in sorted order, every word between the first and the
// last shares at least whatever those two share.
the divide-and-conquer version
// Split the list in half, solve each half, then combine the two
// answers with the same pairwise prefix. Useful when the work can be
// parallelised, and a nice recursion warm-up.
function commonOfTwo(a, b) {
  let i = 0;
  while (i < a.length && i < b.length && a[i] === b[i]) i++;
  return a.slice(0, i);
}

function longestCommonPrefixDivide(words, lo = 0, hi = words.length - 1) {
  if (words.length === 0) return '';
  if (lo === hi) return words[lo];

  const mid = Math.floor((lo + hi) / 2);
  const left = longestCommonPrefixDivide(words, lo, mid);
  const right = longestCommonPrefixDivide(words, mid + 1, hi);

  return commonOfTwo(left, right);
}

console.log(longestCommonPrefixDivide(["flower","flow","flight"]));   // 'fl'
console.log(longestCommonPrefixDivide(["dog","racecar","car"]));      // ''
console.log(longestCommonPrefixDivide(["a"]));                        // 'a'
console.log(longestCommonPrefixDivide(["ab","abc","abcd","abcde"]));  // 'ab'
Step 8

Complexity, in sentences

SolutionTimeSpace
Horizontal shrinkingO(n · k)O(k)
Vertical scanningO(n · k)O(1)
Sort then compare endsO(n · k log n)O(n · k)
Divide and conquerO(n · k)O(k log n)

where n is the number of words and k the length of the shortest one.

Vertical and horizontal share the same worst case — when all the words are identical, both read everything. They differ in the best case: vertical stops at the first disagreeing column, which is why it wins so dramatically in the Step 3 demo. Big-O hides that difference entirely, which is a useful reminder that it is an upper bound, not a description of typical behaviour.

Vertical scanning is O(1) space because it never builds an intermediate string — it tracks a column index and slices once at the end.

Say this in the interview

“I scan vertically: for each column index, take the character from the first word and check every other word matches it, stopping as soon as one differs or runs out. The answer is the first word sliced to that column. O(n·k) worst case, but it exits at the first disagreement rather than trimming a candidate down, and it uses O(1) extra space. Sorting and comparing the first and last word also works and is a nice observation, but the sort makes it slower.”

Step 9

Mistakes people actually make

1. Not handling the empty list

Broken — crashes on []
function broken(words) {
  const first = words[0];               // undefined for []
  for (let col = 0; col < first.length; col++) {
    for (let w = 1; w < words.length; w++) {
      if (words[w][col] !== first[col]) return first.slice(0, col);
    }
  }
  return first;
}

console.log(broken(["flower","flow"]));   // 'flow'

try {
  console.log(broken([]));
} catch (err) {
  console.log('threw:', err.message);
}

// One guard line at the top. Every list-of-things problem needs it.

2. Comparing only the first two words

Broken — ignores the rest
function broken(words) {
  if (words.length === 0) return '';
  if (words.length === 1) return words[0];
  const a = words[0], b = words[1];
  let i = 0;
  while (i < a.length && i < b.length && a[i] === b[i]) i++;
  return a.slice(0, i);                 // stops after two words -- bug
}

console.log(broken(["flower","flow","flight"]));   // 'flow'  WRONG, should be 'fl'
console.log(broken(["abc","abd","x"]));            // 'ab'    WRONG, should be ''

// The common prefix of the first two is an upper BOUND, not the
// answer. Every remaining word can only shorten it further.

3. Forgetting the shorter word runs out

why it accidentally works in JavaScript
const word = 'flo';
console.log(word[3]);              // undefined -- no crash
console.log(word[3] === 'w');      // false -- so a mismatch is reported
console.log(word.charAt(3));       // '' -- also not a crash

// So a solution WITHOUT the length check gives the right answer here:
function noLengthCheck(words) {
  const first = words[0];
  for (let col = 0; col < first.length; col++)
    for (let w = 1; w < words.length; w++)
      if (words[w][col] !== first[col]) return first.slice(0, col);
  return first;
}
console.log(noLengthCheck(["flow","flower","flo"]));   // 'flo'  correct

// It is right by accident. Write `col === words[w].length ||` anyway:
// it documents the case, and the same code in Java or C++ would be
// an out-of-bounds error rather than a convenient undefined.

4. Using the first word as the reference when a later word is shorter

This is fine — as long as the loop checks lengths. What is not fine is looping col to the length of the longest word, or assuming words[0] is shortest. The outer loop must be bounded by the reference word, and every inner comparison must handle a word that has ended.

5. Returning null or undefined instead of ""

“No common prefix” is the empty string, not a missing value. A caller doing result.length crashes on null and works on "". Return the same type on every path.

Step 10

Practice before you move on

  1. Write the vertical scan from memory, including both parts of the inner test — ran out, or disagreed.
  2. Longest common suffix. Same algorithm, walking the columns from the end. Watch the index arithmetic: the last character of word is word[word.length - 1 - col].
  3. Longest common prefix of just two strings. Extract it as a helper, then build the divide-and-conquer version on top of it. It is in Step 7.
  4. Group words by shared prefix length. Which pairs share at least three characters? A natural lead-in to tries.
  5. Build a trie. Insert every word into a prefix tree; the common prefix is the path from the root down to the first node with more than one child. Enormous overkill here, and exactly right when you need to answer many prefix questions about the same word list.
What to carry forward

Change the direction you iterate. The data was a list of words; reading it as a grid of columns made the stopping condition obvious and the early exit free. When a nested loop feels awkward, try swapping which dimension is on the outside — it costs nothing to consider and occasionally turns the problem inside out.
