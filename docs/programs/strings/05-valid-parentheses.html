Strings · Problem 05

Valid Parentheses

The classic stack problem — except this page does not start by telling you to use a stack. It starts with the rule “most recently opened, first closed”, and lets the stack fall out of that. An array with push and pop is all you need.

Step 1

The problem

A string contains only the characters ( ) [ ] { }. Decide whether the brackets are correctly matched and correctly nested.

InputValid?Why
"()"truematched pair
"()[]{}"truethree pairs side by side
"{[()]}"trueproperly nested
"(]"falsewrong closer
"([)]"falsecrossed, not nested
"("falsenever closed
")("falsecloser before any opener
The row that defines the problem

"([)]" has one ( and one ), one [ and one ]. The counts are perfect. It is still invalid, because the brackets cross rather than nest.

That single example kills every counting-based solution. You cannot just tally openers and closers — you have to know which bracket is still waiting to be closed.

Step 2

Think first — two ideas that almost work

Version 0a — counting
function byCounting(s) {
  let round = 0, square = 0, curly = 0;
  for (const ch of s) {
    if (ch === '(') round++;
    else if (ch === ')') { round--; if (round < 0) return false; }
    else if (ch === '[') square++;
    else if (ch === ']') { square--; if (square < 0) return false; }
    else if (ch === '{') curly++;
    else if (ch === '}') { curly--; if (curly < 0) return false; }
  }
  return round === 0 && square === 0 && curly === 0;
}

console.log(byCounting('()'));       // true
console.log(byCounting('()[]{}'));   // true
console.log(byCounting('{[()]}'));   // true
console.log(byCounting('(]'));       // false
console.log(byCounting('('));        // false
console.log(byCounting('([)]'));     // TRUE -- WRONG, should be false

// Counting tracks HOW MANY are open, never WHICH ONE is innermost.
// It cannot tell nesting from crossing.
Version 0b — repeatedly delete matched pairs
function byDeleting(s) {
  let previous;
  do {
    previous = s;
    s = s.replace('()', '').replace('[]', '').replace('{}', '');
  } while (s !== previous);

  return s.length === 0;
}

console.log(byDeleting('()'));       // true
console.log(byDeleting('()[]{}'));   // true
console.log(byDeleting('{[()]}'));   // true
console.log(byDeleting('(]'));       // false
console.log(byDeleting('([)]'));     // false   correct!
console.log(byDeleting(')('));       // false

// This one is actually CORRECT. An innermost pair is always adjacent,
// so peeling adjacent pairs eventually empties a valid string.
// But every pass rebuilds the whole string: O(n^2) at best.

Version 0b is worth pausing on because the idea behind it is exactly right: the pair you can resolve is always the innermost one. That observation is what leads to the real solution — without repeatedly rewriting the string.

Step 3

Why deleting is slow

Each pass creates a brand-new string, and you need up to n/2 passes. O(n²) time and O(n) garbage per pass. On deeply nested input like "((((((...))))))" it removes exactly one pair per pass — the worst case.

Timing demo
// deeply nested: 4,000 open brackets then 4,000 closers
const N = 4000;
const s = '('.repeat(N) + ')'.repeat(N);

function byDeleting(str) {
  let prev;
  do {
    prev = str;
    str = str.replace('()', '').replace('[]', '').replace('{}', '');
  } while (str !== prev);
  return str.length === 0;
}

function byStack(str) {
  const pairs = { ')': '(', ']': '[', '}': '{' };
  const stack = [];
  for (const ch of str) {
    if (ch === '(' || ch === '[' || ch === '{') stack.push(ch);
    else {
      if (stack.pop() !== pairs[ch]) return false;
    }
  }
  return stack.length === 0;
}

let t = performance.now();
const a = byDeleting(s);
const delMs = performance.now() - t;

t = performance.now();
const b = byStack(s);
const stackMs = performance.now() - t;

console.log('delete pairs :', a, 'in', delMs.toFixed(1) + ' ms');
console.log('stack        :', b, 'in', stackMs.toFixed(2) + ' ms');
console.log('speed-up:', Math.round(delMs / Math.max(stackMs, 0.01)) + 'x');
Step 4

The better idea — remember what is still open

Read the string left to right and ask what you actually need to know at each closing bracket. Only one thing: which bracket did I open most recently and not yet close?

The unlock

Brackets close in the reverse order they opened. The most recently opened one must be the first to close. So keep a pile of open brackets: push each opener on top, and when a closer arrives, it must match whatever is on top.

“Add to the top, remove from the top” is a stack. In JavaScript, an array with push and pop is one.

The rules, in full:

  1. Opener — push it. It is now waiting.
  2. Closer — look at the top of the stack.
    • Stack empty? There is nothing to close. Invalid.
    • Top does not match this closer? Wrong bracket. Invalid.
    • Otherwise pop it — that pair is resolved.
  3. End of string — the stack must be empty. Anything left is an opener that was never closed. Invalid.
The two checks people forget

Closer with an empty stack — without it, ")(" passes.
Non-empty stack at the end — without it, "(" passes.

Both failures are asymmetric: the middle of the string looks fine, and the bug lives at an edge. Test "(" and ")" on every solution you write.

Step 5

Dry run — trace it by hand

s = "{[()]}" — valid.

stack = []

'{'   opener  ->  push            stack = ['{']
'['   opener  ->  push            stack = ['{','[']
'('   opener  ->  push            stack = ['{','[','(']
')'   closer  ->  top is '('  matches  ->  pop    stack = ['{','[']
']'   closer  ->  top is '['  matches  ->  pop    stack = ['{']
'}'   closer  ->  top is '{'  matches  ->  pop    stack = []

end of string, stack is empty  ->  VALID

Watch the stack grow to three and unwind in exactly the reverse order. That mirroring is correct nesting.

Now the crossing case, s = "([)]":

stack = []

'('   opener  ->  push            stack = ['(']
'['   opener  ->  push            stack = ['(','[']
')'   closer  ->  top is '['      ')' needs '('    MISMATCH  ->  INVALID

We never even reach the ']'. The stack knew immediately that the
innermost open bracket was a square one, so a round closer is wrong.
Counting could never have caught this.

And the two edge cases:

s = ")("
')'   closer  ->  stack is EMPTY  ->  nothing to close  ->  INVALID

s = "("
'('   opener  ->  push            stack = ['(']
end of string, stack is NOT empty ->  INVALID
the algorithm, narrating itself
function validExplained(s) {
  const needs = { ')': '(', ']': '[', '}': '{' };
  const stack = [];

  console.log('s = "' + s + '"');

  for (const ch of s) {
    if (ch === '(' || ch === '[' || ch === '{') {
      stack.push(ch);
      console.log("  '" + ch + "'  opener -> push          stack = [" + stack.join(',') + "]");
    } else {
      if (stack.length === 0) {
        console.log("  '" + ch + "'  closer -> stack EMPTY, nothing to close  -> INVALID");
        console.log('');
        return false;
      }

      const top = stack.pop();
      if (top !== needs[ch]) {
        console.log("  '" + ch + "'  closer -> top is '" + top + "', needed '" +
                    needs[ch] + "'  MISMATCH -> INVALID");
        console.log('');
        return false;
      }

      console.log("  '" + ch + "'  closer -> top '" + top + "' matches -> pop   stack = [" +
                  stack.join(',') + "]");
    }
  }

  const ok = stack.length === 0;
  console.log('  end of string, stack = [' + stack.join(',') + ']  ->  ' +
              (ok ? 'VALID' : 'INVALID, unclosed openers'));
  console.log('');
  return ok;
}

Step 6

Version 1 — without built-in methods

No push, no pop, no object lookup. An array plus a top index — which is exactly how a stack is implemented underneath.

Version 1 — a stack built by hand
function isValidManual(s) {
  const stack = [];
  let top = 0;              // the number of items currently on the stack

  for (let i = 0; i < s.length; i++) {
    const ch = s[i];

    if (ch === '(' || ch === '[' || ch === '{') {
      stack[top] = ch;      // push
      top = top + 1;

    } else if (ch === ')' || ch === ']' || ch === '}') {

      // nothing open? then this closer has no partner
      if (top === 0) return false;

      top = top - 1;              // pop
      const opener = stack[top];

      // does the opener we popped match this closer?
      let matches = false;
      if (ch === ')' && opener === '(') matches = true;
      if (ch === ']' && opener === '[') matches = true;
      if (ch === '}' && opener === '{') matches = true;

      if (!matches) return false;
    }
    // any other character is ignored
  }

  // everything that opened must have closed
  return top === 0;
}

console.log(isValidManual('()'));         // true
console.log(isValidManual('()[]{}'));     // true
console.log(isValidManual('{[()]}'));     // true
console.log(isValidManual('(]'));         // false
console.log(isValidManual('([)]'));       // false
console.log(isValidManual('('));          // false
console.log(isValidManual(')('));         // false
console.log(isValidManual(''));           // true   nothing to mismatch
console.log(isValidManual('{[]}()'));     // true
console.log(isValidManual('((()))'));     // true
console.log(isValidManual('(()'));        // false

Notice that top does double duty: it is the push position, the pop position minus one, and the “how many are open” count. That is not a coincidence — it is what a stack pointer is.

Why the empty string is valid

Nothing opened, so nothing is unclosed. It sounds like a trick answer but it is the mathematically consistent one, and top === 0 returns it without a special case. Confirm the expected behaviour with your interviewer rather than assuming.

Step 7

Version 2 — with built-in methods

Version 2a — the interview answer
function isValid(s) {
  const needs = { ')': '(', ']': '[', '}': '{' };
  const stack = [];

  for (const ch of s) {
    if (needs[ch]) {
      // it is a closer: the top must be its partner
      if (stack.pop() !== needs[ch]) return false;
    } else {
      stack.push(ch);
    }
  }

  return stack.length === 0;
}

console.log(isValid('()'));         // true
console.log(isValid('()[]{}'));     // true
console.log(isValid('{[()]}'));     // true
console.log(isValid('(]'));         // false
console.log(isValid('([)]'));       // false
console.log(isValid(')('));         // false
console.log(isValid('('));          // false
console.log(isValid(''));           // true

Six lines, and it handles the empty-stack case for free: [].pop() returns undefined, which never equals '(', so the comparison fails and it returns false. That is elegant — but only because undefined can never be a legitimate opener. Know why it works before relying on it.

Version 2b — push the expected closer instead
// A different framing some people find clearer: when you see an
// opener, push the closer you will need later.
function isValidExpect(s) {
  const closerFor = { '(': ')', '[': ']', '{': '}' };
  const expected = [];

  for (const ch of s) {
    if (closerFor[ch]) {
      expected.push(closerFor[ch]);     // remember what must come
    } else if (expected.pop() !== ch) {
      return false;                     // wrong thing came
    }
  }

  return expected.length === 0;
}

console.log(isValidExpect('{[()]}'));   // true
console.log(isValidExpect('([)]'));     // false
console.log(isValidExpect('('));        // false

// Same algorithm, and the stack now reads like a to-do list:
// "{[(" pushes "}", "]", ")" -- literally the ending you owe.
the realistic version — other characters allowed
// Real input has content between the brackets.
function bracketsBalanced(text) {
  const needs = { ')': '(', ']': '[', '}': '{' };
  const openers = new Set(['(', '[', '{']);
  const stack = [];

  for (const ch of text) {
    if (openers.has(ch)) stack.push(ch);
    else if (needs[ch] && stack.pop() !== needs[ch]) return false;
    // everything else is ignored
  }

  return stack.length === 0;
}

console.log(bracketsBalanced('function f(a, b) { return [a, b]; }'));   // true
console.log(bracketsBalanced('if (x) { y[0 }'));                        // false
console.log(bracketsBalanced('no brackets here at all'));               // true

// Report WHERE it went wrong -- far more useful in a real tool.
function checkBrackets(text) {
  const needs = { ')': '(', ']': '[', '}': '{' };
  const openers = new Set(['(', '[', '{']);
  const stack = [];

  for (let i = 0; i < text.length; i++) {
    const ch = text[i];
    if (openers.has(ch)) stack.push({ ch, i });
    else if (needs[ch]) {
      const last = stack.pop();
      if (!last) return { ok: false, at: i, message: 'unexpected "' + ch + '"' };
      if (last.ch !== needs[ch]) {
        return { ok: false, at: i,
                 message: '"' + ch + '" closes "' + last.ch + '" opened at ' + last.i };
      }
    }
  }

  if (stack.length) {
    return { ok: false, at: stack[stack.length - 1].i, message: 'never closed' };
  }
  return { ok: true };
}

console.log(checkBrackets('a(b[c]d)e'));    // { ok: true }
console.log(checkBrackets('a(b[c)d]'));     // mismatch, with positions
console.log(checkBrackets('a(b'));          // never closed
console.log(checkBrackets('a)b'));          // unexpected ")"
Step 8

Complexity, in sentences

SolutionTimeSpaceCorrect?
CountingO(n)O(1)no
Delete pairs repeatedlyO(n²)O(n)yes
StackO(n)O(n)yes

One pass, and every character does a constant amount of work — one comparison and at most one push or pop. So O(n) time.

Space O(n), and the worst case is real: "((((((..." puts every character on the stack. You cannot do better, and that is worth stating — the O(1)-space counting approach is the one that does not work. Sometimes the memory is the price of correctness, not an optimisation you failed to make.

Say this in the interview

“Counting openers and closers fails on ([)], because it tracks how many are open but not which one is innermost. Brackets must close in reverse order of opening, which is a stack. I push openers; on a closer I pop and check it matches, returning false if the stack is empty or the top is the wrong type; at the end the stack must be empty. O(n) time, O(n) space in the worst case of all openers.”

Step 9

Mistakes people actually make

1. Forgetting the final emptiness check

Broken — unclosed openers pass
function broken(s) {
  const needs = { ')': '(', ']': '[', '}': '{' };
  const stack = [];
  for (const ch of s) {
    if (needs[ch]) { if (stack.pop() !== needs[ch]) return false; }
    else stack.push(ch);
  }
  return true;          // no stack.length check -- bug
}

console.log(broken('()'));      // true   fine
console.log(broken('([)]'));    // false  fine
console.log(broken('('));       // TRUE   WRONG
console.log(broken('((('));     // TRUE   WRONG
console.log(broken('{[('));     // TRUE   WRONG

// Nothing ever mismatched, because nothing ever closed. The check
// that everything was resolved happens at the END, not during.

2. Forgetting the empty-stack check on a closer

Broken — a closer with nothing open
function broken(s) {
  const needs = { ')': '(', ']': '[', '}': '{' };
  const stack = [];
  for (const ch of s) {
    if (needs[ch]) {
      const top = stack[stack.length - 1];
      if (top === needs[ch]) stack.pop();      // silently ignores a mismatch
    } else {
      stack.push(ch);
    }
  }
  return stack.length === 0;
}

console.log(broken('()'));      // true   fine
console.log(broken(')('));      // false  fine, by luck -- '(' is left over
console.log(broken('()]'));     // TRUE   WRONG -- the stray ']' was ignored
console.log(broken('(]'));      // false  fine

// Skipping a closer instead of REJECTING it lets stray closers pass
// whenever the stack happens to end up empty anyway.

3. Trying to solve it by counting

Step 2 shows this. It is the single most common wrong answer, and "([)]" is the input that exposes it. If a solution never stores which bracket is open, it cannot be right.

4. Using shift instead of pop

Broken — that is a queue, not a stack
function broken(s) {
  const needs = { ')': '(', ']': '[', '}': '{' };
  const stack = [];
  for (const ch of s) {
    if (needs[ch]) { if (stack.shift() !== needs[ch]) return false; }   // shift -- bug
    else stack.push(ch);
  }
  return stack.length === 0;
}

console.log(broken('()'));        // true   fine
console.log(broken('()[]{}'));    // true   fine
console.log(broken('{[()]}'));    // false  WRONG, should be true

// shift() takes from the FRONT -- the OLDEST opener. Nesting requires
// the NEWEST. Front-out is a queue; back-out is a stack. This problem
// needs a stack, and shift() is also O(n) per call.

5. Assuming only round brackets

A solution written for () alone often uses a counter, which then cannot be extended when [] and {} appear. Write the stack version even for the single-bracket case — it is barely longer and it generalises.

Step 10

Practice before you move on

  1. Write the six-line version from memory, then test it on "(", ")" and "". Those three catch every common bug.
  2. Longest valid parentheses substring. Push indexes rather than characters, and the distance between them gives you the length. A real step up.
  3. Minimum removals to make it valid. Count the unmatched closers as you go and the leftover openers at the end. Two counters, no stack needed — work out why the counting approach is valid for this variant when it was not for the original.
  4. Score of parentheses. "()" is 1, "(A)" is twice A, "AB" is A + B. Same stack, holding running scores instead of characters.
  5. Basic calculator. Evaluate "(1+(4+5+2)-3)+(6+8)". Push the running total and sign when a bracket opens, restore them when it closes. This is what stacks are genuinely for.
What to carry forward

Whenever the rule is “most recent first”, you want a stack. Matching brackets, undo history, function call frames, backtracking, evaluating expressions, parsing nested structures — all the same shape. And the reverse tell: if you find yourself needing to know which of several open things is innermost, a counter will never be enough.
