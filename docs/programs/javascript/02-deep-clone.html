JavaScript semantics · Problem 02

Deep Clone

Everyone knows the one-liner. The interview is about knowing the seven things it silently destroys — and then writing the version that does not.

Step 1

The problem

Copy a value so that changing the copy can never change the original, however deeply nested it is.

shallow versus deep, in six lines
const original = { name: 'Ada', address: { city: 'London' }, tags: ['x'] };

// SHALLOW: top-level keys copied, nested objects SHARED
const shallow = { ...original };
shallow.name = 'Grace';                  // safe -- a new top-level slot
shallow.address.city = 'Paris';          // NOT safe -- same object
shallow.tags.push('y');                  // NOT safe -- same array

console.log('after editing the shallow copy:');
console.log('  original.name        :', original.name);       // 'Ada'   -- fine
console.log('  original.address.city:', original.address.city); // 'Paris' -- LEAKED
console.log('  original.tags        :', original.tags);        // ['x','y'] -- LEAKED
console.log('');
console.log('  same address object? ', shallow.address === original.address);
console.log('  same tags array?     ', shallow.tags === original.tags);
Why this happens at all

A JavaScript variable never holds an object. It holds a reference to one. { ...original } copies the references in each slot, so the copy and the original point at the same nested objects. Primitives — numbers, strings, booleans, null, undefined, symbols, bigints — are copied by value, which is why shallow.name was safe.

A deep clone follows every reference and rebuilds what it finds, all the way down.

The shallow copies you already know, and what they share:

Object.assign({}, obj)the same, and triggers settersevery nested object

Step 4

The better idea — recurse on the shape, remember what you have seen

This is the Flatten page's recursion again: one branch per shape the value can take. Two things make it harder.

The two real problems

Cycles. If an object contains itself, plain recursion never stops. Keep a Map from original object to its clone; before cloning anything, check whether you have already cloned it and return the existing copy.

Shared references. The same map solves a second, subtler problem: if two properties point at the same object, a naive clone produces two separate copies and silently changes the shape of the data. The map preserves the identity relationship.

  clone(value, seen):

      not an object (or null)   ->  return it as-is
      seen.has(value)           ->  return seen.get(value)

      Date      ->  new Date(value.getTime())
      RegExp    ->  new RegExp(value.source, value.flags)
      Map       ->  new Map, register it, then clone each key AND value
      Set       ->  new Set, register it, then clone each member
      Array     ->  new array, register it, then clone each element
      object    ->  new object with the SAME prototype, register it,
                    then clone each own key

  Register BEFORE recursing into the children. That ordering is
  what makes cycles terminate: by the time a child points back at
  the parent, the parent's clone is already in the map.
The ordering is the whole trick

Create the empty shell, put it in the map, then fill it. Fill first and register after, and a self-referencing object recurses forever — the clone is not in the map yet when the child asks for it.

Step 5

Dry run — a cycle, step by step

  const a = { name: 'a' };
  const b = { name: 'b', parent: a };
  a.child = b;                      // a -> b -> a

  clone(a, seen={})
    not seen. shell A' = {}. seen = { a -> A' }
    key 'name'  -> 'a' is a primitive, copy it
    key 'child' -> clone(b, seen)
        not seen. shell B' = {}. seen = { a -> A', b -> B' }
        key 'name'   -> 'b'
        key 'parent' -> clone(a, seen)
            SEEN. return A'          <-- the recursion stops here
        B'.parent = A'
        return B'
    A'.child = B'
    return A'

  Result: A' -> B' -> A'. The cycle is reproduced, not followed.
  And A'.child.parent === A' -- the identity relationship survived.
the algorithm, narrating itself
function cloneLoud(value, seen = new Map(), depth = 0, label = 'root') {
  const pad = '  '.repeat(depth);

  if (value === null || typeof value !== 'object') {
    console.log(pad + label + ': primitive ' + JSON.stringify(value) + ' -- copy');
    return value;
  }

  if (seen.has(value)) {
    console.log(pad + label + ': ALREADY SEEN -- return the existing clone');
    return seen.get(value);
  }

  const shell = Array.isArray(value) ? [] : {};
  seen.set(value, shell);
  console.log(pad + label + ': new ' + (Array.isArray(value) ? 'array' : 'object') +
              ' shell created and registered');

  for (const key of Object.keys(value)) {
    shell[key] = cloneLoud(value[key], seen, depth + 1, key);
  }

  return shell;
}

const a = { name: 'a' };
const b = { name: 'b', parent: a };
a.child = b;

const copy = cloneLoud(a);

console.log('');
console.log('cycle reproduced?      ', copy.child.parent === copy);
console.log('but not the original?  ', copy.child.parent !== a);
console.log('names intact?          ', copy.name, copy.child.name);

Version 1 — without built-in methods

Version 1 — plain data only, loops and index writes
function deepCloneBasic(value) {
  // primitives (and functions, which we return by reference)
  if (value === null || typeof value !== 'object') return value;

  if (Object.prototype.toString.call(value) === '[object Array]') {
    const arr = [];
    for (let i = 0; i < value.length; i++) arr[i] = deepCloneBasic(value[i]);
    return arr;
  }

  const out = {};
  for (const key in value) {
    // for...in walks the prototype chain -- filter to own keys
    if (Object.prototype.hasOwnProperty.call(value, key)) {
      out[key] = deepCloneBasic(value[key]);
    }
  }
  return out;
}

const original = {

  nested: { list: [1, [2, [3]]], flag: true },
  nothing: null,
};

copy.nested.flag = false;

Why hasOwnProperty is called that way

obj.hasOwnProperty(k) breaks on an object created with Object.create(null) — it has no prototype, so no such method — and on any object with a property literally named hasOwnProperty. Calling it through Object.prototype works on both. Modern code can use Object.hasOwn(obj, k) instead.

Step 7

Version 2 — the version worth shipping

Version 2 — the interview answer
function deepClone(value, seen = new Map()) {
  // 1. primitives, functions, null -- nothing to copy
  if (value === null || typeof value !== 'object') return value;

  // 2. already cloned? return the same clone, so cycles terminate
  //    and shared references stay shared
  if (seen.has(value)) return seen.get(value);

  // 3. the built-ins that need their own constructor
  if (value instanceof Date) return new Date(value.getTime());
  if (value instanceof RegExp) {
    const re = new RegExp(value.source, value.flags);
    re.lastIndex = value.lastIndex;
    return re;
  }

  // 4. containers -- create the shell, REGISTER IT, then fill it
  if (value instanceof Map) {
    const out = new Map();
    seen.set(value, out);
    for (const [k, v] of value) out.set(deepClone(k, seen), deepClone(v, seen));
    return out;
  }

  if (value instanceof Set) {
    const out = new Set();
    seen.set(value, out);
    for (const v of value) out.add(deepClone(v, seen));
    return out;
  }

  if (Array.isArray(value)) {
    const out = new Array(value.length);
    seen.set(value, out);
    for (let i = 0; i < value.length; i++) out[i] = deepClone(value[i], seen);
    return out;
  }

  // 5. anything else: keep the prototype so class instances survive
  const out = Object.create(Object.getPrototypeOf(value));
  seen.set(value, out);

  // Reflect.ownKeys includes symbol keys and non-enumerable ones
  for (const key of Reflect.ownKeys(value)) {
    const desc = Object.getOwnPropertyDescriptor(value, key);
    if (desc.get || desc.set) {
      Object.defineProperty(out, key, desc);      // keep accessors as accessors
    } else {
      Object.defineProperty(out, key, {
        ...desc,
        value: deepClone(desc.value, seen),
      });
    }
  }

  return out;
}

Functions are copied by reference — on purpose

You cannot deep clone a function in any meaningful sense: its closure holds live variables that the copy would have to share anyway. Every serious library, and structuredClone itself, either shares the reference or refuses. Sharing is the honest choice.

Step 8

Complexity, in sentences

ApproachTimeExtra space
JSON round tripO(n)O(n) + a full string
Recursive with a seen mapO(n)O(n) map + O(d) stack
structuredCloneO(n)O(n)

n is the number of nodes in the object graph and d its depth. Every node is visited once — the seen map is what guarantees “once” even when the graph is not a tree.

Two things worth calling out. The seen map holds a reference to every source object for the duration of the clone; for a very large graph that is real memory, and a WeakMap does not help because it lives only as long as the call anyway. And the recursion is depth-bounded — a linked list ten thousand nodes long will overflow the stack, exactly as on the Flatten page.

Say this in the interview

“JSON.parse(JSON.stringify(x)) works for plain JSON data and nothing else — it turns Dates into strings, drops undefined and functions, flattens Maps and Sets to {}, loses the prototype, and throws on cycles and BigInt. A real clone recurses on the value's shape with a Map from source object to clone. I register the empty shell in that map before filling it, which is what makes cycles terminate and keeps shared references shared. In production I would reach for structuredClone unless class instances or functions are involved.”

Step 9

Mistakes people actually make

1. Registering the clone after filling it

Broken — cycles still hang
function broken(value, seen = new Map()) {
  if (value === null || typeof value !== 'object') return value;
  if (seen.has(value)) return seen.get(value);

  const out = Array.isArray(value) ? [] : {};
  for (const k of Object.keys(value)) out[k] = broken(value[k], seen);
  seen.set(value, out);            // registered too late -- bug
  return out;
}

function correct(value, seen = new Map()) {
  if (value === null || typeof value !== 'object') return value;
  if (seen.has(value)) return seen.get(value);
  const out = Array.isArray(value) ? [] : {};
  seen.set(value, out);            // registered FIRST
  for (const k of Object.keys(value)) out[k] = correct(value[k], seen);
  return out;
}

function noSeenMap(value) {

Practice before you move on

  1. List the seven JSON failures from memory. Dates, undefined and functions, Map and Set, NaN and Infinity, prototypes, BigInt, cycles. That list is the answer to “what is wrong with the one-liner?”
  2. Write the twelve-line version — primitives, seen map, Date, Array, object — and be able to say why the shell is registered before it is filled.
  3. Add Map and Set to your version. Note that Map keys can be objects too, and need cloning.
  4. Deep equality. The mirror image of this page: the same shape recursion, the same cycle problem, and a different set of traps (NaN, key order, -0). It has its own page later.
  5. Deep merge. Also its own page later — and once you have written a clone, the only new question is what to do when both sides have an array at the same key.
What to carry forward

A seen-map is the standard tool for recursing over a graph rather than a tree. Clone, deep equal, serialise, traverse — the moment references can repeat, you need a record of what you have already handled, and you need to write that record before you descend. Everything else on this page is a list of JavaScript's special cases, which you learn by having been bitten.
