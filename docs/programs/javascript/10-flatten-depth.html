JavaScript semantics · Problem 10

Flatten a Nested Array to Depth N

The recursion page already flattened arrays. This one adds a budget — one extra parameter that turns “go all the way down” into “go exactly this far” — and then matches every edge case of the real Array.prototype.flat, holes included.

Step 1

The problem

CallResult
[1,[2,[3,[4]]]].flat(0)[1,[2,[3,[4]]]]
[1,[2,[3,[4]]]].flat(1)[1,2,[3,[4]]]
[1,[2,[3,[4]]]].flat(2)[1,2,3,[4]]
[1,[2,[3,[4]]]].flat(Infinity)[1,2,3,4]
[1,[2,[3,[4]]]].flat()[1,2,[3,[4]]] — the default is 1
The one change from an unlimited flatten

Carry a depth parameter and decrement it on the way down. The test becomes “is this an array and do I have budget left?” — when the budget runs out, the array is kept as a value rather than descended into.

That is the same shape as the remaining counter in Combination Sum: one number that both drives the recursion and stops it.

Version 0 — the eight-line answer
function flatten(arr, depth = 1) {
  const out = [];

  for (const item of arr) {
    if (Array.isArray(item) && depth > 0) {
      out.push(...flatten(item, depth - 1));   // spend one unit of budget
    } else {
      out.push(item);                          // keep it as-is
    }
  }

  return out;
}

Step 3

Why the naive version is slow

Two traps, and they are the same two as on the Flatten page: concat in a reduce, and push(...spread) on a large array.

Timing demo — three ways to accumulate
function buildDeepWide(depth, width) {
  let node = [];
  for (let d = 0; d < depth; d++) {
    const level = [];
    for (let w = 0; w < width; w++) level.push(d * width + w);
    level.push(node);
    node = level;
  }
  return node;
}
const data = buildDeepWide(300, 300);

// (a) reduce + concat -- copies the accumulator every step
function withConcat(arr, depth) {
  return depth < 1 ? arr.slice() : arr.reduce(
    (acc, x) => acc.concat(Array.isArray(x) ? withConcat(x, depth - 1) : x), []);
}

// (b) push(...spread) -- allocates an argument list per level
function withSpread(arr, depth) {
  const out = [];
  for (const item of arr) {
    if (Array.isArray(item) && depth > 0) out.push(...withSpread(item, depth - 1));
    else out.push(item);
  }
  return out;
}

// (c) one shared accumulator, pushed into directly
function withAccumulator(arr, depth) {
  const out = [];
  (function walk(list, d) {
    for (const item of list) {
      if (Array.isArray(item) && d > 0) walk(item, d - 1);
      else out.push(item);
    }
  })(arr, depth);
  return out;
}

Step 4

The better idea — the budget, and what the real flat does

  walk(list, depth):

      for each item:
          if it is an array AND depth > 0:
              walk(item, depth - 1)        <-- spend one unit
          else:
              out.push(item)               <-- keep it, whatever it is


  [1, [2, [3, [4]]]] with depth 2:

      walk([1, [2,[3,[4]]]], 2)
          1              not an array   -> keep         out = [1]
          [2,[3,[4]]]    array, 2 > 0   -> walk(.., 1)
              2          not an array   -> keep         out = [1,2]
              [3,[4]]    array, 1 > 0   -> walk(.., 0)
                  3      not an array   -> keep         out = [1,2,3]
                  [4]    array, but 0   -> KEEP AS-IS   out = [1,2,3,[4]]

  The budget hit zero, so the last array was kept as a value
  rather than descended into. That is the entire difference from
  an unlimited flatten.
Four details the real flat has

The default is 1, not Infinity. A surprising number of bugs come from assuming otherwise.

Holes are removed, at every level, even at depth 0.

Depth is coerced with ToIntegerOrInfinity — '2' works, undefined becomes 1, null and NaN become 0, and a negative becomes 0.

Only real arrays are flattened. An array-like object with a length is left alone, and so is a string — even though both are iterable.

Version 1a — index loops, holes handled by hand
function flattenManual(arr, depth) {
  if (depth === undefined) depth = 1;

  // the real flat coerces the depth: ToIntegerOrInfinity
  depth = Number(depth);
  if (Number.isNaN(depth)) depth = 0;
  else if (depth !== Infinity && depth !== -Infinity) depth = Math.trunc(depth);
  if (depth < 0) depth = 0;

  const out = [];
  let count = 0;

  function walk(list, d) {
    const len = list.length;
    for (let i = 0; i < len; i++) {
      if (!(i in list)) continue;              // a hole -- skip it entirely

      const item = list[i];
      if (Object.prototype.toString.call(item) === '[object Array]' && d > 0) {
        walk(item, d - 1);
      } else {
        out[count] = item;
        count = count + 1;
      }
    }
  }

  walk(arr, depth);
  return out;
}

Version 1b — iterative, no recursion limit
// Carry the remaining depth alongside each item on an explicit
// stack. No call stack, so no depth limit.
function flattenIterative(arr, depth = 1) {
  const out = [];
  const stack = [];

  // push in reverse so the first element pops first
  for (let i = arr.length - 1; i >= 0; i--) {
    if (i in arr) stack.push({ value: arr[i], depth });
  }

  while (stack.length > 0) {
    const { value, depth: d } = stack.pop();

    if (Array.isArray(value) && d > 0) {
      for (let i = value.length - 1; i >= 0; i--) {
        if (i in value) stack.push({ value: value[i], depth: d - 1 });
      }
    } else {
      out.push(value);
    }
  }

  return out;
}

function flattenIterables(value, depth = Infinity) {

flattening in place, and the generator version
// A lazy flatten. Nothing is built until you ask for the next item,
// so you can flatten something huge and stop early.
function* flatGen(arr, depth = Infinity) {
  for (const item of arr) {
    if (Array.isArray(item) && depth > 0) yield* flatGen(item, depth - 1);
    else yield item;
  }
}

// and a truly in-place flatten, for when the array must not be replaced
function flattenInPlace(arr) {
  for (let i = 0; i < arr.length; i++) {
    if (Array.isArray(arr[i])) {
      arr.splice(i, 1, ...arr[i]);    // replace the element with its contents
      i--;                            // re-examine the same index
    }
  }
  return arr;
}

Step 8

Complexity, in sentences

ApproachTimeSpace
Recursive with an accumulatorO(n)O(d) call stack
Recursive with concatO(n · d)O(n · d)
Iterative with an explicit stackO(n)O(n) heap
Generator, stopping after kO(k + depth)O(d)
In place with spliceO(n2)O(1)

n is the total number of nodes, d the nesting depth. The accumulator version visits each node once. The depth budget changes which nodes are visited, not the asymptotic cost — a smaller budget simply stops earlier.

Note that the recursion depth is bounded by the nesting depth, not by the depth argument. flatten(deeplyNested, 1) only ever recurses one level, so the stack is safe regardless of how deep the data is.

Say this in the interview

“One recursive walk with a depth counter: if the item is an array and depth is still above zero, recurse with depth minus one; otherwise push it. I use a shared output array rather than concatenating returned arrays, because concat copies and would make it O(n·d). Two details to match the real flat: the default depth is 1, not Infinity, and holes are skipped — which means testing i in arr rather than iterating values. If the input could be pathologically deep I would swap the call stack for an explicit stack carrying {value, depth} pairs.”

What to carry forward

A budget parameter is the general way to bound a recursion. Pass a number down, decrement it, and make the recursive branch conditional on it — the same move as remaining in Combination Sum and k in a bounded search. And the reason Infinity needs no special case is worth keeping: Infinity - 1 is still Infinity.
