JavaScript semantics · Problem 04

Implement call, apply and bind

You cannot write these until you can say what this is. So this page does that first — five rules, in priority order — and then the implementations turn out to be almost trivial, except for the one line of bind that makes new work.

Step 1

The problem — and what this is

The single sentence

In a normal function, this is not decided by where the function was written. It is decided by how the function was called — and specifically, by what was to the left of the dot at the call site.

The rules, highest priority first. Work down the list and the first match wins.

#Call looks likethis is
1new Fn()the brand-new object
2fn.call(o) / fn.apply(o) / fn.bind(o)o
3obj.fn()obj
4fn()undefined in strict mode, the global object otherwise
5an arrow function, however calledwhatever this was where it was written

Rule 5 is not really a rule — arrow functions have no this of their own at all, so the name resolves lexically like any other variable. That is why call cannot change it.

all five rules, one function
'use strict';

function whoAmI() {
  return this === undefined ? 'undefined'
       : this === globalThis ? 'globalThis'
       : this && this.name ? this.name
       : String(this);
}

const obj = { name: 'obj', whoAmI };
const other = { name: 'other' };

console.log('3. obj.whoAmI()      ->', obj.whoAmI());
console.log('2. whoAmI.call(other)->', whoAmI.call(other));
console.log('4. whoAmI()          ->', whoAmI());          // strict: undefined

// 1. new
function Ctor() { this.name = 'the new object'; this.seen = whoAmI.call(this); }
console.log('1. new Ctor()        ->', new Ctor().seen);

// 5. arrow -- written at module level, so `this` is whatever is there
const arrow = () => (this === undefined ? 'undefined (module scope)' : String(this));
console.log('5. arrow()           ->', arrow());
console.log('   arrow.call(other) ->', arrow.call(other), ' -- call had NO effect');

console.log('');
console.log('The classic trap: detaching a method loses the receiver.');

console.log('  detached()   ->', detached(), ' -- same function, no dot, no this');

Step 4

The better idea — use rule 3 to implement rule 2

Here is the trick the whole page turns on. You are asked to set this without using call. But rule 3 already does that: obj.fn() sets this to obj. So — temporarily make the function a property of the target object, call it with a dot, then remove it.

  myCall(fn, thisArg, ...args):

      1. if thisArg is null or undefined, use globalThis
         (non-strict behaviour; strict mode would keep it as-is)

      2. wrap primitives:  Object(thisArg)
         'abc'.call target must become a String object

      3. key = Symbol()          <-- cannot collide with a real key

      4. thisArg[key] = fn       <-- rule 3 is now available

      5. result = thisArg[key](...args)     <-- `this` IS thisArg

      6. delete thisArg[key]     <-- leave no trace

      7. return result
Why a Symbol and not a string

A string key like '__fn' could collide with a real property, and deleting it afterwards would destroy the caller's data. A fresh Symbol() is guaranteed unique, and it is invisible to Object.keys, for...in and JSON.stringify, so even if the function throws mid-call the object still looks untouched to normal code.

why the key choice matters
const target = { fn: 'a real property called fn', data: 1 };

function badCall(fn, thisArg, ...args) {
  thisArg.fn = fn;                       // clobbers the real 'fn' -- bug
  const r = thisArg[ 'fn' ](...args);
  delete thisArg.fn;                     // and now it is gone forever
  return r;
}

function goodCall(fn, thisArg, ...args) {
  const key = Symbol('tmp');
  thisArg[key] = fn;
  const r = thisArg[key](...args);
  delete thisArg[key];
  return r;
}

const before = JSON.stringify(target);
goodCall(function () { return this.data; }, target);
console.log('after goodCall, object unchanged:', JSON.stringify(target) === before);

badCall(function () { return this.data; }, target);
console.log('after badCall :', JSON.stringify(target));
console.log('the real "fn" property was destroyed:', !('fn' in target));

console.log('');
console.log('And a symbol key stays invisible even mid-call:');
const spy = { name: 'spy' };
goodCall(function () {
  console.log('  Object.keys during the call:', Object.keys(this));
  console.log('  JSON.stringify during it   :', JSON.stringify(this));
}, spy);

Step 6

Version 1 — call and apply

Version 1 — myCall and myApply
Function.prototype.myCall = function (thisArg, ...args) {
  if (typeof this !== 'function') {
    throw new TypeError('myCall must be called on a function');
  }

  // non-strict semantics: null/undefined become the global object,
  // and primitives are boxed
  const target = (thisArg === null || thisArg === undefined)
    ? globalThis
    : Object(thisArg);

  const key = Symbol('fn');
  Object.defineProperty(target, key, {
    value: this,
    enumerable: false,       // invisible even to symbol enumeration helpers
    configurable: true,      // so delete works
  });

  try {
    return target[key](...args);
  } finally {
    delete target[key];      // runs even if the function throws
  }
};

Function.prototype.myApply = function (thisArg, argsArray) {
  if (typeof this !== 'function') {
    throw new TypeError('myApply must be called on a function');
  }
  if (argsArray === null || argsArray === undefined) argsArray = [];
  if (typeof argsArray !== 'object') {
    throw new TypeError('CreateListFromArrayLike called on non-object');
  }
  // apply accepts any array-LIKE, not just a real array
  return this.myCall(thisArg, ...Array.from(argsArray));
};

// --- compare against the real methods ---------------------------
function describe(a, b) {
  return [this === globalThis ? 'global' : JSON.stringify(this), a, b].join(' | ');
}

  [42, []],

The finally is not decoration

Without it, a function that throws leaves the temporary property attached to the caller's object forever. Symbol keys are invisible enough that you would probably never notice — which makes it worse, not better.

Version 2 — the interview answer
Function.prototype.myBind = function (thisArg, ...boundArgs) {
  if (typeof this !== 'function') {
    throw new TypeError('Bind must be called on a function');
  }

  const target = this;

  function bound(...callArgs) {
    // `this instanceof bound` is true only when called with `new`.
    // In that case ignore thisArg and use the fresh object.
    const isNew = this instanceof bound;
    return target.apply(isNew ? this : thisArg, [...boundArgs, ...callArgs]);
  }

  // make instances of the bound function instances of the target too
  if (target.prototype) {
    // an intermediate object, so writing to bound.prototype cannot
    // corrupt target.prototype
    bound.prototype = Object.create(target.prototype);
  }

  return bound;
};

// --- check it against the real bind -----------------------------

Two lines that are easy to get wrong

this instanceof bound is the new detector. When called with new, the fresh object's prototype chain runs through bound.prototype, so the test is true. When called normally, this is thisArg or undefined, and it is false.

bound.prototype = Object.create(target.prototype) — and not bound.prototype = target.prototype. Assigning directly means anyone who adds a method to the bound function's prototype silently adds it to the original's too.

why the intermediate prototype object matters
function Point(x) { this.x = x; }
Point.prototype.original = function () { return 'from Point'; };

function shareThePrototype(fn, thisArg) {
  function bound(...args) {
    return fn.apply(this instanceof bound ? this : thisArg, args);
  }
  bound.prototype = fn.prototype;                    // shared -- bug
  return bound;
}

function ownPrototype(fn, thisArg) {
  function bound(...args) {
    return fn.apply(this instanceof bound ? this : thisArg, args);
  }
  bound.prototype = Object.create(fn.prototype);     // linked, not shared
  return bound;
}

const Shared = shareThePrototype(Point, null);
Shared.prototype.addedToTheBoundOne = function () { return 'oops'; };

console.log('  Point.prototype has it too?',
            typeof Point.prototype.addedToTheBoundOne === 'function');

Step 8

Complexity, in sentences

All three are O(1) in the interesting sense — they set up a call and get out of the way. What varies is the allocation.

MethodAllocatesNotes
callnothing extracheapest of the three
applyan argument list from the arraythrows above roughly 105 arguments
binda new function object, oncethen each call is near-direct

The one to watch is bind in a render path. onClick={this.handle.bind(this)} creates a different function object every render, so a memoised child component sees a new prop and re-renders. Bind once in the constructor, or use a class field with an arrow.

Say this in the interview

“this is decided by the call site, not the definition site — new, then explicit binding, then a method call, then a plain call, with arrow functions opting out entirely. To implement call I temporarily attach the function to the target object under a Symbol key, invoke it with a dot so the method rule sets this, and delete it in a finally. apply is call with the array spread. bind returns a closure over the target and the bound arguments, and checks this instanceof bound so that calling it with new uses the fresh object instead of the bound one — because new outranks bind.”

console.log('  fix: const bound = w.method.bind(w) ->', w.method.bind(w)());

4. Binding inside a render or a loop

Broken — a new function object every time
const handler = { count: 0, handle() { this.count++; } };

// pretend this is a component rendering 5 times
const propsPassedDown = [];
for (let render = 0; render < 5; render++) {
  propsPassedDown.push(handler.handle.bind(handler));
}

console.log('5 renders produced 5 handlers.');
console.log('  all the same function object?',
            propsPassedDown.every((f) => f === propsPassedDown[0]));
console.log('  distinct objects:', new Set(propsPassedDown).size);
console.log('');
console.log('A memoised child compares props by identity, sees a new');
console.log('onClick every render, and re-renders every time. The');
console.log('memoisation does nothing.');

// bind once, reuse the same reference
const once = handler.handle.bind(handler);
const stable = [];
for (let render = 0; render < 5; render++) stable.push(once);
console.log('');
console.log('bound once:');
console.log('  all the same function object?', stable.every((f) => f === stable[0]));

// and the cost, at scale
const N = 200000;
let t = performance.now();
for (let i = 0; i < N; i++) handler.handle.bind(handler);
const bindMs = performance.now() - t;

t = performance.now();
for (let i = 0; i < N; i++) once;
const reuseMs = performance.now() - t;

console.log('');
console.log('  ' + N.toLocaleString('en-US') + ' binds : ' + bindMs.toFixed(1) + ' ms');
console.log('  ' + N.toLocaleString('en-US') + ' reuses: ' + reuseMs.toFixed(1) + ' ms');
console.log('  (the identity problem is the real cost, not the ms)');

Step 10

Practice before you move on

  1. Recite the five rules in priority order and give a one-line example of each. Everything on this page follows from them.
  2. Write myCall from memory — Symbol key, invoke with a dot, delete in a finally — then write myApply in one line on top of it.
  3. Write myBind with the new case. Step 7. Be able to explain both this instanceof bound and why the prototype is Object.create(target.prototype).
  4. Predict the output of a method extracted into a variable, a method passed to setTimeout, and the same method as a class field arrow. Then run it.
  5. Write function myNew(Ctor, ...args) — create an object whose prototype is Ctor.prototype, call the constructor on it, and return the constructor's return value if it is an object, otherwise the new one. That last clause is exactly why new and bind interact the way they do.
What to carry forward

this is an argument, passed invisibly, decided at the call site. Once you hold that, the confusing cases stop being confusing: a detached method lost its argument, setTimeout passes a different one, an arrow function never had the parameter, and bind is just a closure that supplies the argument for you.
