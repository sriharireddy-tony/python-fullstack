JavaScript semantics · Problem 03

Implement map, filter and reduce

A five-line answer gets you halfway. The other half is the details the real implementations have: three callback arguments, a thisArg, sparse arrays, a length cached up front, and the one line of reduce that decides whether it throws.

Step 1

The problem

Write myMap, myFilter and myReduce on Array.prototype, so that [1,2,3].myMap(x => x * 2) works.

MethodReturnsCallback receivesLength of result
mapa new array(value, index, array)always the same as the input
filtera new array(value, index, array)0 to n
reducea single value(acc, value, index, array)not an array at all
The relationship worth stating out loud

reduce is the general one. map and filter are both reduce with a particular accumulator, and being able to show that is a small piece of evidence that you understand it rather than having memorised it.

map and filter, expressed as reduce
const nums = [1, 2, 3, 4, 5];

const mapped = nums.reduce((acc, x) => { acc.push(x * 2); return acc; }, []);
const filtered = nums.reduce((acc, x) => { if (x % 2) acc.push(x); return acc; }, []);
const summed = nums.reduce((acc, x) => acc + x, 0);

console.log('map    :', mapped, ' matches:',
            JSON.stringify(mapped) === JSON.stringify(nums.map((x) => x * 2)));
console.log('filter :', filtered, ' matches:',
            JSON.stringify(filtered) === JSON.stringify(nums.filter((x) => x % 2)));
console.log('sum    :', summed);

// reduce can produce any shape at all -- that is the point
console.log('');
console.log('to an object:', nums.reduce((acc, x) => { acc['n' + x] = x; return acc; }, {}));
console.log('to a string :', nums.reduce((acc, x) => acc + x, ''));
console.log('to a Map    :', nums.reduce((acc, x) => acc.set(x, x * x), new Map()));
console.log('the max     :', nums.reduce((a, b) => (a > b ? a : b)));

Think first — the five-line answers

Version 0 — correct for ordinary use
Array.prototype.myMap = function (fn) {
  const out = [];
  for (let i = 0; i < this.length; i++) out.push(fn(this[i], i, this));
  return out;
};

Array.prototype.myFilter = function (fn) {
  const out = [];
  for (let i = 0; i < this.length; i++) {
    if (fn(this[i], i, this)) out.push(this[i]);
  }
  return out;
};

Array.prototype.myReduce = function (fn, initial) {
  let acc = initial;
  for (let i = 0; i < this.length; i++) acc = fn(acc, this[i], i, this);
  return acc;
};

Step 3

Why the details matter — and what they cost

These are not academic. Chaining map().filter().reduce() allocates an intermediate array per link, and each built-in method call carries real overhead compared to one loop.

Timing demo — three passes versus one
const N = 2000000;
const data = new Array(N);
for (let i = 0; i < N; i++) data[i] = i;

// three passes, two intermediate arrays
let t = performance.now();
const chained = data
  .map((x) => x * 2)
  .filter((x) => x % 3 === 0)
  .reduce((a, b) => a + b, 0);

  const doubled = x * 2;

Step 4

The better idea — what the spec actually says

Each of the three follows the same recipe. Learn the recipe and all three fall out.

  1. Reject a non-callable callback with a TypeError.

  2. Cache the length ONCE, before the loop.
     The callback can push or pop; the real methods do not react
     to that, and neither should yours.

  3. Loop by index, and check `i in this` before calling.
     A hole is not the value undefined -- `2 in [1,,3]` is true
     but `1 in [1,,3]` is false. That check is what makes the
     callback skip holes.

  4. Call with the right arguments:
       map/filter   fn.call(thisArg, value, index, array)
       reduce       fn(acc, value, index, array)   -- no thisArg

  5. Return the right shape:
       map     an array of the SAME length (holes preserved)
       filter  a new, dense array
       reduce  the accumulator
The rule that decides reduce's hardest case

With an initial value: start at index 0 with acc = initial.

Without one: the first present element becomes the accumulator and the loop starts after it. If there is no present element at all, throw TypeError: Reduce of empty array with no initial value.

Note “present”, not “index 0”. [, , 5].reduce((a,b) => a+b) starts from 5.

the algorithm, narrating itself
Array.prototype.reduceLoud = function (fn, ...rest) {
  const hasInitial = rest.length > 0;
  const len = this.length;

  let acc;
  let i = 0;

  if (hasInitial) {
    acc = rest[0];
    console.log('  initial value given: acc = ' + JSON.stringify(acc) + ', start at i=0');
  } else {
    console.log('  no initial value: hunting for the first present element');
    while (i < len && !(i in this)) {
      console.log('    index ' + i + ' is a hole -- skip');
      i++;
    }
    if (i >= len) throw new TypeError('Reduce of empty array with no initial value');
    acc = this[i];
    console.log('    acc = ' + JSON.stringify(acc) + ' from index ' + i +
                ', start the loop at i=' + (i + 1));
    i++;
  }

  for (; i < len; i++) {
    if (!(i in this)) { console.log('    index ' + i + ' is a hole -- skip'); continue; }
    const next = fn(acc, this[i], i, this);
    console.log('    fn(' + JSON.stringify(acc) + ', ' + JSON.stringify(this[i]) +
                ', ' + i + ') -> ' + JSON.stringify(next));
    acc = next;
  }

  return acc;
};

Why rest.length > 0 and not initial === undefined

arr.reduce(fn, undefined) passed an initial value — it just happens to be undefined. Testing the value cannot tell that apart from passing nothing; testing arguments.length can. The spec says the same thing.

Version 1 — the full implementations

Version 1 — map, filter and reduce, spec-shaped
Array.prototype.myMap = function (callback, thisArg) {
  if (this == null) throw new TypeError('called on null or undefined');
  if (typeof callback !== 'function') throw new TypeError(callback + ' is not a function');

  const arr = Object(this);
  const len = arr.length >>> 0;      // ToUint32, as the spec says
  const out = new Array(len);        // same length, holes included

  for (let i = 0; i < len; i++) {
    if (i in arr) {                  // skip holes, do not create them
      out[i] = callback.call(thisArg, arr[i], i, arr);
    }
  }

  return out;
};

Array.prototype.myFilter = function (callback, thisArg) {
  if (this == null) throw new TypeError('called on null or undefined');
  if (typeof callback !== 'function') throw new TypeError(callback + ' is not a function');

  const arr = Object(this);
  const len = arr.length >>> 0;
  const out = [];                    // filter's result is always dense

  for (let i = 0; i < len; i++) {
    if (i in arr) {
      const value = arr[i];
      if (callback.call(thisArg, value, i, arr)) out.push(value);
    }
  }

  return out;
};

Array.prototype.myReduce = function (callback) {
  if (this == null) throw new TypeError('called on null or undefined');
  if (typeof callback !== 'function') throw new TypeError(callback + ' is not a function');

  const arr = Object(this);
  const len = arr.length >>> 0;
  const hasInitial = arguments.length > 1;

  let acc;
  let i = 0;

  if (hasInitial) {
    acc = arguments[1];
  } else {
    while (i < len && !(i in arr)) i++;
    if (i >= len) throw new TypeError('Reduce of empty array with no initial value');
    acc = arr[i];
    i++;
  }

  for (; i < len; i++) {
    if (i in arr) acc = callback(acc, arr[i], i, arr);
  }

  return acc;
};

Version 2 — the follow-ups

Building the rest of the family out of the same recipe
Array.prototype.myForEach = function (cb, thisArg) {
  const arr = Object(this), len = arr.length >>> 0;
  for (let i = 0; i < len; i++) if (i in arr) cb.call(thisArg, arr[i], i, arr);
  return undefined;                                    // note: no return value
};

Array.prototype.mySome = function (cb, thisArg) {
  const arr = Object(this), len = arr.length >>> 0;
  for (let i = 0; i < len; i++) {
    if (i in arr && cb.call(thisArg, arr[i], i, arr)) return true;   // short-circuit
  }
  return false;                                        // vacuously false when empty
};

Array.prototype.myEvery = function (cb, thisArg) {
  const arr = Object(this), len = arr.length >>> 0;
  for (let i = 0; i < len; i++) {
    if (i in arr && !cb.call(thisArg, arr[i], i, arr)) return false;
  }
  return true;                                         // vacuously TRUE when empty
};

Array.prototype.myFind = function (cb, thisArg) {
  const arr = Object(this), len = arr.length >>> 0;
  // note: find does NOT skip holes -- it visits every index
  for (let i = 0; i < len; i++) {
    if (cb.call(thisArg, arr[i], i, arr)) return arr[i];
  }
  return undefined;
};

Array.prototype.myFlat = function (depth = 1) {
  const out = [];
  (function walk(list, d) {
    const len = list.length >>> 0;
    for (let i = 0; i < len; i++) {
      if (!(i in list)) continue;                      // flat removes holes
      const v = list[i];
      if (Array.isArray(v) && d > 0) walk(v, d - 1);
      else out.push(v);
    }
  })(this, depth);
  return out;
};

Array.prototype.myReduceRight = function (cb) {
  const arr = Object(this), len = arr.length >>> 0;
  let i = len - 1, acc;
  if (arguments.length > 1) acc = arguments[1];
  else {
    while (i >= 0 && !(i in arr)) i--;
    if (i < 0) throw new TypeError('Reduce of empty array with no initial value');
    acc = arr[i]; i--;
  }
  for (; i >= 0; i--) if (i in arr) acc = cb(acc, arr[i], i, arr);
  return acc;
};

the one to be careful about — a lazy pipeline
// A chain of map/filter builds a whole array at each step. With a
// generator you can run the same pipeline element by element, which
// matters when the source is huge or infinite.
function* lazyMap(iterable, fn) {
  let i = 0;
  for (const x of iterable) yield fn(x, i++);
}

function* lazyFilter(iterable, fn) {
  let i = 0;
  for (const x of iterable) if (fn(x, i++)) yield x;
}

function take(iterable, n) {
  const out = [];
  for (const x of iterable) {
    if (out.length >= n) break;
    out.push(x);
  }
  return out;
}

function* naturals() {
  let n = 1;
  while (true) yield n++;
}

// first 5 squares divisible by 3, from an INFINITE source
const result = take(
  lazyFilter(lazyMap(naturals(), (x) => x * x), (x) => x % 3 === 0),
  5
);
console.log('first five squares divisible by 3:', result);

Do not actually do this in production

Adding to Array.prototype is fine as an exercise and dangerous in a real codebase: the property is enumerable, so it shows up in for...in, and two libraries defining the same name silently fight. If you must, use Object.defineProperty(Array.prototype, 'myMap', { value: fn, enumerable: false }) — and normally just export a plain function instead.

Step 8

Complexity, in sentences

MethodTimeExtra spaceShort-circuits?
mapO(n)O(n)no
filterO(n)O(k) for k keptno
reduceO(n)O(1) beyond the accumulatorno
some / every / findO(n) worst caseO(1)yes

All linear, all one pass. The column that matters is the last one: some, every, find and findIndex stop as soon as they know the answer, and the others do not. arr.filter(p).length > 0 scans everything and allocates; arr.some(p) stops at the first match.

The trap in the space column is reduce. It is O(1) only if your accumulator is a scalar. reduce((acc, x) => [...acc, x], []) copies the whole accumulator every iteration — O(n²) time and O(n²) allocation. Same for spreading objects.

Say this in the interview

“All three take a callback receiving value, index and array, cache the length before the loop, and skip holes by checking i in arr rather than testing for undefined — a hole and an explicit undefined are different. map and filter accept a thisArg and call the callback with .call; reduce does not. reduce's one hard case is a missing initial value: I check arguments.length, not whether the value is undefined, and if there is no initial value and no present element I throw the same TypeError the spec does.”

Step 9

Mistakes people actually make

1. Spreading the accumulator inside reduce

correct, and quadratic
const N = 20000;
const data = [];
for (let i = 0; i < N; i++) data.push(i);

let t = performance.now();
const spread = data.reduce((acc, x) => [...acc, x * 2], []);
const spreadMs = performance.now() - t;

t = performance.now();
const pushed = data.reduce((acc, x) => { acc.push(x * 2); return acc; }, []);
const pushMs = performance.now() - t;

t = performance.now();
const mapped = data.map((x) => x * 2);
const mapMs = performance.now() - t;

console.log('all three agree:',
            JSON.stringify(spread) === JSON.stringify(pushed) &&
            JSON.stringify(pushed) === JSON.stringify(mapped));
console.log('');
console.log('  [...acc, x] : ' + spreadMs.toFixed(1) + ' ms');
console.log('  acc.push(x) : ' + pushMs.toFixed(1) + ' ms');
console.log('  .map(x)     : ' + mapMs.toFixed(1) + ' ms');
console.log('  ratio       : ' + Math.round(spreadMs / Math.max(pushMs, 0.01)) + 'x');
console.log('');
console.log('Spreading copies the WHOLE accumulator every iteration, so');
console.log('it does 1 + 2 + 3 + ... + n copies -- n^2/2 in total. It');
console.log('reads as elegant and functional, and it is a performance');
console.log('bug the moment n stops being tiny.');
console.log('');
console.log('The same applies to { ...acc, [k]: v } when grouping.');

2. Mutating the array while iterating it

Broken — elements silently skipped

const visited = [];

items.forEach((item, i) => {
  visited.push(item);
  if (item === 'b') items.splice(i, 1);      // remove while iterating -- bug

console.log('visited:', visited);      // ['a','b','d']  -- 'c' was skipped
console.log('left   :', items);

// why: removing 'b' at index 1 slides 'c' down into index 1, but
// the loop counter has already moved on to 2, which now holds 'd'.

console.log('');
console.log('And the length really is cached -- pushing during a map');
console.log('does not extend the run:');

console.log('  result   :', result);
console.log('  array is now', growing.length, 'long');
console.log('');
console.log('To remove items, filter into a NEW array. To iterate while');
console.log('removing, loop backwards.');

works, and says the wrong thing

4. Forgetting that parseInt takes two arguments

Broken — the most famous map bug in JavaScript

// [1, NaN, NaN]  -- not [1, 2, 3]

console.log('');
console.log('map calls the callback with (value, index, array), and');
console.log('parseInt(string, radix) takes the second argument as the');
console.log('base. So it really evaluates:');
console.log('  parseInt("1", 0) =', parseInt('1', 0), ' (radix 0 means "guess")');
console.log('  parseInt("2", 1) =', parseInt('2', 1), ' (base 1 does not exist)');
console.log('  parseInt("3", 2) =', parseInt('3', 2), ' (3 is not a binary digit)');

5. Reading the length inside the loop condition

Broken — an infinite loop
Array.prototype.badMap = function (fn) {
  const out = [];
  // length read fresh every iteration -- bug
  for (let i = 0; i < this.length; i++) out.push(fn(this[i], i, this));
  return out;
};

Array.prototype.goodMap = function (fn) {
  const out = [];
  const len = this.length;             // cached once, as the spec requires
  for (let i = 0; i < len; i++) out.push(fn(this[i], i, this));
  return out;
};

const a = [1, 2, 3];
let guard = 0;
try {
  a.badMap((x) => {
    if (++guard > 100000) throw new Error('runaway -- the array kept growing');
    a.push(x);                          // a callback that appends
    return x;
  });
} catch (e) {
  console.log('badMap :', e.message);
}

const b = [1, 2, 3];
console.log('goodMap:', b.goodMap((x) => { b.push(x); return x; }),
            ' and the real map agrees:',
            JSON.stringify([1,2,3].map(function (x) { return x; })));

console.log('');
console.log('The real map caches length before the first callback runs,');
console.log('so appending during a map can never extend the run. Your');
console.log('version has to do the same, or a callback that grows the');
console.log('array turns into an infinite loop.');

delete Array.prototype.badMap;
delete Array.prototype.goodMap;

What to carry forward

The built-ins have edge cases, and knowing them is what separates a memorised answer from an understood one. Holes are not undefined. Length is cached. reduce without an initial value starts from the first present element and throws on an empty array. every on an empty array is true. None of these matter often — and every one of them is a question someone will ask.
