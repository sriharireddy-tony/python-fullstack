Recursion · Problem 02

Permutations

Same backtracking triple as Subsets, one change: order matters now, so you cannot use a start index to keep things moving forward. Instead you track which elements are already used — and every unused one is a candidate.

Step 1

The problem

Return every possible ordering of the array. All elements are used every time; only the order changes.

InputCountPermutations
[]1[[]]
[1]1[1]

Why the count is n factorial

n choices for the first position, then n - 1 remaining for the second, n - 2 for the third, and so on: n × (n-1) × … × 1 = n!

That grows terrifyingly fast. 10 elements is 3.6 million. 13 is over six billion. 20 is more permutations than there are atoms in a person. Permutation problems are only ever asked with small inputs.

Step 2

Think first — insert into every position

An approach with no recursion: build up one element at a time, inserting the new element into every possible slot of every permutation you already have.

  start:      [[]]

  add 1:      insert 1 into the 1 slot of []
              [[1]]

  add 2:      insert 2 into the 2 slots of [1]
              [2,1]  [1,2]

  add 3:      insert 3 into the 3 slots of each
              from [2,1]:  [3,2,1] [2,3,1] [2,1,3]
              from [1,2]:  [3,1,2] [1,3,2] [1,2,3]

  6 permutations. The list multiplies by k at step k -- which is
  exactly n! by the end.
Version 0 — iterative insertion
function permutationsIterative(nums) {
  let result = [[]];

  for (const n of nums) {
    const next = [];

    for (const perm of result) {
      // insert n at every position, including the very end
      for (let pos = 0; pos <= perm.length; pos++) {
        next.push([...perm.slice(0, pos), n, ...perm.slice(pos)]);
      }
    }

    result = next;
    console.log('after adding ' + n + ': ' + JSON.stringify(result));
  }

  return result;
}

Step 3

Why recursion wins here too

Both approaches are O(n · n!) and that is optimal — the output alone is that big. The difference is again pruning: with backtracking you can abandon a partial ordering the moment it violates a rule, instead of generating all n! and filtering.

Timing demo — pruning versus filtering
const N = 9;
const nums = [];
for (let i = 1; i <= N; i++) nums.push(i);

// rule: no two adjacent elements may differ by exactly 1
const ok = (a, b) => Math.abs(a - b) !== 1;

function generateThenFilter(nums) {
  let result = [[]];
  for (const n of nums) {
    const next = [];
    for (const perm of result) {
      for (let pos = 0; pos <= perm.length; pos++) {
        next.push([...perm.slice(0, pos), n, ...perm.slice(pos)]);
      }
    }
    result = next;
  }
  return result.filter(p => {
    for (let i = 1; i < p.length; i++) if (!ok(p[i - 1], p[i])) return false;
    return true;
  });
}

function pruneEarly(nums) {
  const out = [];
  const path = [];
  const used = new Array(nums.length).fill(false);

  function go() {
    if (path.length === nums.length) { out.push([...path]); return; }

    for (let i = 0; i < nums.length; i++) {
      if (used[i]) continue;
      // PRUNE: reject the choice before recursing into it
      if (path.length > 0 && !ok(path[path.length - 1], nums[i])) continue;

      used[i] = true;
      path.push(nums[i]);
      go();
      path.pop();
      used[i] = false;
    }
  }

  go();
  return out;
}

Step 4

The better idea — track what is used

In Subsets, the loop started at start and recursed with i + 1, which forced the choices to move forward and made [2,1] impossible. That was exactly right there — and it is exactly wrong here, because order is the point.

The unlock

Drop the start index. Loop over all indexes every time, and skip the ones already in the path. Track that with a used array.

The base case is now path.length === nums.length: a permutation is only complete when every element has been placed.

SubsetsPermutations

  Every leaf is a permutation. Note that the SAME element appears
  at different depths on different branches -- that is what `used`
  is for.
Two things to undo, not one

The un-choose step now has two statements: path.pop() and used[i] = false. Forget the second and each element gets used at most once across the entire run — you get one permutation instead of n!.

the algorithm, narrating itself
function permuteExplained(nums) {
  const out = [];
  const path = [];
  const used = new Array(nums.length).fill(false);

  const flags = () => '[' + used.map(u => u ? 'T' : 'F').join(',') + ']';

  function go(depth) {
    const pad = '  '.repeat(depth);

    if (path.length === nums.length) {
      out.push([...path]);
      console.log(pad + 'complete -> RECORD [' + path.join(',') + ']');
      return;
    }

    for (let i = 0; i < nums.length; i++) {
      if (used[i]) {
        console.log(pad + 'i=' + i + ' (' + nums[i] + ') already used -- skip');
        continue;
      }

      used[i] = true;
      path.push(nums[i]);
      console.log(pad + 'take ' + nums[i] + '   path=[' + path.join(',') +
                  ']  used=' + flags());

      go(depth + 1);

      path.pop();
      used[i] = false;
      console.log(pad + 'undo ' + nums[i] + '   path=[' + path.join(',') +
                  ']  used=' + flags());
    }
  }

  go(0);
  console.log('');
  return out;
}

Version 1 — without built-in methods

Version 1a — used array, no spread or push
function permuteManual(nums) {
  const out = [];
  let outCount = 0;

  const path = [];
  let pathLength = 0;

  const used = [];
  for (let i = 0; i < nums.length; i++) used[i] = false;

  function copyPath() {
    const copy = [];
    for (let i = 0; i < pathLength; i++) copy[i] = path[i];
    return copy;
  }

  function go() {
    if (pathLength === nums.length) {
      out[outCount] = copyPath();
      outCount = outCount + 1;
      return;
    }

    for (let i = 0; i < nums.length; i++) {
      if (used[i] === true) continue;

      used[i] = true;                   // choose
      path[pathLength] = nums[i];
      pathLength = pathLength + 1;

      go();                             // explore

      pathLength = pathLength - 1;      // un-choose -- BOTH parts
      used[i] = false;
    }
  }

  go();
  return out;
}

// A different idea: instead of tracking what is used, SWAP the
// chosen element into position `k` and permute the rest.
// Everything from index k onwards is "not yet placed".
function permuteBySwapping(input) {
  const a = [];
  for (let i = 0; i < input.length; i++) a[i] = input[i];

  const out = [];
  let count = 0;

  function swap(x, y) {
    const t = a[x]; a[x] = a[y]; a[y] = t;
  }

  function go(k) {
    if (k === a.length) {
      const copy = [];
      for (let i = 0; i < a.length; i++) copy[i] = a[i];
      out[count] = copy;
      count = count + 1;
      return;
    }

    for (let i = k; i < a.length; i++) {
      swap(k, i);        // choose: put a[i] in position k
      go(k + 1);         // explore: permute the rest
      swap(k, i);        // un-choose: put it back
    }
  }

  go(0);
  return out;
}

function usedArray(nums) {
  const out = [], path = [], used = new Array(nums.length).fill(false);
  (function go() {
    if (path.length === nums.length) { out.push([...path]); return; }
    for (let i = 0; i < nums.length; i++) {
      if (used[i]) continue;
      used[i] = true; path.push(nums[i]);
      go();
      path.pop(); used[i] = false;
    }
  })();
  return out;
}

function swapping(input) {
  const a = [...input], out = [];
  (function go(k) {
    if (k === a.length) { out.push([...a]); return; }
    for (let i = k; i < a.length; i++) {
      [a[k], a[i]] = [a[i], a[k]];
      go(k + 1);
      [a[k], a[i]] = [a[i], a[k]];
    }
  })(0);
  return out;
}

function insertion(nums) {
  let result = [[]];
  for (const n of nums) {
    const next = [];
    for (const p of result)
      for (let pos = 0; pos <= p.length; pos++)
        next.push([...p.slice(0, pos), n, ...p.slice(pos)]);
    result = next;
  }
  return result;
}

const normalise = list =>
  JSON.stringify(list.map(p => p.join(',')).sort());

for (let n = 0; n <= 6; n++) {

Version 2 — the interview answer
function permute(nums) {
  const out = [];
  const path = [];
  const used = new Array(nums.length).fill(false);

  function backtrack() {
    if (path.length === nums.length) {
      out.push([...path]);
      return;
    }

    for (let i = 0; i < nums.length; i++) {
      if (used[i]) continue;

      used[i] = true;          // choose
      path.push(nums[i]);

      backtrack();             // explore

      path.pop();              // un-choose
      used[i] = false;
    }
  }

  backtrack();
  return out;
}

permutations with duplicates in the input
// [1,1,2] has 3 distinct permutations, not 6. Sort first so equal
// values are adjacent, then skip an unused duplicate whose twin
// has not been used yet at this level.
function permuteUnique(nums) {
  const sorted = [...nums].sort((a, b) => a - b);
  const out = [], path = [];
  const used = new Array(sorted.length).fill(false);

  function go() {
    if (path.length === sorted.length) { out.push([...path]); return; }

    for (let i = 0; i < sorted.length; i++) {
      if (used[i]) continue;

      // the key line: if this value equals the previous one AND the
      // previous one is not currently used, then the previous one
      // was already tried at this level -- skip to avoid a repeat
      if (i > 0 && sorted[i] === sorted[i - 1] && !used[i - 1]) continue;

      used[i] = true;
      path.push(sorted[i]);
      go();
      path.pop();
      used[i] = false;
    }
  }

  go();
  return out;
}

the constrained variations — where pruning pays
// 1. Permutations where no element sits in its own original index
//    (a "derangement")
function derangements(nums) {
  const out = [], path = [];
  const used = new Array(nums.length).fill(false);

  function go() {
    if (path.length === nums.length) { out.push([...path]); return; }
    const position = path.length;

    for (let i = 0; i < nums.length; i++) {
      if (used[i]) continue;
      if (i === position) continue;       // PRUNE: no fixed points

      used[i] = true; path.push(nums[i]);
      go();
      path.pop(); used[i] = false;
    }
  }

  go();
  return out;
}

console.log('derangements of [1,2,3,4]:', derangements([1,2,3,4]).length);  // 9

function stringPermutations(s) {
  const chars = [...s];
  const out = [], path = [];
  const used = new Array(chars.length).fill(false);
  function go() {
    if (path.length === chars.length) { out.push(path.join('')); return; }
    for (let i = 0; i < chars.length; i++) {
      if (used[i]) continue;
      used[i] = true; path.push(chars[i]);
      go();
      path.pop(); used[i] = false;
    }
  }
  go();
  return out;
}

// 3. Just the NEXT permutation in lexicographic order -- O(n), no
//    recursion. This is what you use when n! is too big to enumerate.
function nextPermutation(nums) {
  const a = [...nums];
  let i = a.length - 2;

  // find the rightmost element that is smaller than its successor
  while (i >= 0 && a[i] >= a[i + 1]) i--;

  if (i >= 0) {
    // find the rightmost element bigger than a[i], and swap
    let j = a.length - 1;
    while (a[j] <= a[i]) j--;
    [a[i], a[j]] = [a[j], a[i]];
  }

  // reverse the suffix -- it was descending, now it is the smallest
  let lo = i + 1, hi = a.length - 1;
  while (lo < hi) { [a[lo], a[hi]] = [a[hi], a[lo]]; lo++; hi--; }

  return a;
}

Step 8

Complexity, in sentences

SolutionTimeWorking space
Iterative insertionO(n · n!)O(n · n!)
Backtracking, used arrayO(n · n!)O(n)
Backtracking, swappingO(n · n!)O(n) stack only
Next permutationO(n) per callO(1)

Why n · n!: there are n! permutations, and copying each one into the output costs n. The recursion tree itself has fewer than 2 · n! nodes, so the copying dominates.

Working space is O(n): the path, the used array and the call stack are each at most n deep. The output is O(n · n!) and unavoidable.

The last row is worth remembering. When n! is too large to enumerate but you need to step through permutations, nextPermutation gives the next one in O(n) with no recursion and no memory — which is how std::next_permutation works and how you iterate permutations lazily.

Say this in the interview

“Order matters, so unlike Subsets I cannot use a start index — every unused element is a candidate at every position. I keep a used boolean array, loop over all indexes skipping used ones, and record when the path reaches full length. Choose, explore, then un-choose both the path push and the used flag. O(n·n!) time, O(n) working space. For duplicate inputs I sort first and skip a value equal to its predecessor when that predecessor is unused, which prevents generating the same subtree twice.”

function withIncludes(nums) {
  const out = [], path = [];

    if (path.length === nums.length) { out.push([...path]); return; }

console.log('includes on [1,1,2]:', JSON.stringify(withIncludes([1,1,2])));
// [] -- no permutation can ever use both 1s
console.log('used on [1,1,2]    :', JSON.stringify(withUsed([1,1,2])));
// all 6, including the duplicated ones

5. Attempting it on a large input

13! is over six billion. There is no clever trick — the output does not fit. If a problem seems to want all permutations of a large array, you have misread it: it almost certainly wants a count, the next permutation, the kth permutation, or the best permutation under some rule. All three of those have polynomial solutions.

Step 10

Practice before you move on

  1. Write the used-array version from memory, then say the two-part un-choose out loud. Compare it against the Subsets skeleton line by line.
  2. Permutations with duplicates. In Step 7 — write it from memory and explain the !used[i - 1] condition. Test on [1,1,1], which must give exactly one result.
  3. The swap version. Also in Step 6. Write it from memory and note that it needs no auxiliary arrays at all.
  4. Next permutation. In Step 7. O(n), no recursion, and the algorithm has a genuinely nice justification — work out why the suffix must be reversed.
  5. Letter Combinations of a Phone Number. The same skeleton, but the choices at each position come from a different set (the letters on that digit) rather than from a shared pool. A good check that you have the pattern rather than the code.
What to carry forward

The skeleton is fixed; the constraint changes. Subsets and Permutations differ in five lines: how the loop starts, what it skips, what it recurses with, when it records, and what it undoes. Before writing any backtracking problem, answer those five questions explicitly — and then the code writes itself, including the pruning.
