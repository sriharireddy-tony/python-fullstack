Recursion · Problem 04

Generate Parentheses

The first backtracking problem with no input array at all. There is nothing to loop over — just two choices at every step, and two counters that decide which of them is legal. Getting the pruning rule right is the problem.

Step 1

The problem

Given n, generate every well-formed string of n pairs of parentheses.

nCountAnswer
01[""]
11["()"]
22["(())", "()()"]
35["((()))", "(()())", "(())()", "()(())", "()()()"]
414…

Well-formed means exactly two things, and both matter:

  1. Every prefix has at least as many ( as ). You can never close something that was never opened.
  2. The whole string balances — n of each.
Those counts are the Catalan numbers

1, 1, 2, 5, 14, 42, 132, 429, 1430… They come up everywhere combinatorial: valid parenthesisations, binary tree shapes, ways to triangulate a polygon, monotonic lattice paths that stay under the diagonal.

Roughly 4n / n1.5 — exponential, but noticeably smaller than the 22n strings you would get by ignoring validity. The ratio between those two is exactly what pruning buys you.

how much pruning is available
// Catalan(n) = C(2n, n) / (n + 1)
function catalan(n) {
  let c = 1;
  for (let i = 0; i < n; i++) c = c * 2 * (2 * i + 1) / (i + 2);
  return Math.round(c);
}

console.log('n   all 2^2n strings   valid (Catalan)   fraction valid');

Step 2

Think first — generate everything, then check

The straightforward idea: build every string of length 2n over the alphabet { (, ) }, then keep the valid ones.

Version 0 — brute force, correct but wasteful
function isValid(s) {
  let depth = 0;
  for (const ch of s) {
    depth += (ch === '(') ? 1 : -1;
    if (depth < 0) return false;      // closed something never opened
  }
  return depth === 0;                  // and everything got closed
}

function bruteForce(n) {
  const out = [];
  let generated = 0;

  function build(current) {
    if (current.length === 2 * n) {
      generated++;
      if (isValid(current)) out.push(current);
      return;
    }
    build(current + '(');
    build(current + ')');
  }

  build('');
  console.log('n=' + n + ': generated ' + generated + ', kept ' + out.length);
  return out;
}

Step 3

Why it is slow

Once a prefix has more ) than (, no suffix can save it. Brute force keeps going anyway, doubling the wasted work at every remaining position.

Timing demo — filter at the end versus prune as you go
const N = 11;

function isValid(s) {
  let d = 0;
  for (const ch of s) { d += ch === '(' ? 1 : -1; if (d < 0) return false; }
  return d === 0;
}

let bruteNodes = 0;
function bruteForce(n) {
  const out = [];
  (function build(cur) {
    bruteNodes++;
    if (cur.length === 2 * n) { if (isValid(cur)) out.push(cur); return; }
    build(cur + '(');
    build(cur + ')');
  })('');
  return out;
}

let prunedNodes = 0;
function pruned(n) {
  const out = [], path = [];
  (function build(open, close) {
    prunedNodes++;
    if (path.length === 2 * n) { out.push(path.join('')); return; }
    if (open < n) { path.push('('); build(open + 1, close); path.pop(); }
    if (close < open) { path.push(')'); build(open, close + 1); path.pop(); }
  })(0, 0);
  return out;
}

Two separate wins in that number

Fewer nodes visited, and no isValid scan — the pruned version never needs a validity check at all, because it is incapable of building an invalid string. Pruning that strong removes the verification step entirely.

Step 4

The better idea — two counters, two rules

Track how many of each bracket you have placed: open and close. At every step there are only two possible moves, and each has exactly one condition.

MoveAllowed whenWhy
add '('open < nwe have not used up our n opening brackets
add ')'close < openthere is an unmatched '(' waiting to be closed
The rule to memorise

close < open, not close < n.

close < n only enforces the final count and lets you write )(. close < open enforces the prefix condition, which is the actual definition of well-formed. This one comparison is the difference between the right answer and garbage.

The base case is open === n && close === n — or equivalently path.length === 2 * n, since the rules guarantee it is balanced when it is full.

And note what is missing compared to the last three pages: there is no for loop and no start index. The choices are not drawn from a list; they are hard-coded, and the counters decide which are legal. Same choose / explore / un-choose triple, written as two if blocks instead of a loop body.

  n = 2                     (open, close)

                    (0,0) ""
                      |  add '(' since open < n
                    (1,0) "("
              add '(' /     \ add ')' since close < open
          (2,0) "(("          (1,1) "()"
     close < open |             | add '(' -- cannot add ')', close==open
          (2,1) "(()"         (2,1) "()("
     close < open |             | close < open
          (2,2) "(())"        (2,2) "()()"
              RECORD              RECORD

  Notice: at (1,1) the ')' branch is BLOCKED by close < open.
  That is the pruning -- ")" as a prefix never even gets built.

function generateExplained(n) {
  const out = [];
  const path = [];

  function build(open, close, depth) {
    const pad = '  '.repeat(depth);
    const soFar = path.join('') || '""';

    if (path.length === 2 * n) {
      out.push(path.join(''));
      console.log(pad + soFar + '   open=' + open + ' close=' + close +
                  '  ->  FULL, RECORD');
      return;
    }

    console.log(pad + soFar + '   open=' + open + ' close=' + close);

    if (open < n) {
      path.push('(');
      build(open + 1, close, depth + 1);
      path.pop();
    } else {
      console.log(pad + '  cannot add "(" -- open ' + open + ' == n ' + n);
    }

    if (close < open) {
      path.push(')');
      build(open, close + 1, depth + 1);
      path.pop();
    } else {
      console.log(pad + '  cannot add ")" -- close ' + close +
                  ' is not less than open ' + open);
    }
  }

  build(0, 0, 0);
  console.log('');
  return out;
}

Version 1 — without built-in methods

Version 1 — a character buffer, no push or join
function generateParenthesisManual(n) {
  const out = [];
  let outCount = 0;

  const buf = [];              // fixed-size character buffer
  const total = 2 * n;

  function bufToString() {
    let s = '';
    for (let i = 0; i < total; i++) s = s + buf[i];
    return s;
  }

  function build(pos, open, close) {
    if (pos === total) {
      out[outCount] = bufToString();
      outCount = outCount + 1;
      return;
    }

    if (open < n) {
      buf[pos] = '(';                    // choose
      build(pos + 1, open + 1, close);   // explore
      // no un-choose needed: the next write to buf[pos] overwrites it,
      // and we never read past `pos`
    }

    if (close < open) {
      buf[pos] = ')';
      build(pos + 1, open, close + 1);
    }
  }

  if (n === 0) return [''];
  build(0, 0, 0);
  return out;
}

Why this one needs no un-choose

Because pos is passed down rather than being a shared length. The buffer slot gets overwritten by the sibling branch, and nothing ever reads beyond the current pos. It is the same trick as passing pathLength instead of calling pop().

Do not generalise this. The moment you record by reference rather than by copying, or read the whole buffer at a node rather than at a leaf, the missing un-choose becomes a real bug — which is exactly the mistake in Step 9.

Version 2 — the interview answer
function generateParenthesis(n) {
  const out = [];
  const path = [];

  function backtrack(open, close) {
    if (path.length === 2 * n) {
      out.push(path.join(''));
      return;
    }

    if (open < n) {                 // can still open
      path.push('(');
      backtrack(open + 1, close);
      path.pop();
    }

    if (close < open) {             // something is waiting to be closed
      path.push(')');
      backtrack(open, close + 1);
      path.pop();
    }
  }

  backtrack(0, 0);
  return out;
}

the same problem, three other ways
// 1. Different counters. Track how many '(' are still unplaced and
//    how many are currently unclosed. Equivalent, and some people
//    find it clearer.
function twoRemaining(n) {
  const out = [], path = [];
  (function build(remainingOpens, unclosed) {
    if (remainingOpens === 0 && unclosed === 0) { out.push(path.join('')); return; }
    if (remainingOpens > 0) {
      path.push('('); build(remainingOpens - 1, unclosed + 1); path.pop();
    }
    if (unclosed > 0) {
      path.push(')'); build(remainingOpens, unclosed - 1); path.pop();
    }
  })(n, 0);
  return out;
}

// 2. Build from smaller answers. Every valid string of k pairs is
//    "(" + A + ")" + B where A has i pairs and B has k-1-i.
//    This is the Catalan recurrence made literal.
function byComposition(n) {
  const memo = new Map();

  function solve(k) {
    if (k === 0) return [''];
    if (memo.has(k)) return memo.get(k);

    const result = [];
    for (let i = 0; i < k; i++) {
      for (const inner of solve(i)) {
        for (const rest of solve(k - 1 - i)) {
          result.push('(' + inner + ')' + rest);
        }
      }
    }

    memo.set(k, result);
    return result;
  }

  return solve(n);
}

// 3. Iterative -- build level by level, keeping only valid prefixes
function byLevels(n) {
  let level = [{ s: '', open: 0, close: 0 }];
  for (let step = 0; step < 2 * n; step++) {
    const next = [];
    for (const state of level) {
      if (state.open < n)
        next.push({ s: state.s + '(', open: state.open + 1, close: state.close });
      if (state.close < state.open)
        next.push({ s: state.s + ')', open: state.open, close: state.close + 1 });
    }
    level = next;
  }
  return level.map(function (x) { return x.s; });
}

function reference(n) {
  const out = [], path = [];
  (function b(o, c) {
    if (path.length === 2 * n) { out.push(path.join('')); return; }
    if (o < n) { path.push('('); b(o + 1, c); path.pop(); }
    if (c < o) { path.push(')'); b(o, c + 1); path.pop(); }
  })(0, 0);
  return out;
}

// A. Is this string balanced, with three bracket types?
//    Counters no longer work -- you need a stack, because ([)] must
//    be rejected. (This is the Valid Parentheses page.)
function isBalanced(s) {
  const pairs = { ')': '(', ']': '[', '}': '{' };
  const stack = [];
  for (const ch of s) {
    if (ch === '(' || ch === '[' || ch === '{') stack.push(ch);
    else if (pairs[ch]) {
      if (stack.pop() !== pairs[ch]) return false;
    }
  }
  return stack.length === 0;
}
console.log('"([)]" balanced?', isBalanced('([)]'));      // false
console.log('"([])" balanced?', isBalanced('([])'));      // true

// B. Minimum insertions to make a string valid
function minInsertions(s) {
  let unclosed = 0, needed = 0;
  for (const ch of s) {
    if (ch === '(') unclosed++;
    else if (unclosed > 0) unclosed--;
    else needed++;              // a ')' with nothing open: insert a '('
  }
  return needed + unclosed;     // plus a ')' for each still-open '('
}

// C. Longest valid substring -- the depth counter again, but scanned
//    from both ends so a leftover '(' cannot fool it
function longestValid(s) {
  let best = 0;

  for (const dir of ['ltr', 'rtl']) {
    let open = 0, close = 0;
    for (let k = 0; k < s.length; k++) {
      const ch = dir === 'ltr' ? s[k] : s[s.length - 1 - k];
      if (ch === '(') open++; else close++;

      // going left to right, ')' is the one that can go over budget
      const a = dir === 'ltr' ? close : open;
      const b = dir === 'ltr' ? open : close;
      if (a === b) best = Math.max(best, a + b);
      else if (a > b) { open = 0; close = 0; }
    }
  }

  return best;
}

Step 8

Complexity, in sentences

SolutionTimeWorking space
Build all, then filterO(n · 22n)O(n)
Backtracking with pruningO(n · Catalan(n))O(n)
By composition, memoisedO(n · Catalan(n))O(n · Catalan(n))

The honest statement is O(4n / n1.5), which is Catalan(n) answers times O(n) to assemble each string. It is still exponential — there are exponentially many answers, and nothing can change that. What pruning changes is that every node of the tree now leads to at least one real answer, so no work is thrown away.

Working space is O(n): the path and the recursion stack, both bounded by 2n. The output is O(n · Catalan(n)) and unavoidable.

Say this in the interview

“There is no array to loop over — at each position there are only two candidate characters, and I keep two counters to decide which are legal. I can add ( while open < n, and ) while close < open. That second condition is the important one: close < n would let me write )(. Because the rules make an invalid string impossible to build, I never need a validity check, and every leaf is an answer. Output size is the Catalan number, so O(n · 4n / n1.5) time with O(n) working space.”

5. Checking validity at the end anyway

correct, and reveals a misunderstanding
function redundant(n) {
  const out = [], path = [];
  function isValid(s) {
    let d = 0;
    for (const ch of s) { d += ch === '(' ? 1 : -1; if (d < 0) return false; }
    return d === 0;
  }
  function build(open, close) {
    if (path.length === 2 * n) {
      const s = path.join('');
      if (isValid(s)) out.push(s);       // this can never be false
      return;
    }
    if (open < n) { path.push('('); build(open + 1, close); path.pop(); }
    if (close < open) { path.push(')'); build(open, close + 1); path.pop(); }
  }
  build(0, 0);
  return out;
}

      if (!isValid(path.join(''))) rejected++;
      return;
    }
    if (open < n) { path.push('('); build(open + 1, close); path.pop(); }
    if (close < open) { path.push(')'); build(open, close + 1); path.pop(); }
  })(0, 0);
  return leaves;
}

What to carry forward

The strongest pruning makes the invalid state unreachable. Weak pruning skips some bad branches; strong pruning means a bad branch cannot be constructed at all, and then the validity check disappears. When you design a backtracking solution, ask what condition would make the illegal move impossible — not what test would catch it later.
