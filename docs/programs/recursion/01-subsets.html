Recursion · Problem 01

Subsets

The first backtracking problem, and the easiest one to actually understand, because each element poses a single yes-or-no question: is it in, or is it out? Everything else in this topic is a variation on that decision.

Step 1

The problem

Return every possible subset of the given array — the power set. The input has distinct values, and any order of output is fine.

InputCountSubsets
[]1[[]]
[1]2[], [1]
[1,2]4[], [1], [2], [1,2]
[1,2,3]8[], [1], [2], [3], [1,2], [1,3], [2,3], [1,2,3]
Why the count is exactly 2ⁿ

Each element is either in the subset or out of it — two independent choices. With n elements that is 2 × 2 × … × 2 = 2ⁿ combinations.

Note that the empty subset and the whole array both count. An input of 20 elements produces just over a million subsets; 30 elements produces a billion. The output size is the problem, not the algorithm.

Step 2

Think first — build them up iteratively

Before any recursion, here is an approach you can derive with no cleverness at all: start with just the empty subset, then bring in one element at a time.

The iterative insight

Every subset either contains the new element or does not. So when you add a new element, the answer becomes: everything you already had, plus every one of those with the new element appended. The list doubles each round — which is where 2ⁿ comes from, visibly.

Version 0 — iterative doubling
function subsetsIterative(nums) {
  let result = [[]];              // the empty subset, always present

  for (const n of nums) {
    const withN = result.map(subset => [...subset, n]);
    result = [...result, ...withN];
    console.log('after adding ' + n + ':  ' + JSON.stringify(result));
  }

  return result;
}

console.log('ANSWER:', JSON.stringify(subsetsIterative([1, 2, 3])));
console.log('');
console.log('count for [1,2,3]:', subsetsIterative([1,2,3]).length);   // 8
console.log('count for []     :', subsetsIterative([]).length);        // 1

This is a complete, correct answer — and worth leading with, because it makes the “in or out” structure visible before you have to hold a call stack in your head.

Step 3

Why bother with recursion at all?

Both approaches are optimal — you cannot produce 2ⁿ subsets in less than 2ⁿ time. So this is not a speed story. The reason to learn the recursive shape is that it extends, and the iterative one mostly does not.

VariationIterative doublingRecursive backtracking
Subsets of distinct valueseasyeasy
Subsets with duplicates in the inputawkwardone if
Only subsets of size kfilter afterwards, wastefulprune early
Only subsets summing to a targetfilter afterwardsprune early
Permutations, parentheses, N-queensdoes not applysame skeleton

Pruning is the real prize. Backtracking lets you abandon a branch the moment it cannot lead to a valid answer, instead of generating everything and filtering.

Timing demo — pruning versus filtering
const N = 20;
const nums = [];
for (let i = 1; i <= N; i++) nums.push(i);
const K = 3;      // we only want subsets of size 3

// generate everything, then throw most of it away
function generateThenFilter(nums, k) {
  let result = [[]];
  for (const n of nums) result = [...result, ...result.map(s => [...s, n])];
  return result.filter(s => s.length === k);
}

// never build a subset that cannot reach size k
function pruneEarly(nums, k) {
  const out = [];
  const path = [];

  function go(start) {
    if (path.length === k) { out.push([...path]); return; }

    // not enough elements left to reach k -- abandon this branch
    if (path.length + (nums.length - start) < k) return;

    for (let i = start; i < nums.length; i++) {
      path.push(nums[i]);
      go(i + 1);
      path.pop();
    }
  }

  go(0);
  return out;
}

let t = performance.now();
const a = generateThenFilter(nums, K);
const filterMs = performance.now() - t;

t = performance.now();
const b = pruneEarly(nums, K);
const pruneMs = performance.now() - t;

console.log('generate 2^' + N + ' = ' + (2 ** N).toLocaleString('en-US') +
            ' then filter : ' + a.length + ' kept, ' + filterMs.toFixed(1) + ' ms');
console.log('prune to size ' + K + ' directly              : ' +
            b.length + ' built,  ' + pruneMs.toFixed(1) + ' ms');
console.log('same count:', a.length === b.length);
console.log('speed-up:', Math.round(filterMs / Math.max(pruneMs, 0.01)) + 'x');
Step 4

The better idea — take it or leave it

The unlock

Walk the array one element at a time, carrying a path — the subset built so far. At each element make both choices:

  1. Take it. Push it onto the path and recurse to the next index.
  2. Leave it. Pop it back off and recurse to the next index.

When you run out of elements, the path is a complete subset. Record it.

                          []
                 take 1 /  \ leave 1
                      [1]    []
              take 2 / \      / \ leave 2
                 [1,2]  [1]  [2]  []
           take 3 /\    /\    /\   /\
          [1,2,3][1,2][1,3][1][2,3][2][3][]

  8 leaves = 8 subsets. Each level is one element's decision.

The two shapes, and why one is better

There are two standard ways to write this, and they look different enough to confuse people.

shape A — explicit take / leave
function go(i) {
  if (i === nums.length) { out.push([...path]); return; }

  path.push(nums[i]);      // TAKE
  go(i + 1);
  path.pop();              // undo

  go(i + 1);               // LEAVE
}
shape B — a loop over remaining choices
function go(start) {
  out.push([...path]);     // EVERY node is a valid subset

  for (let i = start; i < nums.length; i++) {
    path.push(nums[i]);
    go(i + 1);
    path.pop();
  }
}

Shape A records only at the leaves. Shape B records at every node, which works because a partial subset is itself a valid subset. Shape B is the one to learn: it is the same skeleton as Permutations, Combination Sum and Generate Parentheses, so learning it once covers the whole topic.

The two lines people get wrong

out.push([...path]) — copy the path. Pushing path itself stores a reference, and the very next push/pop mutates it. You end up with an array of identical empty arrays.

path.pop() after the recursive call — undo the choice. That is what “backtracking” means. Without it the path only ever grows and every branch is polluted by the one before it.

Follow the path column. It grows on the way down and shrinks on the way back up, always returning to exactly what it was before the call. That invariant — every function leaves the path as it found it — is what makes backtracking work.

the algorithm, narrating itself
function subsetsExplained(nums) {
  const out = [];
  const path = [];

  function go(start, depth) {
    const pad = '  '.repeat(depth);

    out.push([...path]);
    console.log(pad + 'go(' + start + ')  path=[' + path.join(',') + ']' +
                '   RECORD [' + path.join(',') + ']');

    for (let i = start; i < nums.length; i++) {
      path.push(nums[i]);
      console.log(pad + '  take ' + nums[i] + '  ->  path=[' + path.join(',') + ']');

      go(i + 1, depth + 1);

      const removed = path.pop();
      console.log(pad + '  undo ' + removed + '  ->  path=[' + path.join(',') + ']');
    }
  }

  go(0, 0);
  console.log('');
  return out;
}

Step 6

Version 1 — without built-in methods

Version 1a — backtracking, no spread, no push
function subsetsManual(nums) {
  const out = [];
  let outCount = 0;

  const path = [];
  let pathLength = 0;

  function copyPath() {
    const copy = [];
    for (let i = 0; i < pathLength; i++) copy[i] = path[i];
    return copy;
  }

  function go(start) {
    // every node is a valid subset -- record a COPY
    out[outCount] = copyPath();
    outCount = outCount + 1;

    for (let i = start; i < nums.length; i++) {
      path[pathLength] = nums[i];       // choose
      pathLength = pathLength + 1;

      go(i + 1);                        // explore

      pathLength = pathLength - 1;      // un-choose
    }
  }

  go(0);
  return out;
}

console.log(JSON.stringify(subsetsManual([1, 2, 3])));
console.log(JSON.stringify(subsetsManual([1, 2])));
console.log(JSON.stringify(subsetsManual([1])));
console.log(JSON.stringify(subsetsManual([])));
console.log('count for 4 elements:', subsetsManual([1,2,3,4]).length);   // 16
console.log('count for 5 elements:', subsetsManual([1,2,3,4,5]).length); // 32

Notice pathLength doing the job of push and pop. Shrinking the logical length is the un-choose step — the stale value is still physically in the array, and it is simply never read. That is exactly what pop does underneath.

Version 1b — the bit-mask version
// If each element is a yes/no choice, then a subset IS a binary
// number. Subset number 5 = binary 101 = take elements 0 and 2.
function subsetsBitmask(nums) {
  const n = nums.length;
  const total = 1 << n;              // 2^n
  const out = [];

  for (let mask = 0; mask < total; mask++) {
    const subset = [];
    for (let i = 0; i < n; i++) {
      // is bit i set in mask?
      if ((mask >> i) & 1) subset[subset.length] = nums[i];
    }
    out[mask] = subset;
  }

  return out;
}

console.log(JSON.stringify(subsetsBitmask([1, 2, 3])));
console.log('');

// show the correspondence explicitly
const nums = ['a', 'b', 'c'];
for (let mask = 0; mask < 8; mask++) {
  const bits = mask.toString(2).padStart(3, '0');
  const subset = [];
  for (let i = 0; i < 3; i++) if ((mask >> i) & 1) subset.push(nums[i]);
  console.log('mask ' + mask + ' = ' + bits + '  ->  [' + subset.join(',') + ']');
}

// No recursion, no call stack, O(n * 2^n). Elegant, and it is the
// idea behind bitmask dynamic programming. Its limit: 32 elements,
// because JavaScript bitwise operators work on 32-bit integers.
Step 7

Version 2 — with built-in methods

Version 2 — the interview answer
function subsets(nums) {
  const out = [];
  const path = [];

  function backtrack(start) {
    out.push([...path]);              // copy, not the array itself

    for (let i = start; i < nums.length; i++) {
      path.push(nums[i]);             // choose
      backtrack(i + 1);               // explore
      path.pop();                     // un-choose
    }
  }

  backtrack(0);
  return out;
}

console.log(JSON.stringify(subsets([1, 2, 3])));
console.log(JSON.stringify(subsets([])));
console.log(subsets([1,2,3,4,5]).length);   // 32

Seven lines, and the choose / explore / un-choose triple in the middle is the backtracking skeleton. Every problem in this topic is that triple with a different base case and a different loop.

the variations, all one if apart
// 1. Subsets of exactly size k  ("combinations")
function combinations(nums, k) {
  const out = [], path = [];
  function go(start) {
    if (path.length === k) { out.push([...path]); return; }
    // prune: not enough elements left to ever reach k
    if (path.length + (nums.length - start) < k) return;
    for (let i = start; i < nums.length; i++) {
      path.push(nums[i]);
      go(i + 1);
      path.pop();
    }
  }
  go(0);
  return out;
}
console.log('size 2 of [1,2,3,4]:', JSON.stringify(combinations([1,2,3,4], 2)));

// 2. Subsets when the INPUT has duplicates -- skip equal siblings
function subsetsWithDup(nums) {
  const sorted = [...nums].sort((a, b) => a - b);   // duplicates become adjacent
  const out = [], path = [];
  function go(start) {
    out.push([...path]);
    for (let i = start; i < sorted.length; i++) {
      // skip a value equal to the previous one AT THIS LEVEL
      if (i > start && sorted[i] === sorted[i - 1]) continue;
      path.push(sorted[i]);
      go(i + 1);
      path.pop();
    }
  }
  go(0);
  return out;
}
console.log('');
console.log('with duplicates [1,2,2]:', JSON.stringify(subsetsWithDup([1,2,2])));
// [], [1], [1,2], [1,2,2], [2], [2,2]   -- 6, not 8

// 3. Subsets summing to a target -- prune when we overshoot
function subsetsWithSum(nums, target) {
  const out = [], path = [];
  function go(start, sum) {
    if (sum === target) out.push([...path]);
    if (sum >= target) return;                 // positives only: prune
    for (let i = start; i < nums.length; i++) {
      path.push(nums[i]);
      go(i + 1, sum + nums[i]);
      path.pop();
    }
  }
  go(0, 0);
  return out;
}
console.log('');
console.log('summing to 5 from [1,2,3,4]:', JSON.stringify(subsetsWithSum([1,2,3,4], 5)));
Why the duplicate skip is i > start, not i > 0

The rule is “do not use the same value twice as a choice at this level”. The first iteration of a level (i === start) must always be allowed — that is where a legitimate second copy of a value gets used, one level deeper. Writing i > 0 blocks it and you lose [2,2] entirely.

the same problem, three ways, checked against each other
function backtracking(nums) {
  const out = [], path = [];
  (function go(start) {
    out.push([...path]);
    for (let i = start; i < nums.length; i++) {
      path.push(nums[i]); go(i + 1); path.pop();
    }
  })(0);
  return out;
}

function iterative(nums) {
  let result = [[]];
  for (const n of nums) result = [...result, ...result.map(s => [...s, n])];
  return result;
}

function bitmask(nums) {
  const out = [];
  for (let mask = 0; mask < (1 << nums.length); mask++) {
    const s = [];
    for (let i = 0; i < nums.length; i++) if ((mask >> i) & 1) s.push(nums[i]);
    out.push(s);
  }
  return out;
}

// normalise: sort each subset, then sort the list, so order does
// not affect the comparison
const normalise = (list) =>
  JSON.stringify(list.map(s => [...s].sort((a, b) => a - b)).sort(
    (a, b) => a.length - b.length || JSON.stringify(a).localeCompare(JSON.stringify(b))
  ));

let agree = 0;
for (let n = 0; n <= 8; n++) {
  const nums = [];
  for (let i = 1; i <= n; i++) nums.push(i);

  const a = normalise(backtracking(nums));
  const b = normalise(iterative(nums));
  const c = normalise(bitmask(nums));

  if (a === b && b === c) agree++;
  else console.log('DISAGREE at n=' + n);
}
console.log('sizes 0 through 8, all three methods agree:', agree + '/9');
Step 8

Complexity, in sentences

SolutionTimeSpace
Iterative doublingO(n · 2ⁿ)O(n · 2ⁿ)
Bit maskO(n · 2ⁿ)O(n · 2ⁿ)
BacktrackingO(n · 2ⁿ)O(n) + output

Why n · 2ⁿ and not just 2ⁿ: there are 2ⁿ subsets, and copying each one into the output costs up to n. The copying dominates, so it is n · 2ⁿ. Saying “O(2ⁿ)” is close enough that most interviewers accept it, but the extra factor is real and worth naming.

The backtracking version’s working space is only O(n) — the path plus the call stack, both at most n deep. The output is O(n · 2ⁿ) regardless of approach, and by convention does not count against you.

All three are optimal: you cannot enumerate 2ⁿ things in less than 2ⁿ steps. This is a problem where exponential is the correct answer, not a failure.

Say this in the interview

“Each element is independently in or out, so there are 2ⁿ subsets and the output size makes exponential unavoidable. I use backtracking: maintain a path, and at each index loop over the remaining elements — choose, recurse with i + 1, un-choose. Every node of the recursion is a valid subset, so I record on entry, pushing a copy of the path. O(n·2ⁿ) time, O(n) working space. I would use backtracking rather than the iterative doubling because it extends to size-k, duplicate and sum-constrained variants with a single extra condition, and lets me prune.”

Step 9

Mistakes people actually make

1. Pushing the path instead of a copy

Broken — every subset is the same array
function broken(nums) {
  const out = [], path = [];
  function go(start) {
    out.push(path);                  // the ARRAY, not a copy -- bug
    for (let i = start; i < nums.length; i++) {
      path.push(nums[i]);
      go(i + 1);
      path.pop();
    }
  }
  go(0);
  return out;
}

const result = broken([1, 2, 3]);
console.log('length:', result.length);          // 8 -- the right count
console.log(JSON.stringify(result));            // eight EMPTY arrays
console.log('all the same object?', result[0] === result[7]);   // true

// out holds eight references to ONE array. By the time we look at
// it, every push has been undone by its matching pop, so it is
// empty. push([...path]) takes a snapshot instead.

2. Forgetting to un-choose

Broken — no pop

5. Duplicate handling: skipping at the wrong level

Broken — i > 0 instead of i > start

Step 10

Practice before you move on

  1. Write the seven-line version from memory and say the triple out loud: choose, explore, un-choose. Then say why the path must be copied.
  2. Combinations of size k. In Step 7 — write it from memory including the pruning line, and check the count against n! / (k!(n-k)!).
  3. Subsets with duplicates. Also in Step 7. Get i > start right and test on [2,2,2], which should give four subsets, not eight.
  4. The bit-mask version. Write it from memory, and explain why it caps out at around 32 elements.
  5. Subset sum: does any subset add to a target? Backtracking with pruning answers it, and it is the gateway to the classic dynamic-programming version. Try both.
What to carry forward

Choose, explore, un-choose. That triple, wrapped in a loop over the remaining options, is the whole backtracking pattern — and the next four pages are the same code with a different base case and a different pruning rule. Two habits go with it: always record a copy of the path, and always undo after the recursive call returns.
