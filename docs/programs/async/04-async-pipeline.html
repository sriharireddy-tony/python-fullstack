Async patterns · Problem 04

Async Pipeline / Compose

One line: reduce over a list of functions, threading a promise through. That is the whole answer — and then the useful parts are the variations: middleware that wraps rather than chains, a pipeline that can short-circuit, and where the error handling lives.

Step 1

The problem

Take a value and pass it through a series of steps, some of which are async. Each step's output is the next step's input.

Version 0 — the one-liner
const pipeAsync = (...fns) => (input) =>
  fns.reduce((promise, fn) => promise.then(fn), Promise.resolve(input));

const sleep = (ms) => new Promise((r) => setTimeout(r, ms));

const trim = (s) => s.trim();
const fetchUser = async (name) => { await sleep(20); return { name, id: 7 }; };
const addRole = async (user) => { await sleep(20); return { ...user, role: 'admin' }; };
const format = (user) => user.name + ' (' + user.role + ', #' + user.id + ')';

const process = pipeAsync(trim, fetchUser, addRole, format);

console.log(await process('  Ada  '));
console.log('');
console.log('Four steps, two of them async, one value in and one out.');
console.log('The mix does not matter -- .then() promotes a plain return');
console.log('value into a resolved promise, so sync and async steps are');
console.log('interchangeable.');

// the same thing written with a loop, which is often clearer
async function pipeLoop(fns, input) {
  let value = input;
  for (const fn of fns) value = await fn(value);
  return value;
}
console.log('');
console.log('with a loop:', await pipeLoop([trim, fetchUser, addRole, format], '  Ada  '));
pipe versus compose

pipe(f, g, h) applies left to right: h(g(f(x))). Reads in the order things happen, which is what you want for a data pipeline.

compose(f, g, h) applies right to left: f(g(h(x))). Matches the mathematical notation f ∘ g, and is what reduceRight gives you.

They are the same function with the list reversed. Say which one you mean.

both directions, and both are just reduce
const pipe = (...fns) => (x) =>
  fns.reduce((p, fn) => p.then(fn), Promise.resolve(x));

const compose = (...fns) => (x) =>
  fns.reduceRight((p, fn) => p.then(fn), Promise.resolve(x));

const double = (n) => n * 2;
const inc = (n) => n + 1;
const square = (n) => n * n;

console.log('start with 3');
console.log('  pipe(double, inc, square)   ->', await pipe(double, inc, square)(3));
console.log('    3 -> 6 -> 7 -> 49');
console.log('  compose(double, inc, square)->', await compose(double, inc, square)(3));
console.log('    3 -> 9 -> 10 -> 20');
console.log('');
console.log('Same functions, different order, different answer. The');
console.log('only difference in the implementation is reduce versus');
console.log('reduceRight.');
console.log('');
console.log('And they are exact mirrors:');
console.log('  pipe(a,b,c)(x) === compose(c,b,a)(x) :',
            await pipe(double, inc, square)(3) ===
            await compose(square, inc, double)(3));

// edge cases
console.log('');
console.log('no functions at all -> the identity:', await pipe()(42));
console.log('one function        ->', await pipe(double)(42));

Think first — what this replaces

the same job, four ways
const sleep = (ms) => new Promise((r) => setTimeout(r, ms));
const validate = async (s) => { await sleep(5); if (!s) throw new Error('empty'); return s.trim(); };

  Promise.resolve(input).then(validate).then(enrich).then(save);

  return save(rich);

console.log('');
console.log('The pipeline earns its place when the STEPS ARE DATA:');

Step 3

Why it costs a microtask per step

Timing demo — reduce-over-then versus a loop
const steps = Array.from({ length: 50 }, () => (n) => n + 1);
const N = 20000;

const pipeThen = (...fns) => (x) =>
  fns.reduce((p, f) => p.then(f), Promise.resolve(x));

const pipeLoop = (...fns) => async (x) => {
  let v = x;
  for (const f of fns) v = await f(v);
  return v;
};

// a fully synchronous pipeline: no awaits needed at all
const pipeSync = (...fns) => (x) => fns.reduce((v, f) => f(v), x);

const withThen = pipeThen(...steps);
const withLoop = pipeLoop(...steps);
const withSync = pipeSync(...steps);

let t = performance.now();
for (let i = 0; i < N; i++) await withThen(0);
const thenMs = performance.now() - t;

t = performance.now();
for (let i = 0; i < N; i++) await withLoop(0);
const loopMs = performance.now() - t;

t = performance.now();
for (let i = 0; i < N; i++) withSync(0);
const syncMs = performance.now() - t;

console.log(N.toLocaleString('en-US') + ' runs of a 50-step pipeline');
console.log('  reduce over .then : ' + thenMs.toFixed(0) + ' ms');
console.log('  await in a loop   : ' + loopMs.toFixed(0) + ' ms');
console.log('  no promises at all: ' + syncMs.toFixed(0) + ' ms');
console.log('  all three agree   :', withSync(0) === await withThen(0));

console.log('');
console.log('Each .then and each await is a microtask -- a trip through');
console.log('the event loop. 50 steps is 50 hops, whether or not any');
console.log('step is actually asynchronous.');
console.log('');
console.log('So if every step is synchronous, do not build an async');
console.log('pipeline. And if only two of fifty are async, consider');
console.log('a pipeline that only awaits when the value is thenable:');

const pipeSmart = (...fns) => (x) => {
  let v = x;
  for (const f of fns) {
    v = f(v);
    if (v && typeof v.then === 'function') {
      // from here on we are async, so hand off to the async version
      return fns.slice(fns.indexOf(f) + 1)
        .reduce((p, g) => p.then(g), Promise.resolve(v));
    }
  }
  return v;                            // never went async: a plain value
};

const mixed = [...steps];
const smart = pipeSmart(...mixed);
const value = smart(0);
console.log('  pipeSmart on all-sync steps returns', typeof value === 'object'
  ? 'a promise' : 'the plain value ' + value);
console.log('  (no promise created, no microtasks spent)');
Step 4

The better idea — the accumulator is a promise

  pipe(f, g, h)(x)

      reduce starts with   Promise.resolve(x)

      step 1:  acc = Promise.resolve(x).then(f)
      step 2:  acc = acc.then(g)
      step 3:  acc = acc.then(h)

      return acc


  Nothing has run yet when reduce finishes. It built a CHAIN:

      Promise.resolve(x) --then f--> P1 --then g--> P2 --then h--> P3

  and P3 is what you return. The chain then executes itself over
  the next few microtasks.


  Two properties fall out for free:

    1. `.then(f)` promotes a plain return value into a resolved
       promise, so a synchronous step needs no special handling.

    2. A throw anywhere rejects the rest of the chain, so one
       .catch at the end covers every step.
The mistake to avoid in the reduce

fns.reduce((p, fn) => p.then(fn), Promise.resolve(x)) is right.

fns.reduce(async (p, fn) => fn(await p), Promise.resolve(x)) also works, and fns.reduce((p, fn) => p.then(fn(x)), ...) does not — it calls fn immediately and passes its result to then, which is not a function. Pass the function, do not call it.

the three ways to write the reduce, two of them wrong
const double = (n) => n * 2;
const inc = (n) => n + 1;

// correct: pass the function
const good = (...fns) => (x) =>
  fns.reduce((p, fn) => p.then(fn), Promise.resolve(x));

// wrong 1: calling fn immediately
const bad1 = (...fns) => (x) =>
  fns.reduce((p, fn) => p.then(fn(x)), Promise.resolve(x));

// wrong 2: forgetting to return the accumulator
const bad2 = (...fns) => (x) =>
  fns.reduce((p, fn) => { p.then(fn); }, Promise.resolve(x));

console.log('good :', await good(double, inc)(3));       // 7

console.log('bad1 :', await bad1(double, inc)(3));
console.log('  -- fn(x) evaluated with the ORIGINAL x every time, and');
console.log('     then(6) with a non-function argument is ignored, so');
console.log('     the chain resolves with the untouched input.');

try {
  console.log('bad2 :', await bad2(double, inc)(3));
} catch (e) {
  console.log('bad2 :', e.constructor.name + ':', e.message);
}
console.log('  -- the arrow has braces and no return, so the');
console.log('     accumulator becomes undefined after the first step.');

console.log('');
console.log('Both bugs are the classic reduce mistakes, not async ones.');
console.log('If a pipeline "does nothing", check the reduce first.');

function pipeLoud(...fns) {
  return function (input) {
    console.log(at() + 'building the chain for ' + fns.length + ' steps');

      console.log(at() + '  wiring step ' + (i + 1) + ': ' + fn.name);

labelling the steps, so failures say where
const sleep = (ms) => new Promise((r) => setTimeout(r, ms));

// wrap each step so a failure reports which one it was
function pipeNamed(steps) {
  return async function (input) {
    let value = input;
    for (const [name, fn] of steps) {
      try {
        value = await fn(value);
      } catch (cause) {
        const err = new Error('step "' + name + '" failed: ' + cause.message);
        err.step = name;
        err.cause = cause;
        err.input = value;
        throw err;
      }
    }
    return value;
  };
}

const steps = [
  ['validate', (s) => { if (!s.trim()) throw new Error('empty'); return s.trim(); }],
  ['lookup', async (s) => { await sleep(5); throw new Error('404 not found'); }],
  ['save', async (o) => ({ ...o, saved: true })],
];

try {
  await pipeNamed(steps)(' Ada ');
} catch (e) {
  console.log('message :', e.message);
  console.log('step    :', e.step);
  console.log('cause   :', e.cause.message);
  console.log('input at the time:', JSON.stringify(e.input));
}

console.log('');
console.log('Four lines of wrapping, and now a production failure tells');
console.log('you which step broke and what it was given. Worth it for');
console.log('any pipeline that runs unattended.');

short-circuiting without throwing
const sleep = (ms) => new Promise((r) => setTimeout(r, ms));

// Sometimes a step decides the pipeline is DONE -- not failed.
// A cache hit, an early validation pass, a 304 Not Modified.
const STOP = Symbol('stop');
const stop = (value) => ({ [STOP]: true, value });

async function pipeStoppable(fns, input) {
  let value = input;
  for (const fn of fns) {
    const result = await fn(value);
    if (result && result[STOP]) return result.value;    // done, early
    value = result;
  }
  return value;
}

const ran = [];
const cache = new Map([['ada', { name: 'ada', cached: true }]]);

const steps = [
  (s) => { ran.push('normalise'); return s.trim().toLowerCase(); },
  (s) => {
    ran.push('checkCache');
    return cache.has(s) ? stop(cache.get(s)) : s;
  },
  async (s) => { ran.push('fetch'); await sleep(20); return { name: s, cached: false }; },
  async (o) => { ran.push('store'); cache.set(o.name, o); return o; },
];

ran.length = 0;
console.log('cache HIT  :', JSON.stringify(await pipeStoppable(steps, '  ADA  ')));
console.log('  steps run:', ran.join(' -> '));

ran.length = 0;
console.log('');
console.log('cache MISS :', JSON.stringify(await pipeStoppable(steps, '  Grace  ')));
console.log('  steps run:', ran.join(' -> '));

ran.length = 0;
console.log('');
console.log('again      :', JSON.stringify(await pipeStoppable(steps, 'grace')));
console.log('  steps run:', ran.join(' -> '), '-- now cached');

console.log('Using a throw for "we are finished successfully" is the');
console.log('common mistake here: the caller then cannot tell a cache');
console.log('hit from a real failure. An explicit sentinel keeps the');
console.log('two apart.');
Step 7

Version 2 — middleware, which is a different shape

Pipeline versus middleware

A pipeline is a chain: each step transforms a value and hands it on. Control only moves forward.

Middleware is nested: each layer gets a next function and can run code before and after calling it. Control comes back — which is what makes timing, logging, error boundaries and transactions possible.

Express, Koa, Redux and most HTTP clients use the second shape. It is worth being able to write it.

  PIPELINE -- forward only

      f --> g --> h --> result


  MIDDLEWARE -- an onion

      +------------ A ------------+
      |   before                  |
      |   +-------- B --------+   |
      |   |   before          |   |
      |   |   +---- C ----+   |   |
      |   |   |  handler  |   |   |
      |   |   +-----------+   |   |
      |   |   after           |   |
      |   +-------------------+   |
      |   after                   |
      +---------------------------+

      A-before, B-before, C, B-after, A-after
middleware in twelve lines
const sleep = (ms) => new Promise((r) => setTimeout(r, ms));

function compose(middleware) {
  return function (context) {
    let index = -1;

    function dispatch(i) {
      if (i <= index) return Promise.reject(new Error('next() called twice'));
      index = i;

      const fn = middleware[i];
      if (!fn) return Promise.resolve();          // ran off the end

      return Promise.resolve(fn(context, () => dispatch(i + 1)));
    }

    return dispatch(0);
  };
}

a transform pipeline over a stream of values
// A pipeline over one value is a reduce. A pipeline over a STREAM
// of values is a chain of async generators -- each stage pulls from
// the one before it, so nothing is buffered.
const sleep = (ms) => new Promise((r) => setTimeout(r, ms));

async function* source(n) {
  for (let i = 1; i <= n; i++) {
    await sleep(2);
    yield i;
  }
}

const mapStage = (fn) => async function* (input) {
  for await (const x of input) yield await fn(x);
};

const filterStage = (fn) => async function* (input) {
  for await (const x of input) if (await fn(x)) yield x;
};

const takeStage = (n) => async function* (input) {
  let taken = 0;
  for await (const x of input) {
    yield x;
    if (++taken >= n) return;          // stops the whole upstream
  }
};

const pipeStream = (...stages) => (input) =>
  stages.reduce((stream, stage) => stage(stream), input);

let produced = 0;
async function* countedSource(n) {
  for (let i = 1; i <= n; i++) { produced++; await sleep(2); yield i; }
}

const stream = pipeStream(
  mapStage((x) => x * x),
  filterStage((x) => x % 2 === 1),
  takeStage(4),
)(countedSource(1000));

const out = [];
for await (const value of stream) out.push(value);

console.log('first four odd squares:', JSON.stringify(out));
console.log('values the source produced:', produced, 'of 1000');
console.log('');
console.log('The take(4) stage stopped, which stopped the filter, which');
console.log('stopped the map, which stopped the source. Back-pressure,');
console.log('for free, because each stage PULLS.');
console.log('');
console.log('Compare an array pipeline: it would have produced all 1000');
console.log('values, squared all 1000, filtered all 1000, and then');
console.log('taken 4.');
Step 8

Complexity, in sentences

ShapeCost for n stepsCan a step see the result?
Synchronous pipen calls, 0 microtasksno
Async pipen calls, n microtasksno
Middlewaren calls, n microtasks, n stack framesyes
Generator stagesn microtasks per VALUEpull-based

None of it is algorithmically interesting; the cost is one microtask hop per step, which is negligible unless the pipeline is inside a hot loop — and Step 3 shows what that looks like at a million steps a second.

The row that matters is the last column. A pipeline is cheaper and simpler; middleware costs a live stack frame per layer for the whole request, in exchange for letting a layer act after the ones inside it. Choose on that, not on performance.

Say this in the interview

“pipe is a reduce whose accumulator is a promise: start from Promise.resolve(input) and .then each function onto it. Because then promotes a plain return value, synchronous and async steps mix freely, and one catch at the end covers every step because a rejection skips the rest of the chain. compose is the same thing with reduceRight. If a step needs to run code after the remaining steps — timing, an error boundary, a transaction — a pipeline cannot express that and you want the middleware shape instead: each layer receives a next function and awaits it.”

Step 9

Mistakes people actually make

1. Calling the function instead of passing it

Step 4's bad1. It fails silently — the chain resolves with the untouched input and nobody throws.

3. Using reduce when the steps do not depend on each other

correct, and needlessly sequential
const sleep = (ms) => new Promise((r) => setTimeout(r, ms));

const fetchProfile = async (id) => { await sleep(30); return { profile: id }; };
const fetchSettings = async (id) => { await sleep(30); return { settings: id }; };
const fetchFriends = async (id) => { await sleep(30); return { friends: id }; };

// a pipeline where each step MERGES into an accumulator -- looks
// like composition, but the three fetches are independent
const pipe = (...fns) => (x) => fns.reduce((p, f) => p.then(f), Promise.resolve(x));

let t = Date.now();
const sequential = await pipe(
  async (acc) => ({ ...acc, ...await fetchProfile(acc.id) }),
  async (acc) => ({ ...acc, ...await fetchSettings(acc.id) }),
  async (acc) => ({ ...acc, ...await fetchFriends(acc.id) }),
)({ id: 7 });
console.log('pipeline    : ~' + (Date.now() - t) + ' ms', JSON.stringify(sequential));

// they only need `id`, which was available at the start
t = Date.now();
const [a, b, c] = await Promise.all([
  fetchProfile(7), fetchSettings(7), fetchFriends(7),
]);
const parallel = { id: 7, ...a, ...b, ...c };
console.log('Promise.all : ~' + (Date.now() - t) + ' ms', JSON.stringify(parallel));

console.log('');
console.log('same result:', JSON.stringify(sequential) === JSON.stringify(parallel));
console.log('');
console.log('A pipeline SERIALISES by construction -- that is what it');
console.log('is for. Reaching for it when the steps are independent');
console.log('buys you nothing and costs you the concurrency.');
console.log('');
console.log('Ask the same question as on the previous page: does step');
console.log('n+1 actually need step n? Here it needed only `id`.');

// wrap the steps so the pipeline reports position and input
const pipeTraced = (...fns) => async (x) => {
  let value = x;
  for (let i = 0; i < fns.length; i++) {
    try {
      value = await fns[i](value);
    } catch (cause) {
      throw Object.assign(
        new Error('pipeline step ' + (i + 1) + '/' + fns.length +
                  ' (' + (fns[i].name || 'anonymous') + ') failed: ' + cause.message),
        { step: i + 1, stepName: fns[i].name, input: value, cause }
      );
    }
  }
  return value;
};

console.log('');

  await pipeTraced(stepA, stepB, stepC)(1);
} catch (e) {
  console.log('traced :', e.message);
  console.log('  step :', e.step, 'of 3 -', e.stepName);
  console.log('  input:', JSON.stringify(e.input));
}

console.log('');
console.log('Named function declarations rather than anonymous arrows');
console.log('are worth it here for exactly this reason -- fn.name is');
console.log('the only handle the wrapper has.');

5. Building the pipeline inside the request handler

correct, and re-wired on every call
const pipe = (...fns) => (x) => fns.reduce((p, f) => p.then(f), Promise.resolve(x));

let composeCalls = 0;
function makePipeline() {
  composeCalls++;
  return pipe((n) => n + 1, (n) => n * 2, (n) => n - 3);
}

// built per call
composeCalls = 0;
let t = performance.now();
for (let i = 0; i < 200000; i++) await makePipeline()(i);
const perCallMs = performance.now() - t;
console.log('built inside the loop : ' + perCallMs.toFixed(0) + ' ms, ' +
            composeCalls.toLocaleString('en-US') + ' compositions');

// built once
composeCalls = 0;
const once = makePipeline();
t = performance.now();
for (let i = 0; i < 200000; i++) await once(i);
const onceMs = performance.now() - t;
console.log('built once            : ' + onceMs.toFixed(0) + ' ms, ' +
            composeCalls + ' composition');

console.log('');
console.log('The difference is modest -- composition is cheap. The');
console.log('reason to hoist it is not speed:');
console.log('  a pipeline built once is a VALUE you can test, log and');
console.log('    reason about;');
console.log('  a pipeline built per request can silently differ');
console.log('    between requests;');
console.log('  and if any step holds state -- a cache, a counter, a');
console.log('    limiter -- rebuilding it throws that state away every');
console.log('    time.');

// the state case, which is the real bug
const makeCounting = () => {
  let seen = 0;
  return pipe((n) => { seen++; return n; }, (n) => ({ n, seen }));
};

console.log('');
console.log('rebuilt each time :',
            JSON.stringify(await makeCounting()(1)),
            JSON.stringify(await makeCounting()(2)));
const shared = makeCounting();
console.log('built once        :',
            JSON.stringify(await shared(1)),
            JSON.stringify(await shared(2)));
console.log('  -- the second one actually counts.');
Step 10

Practice before you move on

  1. Write pipeAsync from memory — one line — then write composeAsync and say which is which.
  2. Write the loop version and say when you would prefer it (readability, per-step error labelling, short-circuiting).
  3. Write the middleware compose. Step 7. Then explain what it can do that a pipeline cannot.
  4. Add per-step error labelling. Step 6 — and note that it needs fn.name, so name your steps.
  5. Write the generator-stage version. Step 7's last block. Understanding why take(4) stops the source is the best available intuition for back-pressure.
What to carry forward

A pipeline is a reduce whose accumulator is a promise. Once you see that, the whole family follows: compose is reduceRight, middleware is the same idea turned inside out so control returns, and a stream pipeline is the same idea one value at a time. And before reaching for any of them, check whether the steps are actually dependent — a pipeline serialises by construction.
