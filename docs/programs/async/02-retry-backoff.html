Async patterns · Problem 02

Retry With Exponential Backoff

Ten lines to retry, and three follow-ups that separate a working answer from a correct one: why the delay doubles, why it needs jitter, and which errors must never be retried at all.

Step 1

The problem

A network call fails intermittently. Try it again — but not immediately, and not forever.

Version 0 — the ten-line answer
const sleep = (ms) => new Promise((r) => setTimeout(r, ms));

async function retry(fn, attempts = 3, delay = 100) {
  let lastError;

  for (let i = 0; i < attempts; i++) {
    try {
      return await fn(i);
    } catch (err) {
      lastError = err;
      if (i < attempts - 1) await sleep(delay * 2 ** i);   // 100, 200, 400...
    }
  }

  throw lastError;
}

// a call that fails twice, then succeeds
let calls = 0;
const flaky = async () => {
  calls++;
  if (calls < 3) throw new Error('temporary failure ' + calls);
  return 'succeeded on attempt ' + calls;
};

const t0 = Date.now();
console.log(await retry(flaky));
console.log('took ~' + (Date.now() - t0) + ' ms  (0 + 100 + 200 of waiting)');

// and one that never succeeds
calls = 0;
const broken = async () => { calls++; throw new Error('always fails'); };
try {
  await retry(broken, 3, 20);
} catch (e) {
  console.log('');
  console.log('after 3 attempts ->', e.message);
  console.log('attempts made    :', calls);
}
Three numbers, and what each is for

attempts — the total number of tries, including the first. Bounds the worst case.

base delay — how long to wait after the first failure. Should be longer than the thing you are waiting to recover.

factor — usually 2. Each wait doubles, so the total time grows fast enough to actually give the dependency room, without needing many attempts.

function schedule(kind, base, attempts) {

Step 3

Why jitter is not optional

Suppose a service goes down and a thousand clients all start retrying. Without jitter they all wait the same 100 ms, then the same 200, then the same 400 — and hit the recovering service in perfectly synchronised waves.

Demo — the thundering herd
// simulate 1000 clients that all failed at t=0 and are now retrying
const CLIENTS = 1000;
const BASE = 100;
const ATTEMPTS = 5;

function simulate(jitterKind) {
  const hits = new Map();     // millisecond bucket -> number of requests

  for (let c = 0; c < CLIENTS; c++) {
    let elapsed = 0;
    for (let i = 0; i < ATTEMPTS; i++) {
      const exp = BASE * 2 ** i;
      let wait;
      if (jitterKind === 'none') wait = exp;
      else if (jitterKind === 'full') wait = Math.random() * exp;
      else if (jitterKind === 'equal') wait = exp / 2 + Math.random() * exp / 2;
      elapsed += wait;
      const bucket = Math.floor(elapsed / 50) * 50;      // 50 ms buckets
      hits.set(bucket, (hits.get(bucket) || 0) + 1);
    }
  }

  return hits;
}

function report(label, hits) {
  const buckets = [...hits.entries()].sort((a, b) => a[0] - b[0]);
  const peak = Math.max(...buckets.map((b) => b[1]));
  console.log(label);
  console.log('  busiest 50 ms window: ' + peak + ' requests');
  console.log('  spread over ' + buckets.length + ' windows');
  console.log('  first few windows:');
  for (const [ms, n] of buckets.slice(0, 6)) {
    const bar = '#'.repeat(Math.max(1, Math.round(n / 40)));
    console.log('    ' + String(ms).padStart(5) + ' ms  ' +
                String(n).padStart(5) + '  ' + bar);
  }
  console.log('');
}

report('full jitter  (wait = random(0, exp))', simulate('full'));
report('equal jitter (wait = exp/2 + random(0, exp/2))', simulate('equal'));

console.log('spikes of 1000 requests each, in five 50 ms windows. The');
console.log('service, which was already failing, gets hit by a wall');
console.log('five times.');
console.log('');
console.log('Full jitter spreads the same 5000 requests over ~56');
console.log('windows and cuts the peak substantially.');
console.log('');
console.log('Equal jitter is interesting: it spreads over just as many');
console.log('windows, but its FIRST window is still 1000, because');
console.log('exp/2 + random(0, exp/2) with exp=100 always lands between');

Which jitter to use

Full jitter — random(0, exp) — spreads the load best, and AWS's own analysis recommends it. The cost is that a retry can happen almost immediately.

Equal jitter — exp/2 + random(0, exp/2) — keeps a guaranteed minimum wait while still spreading. A reasonable default when you want the backoff property preserved.

Decorrelated jitter — random(base, previous * 3) — spreads even better over long retry sequences. Worth mentioning; rarely needed.

Step 4

The better idea — decide what is retryable first

Before any backoff maths, the more important question: should this error be retried at all? Retrying a permanent failure is pure waste; retrying a non-idempotent write is a correctness bug.

FailureRetry?Why
Network timeout, connection resetyestransient by definition
500, 502, 503, 504yesthe server said it is having a bad time
429 Too Many Requestsyes — but honour Retry-Afterthe server told you when
400 Bad Requestnothe request is wrong; it will be wrong next time
401, 403norefresh the token instead, then make one new attempt
404noit is not there
422 validationnosame as 400
A non-idempotent POSTcarefulthe first one may have succeeded
The one that causes real damage

A POST /charge that times out may well have succeeded — the response was lost, not the request. Retry it and you have charged the customer twice.

The fix is an idempotency key: the client generates a unique id per logical operation and sends it with every attempt; the server records it and returns the original result for a repeat. Retry safely only when the operation is idempotent, by nature or by key.

  retry(fn, { attempts, baseDelay, factor, maxDelay, isRetryable }):

      for i in 0 .. attempts-1:

          try:
              return await fn(i)

          catch err:
              if not isRetryable(err):     ->  throw immediately
              if i is the last attempt:    ->  throw

              exp    = min(baseDelay * factor^i, maxDelay)
              wait   = jitter(exp)
              await sleep(wait)

  Four guards, in order:
      1. is it retryable at all
      2. have we run out of attempts
      3. cap the delay so it does not reach hours
      4. jitter it so clients do not synchronise

const sleep = (ms) => new Promise((r) => setTimeout(r, ms));
const t0 = Date.now();
const at = () => String(Date.now() - t0).padStart(5) + ' ms  ';

async function retryLoud(fn, opts = {}) {
  const attempts = opts.attempts ?? 5;
  const base = opts.baseDelay ?? 50;
  const factor = opts.factor ?? 2;
  const maxDelay = opts.maxDelay ?? Infinity;
  const isRetryable = opts.isRetryable ?? (() => true);

  let lastError;

  for (let i = 0; i < attempts; i++) {
    console.log(at() + 'attempt ' + (i + 1) + ' of ' + attempts);
    try {
      const value = await fn(i);
      console.log(at() + '  SUCCESS -> ' + JSON.stringify(value));
      return value;
    } catch (err) {
      lastError = err;
      console.log(at() + '  failed: ' + err.message);

      if (!isRetryable(err)) {
        console.log(at() + '  not retryable -- giving up now');
        throw err;
      }
      if (i === attempts - 1) {
        console.log(at() + '  no attempts left');
        break;
      }

      const exp = Math.min(base * factor ** i, maxDelay);
      console.log(at() + '  backoff: ' + base + ' * ' + factor + '^' + i +
                  ' = ' + exp + ' ms' +
                  (base * factor ** i > maxDelay ? '  (capped)' : ''));
      await sleep(exp);
    }
  }

  throw lastError;
}

Version 1a — promise chaining, no async/await
function sleep(ms) {
  return new Promise(function (resolve) { setTimeout(resolve, ms); });

function retry(fn, attempts, delay) {
  if (attempts === undefined) attempts = 3;
  if (delay === undefined) delay = 100;

  function attempt(i) {
    return Promise.resolve()
      .then(function () { return fn(i); })      // catches a SYNCHRONOUS throw too
      .catch(function (err) {
        if (i >= attempts - 1) throw err;
        return sleep(delay * Math.pow(2, i)).then(function () {
          return attempt(i + 1);                // recursive, not a loop
        });
      });
  }

  return attempt(0);
}

Version 2 — the one to write

Version 2 — the interview answer
const sleep = (ms, signal) => new Promise((resolve, reject) => {
  const timer = setTimeout(resolve, ms);
  if (signal) signal.addEventListener('abort', () => {
    clearTimeout(timer);
    reject(new Error('aborted'));
  });
});

async function retry(fn, options = {}) {
  const {
    attempts = 3,
    baseDelay = 100,
    factor = 2,
    maxDelay = 30000,
    jitter = 'equal',            // 'none' | 'full' | 'equal'
    isRetryable = () => true,
    onRetry = () => {},
    signal,
  } = options;

  let lastError;

  for (let i = 0; i < attempts; i++) {
    if (signal?.aborted) throw new Error('aborted');

    try {
      return await fn(i);
    } catch (err) {
      lastError = err;

      if (!isRetryable(err, i)) throw err;      // permanent -- stop now
      if (i === attempts - 1) break;            // out of attempts

      const exp = Math.min(baseDelay * factor ** i, maxDelay);
      const wait =
        jitter === 'full' ? Math.random() * exp :
        jitter === 'equal' ? exp / 2 + Math.random() * (exp / 2) :
        exp;

      onRetry({ attempt: i + 1, error: err, delay: Math.round(wait) });
      await sleep(wait, signal);
    }
  }

  throw lastError;
}

const sleep = (ms) => new Promise((r) => setTimeout(r, ms));

// 1. When the server tells you when to come back, listen to it.
async function retryHonouringHeader(fn, opts = {}) {
  const { attempts = 4, baseDelay = 50, maxDelay = 5000 } = opts;
  let lastError;

  for (let i = 0; i < attempts; i++) {
    try { return await fn(i); }
    catch (err) {
      lastError = err;
      if (i === attempts - 1) break;

      let wait;
      if (typeof err.retryAfterMs === 'number') {
        wait = err.retryAfterMs;                       // the server's number wins
        console.log('  server said Retry-After ' + wait + ' ms');
      } else {
        wait = Math.min(baseDelay * 2 ** i, maxDelay);
        wait = wait / 2 + Math.random() * wait / 2;
        console.log('  backing off ~' + Math.round(wait) + ' ms');
      }
      await sleep(wait);
    }
  }
  throw lastError;
}

// 2. A per-attempt timeout, so a hung request does not block all retries
function withTimeout(promise, ms) {
  let timer;
  return Promise.race([
    promise.finally(() => clearTimeout(timer)),
    new Promise((_, reject) => {
      timer = setTimeout(() => reject(new Error('timed out after ' + ms + ' ms')), ms);
    }),
  ]);
}

the circuit breaker — when retrying is the wrong answer
const sleep = (ms) => new Promise((r) => setTimeout(r, ms));

// Retrying helps with a blip. If a dependency is properly down,
// every client retrying just prolongs it. A circuit breaker stops
// trying at all for a while.
function createBreaker(fn, { threshold = 3, cooldown = 100 } = {}) {
  let failures = 0;
  let state = 'closed';          // closed = normal, open = refusing
  let openedAt = 0;
  let calls = 0;

  return {
    async call(...args) {
      if (state === 'open') {
        if (Date.now() - openedAt < cooldown) {
          throw new Error('circuit open -- not even trying');
        }
        state = 'half-open';     // let ONE request through to test
      }

      try {
        calls++;
        const value = await fn(...args);
        failures = 0;
        state = 'closed';
        return value;
      } catch (err) {
        failures++;
        if (failures >= threshold) { state = 'open'; openedAt = Date.now(); }
        throw err;
      }
    },
    get state() { return state; },
    get calls() { return calls; },
  };
}

let down = true;
const service = async () => {
  if (down) throw new Error('service down');
  return 'ok';
};

const breaker = createBreaker(service, { threshold: 3, cooldown: 80 });

for (let i = 1; i <= 8; i++) {
  try { await breaker.call(); console.log(i + '. ok'); }
  catch (e) { console.log(i + '. ' + e.message + '   [' + breaker.state + ']'); }
}
console.log('  actual calls to the service:', breaker.calls, 'out of 8');

console.log('');
console.log('after the cooldown, and with the service back:');
down = false;
await sleep(100);
for (let i = 1; i <= 3; i++) {
  try { console.log('  ' + await breaker.call() + '   [' + breaker.state + ']'); }
  catch (e) { console.log('  ' + e.message); }
}

console.log('');
console.log('Retry and circuit-break solve different halves of the same');
console.log('problem. Retry handles a transient failure; a breaker');
console.log('handles a sustained one, by refusing to add load. Real');
console.log('systems use both, with the breaker outside the retry.');
Step 8

Complexity, in sentences

The interesting number is not time complexity, it is worst-case latency — and it is easy to get badly wrong.

attemptsbasefactor 2, total waiting
3100 ms0.3 s
5100 ms1.5 s
8100 ms12.7 s
10100 ms51 s
101000 ms8.5 minutes

The total waiting for n attempts is base · (2n-1 - 1) — it doubles with every attempt you add. Two more attempts is four times the worst case. Always set a maxDelay, and ideally a total deadline for the whole operation.

The other cost is invisible in a diagram: a retrying request holds a connection, a request context, and whatever the caller is holding, for the entire retry window. Retry an upstream call inside a request handler and you extend the lifetime of everything in that handler.

Say this in the interview

“A loop with a try/catch: on failure, check whether the error is retryable at all, check whether attempts remain, then sleep for min(base · factor^i, maxDelay) with jitter applied. The delay doubles so a struggling dependency gets exponentially more room; the jitter is there because otherwise every client that failed at the same moment retries at the same moment, which is a thundering herd. I would never retry a 4xx other than 429, and I would only retry a write if it is idempotent or carries an idempotency key — a timed-out POST may already have succeeded.”

function schedule(base, factor, attempts, maxDelay) {
  const waits = [];
  for (let i = 0; i < attempts - 1; i++) {
    waits.push(Math.min(base * factor ** i, maxDelay ?? Infinity));
  }
  return waits;
}

4. Retrying inside a retry

Broken — the attempt counts multiply
const sleep = (ms) => new Promise((r) => setTimeout(r, ms));

async function retry(fn, attempts = 3, base = 5) {
  let last;
  for (let i = 0; i < attempts; i++) {
    try { return await fn(); }
    catch (e) { last = e; if (i < attempts - 1) await sleep(base * 2 ** i); }
  }
  throw last;
}

let networkCalls = 0;
const rawFetch = async () => { networkCalls++; throw new Error('down'); };

// layer 1: the HTTP client retries
const httpClient = () => retry(rawFetch, 3);

// layer 2: the service wrapper retries
const userService = () => retry(httpClient, 3);

// layer 3: the caller retries too, "just in case"
const handler = () => retry(userService, 3);

networkCalls = 0;
const t0 = Date.now();
try { await handler(); } catch (e) { /* expected */ }

console.log('three layers, each configured for 3 attempts');
console.log('  actual network calls:', networkCalls);
console.log('  time                : ~' + (Date.now() - t0) + ' ms');
console.log('');
console.log('3 x 3 x 3 = 27. Nobody wrote 27 anywhere. Each layer was');
console.log('reasonable on its own.');
console.log('');
console.log('Retry in exactly ONE place -- normally the lowest layer');
console.log('that understands which errors are transient. Everything');
console.log('above it should pass the failure up.');
console.log('');
console.log('And note the delays compound too: the outer retry waits');
console.log('for the inner retry to exhaust ITS backoff before it even');
console.log('starts counting.');

// the fix: keep them all
async function retryKeepingErrors(fn, attempts = 3) {
  const errors = [];
  for (let i = 0; i < attempts; i++) {
    try { return await fn(i); }
    catch (e) { errors.push(e); await sleep(5); }
  }
  const err = new Error('all ' + attempts + ' attempts failed: ' +
                        errors.map((e) => e.message).join(' | '));
  err.attempts = errors;
  err.cause = errors[0];                          // the FIRST one, usually the cause
  throw err;
}

n = 0;
console.log('');
try { await retryKeepingErrors(service, 3); }
catch (e) {
  console.log('b) reported:', e.message);
  console.log('   first cause:', e.cause.message);
}

What to carry forward

A retry is a load multiplier. Every retry policy you write is a decision about how much extra traffic a failing dependency receives, and the default answer — retry everything, immediately, at every layer — is the one that turns a blip into an outage. Classify the error first, back off exponentially, add jitter, cap the delay, and retry in exactly one place.
