Hash map · Problem 01

Top K Frequent Elements

Count, then pick the biggest counts. Sorting gets you there in O(n log n) — but a count can never exceed n, and that bound lets you do it in O(n) with a trick called bucket sort.

Step 1

The problem

Return the k values that appear most often in the array. Any order is fine.

InputkAnswerCounts
[1,1,1,2,2,3]2[1, 2]1×3, 2×2, 3×1
[1]1[1]
[4,4,4,5,5,6]2[4, 5]
[1,2,3,4]2any twoall tie at 1

Two things to settle before coding, and both are worth asking out loud:

  • Ties. When several values share a count, which do you return? The problem usually says any answer is acceptable. If it does not, you need a tie-breaking rule.
  • Is k valid? It is normally guaranteed that k is at most the number of distinct values.
The bound that unlocks the fast solution

A count is at least 1 and at most n, the length of the array. So the counts live in a small, known range of integers — and whenever that is true, you can sort by them without actually sorting.

Step 2

Think first — count then sort

Version 0 — count, sort, take k
function topKSort(nums, k) {
  // 1. count every value
  const counts = new Map();
  for (const n of nums) counts.set(n, (counts.get(n) || 0) + 1);

  // 2. sort the [value, count] pairs by count, descending
  const pairs = [...counts.entries()].sort((a, b) => b[1] - a[1]);

  // 3. take the first k values
  return pairs.slice(0, k).map(pair => pair[0]);
}

console.log(topKSort([1,1,1,2,2,3], 2));     // [1, 2]
console.log(topKSort([1], 1));               // [1]
console.log(topKSort([4,4,4,5,5,6], 2));     // [4, 5]
console.log(topKSort([1,2,3,4], 2));         // [1, 2]  (all tie)
console.log(topKSort([5,5,4,4,3], 3));       // [5, 4, 3]

Three lines of real work, obviously correct, and a perfectly good interview answer. Say it out loud, quote its complexity as O(n log n) because of the sort, and then offer to do better.

The comparator, again

(a, b) => b[1] - a[1] sorts descending by the second element. Swap a and b and you get ascending. The default .sort() would stringify the pairs and sort alphabetically, which is meaningless here.

Step 3

Why sorting is more than you need

Sorting produces a total order — it tells you exactly how the 500th most frequent value compares with the 501st. You asked for the top k. Everything below that is wasted work.

Timing demo
const N = 500000;
const nums = [];
for (let i = 0; i < N; i++) nums.push(Math.floor(Math.random() * 50000));
const k = 10;

function bySorting(arr, k) {
  const c = new Map();
  for (const n of arr) c.set(n, (c.get(n) || 0) + 1);
  return [...c.entries()].sort((a, b) => b[1] - a[1]).slice(0, k).map(p => p[0]);
}

function byBuckets(arr, k) {
  const c = new Map();
  let maxCount = 0;
  for (const n of arr) {
    const next = (c.get(n) || 0) + 1;
    c.set(n, next);
    if (next > maxCount) maxCount = next;
  }

  // Size the buckets by the LARGEST count actually seen, not by
  // arr.length. Both are correct; this one allocates 21 arrays here
  // instead of half a million, which matters at this scale.
  const buckets = Array.from({ length: maxCount + 1 }, () => []);
  for (const [value, count] of c) buckets[count].push(value);

  const out = [];
  for (let count = maxCount; count >= 1 && out.length < k; count--) {
    for (const value of buckets[count]) {
      out.push(value);
      if (out.length === k) break;
    }
  }
  return out;
}

Step 4

The better idea — bucket by count

The unlock

Counts are integers between 1 and n. So make an array of n + 1 buckets, and put each value into the bucket numbered by its count. Then read the buckets from the highest index downwards until you have collected k values.

No comparisons, no sorting. The array index is the ordering.

  nums = [1, 1, 1, 2, 2, 3]        n = 6

  counts:   1 -> 3      2 -> 2      3 -> 1

  buckets (index = count):
      0: []
      1: [3]          <- values seen once
      2: [2]          <- values seen twice
      3: [1]          <- values seen three times
      4: []
      5: []
      6: []

  read from the top:  index 6, 5, 4 are empty
                      index 3 -> collect 1
                      index 2 -> collect 2
                      we have k = 2, stop

  answer: [1, 2]

This is bucket sort (sometimes counting sort). It works whenever the key you are sorting by is an integer in a small known range — then you can use the key directly as an array index instead of comparing keys to each other.

Why n + 1 buckets and not n

A value can appear n times — every element being the same. So you need a bucket at index n, and array indexes start at 0, giving n + 1 slots. Index 0 is never used, and that is fine; the alternative is subtracting 1 everywhere and introducing an off-by-one.

In practice you can do better: track the largest count you actually saw during the counting pass and size the array to maxCount + 1. Same complexity, but on an array of 500,000 values with 50,000 distinct ones it allocates about 20 buckets instead of 500,000 — and that difference is large enough to decide whether bucket sort really beats sorting. The timing demo above uses this version.

The third approach: a heap

There is a middle option worth naming. Keep a min-heap of size k: push each [value, count] pair, and whenever the heap exceeds k, remove the smallest count. At the end the heap holds the top k. That is O(n log k) — better than sorting, worse than buckets, and the right answer when the counts are not bounded by a small number, or when the data is a stream too large to hold.

Step 6

Version 1 — without built-in methods

Version 1 — bucket sort, loops only
function topKManual(nums, k) {
  if (nums.length === 0 || k === 0) return [];

  // PASS 1: count, using a plain object
  const counts = {};
  const distinct = [];        // remember the distinct values, in order
  let distinctCount = 0;

  for (let i = 0; i < nums.length; i++) {
    const n = nums[i];
    if (counts[n] === undefined) {
      counts[n] = 0;
      distinct[distinctCount] = n;
      distinctCount = distinctCount + 1;
    }
    counts[n] = counts[n] + 1;
  }

  // PASS 2: one bucket per possible count
  const buckets = [];
  for (let c = 0; c <= nums.length; c++) buckets[c] = [];

  for (let i = 0; i < distinctCount; i++) {
    const value = distinct[i];
    const count = counts[value];
    buckets[count][buckets[count].length] = value;
  }

  // PASS 3: read from the highest count downwards
  const result = [];
  let found = 0;

  for (let c = nums.length; c >= 1; c--) {
    for (let j = 0; j < buckets[c].length; j++) {
      result[found] = buckets[c][j];
      found = found + 1;
      if (found === k) return result;
    }
  }

  return result;
}

console.log(topKManual([1,1,1,2,2,3], 2));         // [1, 2]
console.log(topKManual([1], 1));                   // [1]
console.log(topKManual([4,4,4,5,5,6], 2));         // [4, 5]
console.log(topKManual([1,2,3,4], 2));             // [1, 2]
console.log(topKManual([5,5,4,4,3], 3));           // [5, 4, 3]
console.log(topKManual([7,7,7,7], 1));             // [7]
console.log(topKManual([], 2));                    // []
console.log(topKManual([-1,-1,-2], 1));            // [-1]
Why distinct exists

Object keys are strings, so counts turns the number -1 into the key "-1". Iterating the object with for...in would hand back strings and reorder integer-like keys. Keeping a separate array of the distinct values, in the order they first appeared, sidesteps both problems — and it is exactly what a Map would have given you for free.

Step 7

Version 2 — with built-in methods

Version 2a — bucket sort, the O(n) answer
function topKFrequent(nums, k) {
  const counts = new Map();
  for (const n of nums) counts.set(n, (counts.get(n) || 0) + 1);

  // index = count, value = the numbers with that count
  const buckets = Array.from({ length: nums.length + 1 }, () => []);
  for (const [value, count] of counts) buckets[count].push(value);

  const out = [];
  for (let count = buckets.length - 1; count >= 1 && out.length < k; count--) {
    for (const value of buckets[count]) {
      out.push(value);
      if (out.length === k) break;
    }
  }

  return out;
}

console.log(topKFrequent([1,1,1,2,2,3], 2));   // [1, 2]
console.log(topKFrequent([1], 1));             // [1]
console.log(topKFrequent([4,4,4,5,5,6], 2));   // [4, 5]
console.log(topKFrequent([1,2,3,4], 4));       // [1, 2, 3, 4]
console.log(topKFrequent([3,0,1,0], 1));       // [0]
Version 2b — count, sort, take k
function topKSorted(nums, k) {
  const counts = new Map();
  for (const n of nums) counts.set(n, (counts.get(n) || 0) + 1);

  return [...counts.entries()]
    .sort((a, b) => b[1] - a[1])
    .slice(0, k)
    .map(([value]) => value);
}

console.log(topKSorted([1,1,1,2,2,3], 2));   // [1, 2]
console.log(topKSorted([4,4,4,5,5,6], 2));   // [4, 5]

Version 2c — a min-heap of size k
// A tiny binary min-heap, enough for this problem.
class MinHeap {
  constructor(scoreOf) { this.items = []; this.scoreOf = scoreOf; }
  get size() { return this.items.length; }

  push(item) {
    this.items.push(item);
    let i = this.items.length - 1;
    while (i > 0) {
      const parent = (i - 1) >> 1;
      if (this.scoreOf(this.items[parent]) <= this.scoreOf(this.items[i])) break;
      [this.items[parent], this.items[i]] = [this.items[i], this.items[parent]];
      i = parent;
    }
  }

  pop() {
    const top = this.items[0];
    const last = this.items.pop();
    if (this.items.length) {
      this.items[0] = last;
      let i = 0;
      for (;;) {
        const l = 2 * i + 1, r = 2 * i + 2;
        let smallest = i;
        if (l < this.items.length &&
            this.scoreOf(this.items[l]) < this.scoreOf(this.items[smallest])) smallest = l;
        if (r < this.items.length &&
            this.scoreOf(this.items[r]) < this.scoreOf(this.items[smallest])) smallest = r;
        if (smallest === i) break;
        [this.items[i], this.items[smallest]] = [this.items[smallest], this.items[i]];
        i = smallest;
      }
    }
    return top;
  }
}

function topKHeap(nums, k) {
  const counts = new Map();
  for (const n of nums) counts.set(n, (counts.get(n) || 0) + 1);

  const heap = new MinHeap(pair => pair[1]);

  for (const entry of counts.entries()) {
    heap.push(entry);
    if (heap.size > k) heap.pop();     // evict the smallest count
  }

  return heap.items.map(pair => pair[0]);
}

console.log(topKHeap([1,1,1,2,2,3], 2).sort());          // [1, 2]
console.log(topKHeap([5,5,4,4,4,3,3,3,3], 2).sort());    // [3, 4]
console.log(topKHeap([1], 1));                           // [1]

// O(n log k). The heap never holds more than k+1 items, so it works
// on a stream of a billion values where you could never build the
// bucket array. That is when you reach for it.
Step 8

Complexity, in sentences

SolutionTimeSpaceWhen to use it
Count + sortO(n log n)O(n)default; most readable
Count + min-heapO(n log k)O(n + k)streams, or k much smaller than n
Count + bucketsO(n)O(n)counts bounded by n — which they always are

Why buckets is O(n). Counting is one pass. Filling the buckets touches each distinct value once, which is at most n. Reading the buckets walks n + 1 indexes and collects each value at most once. Three sequential passes, each O(n) — they add, giving O(n).

Note that O(n) is optimal: you have to look at every element to count it.

The trade is space. The bucket array has n + 1 slots even if there are only three distinct values, so on [1,1,1,...,1] with a million elements you allocate a million mostly-empty arrays. The heap version does not. That is the honest reason both exist.

Say this in the interview

“Count with a hash map, then I need the k largest counts. Sorting is O(n log n). But a count is an integer between 1 and n, so instead of comparing counts I can use them as array indexes: bucket each value under its count, then read the buckets from the highest index down until I have k. O(n) time and O(n) space. If k is tiny or the data is a stream, a size-k min-heap gives O(n log k) with much less memory.”

Step 9

Mistakes people actually make

1. Sizing the bucket array by the value range instead of the count range

Broken — indexes by value, not by count
function broken(nums, k) {
  const counts = new Map();
  for (const n of nums) counts.set(n, (counts.get(n) || 0) + 1);

  const buckets = Array.from({ length: nums.length + 1 }, () => []);
  for (const [value, count] of counts) buckets[value].push(count);   // swapped -- bug

  const out = [];
  for (let i = buckets.length - 1; i >= 0 && out.length < k; i--) {
    for (const v of buckets[i]) { out.push(i); if (out.length === k) break; }
  }
  return out;
}

console.log(broken([1,1,1,2,2,3], 2));   // [3, 2]  WRONG, should be [1, 2]

// Bucketing by VALUE returns the largest values, not the most
// frequent ones. And it breaks entirely on negative numbers or
// values larger than n -- buckets[1000000] does not exist.
// The index must be the COUNT.

2. fill([]) instead of a factory

Broken — every bucket is the same array
const bad = new Array(5).fill([]);
bad[2].push('x');
console.log(bad);        // [['x'],['x'],['x'],['x'],['x']] -- all five!

const good = Array.from({ length: 5 }, () => []);
good[2].push('x');
console.log(good);       // [[],[],['x'],[],[]]

// fill() stores the SAME array reference in every slot.
// Array.from with a function calls it once per slot.
// This is the same trap as building a 2D matrix.

3. Sorting ascending by mistake

Broken — least frequent
function broken(nums, k) {
  const counts = new Map();
  for (const n of nums) counts.set(n, (counts.get(n) || 0) + 1);
  return [...counts.entries()]
    .sort((a, b) => a[1] - b[1])       // ascending -- bug
    .slice(0, k)

}

console.log(broken([1,1,1,2,2,3], 2));   // [3, 2]  WRONG, should be [1, 2]

// a - b is ascending, b - a is descending. Say it out loud when you
// write it: "b minus a means biggest first".

4. Returning the counts instead of the values

The answer is [1, 2] — the values — not [3, 2], their counts. After .sort() on entries you are holding [value, count] pairs; remember to map back to the values.

5. Stopping the bucket scan at index 0

Bucket 0 is always empty — no value has a count of zero, because a value only exists in the map if it appeared. Scanning down to count >= 1 instead of count >= 0 is not a correctness issue, just one wasted iteration. What is a bug is forgetting the out.length < k guard in the outer loop, so you keep scanning after the answer is complete.

Step 10

Practice before you move on

  1. Write the bucket version from memory, then say why the bucket array has n + 1 slots.
  2. Top K frequent words. Same problem on strings, with a tie-break: equal counts are ordered alphabetically. The bucket approach still works — you just sort within each bucket.
  3. Sort characters by frequency. Return the whole string reordered so the most frequent characters come first. Buckets again, collecting everything rather than stopping at k.
  4. Kth largest element. Not about frequency — the kth largest value. Heap or quickselect; it is in the searching topic here.
  5. Write the min-heap from scratch. The one in Step 7 is about 30 lines. Being able to produce a basic heap is genuinely useful, and JavaScript is one of the few mainstream languages with no built-in priority queue.
What to carry forward

When the key you are sorting by is a small bounded integer, do not sort — index. Bucket sort turns O(n log n) into O(n) by using the key as an array position. Counts, ages, scores out of 100, priorities, days of the year: all bounded integers, all bucketable. The question to ask is always: how big can this key get? If the answer is “at most n”, you can index by it.
