Hash map · Problem 04

Longest Consecutive Sequence

Sorting solves this in O(n log n) and is a fine answer. The O(n) solution turns on one deceptively small idea: only start counting a run from its head. That single if is what stops the algorithm being quadratic.

Step 1

The problem

Given an unsorted array of integers, find the length of the longest run of consecutive numbers — numbers that differ by one. They do not need to be next to each other in the array.

InputAnswerThe run
[100, 4, 200, 1, 3, 2]41, 2, 3, 4
[0,3,7,2,5,8,4,6,0,1]90…8
[]0
[5]15
[1, 1, 1]1duplicates count once
[-3, -2, 5, -1]3-3, -2, -1

Three things to notice:

  • Position does not matter. The run 1,2,3,4 is scattered across the array; consecutive refers to the values, not the indexes.
  • Duplicates count once. [1,1,1] is a run of length 1, which is why a Set is the right container.
  • Negatives are fine. Nothing in the problem restricts the values, which rules out any solution that uses the numbers as array indexes.
The constraint that makes it interesting

The problem asks for O(n). Sorting is O(n log n) and would be the obvious route. That extra requirement is the whole exercise — and it is worth writing the sorted version first anyway, so you have a correct answer on the board.

Step 2

Think first — sort it

Version 0 — sort, then walk
function longestSorted(nums) {
  if (nums.length === 0) return 0;

  const s = [...nums].sort((a, b) => a - b);

  let best = 1;
  let current = 1;

  for (let i = 1; i < s.length; i++) {
    if (s[i] === s[i - 1]) continue;           // duplicate, ignore it

    if (s[i] === s[i - 1] + 1) {
      current++;                               // the run continues
    } else {
      current = 1;                             // a gap: start over
    }

    if (current > best) best = current;
  }

  return best;
}

console.log(longestSorted([100, 4, 200, 1, 3, 2]));      // 4
console.log(longestSorted([0,3,7,2,5,8,4,6,0,1]));       // 9
console.log(longestSorted([]));                          // 0
console.log(longestSorted([5]));                         // 1
console.log(longestSorted([1, 1, 1]));                   // 1
console.log(longestSorted([-3, -2, 5, -1]));             // 3

Sorting puts consecutive numbers next to each other, and then it is a single walk with the Kadane-like “extend or restart” shape. Correct, short, and O(n log n). Write it, say its complexity, then go after the linear version.

Note the continue for duplicates. Without it, [1,1,2] would see 1 === 1 + 1 as false and reset the run.

Step 3

The trap: the version that looks O(n) and is not

The natural first attempt at a linear solution: put everything in a Set, then for each number, walk upwards counting how far the run goes.

Version 0b — correct, but O(n²)
function longestNaiveSet(nums) {
  const set = new Set(nums);
  let best = 0;

  for (const n of set) {
    let length = 1;
    let next = n + 1;

    while (set.has(next)) {      // walk up from EVERY number
      length++;
      next++;
    }

    if (length > best) best = length;
  }

  return best;
}

console.log(longestNaiveSet([100, 4, 200, 1, 3, 2]));   // 4   correct
console.log(longestNaiveSet([0,3,7,2,5,8,4,6,0,1]));    // 9   correct

// The answers are right. The COST is the problem.
// On [1,2,3,...,n]:
//   starting at 1, walk n steps
//   starting at 2, walk n-1 steps
//   starting at 3, walk n-2 steps
//   ...
// which is n^2/2 total.
Timing demo — the two Set versions
// One long consecutive run: the worst case for the naive version.
const N = 30000;
const nums = [];
for (let i = 0; i < N; i++) nums.push(i);

function naive(arr) {
  const set = new Set(arr);
  let best = 0;
  for (const n of set) {
    let len = 1, next = n + 1;
    while (set.has(next)) { len++; next++; }
    if (len > best) best = len;
  }
  return best;
}

function headsOnly(arr) {
  const set = new Set(arr);
  let best = 0;
  for (const n of set) {
    if (set.has(n - 1)) continue;      // not the head of a run -- skip
    let len = 1, next = n + 1;
    while (set.has(next)) { len++; next++; }
    if (len > best) best = len;
  }
  return best;
}

function sorted(arr) {
  const s = [...arr].sort((a, b) => a - b);
  let best = 1, cur = 1;
  for (let i = 1; i < s.length; i++) {
    if (s[i] === s[i - 1]) continue;
    cur = s[i] === s[i - 1] + 1 ? cur + 1 : 1;
    if (cur > best) best = cur;
  }
  return best;
}

Step 4

The better idea — only start at a head

Look at what the naive version repeats. For [1,2,3,4] it counts the run four times: starting at 1 it finds a run of 4; starting at 2 it re-walks the same numbers and finds 3; and so on. Every run is walked once per member.

The unlock

A number is the head of its run exactly when n - 1 is not in the set. Only walk upwards from heads. Every other number is skipped in O(1).

One line: if (set.has(n - 1)) continue;

  set = {1, 2, 3, 4, 100, 200}

  n=1    is 0 in the set?  no  ->  1 IS a head.  walk: 2,3,4 -> length 4
  n=2    is 1 in the set?  YES ->  skip immediately
  n=3    is 2 in the set?  YES ->  skip
  n=4    is 3 in the set?  YES ->  skip
  n=100  is 99 in the set? no  ->  head.  walk: nothing -> length 1
  n=200  is 199 in the set? no ->  head.  walk: nothing -> length 1

  answer: 4

Why this is genuinely O(n)

The inner while loop still exists, so the code looks quadratic. It is not, and the argument is worth having ready:

  Every number in the set is visited at most TWICE:

    once by the outer loop, when it is its own turn
    once by an inner walk -- but only by the walk that started at
      the head of ITS run, because runs do not overlap

  A number belongs to exactly one run, and that run is walked
  exactly once (from its head). So total work is at most 2n.

That is the same style of argument as the sliding window: count the total work across the whole run, not the shape of the nested loops.

the algorithm, narrating itself
function longestExplained(nums) {
  const set = new Set(nums);
  console.log('nums =', nums);
  console.log('set  =', set);
  console.log('');

  let best = 0;
  let work = 0;

  for (const n of set) {
    work++;

    if (set.has(n - 1)) {
      console.log('n=' + n + '   ' + (n - 1) + ' is in the set -> not a head, skip');
      continue;
    }

    let length = 1;
    let next = n + 1;
    const walked = [n];

    while (set.has(next)) {
      work++;
      walked.push(next);
      length++;
      next++;
    }

    console.log('n=' + n + '   ' + (n - 1) + ' not in the set -> HEAD.  walked [' +
                walked.join(', ') + ']  length ' + length);

    if (length > best) {
      best = length;
      console.log('        new best = ' + best);
    }
  }

  console.log('');
  console.log('total set lookups in walks + outer visits: ' + work +
              '   (bounded by 2 x ' + set.size + ')');
  console.log('');
  return best;
}

Step 6

Version 1 — without built-in methods

Version 1 — plain object as the set
function longestConsecutiveManual(nums) {
  if (nums.length === 0) return 0;

  // build the set, and keep the distinct values in a list
  const present = {};
  const distinct = [];
  let distinctCount = 0;

  for (let i = 0; i < nums.length; i++) {
    const n = nums[i];
    if (present[n] !== true) {
      present[n] = true;
      distinct[distinctCount] = n;
      distinctCount = distinctCount + 1;
    }
  }

  let best = 0;

  for (let i = 0; i < distinctCount; i++) {
    const n = distinct[i];

    // only start walking from the head of a run
    if (present[n - 1] === true) continue;

    let length = 1;
    let next = n + 1;

    while (present[next] === true) {
      length = length + 1;
      next = next + 1;
    }

    if (length > best) best = length;
  }

  return best;
}

console.log(longestConsecutiveManual([100, 4, 200, 1, 3, 2]));   // 4
console.log(longestConsecutiveManual([0,3,7,2,5,8,4,6,0,1]));    // 9
console.log(longestConsecutiveManual([]));                       // 0
console.log(longestConsecutiveManual([5]));                      // 1
console.log(longestConsecutiveManual([1, 1, 1]));                // 1
console.log(longestConsecutiveManual([-3, -2, 5, -1]));          // 3
console.log(longestConsecutiveManual([1, 2, 0, 1]));             // 3
console.log(longestConsecutiveManual([-1, 0, 1]));               // 3
Why negatives still work with a plain object

Object keys are strings, so present[-3] becomes the key "-3", and present[n - 1] with n = -2 looks up "-3" too. The stringification is consistent in both directions, so lookups line up. What you must not do is use an array indexed by the value — arr[-3] is not a real array slot and negative numbers silently break it.

variation — return the run itself
function longestRun(nums) {
  const set = new Set(nums);
  let bestStart = null, bestLength = 0;

  for (const n of set) {
    if (set.has(n - 1)) continue;

    let length = 1;
    while (set.has(n + length)) length++;

    if (length > bestLength) {
      bestLength = length;
      bestStart = n;
    }
  }

  if (bestStart === null) return [];

  const run = [];
  for (let i = 0; i < bestLength; i++) run.push(bestStart + i);
  return run;
}

console.log(longestRun([100, 4, 200, 1, 3, 2]));    // [1, 2, 3, 4]
console.log(longestRun([0,3,7,2,5,8,4,6,0,1]));     // [0..8]
console.log(longestRun([-3, -2, 5, -1]));           // [-3, -2, -1]
console.log(longestRun([]));                        // []

// Note `set.has(n + length)` instead of a separate `next` variable:
// the length IS the offset from the head. One less thing to keep
// in sync.
Step 7

Version 2 — with built-in methods

Version 2 — the interview answer
function longestConsecutive(nums) {
  const set = new Set(nums);
  let best = 0;

  for (const n of set) {
    if (set.has(n - 1)) continue;      // only start from a run's head

    let length = 1;
    while (set.has(n + length)) length++;

    best = Math.max(best, length);
  }

  return best;
}

console.log(longestConsecutive([100, 4, 200, 1, 3, 2]));   // 4
console.log(longestConsecutive([0,3,7,2,5,8,4,6,0,1]));    // 9
console.log(longestConsecutive([]));                       // 0
console.log(longestConsecutive([5]));                      // 1
console.log(longestConsecutive([1, 1, 1]));                // 1
console.log(longestConsecutive([-3, -2, 5, -1]));          // 3
console.log(longestConsecutive([9,1,4,7,3,-1,0,5,8,-1,6])); // 7

Eight lines. The entire difference between O(n²) and O(n) is if (set.has(n - 1)) continue; — which is worth saying out loud, because an interviewer who sees the loop may assume it is quadratic unless you explain otherwise.

iterating the Set vs iterating the array
const nums = [1, 1, 1, 1, 2, 3];

function overArray(arr) {
  const set = new Set(arr);
  let best = 0, visits = 0;
  for (const n of arr) {                 // the ARRAY -- includes duplicates
    visits++;
    if (set.has(n - 1)) continue;
    let len = 1;
    while (set.has(n + len)) { len++; visits++; }
    best = Math.max(best, len);
  }
  return { best, visits };
}

function overSet(arr) {
  const set = new Set(arr);
  let best = 0, visits = 0;
  for (const n of set) {                 // the SET -- distinct only
    visits++;
    if (set.has(n - 1)) continue;
    let len = 1;
    while (set.has(n + len)) { len++; visits++; }
    best = Math.max(best, len);
  }
  return { best, visits };
}

console.log('over the array:', overArray(nums));
console.log('over the set  :', overSet(nums));

// Same answer, but iterating the array re-walks the run once per
// duplicate. With n copies of the same head, that is n walks.
// Both are correct; iterating the SET is the one that keeps the
// 2n bound honest.
the union-find version, for completeness
// A different O(n)-ish approach: treat each number as a node and
// union it with n-1 and n+1 whenever both exist. The answer is the
// size of the largest component.
function longestUnionFind(nums) {
  const parent = new Map();
  const size = new Map();

  for (const n of nums) {
    if (!parent.has(n)) { parent.set(n, n); size.set(n, 1); }
  }

  function find(x) {
    while (parent.get(x) !== x) {
      parent.set(x, parent.get(parent.get(x)));   // path halving
      x = parent.get(x);
    }
    return x;
  }

  function union(a, b) {
    const ra = find(a), rb = find(b);
    if (ra === rb) return;
    const sa = size.get(ra), sb = size.get(rb);
    if (sa < sb) { parent.set(ra, rb); size.set(rb, sa + sb); }
    else { parent.set(rb, ra); size.set(ra, sa + sb); }
  }

  for (const n of parent.keys()) {
    if (parent.has(n + 1)) union(n, n + 1);
  }

  let best = 0;
  for (const n of parent.keys()) best = Math.max(best, size.get(find(n)));
  return best;
}

console.log(longestUnionFind([100, 4, 200, 1, 3, 2]));   // 4
console.log(longestUnionFind([0,3,7,2,5,8,4,6,0,1]));    // 9
console.log(longestUnionFind([]));                       // 0
console.log(longestUnionFind([-3, -2, 5, -1]));          // 3

// Nearly O(n), far more code, and no better in practice. Worth
// knowing that it works -- consecutive numbers really are a graph
// problem -- and worth NOT writing when the eight-line version does
// the same job.
Step 8

Complexity, in sentences

SolutionTimeSpace
Sort, then walkO(n log n)O(n)
Set, walk from every numberO(n²)O(n)
Set, walk from heads onlyO(n)O(n)
Union-find~O(n)O(n)

The O(n) argument, restated because it is the point of the problem. The outer loop visits each distinct number once. The inner walk only runs for heads, and a head’s walk covers exactly the members of its own run. Runs are disjoint, so across the entire algorithm the inner walks touch each number at most once. Total: at most 2n set lookups.

Space is O(n) for the set. This is a straight time-for-space trade — the sorted version can be O(1) space if you are allowed to sort in place, and it is genuinely the better choice when memory is tight or the input is already sorted.

Say this in the interview

“Sorting gives O(n log n). For O(n), put everything in a hash set and, for each value, walk upwards counting the run — but only if n - 1 is absent, meaning this value is the start of its run. That guard is what makes it linear: each number is visited once by the outer loop and at most once by the single walk over its own run, so at most 2n lookups. O(n) time, O(n) space.”

Step 9

Mistakes people actually make

1. Omitting the head check

Step 3 shows it: correct answers, quadratic cost, and on a long consecutive run the difference is dramatic. If you write the loop without the guard and then claim O(n), that is worse than not claiming a complexity at all.

2. Walking downwards as well as upwards

Broken — double counting
function broken(nums) {
  const set = new Set(nums);
  let best = 0;
  for (const n of set) {
    let len = 1;
    let up = n + 1, down = n - 1;
    while (set.has(up)) { len++; up++; }
    while (set.has(down)) { len++; down--; }   // also walks down
    best = Math.max(best, len);
  }
  return best;
}

console.log(broken([100, 4, 200, 1, 3, 2]));   // 4   correct answer...
console.log(broken([1,2,3,4,5]));              // 5   ...also correct

// The ANSWERS are right -- walking both ways from any member gives
// the full run length. But now every member walks the entire run,
// so it is O(n^2) again, and the head check would be pointless.
// Pick one direction and only start from the head.

3. Using an array indexed by value

Broken — negatives and huge values
function broken(nums) {
  const present = [];
  for (const n of nums) present[n] = true;     // array indexed by VALUE

  let best = 0;
  for (const n of nums) {
    if (present[n - 1]) continue;
    let len = 1;
    while (present[n + len]) len++;
    best = Math.max(best, len);
  }
  return best;
}

console.log(broken([1, 2, 3]));         // 3   fine
console.log(broken([-3, -2, -1]));      // 1   WRONG, should be 3

// present[-3] = true does not create array slot -3; it adds a
// property named "-3" to the array object. Then present[n - 1] with
// n = -2 looks up index -3 as a PROPERTY and... actually finds it.
// The real breakage is subtler and version-dependent -- which is
// exactly why you should not do it. Use a Set or a plain object.

// And the memory trap:
console.log(broken([1, 1000000]));      // 1   correct, but it just
                                        // allocated a sparse array
                                        // a million slots wide.

4. Forgetting the empty array

Initialising best = 1 returns 1 for []. Start at 0 and let the loop raise it, or guard the empty case explicitly. The Set version handles it naturally because the loop body never runs.

5. Forgetting duplicates in the sorted version

Broken — duplicates reset the run
function broken(nums) {
  if (!nums.length) return 0;
  const s = [...nums].sort((a, b) => a - b);
  let best = 1, cur = 1;
  for (let i = 1; i < s.length; i++) {
    // missing:  if (s[i] === s[i-1]) continue;
    cur = s[i] === s[i - 1] + 1 ? cur + 1 : 1;
    best = Math.max(best, cur);
  }
  return best;

console.log(broken([1, 2, 3]));         // 3   fine
console.log(broken([1, 2, 2, 3]));      // 2   WRONG, should be 3

// Sorted, [1,2,2,3] has 2 next to 2. That is neither a duplicate to
// skip nor a step of one, so the run resets. The Set version never

Step 10

Practice before you move on

  1. Write the eight-line version from memory, then say the 2n argument out loud. Being able to defend the complexity matters more here than producing the code.
  2. Return the run, not its length. In Step 6 — write it from memory.
  3. Longest consecutive run allowing one gap. You may skip a single missing number. What changes? (Hint: the head condition becomes more complicated, and the sorted version starts looking attractive again.)
  4. Count how many runs there are. The number of heads — one line, once you have the head test.
  5. Binary Tree Longest Consecutive Sequence. Same idea, different structure. Doing it once shows that “consecutive” is about values, and the container is incidental.
What to carry forward

Find the canonical starting point. The naive version re-derived every run from every member; the fast one identifies a unique representative — the head — and does the work exactly once. That pattern appears everywhere: counting connected components, grouping intervals, de-duplicating cycles. When you catch yourself computing the same thing from several entry points, ask which one entry point should own this work?
