Isomorphic Strings

Can you rename the characters of one string to get the other? The obvious answer uses one map and is wrong. Finding out why — and that a valid mapping must be consistent in both directions — is the whole point of the problem.

Step 1

The problem

Two strings are isomorphic if you can replace every character of the first with some character to get the second, where the replacement is consistent: the same input character always becomes the same output character, and no two different input characters map to the same output character.

stAnswerWhy
"egg""add"truee→a, g→d
"paper""title"truep→t, a→i, e→l, r→e
"foo""bar"falseo would have to be both a and r
"badc""baba"falsed and c would both map to a
"ab""aa"falsea and b would both map to a
The half of the rule everyone forgets

Take s = "ab", t = "aa". Reading left to right: a→a is fine, then b→a is fine too — b has not been mapped before. One map says true.

But now two different characters, a and b, both produce a. You could not undo the renaming: given "aa" you could not tell which a came from a b. Isomorphic means a one-to-one mapping, and one-to-one has to hold in both directions.

Note that the two characters may be the same — a mapping to a is perfectly legal, as in "paper" where nothing maps to itself but nothing forbids it.

Step 2

Think first — the answer that looks right

Version 0 — one map
function isomorphicOneMap(s, t) {
  if (s.length !== t.length) return false;

  const map = new Map();     // character of s -> character of t

  for (let i = 0; i < s.length; i++) {
    const from = s[i];
    const to = t[i];

    if (map.has(from)) {
      if (map.get(from) !== to) return false;   // inconsistent
    } else {
      map.set(from, to);
    }
  }

  return true;
}

console.log(isomorphicOneMap('egg', 'add'));       // true    correct
console.log(isomorphicOneMap('paper', 'title'));   // true    correct
console.log(isomorphicOneMap('foo', 'bar'));       // false   correct
console.log(isomorphicOneMap('ab', 'aa'));         // TRUE    WRONG
console.log(isomorphicOneMap('badc', 'baba'));     // TRUE    WRONG

// It only checks that each character of s maps CONSISTENTLY.
// It never checks that two different characters of s avoid
// landing on the SAME character of t.

This is the single most common wrong answer, and it passes the three obvious test cases. The bug only shows on inputs where t has fewer distinct characters than s.

Step 3

Why one map is not enough

A mapping that is consistent in one direction is a function. A mapping you could undo is a bijection. Isomorphism needs the second.

  s = "ab"      t = "aa"

  one map:      a -> a      b -> a
                             ^
                two different sources, one destination

  Try to reverse it: given "aa", what was the original?
      "aa"?  "ab"?  "ba"?  "bb"?
  You cannot tell. The renaming destroyed information, so it was
  not a renaming at all -- it was a merge.

  A legal isomorphism looks like this:

  s = "paper"   t = "title"
      p -> t        t -> p
      a -> i        i -> a
      e -> l        l -> e
      r -> e        e -> r
      \_______/     \_______/
      forwards       backwards -- both are functions
the difference, demonstrated
function oneMap(s, t) {
  if (s.length !== t.length) return false;
  const m = new Map();
  for (let i = 0; i < s.length; i++) {
    if (m.has(s[i])) { if (m.get(s[i]) !== t[i]) return false; }
    else m.set(s[i], t[i]);
  }
  return true;
}

function twoMaps(s, t) {
  if (s.length !== t.length) return false;
  const forward = new Map(), backward = new Map();
  for (let i = 0; i < s.length; i++) {
    const a = s[i], b = t[i];
    if (forward.has(a) && forward.get(a) !== b) return false;
    if (backward.has(b) && backward.get(b) !== a) return false;
    forward.set(a, b);
    backward.set(b, a);
  }
  return true;
}

const cases = [
  ['egg', 'add'], ['paper', 'title'], ['foo', 'bar'],
  ['ab', 'aa'], ['badc', 'baba'], ['abc', 'xyz'], ['aba', 'xyx'],
  ['abab', 'baba'], ['abcd', 'aabb']
];

for (const [a, b] of cases) {
  const one = oneMap(a, b);
  const two = twoMaps(a, b);
  console.log('"' + a + '" -> "' + b + '"   one map: ' + one +
              '   two maps: ' + two + (one !== two ? '   <-- DISAGREE' : ''));
}
Step 4

The better idea — check both directions

The unlock

Keep two maps. forward answers “what does this character of s become?” and backward answers “what did this character of t come from?”. At each position, both must either be unset or already agree with what you are about to record.

The rule at position i, with a = s[i] and b = t[i]:

  1. If forward already maps a to something other than b → false. One character of s cannot become two things.
  2. If backward already maps b to something other than a → false. One character of t cannot have two sources.
  3. Otherwise record both and continue.

That is it. One pass, two constant-time lookups per character.

The elegant alternative: compare first-occurrence patterns

There is a second solution that needs no explicit mapping at all. Replace each character with the index where that character first appeared. Two strings are isomorphic exactly when those patterns match.

  "paper"          "title"
   p a p e r        t i t l e
   0 1 0 3 4        0 1 0 3 4      identical  ->  isomorphic

  "foo"            "bar"
   f o o            b a r
   0 1 1            0 1 2          different  ->  not isomorphic

  "ab"             "aa"
   a b              a a
   0 1              0 0            different  ->  not isomorphic
                                   (and this one catches the bug
                                    the single map missed)

This works because the pattern of first occurrences captures the structure of a string independently of which characters it uses — and it is symmetric by construction, so both directions are checked at once.

Dry run — trace it by hand

      record: forward{...r:e}  backward{...e:r}

Note i=4: e appears as a source (mapping to l) and also as a destination (coming from r). That is perfectly fine — the two maps are separate namespaces. Using one shared map would confuse them.

Now the failing case, s = "badc", t = "baba":

i=0   b -> b    both unseen   forward{b:b}   backward{b:b}
i=1   a -> a    both unseen   forward{b:b,a:a}  backward{b:b,a:a}
i=2   d -> b
      forward has d? no.
      backward has b?  YES, backward[b] = 'b', but we want 'd'
      MISMATCH  ->  FALSE

The character 'b' in t already came from 'b'. It cannot also come
from 'd'. The forward map alone would have missed this entirely.
the algorithm, narrating itself
function isomorphicExplained(s, t) {
  console.log('s = "' + s + '"   t = "' + t + '"');

  if (s.length !== t.length) {
    console.log('lengths differ -> FALSE');
    console.log('');
    return false;
  }

  const forward = new Map();
  const backward = new Map();

  for (let i = 0; i < s.length; i++) {
    const a = s[i], b = t[i];

    if (forward.has(a) && forward.get(a) !== b) {
      console.log('i=' + i + '  ' + a + ' -> ' + b + '   but forward says ' + a +
                  ' -> ' + forward.get(a) + '   MISMATCH -> FALSE');
      console.log('');
      return false;
    }

    if (backward.has(b) && backward.get(b) !== a) {
      console.log('i=' + i + '  ' + a + ' -> ' + b + '   but backward says ' + b +
                  ' came from ' + backward.get(b) + '   MISMATCH -> FALSE');
      console.log('');
      return false;
    }

    const known = forward.has(a);
    forward.set(a, b);
    backward.set(b, a);
    console.log('i=' + i + '  ' + a + ' -> ' + b + '   ' +
                (known ? 'consistent with what we knew' : 'new pair, recorded'));
    console.log('        forward ' + JSON.stringify([...forward]) +
                '   backward ' + JSON.stringify([...backward]));
  }

  console.log('reached the end -> TRUE');
  console.log('');
  return true;
}

Step 6

Version 1 — without built-in methods

Version 1a — two plain objects
function isIsomorphicManual(s, t) {
  if (s.length !== t.length) return false;

  const forward = {};    // character of s -> character of t
  const backward = {};   // character of t -> character of s

  for (let i = 0; i < s.length; i++) {
    const a = s[i];
    const b = t[i];

    const mappedTo = forward[a];
    const cameFrom = backward[b];

    // a already maps somewhere else?
    if (mappedTo !== undefined && mappedTo !== b) return false;

    // b already has a different source?
    if (cameFrom !== undefined && cameFrom !== a) return false;

    forward[a] = b;
    backward[b] = a;
  }

  return true;
}

console.log(isIsomorphicManual('egg', 'add'));       // true
console.log(isIsomorphicManual('paper', 'title'));   // true
console.log(isIsomorphicManual('foo', 'bar'));       // false
console.log(isIsomorphicManual('ab', 'aa'));         // false
console.log(isIsomorphicManual('badc', 'baba'));     // false
console.log(isIsomorphicManual('', ''));             // true
console.log(isIsomorphicManual('a', 'a'));           // true
console.log(isIsomorphicManual('abab', 'baba'));     // true
console.log(isIsomorphicManual('abcd', 'aabb'));     // false
Version 1b — the first-occurrence pattern
function patternOf(s) {
  const firstSeen = {};       // character -> the index it first appeared at
  const pattern = [];

  for (let i = 0; i < s.length; i++) {
    const ch = s[i];
    if (firstSeen[ch] === undefined) {
      firstSeen[ch] = i;
    }
    pattern[i] = firstSeen[ch];
  }

  return pattern;
}

function isIsomorphicPattern(s, t) {
  if (s.length !== t.length) return false;

  const a = patternOf(s);
  const b = patternOf(t);

  for (let i = 0; i < a.length; i++) {
    if (a[i] !== b[i]) return false;
  }

  return true;
}

console.log(patternOf('paper'));    // [0, 1, 0, 3, 4]
console.log(patternOf('title'));    // [0, 1, 0, 3, 4]
console.log(patternOf('foo'));      // [0, 1, 1]
console.log(patternOf('bar'));      // [0, 1, 2]
console.log('');
console.log(isIsomorphicPattern('paper', 'title'));   // true
console.log(isIsomorphicPattern('egg', 'add'));       // true
console.log(isIsomorphicPattern('foo', 'bar'));       // false
console.log(isIsomorphicPattern('ab', 'aa'));         // false
console.log(isIsomorphicPattern('badc', 'baba'));     // false

// No explicit mapping, no direction to forget. The pattern IS the
// structure, and two structures either match or they do not.
Step 7

Version 2 — with built-in methods

Version 2a — two Maps, the interview answer
function isIsomorphic(s, t) {
  if (s.length !== t.length) return false;

  const forward = new Map();
  const backward = new Map();

  for (let i = 0; i < s.length; i++) {
    const a = s[i], b = t[i];

    if (forward.has(a) && forward.get(a) !== b) return false;
    if (backward.has(b) && backward.get(b) !== a) return false;

    forward.set(a, b);
    backward.set(b, a);
  }

  return true;
}

console.log(isIsomorphic('egg', 'add'));       // true
console.log(isIsomorphic('paper', 'title'));   // true
console.log(isIsomorphic('foo', 'bar'));       // false
console.log(isIsomorphic('ab', 'aa'));         // false
console.log(isIsomorphic('13', '42'));         // true  -- digits work too
Version 2b — pattern comparison, one line each
const pattern = s => [...s].map((ch, i) => s.indexOf(ch)).join(',');

const isIsomorphicPattern = (s, t) =>
  s.length === t.length && pattern(s) === pattern(t);

console.log(pattern('paper'));    // '0,1,0,3,4'
console.log(pattern('title'));    // '0,1,0,3,4'
console.log('');
console.log(isIsomorphicPattern('paper', 'title'));   // true
console.log(isIsomorphicPattern('foo', 'bar'));       // false
console.log(isIsomorphicPattern('ab', 'aa'));         // false

// Beautiful, and O(n^2): indexOf scans the string for every
// character. Fine for short strings, quietly quadratic for long ones.
// The Step 6 version builds the same pattern in one pass with a map.
the same idea, generalised
// Isomorphism is really "do these two sequences have the same
// structure?" -- which applies far beyond strings.
function sameStructure(a, b) {
  if (a.length !== b.length) return false;

  const forward = new Map(), backward = new Map();

  for (let i = 0; i < a.length; i++) {
    const x = a[i], y = b[i];
    if (forward.has(x) && forward.get(x) !== y) return false;
    if (backward.has(y) && backward.get(y) !== x) return false;
    forward.set(x, y);
    backward.set(y, x);
  }

  return true;
}

console.log(sameStructure([1,2,1,3], ['a','b','a','c']));     // true
console.log(sameStructure([1,2,1,3], ['a','b','a','a']));     // false
console.log(sameStructure('abba'.split(''), [9,8,8,9]));      // true

// Word Pattern -- the classic follow-up -- is exactly this with a
// string on one side and a list of words on the other.
function wordPattern(pattern, sentence) {
  return sameStructure([...pattern], sentence.split(' '));
}

console.log(wordPattern('abba', 'dog cat cat dog'));   // true
console.log(wordPattern('abba', 'dog cat cat fish'));  // false
console.log(wordPattern('aaaa', 'dog cat cat dog'));   // false
console.log(wordPattern('abba', 'dog dog dog dog'));   // false  -- needs both maps
Step 8

Complexity, in sentences

SolutionTimeSpaceCorrect?
One mapO(n)O(k)no
Two mapsO(n)O(k)yes
Pattern with indexOfO(n²)O(n)yes
Pattern with a mapO(n)O(n)yes

One pass, two constant-time map operations per character. O(n) time, O(k) space where k is the number of distinct characters — bounded by the alphabet, so effectively constant.

Notice that the wrong answer has the same complexity as the right one. This is not a performance problem; it is a correctness problem, and the fix costs nothing. That is worth remembering: not every improvement is about speed.

Say this in the interview

“A single map only checks that each character of s maps consistently. It misses the case where two different characters of s map to the same character of t — "ab" to "aa". Isomorphism needs a one-to-one mapping, so I keep two maps, forward and backward, and reject if either disagrees. O(n) time, O(k) space. An equivalent trick is to replace each character with the index of its first occurrence and compare those patterns — that is symmetric, so it checks both directions automatically.”

Step 9

Mistakes people actually make

1. Only mapping one way

Covered in Step 2, and it is the reason this problem exists. If you take one thing from this page: a renaming has to be reversible.

2. Using one map for both directions

Broken — the namespaces collide
function broken(s, t) {
  if (s.length !== t.length) return false;
  const map = new Map();
  for (let i = 0; i < s.length; i++) {
    const a = s[i], b = t[i];
    if (map.has(a) && map.get(a) !== b) return false;
    if (map.has(b) && map.get(b) !== a) return false;
    map.set(a, b);
    map.set(b, a);            // same map -- bug
  }
  return true;
}

console.log(broken('egg', 'add'));       // true    fine
console.log(broken('ab', 'aa'));         // false   fine
console.log(broken('paper', 'title'));   // false   WRONG, should be true

// In "paper"/"title", 'e' maps to 'l' AND 'e' is what 'r' maps to.
// Sharing one map means map.set('e','l') then map.set('e','r')
// overwrite each other, and the check fails on a valid input.
// The two directions need two separate maps.

3. Comparing distinct-character counts instead

Broken — ignores position
function broken(s, t) {
  return s.length === t.length && new Set(s).size === new Set(t).size;
}

console.log(broken('egg', 'add'));       // true   right, by luck
console.log(broken('foo', 'bar'));       // false  right
console.log(broken('ab', 'aa'));         // false  right
console.log(broken('abc', 'aab'));       // false  right
console.log(broken('aab', 'abb'));       // TRUE   WRONG, should be false

// "aab" has structure 0,0,2 and "abb" has 0,1,1 -- different shapes,
// same number of distinct characters. Counting distinct characters
// throws away WHERE the repeats are, which is the whole question.

4. Forgetting the length check

"ab" and "abc" cannot be isomorphic. Without the guard the loop reads t[i] past the end, gets undefined, and happily maps a character to undefined — producing true on inputs of different lengths.

5. Using if (forward[a]) instead of checking existence

a falsy-value trap waiting to happen
// With characters this is safe, because no character is falsy...
console.log(Boolean('a'), Boolean('0'), Boolean(' '));   // true true true

// ...but the moment you generalise to the sameStructure version,
// falsy values appear and truthiness checks break:
const forward = new Map();
forward.set('x', 0);

console.log('truthiness says unmapped:', !forward.get('x'));   // true -- WRONG
console.log('has() says mapped:', forward.has('x'));           // true -- correct

// The empty string is the trap for strings specifically:
forward.set('y', '');
console.log('truthiness on "":', !forward.get('y'));           // true -- WRONG
console.log('has() on "":', forward.has('y'));                 // true -- correct

// Always ask "does the key exist?" (has / hasOwnProperty /
// !== undefined), never "is the value truthy?".
Step 10

Practice before you move on

  1. Write the two-map version from memory, then say in one sentence why one map is not enough. That sentence is the answer to this problem.
  2. Word Pattern. Does "abba" match "dog cat cat dog"? It is in Step 7 — write it from memory, and check "abba" against "dog dog dog dog", which needs the backward map.
  3. Write the pattern version in one pass (no indexOf), and confirm it agrees with the two-map version on every test case on this page.
  4. Group isomorphic strings. Given a list of words, group the ones with the same structure. The pattern is the canonical key — the same idea as Group Anagrams, with a different key function.
  5. Find the actual mapping. Return the character correspondence rather than a boolean, so a caller could perform the renaming. You have already built it; you just have to return forward.
What to carry forward

“Consistent” usually means consistent in both directions. Any time you build a correspondence between two sets — renaming, matching, pairing, joining — ask whether it needs to be reversible. If two different inputs can produce the same output, you have a function, not a bijection, and a single map will silently accept the merge. Two maps, or a symmetric canonical form, is the fix.
