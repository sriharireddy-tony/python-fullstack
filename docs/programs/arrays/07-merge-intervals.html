Arrays · Problem 07

Merge Intervals

The most practical problem on this list. Calendar bookings, meeting rooms, log windows, rate-limit buckets, video timelines — every one of them eventually needs this exact function. And the whole thing turns on one setup move: sort by start time.

Step 1

The problem

You are given a list of intervals — pairs of [start, end]. Merge every group that overlaps into one, and return the result.

InputAnswerWhy
[[1,3],[2,6],[8,10],[15,18]][[1,6],[8,10],[15,18]][1,3] and [2,6] overlap
[[1,4],[4,5]][[1,5]]touching at 4 counts as overlapping
[[1,4],[0,4]][[0,4]]input is not sorted
[[1,4],[2,3]][[1,4]]one interval swallows the other

Picture it as a timeline. Two bookings overlap if one starts before the other ends:

       1     2     3     4     5     6  ...  8     9    10
[1,3]  |===========|
[2,6]        |=======================|
[8,10]                                     |===========|

merged:
[1,6]  |=======================================|
[8,10]                                     |===========|
Ask this before you write code

Does [1,4] and [4,5] count as overlapping? It depends whether the interval is closed (includes its end) or half-open (excludes it). For meeting rooms, a meeting ending at 4 and another starting at 4 do not conflict. For the classic version of this problem, they do merge. The difference is a single character: <= versus <. Ask, then write the version you were asked for. This page uses the classic <=.

Step 2

Think first — the obvious answer

Without sorting, an overlapping pair could be anywhere. So you compare everything to everything, merge a pair when you find one, and start over — because merging can create a new overlap that did not exist before.

Version 0 — brute force, repeat until stable
function mergeBrute(intervals) {
  const list = intervals.map(iv => [iv[0], iv[1]]);   // copy

  let changed = true;
  while (changed) {
    changed = false;

    outer:
    for (let i = 0; i < list.length; i++) {
      for (let j = i + 1; j < list.length; j++) {

        // do intervals i and j touch or overlap?
        if (list[i][0] <= list[j][1] && list[j][0] <= list[i][1]) {
          list[i] = [Math.min(list[i][0], list[j][0]),
                     Math.max(list[i][1], list[j][1])];
          list.splice(j, 1);        // remove the one we absorbed
          changed = true;           // something merged -- go round again
          break outer;
        }
      }
    }
  }

  return list.sort((a, b) => a[0] - b[0]);
}

console.log(mergeBrute([[1,3],[2,6],[8,10],[15,18]]));   // [[1,6],[8,10],[15,18]]
console.log(mergeBrute([[1,4],[4,5]]));                  // [[1,5]]
console.log(mergeBrute([[1,4],[0,4]]));                  // [[0,4]]
console.log(mergeBrute([[1,4],[2,3]]));                  // [[1,4]]

The overlap test a.start <= b.end && b.start <= a.end is worth memorising on its own — it is the general “do these two ranges touch?” check and you will use it outside this problem. Think of it as: neither one finishes entirely before the other begins.

Step 3

Why it is slow

Each full scan is O(n²), and one merge can force another full scan, so the worst case is O(n³). Chain intervals like [[1,2],[2,3],[3,4],[4,5]...] and it rescans after every single merge.

Timing demo
// 6,000 mostly-disjoint intervals with a handful of overlaps hidden
// in them, then shuffled. The brute force has to compare every pair
// to discover the overlaps -- and start the whole scan again after
// each merge it finds.
const N = 6000;
const chain = [];
for (let i = 0; i < N; i++) chain.push([i * 10, i * 10 + 5]);
for (let k = 0; k < 5; k++) {                          // plant 5 overlaps
  const at = Math.floor(Math.random() * (N - 1));
  chain[at] = [chain[at][0], chain[at + 1][0] + 1];
}
for (let i = chain.length - 1; i > 0; i--) {           // shuffle
  const j = Math.floor(Math.random() * (i + 1));
  const t2 = chain[i]; chain[i] = chain[j]; chain[j] = t2;
}

function brute(intervals) {
  const list = intervals.map(iv => [iv[0], iv[1]]);
  let changed = true;
  while (changed) {
    changed = false;
    outer:
    for (let i = 0; i < list.length; i++)
      for (let j = i + 1; j < list.length; j++)
        if (list[i][0] <= list[j][1] && list[j][0] <= list[i][1]) {
          list[i] = [Math.min(list[i][0], list[j][0]), Math.max(list[i][1], list[j][1])];
          list.splice(j, 1);
          changed = true;
          break outer;
        }
  }
  return list;
}

function sweep(intervals) {
  const s = [...intervals].sort((a, b) => a[0] - b[0]);
  const out = [];
  for (const [start, end] of s) {
    const last = out[out.length - 1];
    if (last && start <= last[1]) last[1] = Math.max(last[1], end);
    else out.push([start, end]);
  }
  return out;
}

let t = performance.now();
const a = brute(chain);
const bruteMs = performance.now() - t;

t = performance.now();
const b = sweep(chain);
const fastMs = performance.now() - t;

console.log('brute  :', a.length, 'intervals in', bruteMs.toFixed(1) + ' ms');
console.log('sweep  :', b.length, 'intervals in', fastMs.toFixed(2) + ' ms');
console.log('same count:', a.length === b.length);
console.log('speed-up:', Math.round(bruteMs / Math.max(fastMs, 0.01)) + 'x');
Step 4

The better idea — sort, then sweep once

Everything hard about this problem comes from the intervals arriving in a random order. So fix that first.

The unlock

Sort by start time. Now, walking left to right, an interval can only ever overlap with the one you are currently building — never with anything further back.

Why is that true? Because the list is sorted by start, so the next interval starts at or after the current one. If it does not reach back far enough to touch the interval you are holding, it certainly cannot touch anything older, which ended even earlier. Every comparison against the rest of the list becomes unnecessary.

So the whole algorithm is:

  1. Sort by start.
  2. Put the first interval in the output.
  3. For each remaining interval: if it starts at or before the end of the last output interval, extend that one. Otherwise, push a new one.

Two branches. That is the entire solution.

The line that trips people up

When extending, the new end is Math.max(last.end, current.end), not current.end. Consider [[1,10],[2,3]]: the second interval sits entirely inside the first. Blindly assigning current.end would shrink [1,10] to [1,3] and throw away real coverage. Always take the larger end.

Step 6

Version 1 — without built-in methods

Hand-written sort, hand-written min and max, hand-written push.

Version 1 — loops only
function mergeManual(intervals) {
  if (intervals.length === 0) return [];

  // copy so we never reorder the caller's array
  const list = [];
  for (let i = 0; i < intervals.length; i++) {
    list[i] = [intervals[i][0], intervals[i][1]];
  }

  // insertion sort by start time
  for (let i = 1; i < list.length; i++) {
    const item = list[i];
    let j = i - 1;
    while (j >= 0 && list[j][0] > item[0]) {
      list[j + 1] = list[j];
      j--;
    }
    list[j + 1] = item;
  }

  const out = [];
  out[0] = list[0];

  for (let i = 1; i < list.length; i++) {
    const current = list[i];
    const last = out[out.length - 1];

    if (current[0] <= last[1]) {
      // overlap: stretch the end, but only if it actually reaches further
      if (current[1] > last[1]) {
        last[1] = current[1];
      }
    } else {
      out[out.length] = current;      // no overlap: begin a new interval
    }
  }

  return out;
}

console.log(JSON.stringify(mergeManual([[1,3],[2,6],[8,10],[15,18]])));  // [[1,6],[8,10],[15,18]]
console.log(JSON.stringify(mergeManual([[1,4],[4,5]])));                 // [[1,5]]
console.log(JSON.stringify(mergeManual([[1,4],[0,4]])));                 // [[0,4]]
console.log(JSON.stringify(mergeManual([[1,10],[2,3]])));                // [[1,10]]
console.log(JSON.stringify(mergeManual([[1,4]])));                       // [[1,4]]
console.log(JSON.stringify(mergeManual([])));                            // []

Notice if (current[1] > last[1]) last[1] = current[1]; — that is Math.max written out by hand, and writing it this way makes the “interval fully inside another” case impossible to overlook.

Step 7

Version 2 — with built-in methods

Version 2 — the one to write in an interview
function merge(intervals) {
  if (intervals.length === 0) return [];

  const sorted = [...intervals].sort((a, b) => a[0] - b[0]);
  const out = [sorted[0].slice()];      // slice: do not alias the input

  for (let i = 1; i < sorted.length; i++) {
    const [start, end] = sorted[i];
    const last = out[out.length - 1];

    if (start <= last[1]) {
      last[1] = Math.max(last[1], end);   // overlap -> extend
    } else {
      out.push([start, end]);             // gap -> new interval
    }
  }

  return out;
}

console.log(JSON.stringify(merge([[1,3],[2,6],[8,10],[15,18]])));  // [[1,6],[8,10],[15,18]]
console.log(JSON.stringify(merge([[1,4],[4,5]])));                 // [[1,5]]
console.log(JSON.stringify(merge([[1,4],[2,3]])));                 // [[1,4]]
console.log(JSON.stringify(merge([[2,3],[4,5],[6,7],[1,10]])));    // [[1,10]]
console.log(JSON.stringify(merge([[1,4],[5,6]])));                 // [[1,4],[5,6]]  no merge

The .slice() on the first interval matters more than it looks. Without it, out[0] is the same array object as sorted[0], and last[1] = ... would mutate the caller’s data. This is the kind of bug that passes every test and then corrupts state in production.

see the aliasing bug
const input = [[1,3],[2,6]];

function mergeAliasing(intervals) {
  const sorted = [...intervals].sort((a, b) => a[0] - b[0]);
  const out = [sorted[0]];              // NO slice -- shares the object
  for (let i = 1; i < sorted.length; i++) {
    const last = out[out.length - 1];
    if (sorted[i][0] <= last[1]) last[1] = Math.max(last[1], sorted[i][1]);
    else out.push(sorted[i]);
  }
  return out;
}

console.log('before:', JSON.stringify(input));
mergeAliasing(input);
console.log('after :', JSON.stringify(input));   // [[1,6],[2,6]]  -- the input changed!

Working with objects instead of pairs

the real-world shape
// In an actual codebase intervals are objects, not pairs.
function mergeBookings(bookings) {
  if (bookings.length === 0) return [];

  const sorted = [...bookings].sort((a, b) => a.start - b.start);
  const out = [{ ...sorted[0] }];

  for (let i = 1; i < sorted.length; i++) {
    const current = sorted[i];
    const last = out[out.length - 1];

    if (current.start <= last.end) {
      last.end = Math.max(last.end, current.end);
      last.rooms = (last.rooms || 1) + 1;    // carry extra data along
    } else {
      out.push({ ...current });
    }
  }

  return out;
}

console.log(mergeBookings([
  { start: 9,  end: 10, rooms: 1 },
  { start: 10, end: 12, rooms: 1 },
  { start: 14, end: 15, rooms: 1 }
]));
// [{start:9, end:12, rooms:2}, {start:14, end:15, rooms:1}]
Step 8

Complexity, in sentences

SolutionTimeSpace
Brute force with restartsO(n³)O(n)
Sort + one sweepO(n log n)O(n)

This is one of the rare problems where the sort is the expensive part. The sweep itself is a single O(n) pass, so the total is dominated by O(n log n). You cannot do better in general — if you could merge intervals in O(n), you could sort numbers in O(n) by turning each number x into the interval [x, x], which is known to be impossible for comparison-based sorting.

That argument is genuinely worth having ready. “Can we do better than O(n log n)?” is a standard follow-up, and “no, and here is the reduction that proves it” is a much stronger answer than “I do not think so”.

Space is O(n) for the output. If you are allowed to sort in place and overwrite the input, it drops to O(1) extra.

Say this in the interview

“Sort by start time. Then sweep once, keeping the last merged interval: if the next one starts at or before that interval’s end, extend the end to the max of the two; otherwise push it as a new interval. Sorting guarantees an interval can only overlap the one I am currently building. O(n log n) time, dominated by the sort, and O(n) space for the output.”

Step 9

Mistakes people actually make

1. Not sorting

Broken — assumes sorted input
function broken(intervals) {
  const out = [intervals[0].slice()];
  for (let i = 1; i < intervals.length; i++) {
    const [start, end] = intervals[i];
    const last = out[out.length - 1];
    if (start <= last[1]) last[1] = Math.max(last[1], end);
    else out.push([start, end]);
  }
  return out;
}

console.log(JSON.stringify(broken([[1,3],[2,6],[8,10]])));   // [[1,6],[8,10]]  fine
console.log(JSON.stringify(broken([[8,10],[1,3],[2,6]])));
// [[8,10],[1,3],[2,6]]   WRONG -- nothing merged at all

// Same data, different order, completely different answer.
// The sweep only works because sorting guarantees an interval can
// only overlap the CURRENT one.

2. Assigning the end instead of taking the max

Broken — loses coverage
function broken(intervals) {
  const s = [...intervals].sort((a, b) => a[0] - b[0]);
  const out = [s[0].slice()];
  for (let i = 1; i < s.length; i++) {
    const last = out[out.length - 1];
    if (s[i][0] <= last[1]) last[1] = s[i][1];    // no Math.max -- bug
    else out.push(s[i].slice());
  }
  return out;
}

console.log(JSON.stringify(broken([[1,3],[2,6]])));      // [[1,6]]   fine
console.log(JSON.stringify(broken([[1,10],[2,3]])));     // [[1,3]]   WRONG, should be [[1,10]]
console.log(JSON.stringify(broken([[1,10],[2,3],[4,5]])));  // [[1,5]]  WRONG

// A nested interval shrinks the one that contains it. This passes
// most hand-written tests because people rarely think to test a
// fully-contained interval.

3. Sorting with the default comparator

intervals.sort() stringifies each pair, so [10, 12] becomes "10,12" and sorts before "9,11". Always .sort((a, b) => a[0] - b[0]).

4. Sorting by end time

Sorting by end is correct for a different problem — “how many meetings can I fit without overlaps?”, the classic greedy interval-scheduling question. For merging, sort by start. Using the wrong key gives a plausible-looking but wrong answer, so know which problem you are solving.

5. Forgetting the empty input

intervals[0].slice() on an empty array throws Cannot read properties of undefined. One guard line at the top.

Step 10

Practice before you move on

  1. Insert Interval. The list is already sorted and non-overlapping; insert one new interval and re-merge. It is the next page, and it can be done without sorting at all.
  2. Meeting Rooms. Given intervals, can one person attend all of them? Sort by start; if any interval begins before the previous one ends, the answer is no. Two lines once sorted.
  3. Meeting Rooms II. How many rooms do you need at once? The trick: separate the starts and the ends into two sorted lists, then sweep both, adding a room on each start and freeing one on each end. Track the maximum.
  4. Interval intersection. Given two sorted lists, return the overlaps. The overlap of [a1,a2] and [b1,b2] is [max(a1,b1), min(a2,b2)], and it is real only when that start is at most that end.
  5. Employee free time. Merge everyone’s busy intervals, then return the gaps. Once you have this page’s function, it is five more lines.
What to carry forward

Sorting is a setup move. It costs O(n log n) once and turns a problem where anything can interact with anything into one where only neighbours can interact. That is why sorting appears at the start of Three Sum, Merge Intervals, Group Anagrams and half a dozen others. When a problem feels like it needs all-pairs comparison, ask: if this were sorted, would I only ever need to look at the previous item?
