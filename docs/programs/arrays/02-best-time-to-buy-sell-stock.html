Arrays · Problem 02

Best Time to Buy and Sell Stock

Two variables and one loop. This problem teaches the habit that separates slow code from fast code: instead of searching backwards for something you need, carry it forward with you.

Step 1

The problem

You are given the price of one share on each day, in order. You may buy once and sell once, and you must buy before you sell. Return the largest profit you could have made. If every possible trade loses money, return 0 — you simply do not trade.

PricesAnswerBecause
[7, 1, 5, 3, 6, 4]5buy on day 1 at 1, sell on day 4 at 6
[7, 6, 4, 3, 1]0prices only fall — never buy
[2, 4, 1]2buy at 2, sell at 4. The 1 at the end is too late to help.
[3, 3, 3]0no movement, no profit
The rule everyone breaks

Buy must come before sell. So this is not “maximum minus minimum”. In [2, 4, 1] the maximum is 4 and the minimum is 1, giving 3 — but the 1 happens on the last day, after the 4. You cannot travel back in time to sell. The correct answer is 2. Any solution that reaches for Math.max(...prices) - Math.min(...prices) is wrong, and it is wrong on exactly this kind of input.

Step 2

Think first — the obvious answer

What would you do by hand? Probably: “pick a day to buy, then look at every later day, work out the profit, and keep the best one I have seen.”

That is two nested loops again, and the j = i + 1 is now carrying the actual business rule — you can only sell on a day that comes after the day you bought.

Version 0 — brute force
function maxProfitBrute(prices) {
  let best = 0;                     // 0, not -Infinity: doing nothing is allowed

  for (let buy = 0; buy < prices.length; buy++) {
    for (let sell = buy + 1; sell < prices.length; sell++) {

      const profit = prices[sell] - prices[buy];

      if (profit > best) {
        best = profit;
      }
    }
  }

  return best;
}

console.log(maxProfitBrute([7, 1, 5, 3, 6, 4]));   // 5
console.log(maxProfitBrute([7, 6, 4, 3, 1]));      // 0
console.log(maxProfitBrute([2, 4, 1]));            // 2
console.log(maxProfitBrute([]));                   // 0

Notice best starts at 0, not at -Infinity. That single choice is what encodes “you are allowed to not trade at all”. Start it at -Infinity and [7, 6, 4, 3, 1] returns -1, which is a loss you were never forced to take.

Step 3

Why it is slow

Same shape as Two Sum: n × (n − 1) / 2 pairs, so O(n²). With one year of daily prices (250 days) that is about 31,000 subtractions — nothing. With five years of minute-by-minute data (about 500,000 points) it is 125 billion, and your process dies.

Press Run. This is 30,000 days of prices where the best trade is deliberately buried:

Timing demo
// A sawtooth price series, then one big spike near the end,
// so neither solution can get lucky and finish early.
const N = 30000;
const prices = [];
for (let i = 0; i < N; i++) prices.push(500 + (i % 50));
prices[10] = 1;          // a very cheap day, early
prices[N - 5] = 9999;    // a very expensive day, late

function brute(p) {
  let best = 0;
  for (let i = 0; i < p.length; i++)
    for (let j = i + 1; j < p.length; j++)
      if (p[j] - p[i] > best) best = p[j] - p[i];
  return best;
}

function onePass(p) {
  let cheapest = Infinity, best = 0;
  for (let i = 0; i < p.length; i++) {
    if (p[i] < cheapest) cheapest = p[i];
    else if (p[i] - cheapest > best) best = p[i] - cheapest;
  }
  return best;
}

Step 4

The better idea — and where it comes from

Ask the Step 4 question again: what am I doing over and over?

Stand on day 4, where the price is 6. The brute force is asking “what if I had bought on day 0? day 1? day 2? day 3?” — four subtractions. But think about what I actually want. I am selling at 6. Out of all the days before now, I do not care about most of them. I only care about the cheapest one, because that is the buy that makes today’s sale most profitable.

The unlock

To decide today’s best sale, the only thing I need to know about the entire past is the smallest price so far. That is one number. And I can keep it up to date as I walk forward, for free.

So the algorithm becomes a walk from left to right holding two facts:

  • cheapest — the lowest price seen up to and including today.
  • best — the biggest profit found so far.

And on each day you ask exactly two questions:

  1. Is today cheaper than anything I have seen? Then today is my new best buying day.
  2. Otherwise, if I sold today at the cheapest price I have seen, would that beat my best? Then record it.

The reason this is airtight on the buy-before-sell rule: cheapest can only ever contain a price from today or earlier, because we have not looked at tomorrow yet. The order of the loop enforces the business rule for us. That is worth pausing on — it is why the “max minus min” shortcut fails and this does not.

Now the losing case, prices = [7, 6, 4, 3, 1]:

start:  cheapest = Infinity    best = 0

day 0   price 7    7 < Infinity  ->  cheapest = 7
day 1   price 6    6 < 7         ->  cheapest = 6

Every single day took the first branch, so the profit branch never ran and best stayed at its starting 0. The “do not trade” rule falls out of the code for free — there is no special case for it anywhere.

And the trap case, prices = [2, 4, 1]:

day 0   price 2    cheapest = 2                       best = 0
day 1   price 4    4 - 2 = 2  >  0                    best = 2
day 2   price 1    1 < 2  ->  cheapest = 1            best = 2

answer: 2       (not 3 -- the cheap day came too late to sell into the 4)

Step 6

Version 1 — without built-in methods

Loops, comparisons and two variables. Not a single method call — and there is nothing missing, because there is nothing a built-in could add here.

Version 1 — loops only
function maxProfitManual(prices) {
  // guard: fewer than 2 days means no trade is possible at all
  if (prices.length < 2) return 0;

  let cheapest = prices[0];   // the best buy price seen so far
  let best = 0;               // the best profit found so far

  // start at day 1 -- you cannot sell on the day you first look at
  for (let i = 1; i < prices.length; i++) {
    const price = prices[i];

    if (price < cheapest) {
      cheapest = price;                 // better buying opportunity
    } else {
      const profit = price - cheapest;  // what selling today would earn
      if (profit > best) {
        best = profit;
      }
    }
  }

  return best;
}

console.log(maxProfitManual([7, 1, 5, 3, 6, 4]));   // 5
console.log(maxProfitManual([7, 6, 4, 3, 1]));      // 0
console.log(maxProfitManual([2, 4, 1]));            // 2
console.log(maxProfitManual([3, 3, 3]));            // 0
console.log(maxProfitManual([5]));                  // 0
console.log(maxProfitManual([]));                   // 0
Why else and not two separate ifs?

If today is the cheapest price so far, then price - cheapest is 0 — you would be buying and selling on the same day. That can never beat best (which starts at 0), so checking it is harmless but pointless. The else skips it. Using two separate ifs gives the same answer and is not a bug; the else is just honest about the fact that only one of the two things can be true.

Also return when to buy and sell

Interviewers love this follow-up, and it is a small change: track the day alongside the price.

variation — report the actual days
function bestTrade(prices) {
  if (prices.length < 2) return { profit: 0, buy: -1, sell: -1 };

  let cheapest = prices[0];
  let cheapestDay = 0;

  let best = 0;
  let buyDay = -1;
  let sellDay = -1;

  for (let i = 1; i < prices.length; i++) {
    if (prices[i] < cheapest) {
      cheapest = prices[i];
      cheapestDay = i;              // remember WHERE the cheap day was
    } else if (prices[i] - cheapest > best) {
      best = prices[i] - cheapest;
      buyDay = cheapestDay;         // ...so we can report it now
      sellDay = i;
    }
  }

  return { profit: best, buy: buyDay, sell: sellDay };
}

console.log(bestTrade([7, 1, 5, 3, 6, 4]));   // { profit: 5, buy: 1, sell: 4 }
console.log(bestTrade([7, 6, 4, 3, 1]));      // { profit: 0, buy: -1, sell: -1 }

The subtle part: buyDay is only written inside the profit branch, not the cheap-day branch. If you updated it every time you found a new cheapest day, a later cheap day that never got sold into would overwrite the buy day of your actual best trade.

Step 7

Version 2 — with built-in methods

Honest answer first: this problem barely benefits from built-ins. The loop version is already the idiomatic one. But there are two built-in shapes worth knowing, and one worth avoiding.

Using Math.min and Math.max

Version 2a — Math.min / Math.max
function maxProfit(prices) {
  let cheapest = Infinity;
  let best = 0;

  for (const price of prices) {
    cheapest = Math.min(cheapest, price);        // update the running minimum
    best     = Math.max(best, price - cheapest); // update the running best
  }

  return best;
}

console.log(maxProfit([7, 1, 5, 3, 6, 4]));   // 5
console.log(maxProfit([7, 6, 4, 3, 1]));      // 0
console.log(maxProfit([2, 4, 1]));            // 2
console.log(maxProfit([]));                   // 0  (loop never runs)

Six lines, no branches, no guard needed for an empty array. Note the order: cheapest is updated before the profit line, so on a brand-new lowest day the profit works out as price - price = 0, which Math.max harmlessly ignores. This is the version to write in an interview.

Using reduce

Version 2b — reduce, for the pattern
function maxProfitReduce(prices) {
  const result = prices.reduce(
    (state, price) => {
      const cheapest = Math.min(state.cheapest, price);
      return {
        cheapest,
        best: Math.max(state.best, price - cheapest)
      };
    },
    { cheapest: Infinity, best: 0 }   // the starting state
  );

  return result.best;
}

console.log(maxProfitReduce([7, 1, 5, 3, 6, 4]));   // 5
console.log(maxProfitReduce([2, 4, 1]));            // 2

// Worth knowing, but be honest about the trade:
// it allocates a fresh object on every single element, so it is
// slower and harder to read than the plain loop. Know the pattern;
// reach for the loop.

The built-in version that is wrong

Broken — max minus min
function wrong(prices) {
  if (prices.length === 0) return 0;
  return Math.max(0, Math.max(...prices) - Math.min(...prices));
}

console.log(wrong([7, 1, 5, 3, 6, 4]));   // 6   WRONG, should be 5
console.log(wrong([7, 6, 4, 3, 1]));      // 6   WRONG, should be 0
console.log(wrong([2, 4, 1]));            // 3   WRONG, should be 2

// Wrong on all three. Take the first: the highest price 7 is on day 0
// and the lowest price 1 is on day 1, so it "sells" a day before it
// "buys". It throws away the one thing that matters: the order of the days.
// Also, Math.max(...prices) spreads the whole array into function
// arguments -- with ~100k+ elements that throws RangeError:
// Maximum call stack size exceeded.
Step 8

Complexity, in sentences

SolutionTimeSpaceIn words
Brute forceO(n²)O(1)Every buy day against every later sell day.
One passO(n)O(1)Each day looked at once; two variables kept, whatever the input size.

This one is better than Two Sum in a way worth noticing. Two Sum bought its speed with memory — O(n) time but O(n) space. Here you get O(n) time at O(1) space: two numbers, forever, whether the array holds ten prices or ten million.

The reason is that the past compresses. In Two Sum you might need any earlier value, so you had to keep them all. Here every earlier day collapses into a single fact — the minimum — and the rest can be forgotten. Whenever you can find that one summarising fact, you get the free version of the trade.

Say this in the interview

“Brute force is O(n²). But to evaluate selling on day i, the only thing I need from the past is the minimum price before i — so I keep a running minimum and a running best profit as I sweep left to right. O(n) time, O(1) space. The left-to-right order is what guarantees I never sell before I buy.”

Step 9

Mistakes people actually make

1. Starting best at -Infinity

Broken
function broken(prices) {
  let cheapest = Infinity, best = -Infinity;   // bug is here
  for (const p of prices) {
    cheapest = Math.min(cheapest, p);
    best = Math.max(best, p - cheapest);
  }
  return best;
}

console.log(broken([7, 6, 4, 3, 1]));   // 0 ... which happens to be right
console.log(broken([5]));               // 0 ... also right
console.log(broken([]));                // -Infinity  <- crashes the caller

// The real damage shows on an empty array. Start at 0: it means
// "the profit from not trading", which is always an option.

2. Updating the minimum after using it

Broken — wrong order
function broken(prices) {
  let cheapest = Infinity, best = 0;
  for (const p of prices) {
    best = Math.max(best, p - cheapest);   // used BEFORE updating
    cheapest = Math.min(cheapest, p);
  }
  return best;
}

console.log(broken([7, 1, 5, 3, 6, 4]));   // 5   still right here
console.log(broken([2, 4, 1]));            // 2   still right here

// On day 0, cheapest is still Infinity, so p - cheapest is -Infinity.
// Math.max ignores it, so you get away with it -- this time.
// It is fragile reasoning though. Update the running minimum FIRST,
// then use it. The invariant should be true when you read it.

3. Allowing buy and sell on the same day

If your inner loop starts at sell = buy instead of buy + 1, you allow a zero-profit same-day trade. Harmless for the answer (0 never beats 0), but it shows you did not think about the constraint — and in the “report the days” variation it produces nonsense like { buy: 3, sell: 3 }.

4. Not handling short arrays

[] and [5] both have to return 0. The Math.min version handles them without a guard because the loop simply never finds a second day; the manual version needs the explicit if (prices.length < 2) return 0;. Whichever you write, say out loud which inputs it covers.

5. Confusing this with the “buy and sell many times” version

They are different problems with very different answers, and interviewers ask the second one immediately after the first. It is in the next section.

The follow-up

Part II — unlimited transactions

Same prices, but now you may buy and sell as many times as you like — as long as you sell before you buy again (no holding two shares at once). What is the maximum profit?

People expect this to be much harder. It is dramatically easier, and the reason is a genuinely lovely bit of reasoning.

Take [1, 5, 3, 6]. Buying at 1 and selling at 6 would earn 5 — but you are not restricted to one trade any more. Buy at 1, sell at 5 (+4). Buy at 3, sell at 6 (+3). Total 7.

Now look at where that 7 comes from. The price went 1→5 (+4), then 5→3 (−2), then 3→6 (+3). The profit is every upward step, added together, and the downward steps are simply the days you were not holding anything. So:

The unlock

With unlimited trades, the answer is the sum of every day-to-day increase. You do not need to identify peaks and valleys at all — walking every rise is exactly the same total as jumping from each valley to its next peak.

Part II — both versions
// Version 1 -- no built-ins
function maxProfitManyManual(prices) {
  let total = 0;
  for (let i = 1; i < prices.length; i++) {
    if (prices[i] > prices[i - 1]) {
      total += prices[i] - prices[i - 1];   // pocket every rise
    }
  }
  return total;
}

// Version 2 -- with reduce
function maxProfitMany(prices) {
  return prices.reduce(
    (sum, price, i) => i === 0 ? 0 : sum + Math.max(0, price - prices[i - 1]),
    0
  );
}

console.log(maxProfitManyManual([7, 1, 5, 3, 6, 4]));  // 7   (4 + 3)
console.log(maxProfitMany([7, 1, 5, 3, 6, 4]));        // 7
console.log(maxProfitManyManual([1, 2, 3, 4, 5]));     // 4   one long climb
console.log(maxProfitManyManual([7, 6, 4, 3, 1]));     // 0   nothing ever rises

Look at [1, 2, 3, 4, 5]. Adding every rise gives 1+1+1+1 = 4, which is exactly the same as one trade from 1 to 5. Buying and selling on consecutive days costs nothing in this problem, so the two strategies are worth the same — that is the proof that summing the rises is not just a hack.

Both are O(n) time and O(1) space. The Part I answer is always less than or equal to the Part II answer, which is a handy self-check when you test them side by side.

Practice

Before you move on

  1. Rewrite the six-line Math.min version from memory. Then say out loud why the order of those two lines matters.
  2. Maximum loss. Find the worst trade you could have made. One character changes.
  3. Part II with a fee. Each completed trade costs a flat 2. Now consecutive small rises are not free, so summing every rise stops working. What has to change?
  4. At most two transactions. The genuinely hard version. Hint: for every split point, the answer is the best single trade on the left plus the best single trade on the right — and both of those can be precomputed in one pass each. You will meet this prefix/suffix idea again.
  5. Cooldown. After you sell, you must skip one day before buying again. Try to trace it by hand on [1, 2, 3, 0, 2] before writing any code.
What to carry forward

The pattern here is called a running aggregate: sweep once, carrying the one summary of the past that your decision actually depends on. Two Sum kept a whole notebook because it needed any earlier value; this problem kept a single number because it only needed the minimum. Before you write a nested loop, always ask: what is the smallest thing I could carry forward that would let me answer this in one pass?
