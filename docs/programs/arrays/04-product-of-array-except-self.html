Arrays · Problem 04

Product of Array Except Self

The problem that bans the obvious tool. You are not allowed to divide, which forces you to discover a genuinely useful pattern: everything except me = everything on my left, times everything on my right.

Step 1

The problem

Given an array, return a new array where each position holds the product of all the other numbers — everything except the one standing there.

InputAnswerWorking
[1, 2, 3, 4][24, 12, 8, 6]2×3×4, 1×3×4, 1×2×4, 1×2×3
[2, 3, 4, 5][60, 40, 30, 24]same idea
[1, 0][0, 1]a zero flattens everything except its own slot
[0, 0, 3][0, 0, 0]two zeros flatten everything

Two constraints come with it, and both are there to stop you taking a shortcut:

  • No division. Which kills the one-liner everybody thinks of first.
  • O(n) time. Which kills the nested loop.
Why division is banned — and it is not arbitrary

The obvious idea is: multiply everything once, then divide by nums[i] at each position. It is elegant and it explodes the moment the array contains a zero. totalProduct becomes 0, and every answer becomes 0 / nums[i], or worse 0 / 0 = NaN. You would then need one special case for exactly one zero and another for two or more zeros. The ban is the interviewer saving you from writing that.

Real uses: “each region’s share of everyone else’s traffic”, “leave-one-out” scoring, and any “everything but this one” aggregate. The pattern generalises far past multiplication.

Step 2

Think first — the obvious answer

By hand you would stand on each position and multiply everything else together. Two loops: the outer one picks the position, the inner one multiplies every other number.

Version 0 — brute force
function productExceptSelfBrute(nums) {
  const result = [];

  for (let i = 0; i < nums.length; i++) {
    let product = 1;                    // start at 1, the identity for multiplication

    for (let j = 0; j < nums.length; j++) {
      if (j === i) continue;            // skip myself -- that is the whole rule
      product *= nums[j];
    }

    result[i] = product;
  }

  return result;
}

console.log(productExceptSelfBrute([1, 2, 3, 4]));   // [24, 12, 8, 6]
console.log(productExceptSelfBrute([2, 3, 4, 5]));   // [60, 40, 30, 24]
console.log(productExceptSelfBrute([1, 0]));         // [0, 1]
console.log(productExceptSelfBrute([0, 0, 3]));      // [0, 0, 0]

Note let product = 1. Starting a sum at 0 and a product at 1 is the same idea: the value that changes nothing. Start a product at 0 and every answer is 0.

Step 3

Why it is slow — and what it repeats

n positions, each doing n multiplications: n². But look closer at what it repeats, because that is where the fix hides.

nums = [1, 2, 3, 4]

position 0:  skip 1,  multiply  2 x 3 x 4
position 1:  skip 2,  multiply  1     x 3 x 4
position 2:  skip 3,  multiply  1 x 2     x 4
position 3:  skip 4,  multiply  1 x 2 x 3

         ^^^^^^^^^^^          ^^^^^^^^^^^
         the left part        the right part
         is recomputed        is recomputed
         from scratch         from scratch
         every single row     every single row

Every row rebuilds “the product of everything to my left” from position 0, even though the row above it already worked out almost the same thing. Same waste as always.

Timing demo
const N = 20000;
const nums = [];
for (let i = 0; i < N; i++) nums.push((i % 9) + 1);   // 1..9, never zero

function brute(a) {
  const out = [];
  for (let i = 0; i < a.length; i++) {
    let p = 1;
    for (let j = 0; j < a.length; j++) if (j !== i) p *= a[j];
    out[i] = p;
  }
  return out;
}

function twoPass(a) {
  const out = new Array(a.length).fill(1);
  let running = 1;
  for (let i = 0; i < a.length; i++) { out[i] = running; running *= a[i]; }
  running = 1;
  for (let i = a.length - 1; i >= 0; i--) { out[i] *= running; running *= a[i]; }
  return out;
}

let t = performance.now();
const x = brute(nums);
const bruteMs = performance.now() - t;

t = performance.now();
const y = twoPass(nums);
const fastMs = performance.now() - t;

console.log('brute force : ' + bruteMs.toFixed(1) + ' ms');
console.log('two passes  : ' + fastMs.toFixed(2) + ' ms');
console.log('first 4 match:', x[0] === y[0] && x[1] === y[1] && x[2] === y[2] && x[3] === y[3]);

(The numbers go astronomically large and turn into Infinity at this size — that is fine, we are timing the work, not trusting the values.)

Step 4

The better idea — split at the gap

Look again at that trace. Each row is a product with a hole punched in it. And a product with a hole in it is really two products stuck together:

The unlock

everything except me = (everything to my left) × (everything to my right)

Draw it for [1, 2, 3, 4] at position 2:

      index:     0     1    [2]    3
      value:     1     2    [3]    4
                 \_____/           |
                 left = 1x2 = 2    |
                                  \|/
                          right = 4

      answer[2] = left x right = 2 x 4 = 8

And here is the payoff: left for position 2 is just left for position 1 multiplied by nums[1]. Each one is one step past the previous one. So a single sweep left-to-right can compute all the left products, and a single sweep right-to-left can compute all the right products. Two passes, no nesting.

index0123
value1234
left products1126
right products241241
left × right241286

Read the ends carefully, because this is where the off-by-one bugs live. left[0] = 1: there is nothing to the left of position 0, and the product of nothing is 1. Same for right[3]. Those two 1s are not padding — they are the mathematically correct answer for “multiply an empty set of numbers”.

Notice too that the zero problem simply disappears. Nothing is divided, so a zero just multiplies through like any other number and every answer comes out right without a single special case.

Step 5

Dry run — trace both passes

nums = [1, 2, 3, 4]. Pass one goes left to right and writes the left product into the output before updating the running total.

PASS 1  (left to right)     running = 1     out = [_, _, _, _]

i=0   out[0] = running = 1        then  running = 1 x nums[0] = 1 x 1 = 1
      out = [1, _, _, _]
i=1   out[1] = running = 1        then  running = 1 x nums[1] = 1 x 2 = 2
      out = [1, 1, _, _]
i=2   out[2] = running = 2        then  running = 2 x nums[2] = 2 x 3 = 6
      out = [1, 1, 2, _]
i=3   out[3] = running = 6        then  running = 6 x nums[3] = 6 x 4 = 24
      out = [1, 1, 2, 6]          <-- every left product

Pass two goes right to left and multiplies into what is already there.

PASS 2  (right to left)     running = 1     out = [1, 1, 2, 6]

i=3   out[3] = 6 x running = 6 x 1  = 6     then running = 1 x nums[3] = 4
      out = [1, 1, 2, 6]
i=2   out[2] = 2 x running = 2 x 4  = 8     then running = 4 x nums[2] = 12
      out = [1, 1, 8, 6]
i=1   out[1] = 1 x running = 1 x 12 = 12    then running = 12 x nums[1] = 24
      out = [1, 12, 8, 6]
i=0   out[0] = 1 x running = 1 x 24 = 24    then running = 24 x nums[0] = 24
      out = [24, 12, 8, 6]        <-- the answer

The rhythm in both passes is identical and it is worth saying out loud: write first, then update. If you update running before writing, you include yourself in your own answer — which is exactly what the problem forbids.

Step 6

Version 1 — without built-in methods

Written the clearest way first: two explicit helper arrays, one for the left products and one for the right. Slower on memory, but you can see exactly what the table in Step 4 is.

Version 1a — two helper arrays, loops only
function productExceptSelfArrays(nums) {
  const n = nums.length;

  const left  = [];     // left[i]  = product of everything BEFORE i
  const right = [];     // right[i] = product of everything AFTER i
  const out   = [];

  // nothing is to the left of position 0
  left[0] = 1;
  for (let i = 1; i < n; i++) {
    left[i] = left[i - 1] * nums[i - 1];
  }

  // nothing is to the right of the last position
  right[n - 1] = 1;
  for (let i = n - 2; i >= 0; i--) {
    right[i] = right[i + 1] * nums[i + 1];
  }

  for (let i = 0; i < n; i++) {
    out[i] = left[i] * right[i];
  }

  return out;
}

console.log(productExceptSelfArrays([1, 2, 3, 4]));   // [24, 12, 8, 6]
console.log(productExceptSelfArrays([2, 3, 4, 5]));   // [60, 40, 30, 24]
console.log(productExceptSelfArrays([1, 0]));         // [0, 1]
console.log(productExceptSelfArrays([5]));            // [1]

Read the two index shifts. left[i] uses nums[i - 1], not nums[i] — because “everything before me” ends at the element before me. Getting that wrong by one is the single most common bug in this problem, and the trace in Step 5 is how you catch it.

Now collapse the helper arrays away

The two extra arrays are not needed. Write the left products directly into the output, then multiply the right products into it on the way back — using one variable instead of an array.

Version 1b — two passes, one output array
function productExceptSelfManual(nums) {
  const n = nums.length;
  const out = [];

  // PASS 1: out[i] = product of everything to the LEFT of i
  let running = 1;
  for (let i = 0; i < n; i++) {
    out[i] = running;       // write first...
    running *= nums[i];     // ...then include myself for the next position
  }

  // PASS 2: multiply in the product of everything to the RIGHT of i
  running = 1;
  for (let i = n - 1; i >= 0; i--) {
    out[i] *= running;      // write first...
    running *= nums[i];     // ...then include myself
  }

  return out;
}

console.log(productExceptSelfManual([1, 2, 3, 4]));   // [24, 12, 8, 6]
console.log(productExceptSelfManual([2, 3, 4, 5]));   // [60, 40, 30, 24]
console.log(productExceptSelfManual([1, 0]));         // [0, 1]
console.log(productExceptSelfManual([0, 0, 3]));      // [0, 0, 0]
console.log(productExceptSelfManual([-1, 2, -3]));    // [-6, 3, -2]  negatives are fine
console.log(productExceptSelfManual([5]));            // [1]

Six lines of real work. Both passes are the identical two-line rhythm, once forwards and once backwards. If you can hold “write, then update” in your head you can reproduce this from nothing.

Step 7

Version 2 — with built-in methods

Version 2 — Array.fill and reduceRight
function productExceptSelf(nums) {
  const out = new Array(nums.length).fill(1);

  // left pass: reduce carries the running product for us
  nums.reduce((running, value, i) => {
    out[i] = running;
    return running * value;
  }, 1);

  // right pass: reduceRight is reduce, walking backwards
  nums.reduceRight((running, value, i) => {
    out[i] *= running;
    return running * value;
  }, 1);

  return out;
}

console.log(productExceptSelf([1, 2, 3, 4]));   // [24, 12, 8, 6]
console.log(productExceptSelf([1, 0]));         // [0, 1]
console.log(productExceptSelf([-1, 2, -3]));    // [-6, 3, -2]

reduceRight is the one genuinely useful built-in here — it is exactly reduce with the loop running backwards, which saves you writing for (let i = n - 1; i >= 0; i--) and getting the bounds wrong. Note that we are using reduce for its side effect of writing into out and throwing the return value away, which some reviewers dislike. It is honest here because the running product is genuinely a fold; if it bothers you, ship Version 1b.

new Array(n) vs new Array(n).fill(1)

new Array(4) makes an array with four holes, not four values. Holes are skipped by map, forEach and filter, which produces baffling bugs where your loop appears not to run. .fill(1) turns the holes into real values. In Version 1 we sidestepped it by assigning out[i] directly, which fills holes as it goes.

The banned version, for completeness

Broken — the division shortcut
function withDivision(nums) {
  const total = nums.reduce((a, b) => a * b, 1);
  return nums.map(n => total / n);
}

console.log(withDivision([1, 2, 3, 4]));   // [24, 12, 8, 6]   works...
console.log(withDivision([1, 0]));         // [0, NaN]         should be [0, 1]
console.log(withDivision([0, 0, 3]));      // [NaN, NaN, 0]    should be [0, 0, 0]

// The moment a zero appears, `total` is 0, so every answer becomes
// 0 / nums[i] -- and 0 / 0 is NaN. Patching this needs a zero count
// and two special cases: more code than just doing it properly.
Step 8

Complexity, in sentences

SolutionTimeExtra spaceIn words
Brute forceO(n²)O(1)Every position multiplies every other.
Two helper arraysO(n)O(n)Two extra arrays of size n.
Two passesO(n)O(1)Two sweeps, one running variable each.

Two passes is still O(n). Beginners often think two loops means O(n²) — it does not. Nested loops multiply; sequential loops add. n + n = 2n, and Big-O ignores the constant, so 2n is O(n). You can make ten separate passes over an array and still be linear.

“O(1) extra space” needs one caveat and interviewers listen for it: the output array is size n, so the total memory is obviously O(n). By convention the array you are required to return does not count against your space complexity — only the scratch space does, and here that is one variable. Say that out loud rather than claiming O(1) and hoping.

Say this in the interview

“Division would be O(n) but breaks on zeros, and it is disallowed. Instead, the answer at i is the product of everything left of i times everything right of i. Both of those are running products, so I sweep left to right writing left-products into the output, then right to left multiplying right-products in. O(n) time, O(1) extra space beyond the output.”

Step 9

Mistakes people actually make

1. Update before write

Broken — includes itself
function broken(nums) {
  const out = [];
  let running = 1;
  for (let i = 0; i < nums.length; i++) {
    running *= nums[i];    // updated FIRST -- bug
    out[i] = running;
  }
  running = 1;
  for (let i = nums.length - 1; i >= 0; i--) {
    running *= nums[i];
    out[i] *= running;
  }
  return out;
}

console.log(broken([1, 2, 3, 4]));   // [24, 48, 72, 96]  every value counted twice

// out[1] became (1x2) x (4x3x2) = 2 x 24 = 48.
// The 2 appears in BOTH halves. Write the value, THEN update the
// running product -- that gap is what excludes the current element.

2. Off-by-one in the helper arrays

Broken — wrong index
function broken(nums) {
  const n = nums.length, left = [], right = [], out = [];
  left[0] = 1;
  for (let i = 1; i < n; i++) left[i] = left[i - 1] * nums[i];   // should be nums[i-1]
  right[n - 1] = 1;
  for (let i = n - 2; i >= 0; i--) right[i] = right[i + 1] * nums[i];  // should be nums[i+1]
  for (let i = 0; i < n; i++) out[i] = left[i] * right[i];
  return out;
}

console.log(broken([1, 2, 3, 4]));   // [6, 12, 18, 24]  wrong

// Every answer is 6x too big -- it is the product of the WHOLE array
// (24) divided by nothing, because each element got counted in both
// halves. "Everything before me" ends at i-1, not at i.
// A single dry run on [1,2,3,4] catches this in ten seconds.

3. Starting the product at 0

let product = 0 makes every answer 0, because anything times zero is zero. Sums start at 0, products start at 1. The rule is: start at the value that does not change the result.

4. Assuming no zeros, no negatives

Both are allowed. [-1, 2, -3] answers [-6, 3, -2] — the signs take care of themselves as long as you are multiplying rather than dividing. Test with a zero, with two zeros, and with an odd number of negatives.

5. Forgetting the single-element array

[5] answers [1]: there are no other elements, and the product of nothing is 1. Both versions here get this right for free — but only because the passes are written to handle an empty left and an empty right, which is the same reason the 1s at the ends of the Step 4 table are there.

Step 10

Practice before you move on

  1. Sum of array except self. Much easier — one total, then total - nums[i]. Do it, then say why subtraction is safe here when division was not. (Because there is no value of nums[i] that makes subtraction undefined.)
  2. Do it with division anyway, correctly. Count the zeros first. Zero zeros: divide as normal. Exactly one zero: every answer is 0 except at the zero’s own position, which gets the product of the rest. Two or more zeros: all zeros. Writing this is the fastest way to appreciate why the two-pass version is better.
  3. Running prefix sums. Build prefix[i] = sum of nums[0..i], then answer “what is the sum between index a and b?” in O(1) with prefix[b] - prefix[a-1]. This is the same left-sweep idea and it is one of the most reused tools in the whole subject.
  4. Product of the array except a whole range. Given a and b, return the product of everything outside [a, b]. Your left and right arrays already contain the answer.
  5. Trapping rain water. A famously hard problem that becomes easy with exactly this idea: for each position, compute the tallest bar to its left and the tallest to its right in two sweeps. Try it — you now have the technique.
What to carry forward

The pattern is prefix and suffix sweeps. Whenever the answer at position i depends on “everything before i” and “everything after i”, you can almost always compute both in one forward pass and one backward pass instead of a nested loop. It works for products, sums, maximums, minimums and counts — anything you can accumulate one element at a time.
