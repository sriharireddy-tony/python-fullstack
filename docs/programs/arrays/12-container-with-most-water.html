Arrays · Problem 12

Container With Most Water

Two pointers starting at opposite ends and walking inwards. The code is six lines. The interesting part is the argument for why moving the shorter side is always safe — that argument is the answer the interviewer is listening for.

Step 1

The problem

An array of heights. Each number is a vertical line standing on the x-axis. Pick two lines so that they, plus the ground between them, hold the most water. Return that amount.

The area formula is the whole problem in one line:

the formula
area = (right - left) * Math.min(height[left], height[right])
        \___________/    \_____________________________________/
           width          the SHORTER wall -- water spills over it
Two things the picture might mislead you about

The lines have no thickness, and the ones between your two chosen lines are ignored completely — water is not blocked by them. This is not the “trapping rain water” problem, which is a different question with a different answer. Here you pick exactly two lines and everything else disappears.

Step 2

Think first — the obvious answer

Try every pair, compute the area, keep the biggest.

Version 0 — brute force
function maxAreaBrute(height) {
  let best = 0;

  for (let left = 0; left < height.length; left++) {
    for (let right = left + 1; right < height.length; right++) {

      const width = right - left;
      const shorter = Math.min(height[left], height[right]);
      const area = width * shorter;

      if (area > best) best = area;
    }
  }

  return best;
}

console.log(maxAreaBrute([1, 8, 6, 2, 5, 4, 8, 3, 7]));   // 49
console.log(maxAreaBrute([1, 1]));                        // 1
console.log(maxAreaBrute([4, 3, 2, 1, 4]));               // 16
console.log(maxAreaBrute([1, 2, 1]));                     // 2
Step 3

Why it is slow

Every pair, so n(n-1)/2 — O(n²). With 100,000 lines that is five billion area calculations.

Timing demo
const N = 20000;
const height = [];
for (let i = 0; i < N; i++) height.push(Math.floor(Math.random() * 1000) + 1);

function brute(h) {
  let best = 0;
  for (let l = 0; l < h.length; l++)
    for (let r = l + 1; r < h.length; r++) {
      const a = (r - l) * Math.min(h[l], h[r]);
      if (a > best) best = a;
    }
  return best;
}

function twoPointer(h) {
  let l = 0, r = h.length - 1, best = 0;
  while (l < r) {
    const a = (r - l) * Math.min(h[l], h[r]);
    if (a > best) best = a;
    if (h[l] < h[r]) l++; else r--;
  }
  return best;
}

let t = performance.now();
const x = brute(height);
const bruteMs = performance.now() - t;

t = performance.now();
const y = twoPointer(height);
const fastMs = performance.now() - t;

console.log('two pointers:', y, 'in', fastMs.toFixed(2) + ' ms');
console.log('same answer :', x === y);
console.log('speed-up:', Math.round(bruteMs / Math.max(fastMs, 0.01)) + 'x');
Step 4

The better idea — start wide, then commit

Begin with the two outermost lines. That gives you the widest container possible. Any other pair is narrower, so to beat this one it must be taller.

Now the key question: which pointer should move?

The unlock

Move the pointer at the shorter line. Always.

Why it is safe: the area is capped by the shorter wall. If you keep the shorter wall and move the taller one inwards, the width definitely shrinks, and the height cannot possibly grow — it is still limited by that same short wall. So every one of those pairs is worse than the one you already measured. You can discard all of them at once.

Spell that out with numbers. Suppose height[left] = 3 and height[right] = 9, with width 8, so the area is 8 × 3 = 24. Now consider every pair that keeps the 3 and moves the right pointer inwards:

keeping left = 3, pulling right inwards:

  width 7,  height = min(3, whatever) <= 3   ->  area <= 21
  width 6,  height = min(3, whatever) <= 3   ->  area <= 18
  width 5,  height = min(3, whatever) <= 3   ->  area <= 15
  ...

every single one is smaller than the 24 we just measured.
So we can skip ALL of them by moving `left` instead.

That is the whole algorithm, and it is why this counts as a greedy solution: at each step you make a locally-obvious choice, and you can prove no better answer was thrown away.

Each step moves one pointer inwards by one, so the two pointers together travel the length of the array once: O(n).

What if the two lines are equal?

It does not matter which one you move — move either. The argument above applies to both sides simultaneously: keeping either wall fixed caps the height at that same value while the width shrinks. Some solutions move both at once, which is also fine.

Eight steps for a nine-element array. The brute force would have done 36. Notice how the very first move — abandoning the height-1 line at index 0 — wiped out seven pairs in one step, and the greedy argument guarantees none of them could have won.

Step 6

Version 1 — without built-in methods

Version 1 — no Math.min, no Math.max
function maxAreaManual(height) {
  let left = 0;
  let right = height.length - 1;
  let best = 0;

  while (left < right) {
    const width = right - left;

    // the shorter of the two walls, by hand
    let shorter;
    if (height[left] < height[right]) {
      shorter = height[left];
    } else {
      shorter = height[right];
    }

    const area = width * shorter;
    if (area > best) {
      best = area;
    }

    // move the pointer standing on the shorter wall
    if (height[left] < height[right]) {
      left++;
    } else {
      right--;
    }
  }

  return best;
}

console.log(maxAreaManual([1, 8, 6, 2, 5, 4, 8, 3, 7]));   // 49
console.log(maxAreaManual([1, 1]));                        // 1
console.log(maxAreaManual([4, 3, 2, 1, 4]));               // 16
console.log(maxAreaManual([1, 2, 1]));                     // 2
console.log(maxAreaManual([2, 3, 4, 5, 18, 17, 6]));       // 17
console.log(maxAreaManual([1]));                           // 0  one line holds nothing
console.log(maxAreaManual([]));                            // 0

Reporting which two lines won

variation — return the pair too
function bestContainer(height) {
  let left = 0, right = height.length - 1;
  let best = 0, bestLeft = -1, bestRight = -1;

  while (left < right) {
    const area = (right - left) * Math.min(height[left], height[right]);

    if (area > best) {
      best = area;
      bestLeft = left;       // freeze only when a new best is confirmed
      bestRight = right;
    }

    if (height[left] < height[right]) left++;
    else right--;
  }

  return { area: best, left: bestLeft, right: bestRight,
           heights: [height[bestLeft], height[bestRight]] };
}

console.log(bestContainer([1, 8, 6, 2, 5, 4, 8, 3, 7]));
// { area: 49, left: 1, right: 8, heights: [8, 7] }

console.log(bestContainer([4, 3, 2, 1, 4]));
// { area: 16, left: 0, right: 4, heights: [4, 4] }
Step 7

Version 2 — with built-in methods

Version 2 — the interview answer
function maxArea(height) {
  let left = 0;
  let right = height.length - 1;
  let best = 0;

  while (left < right) {
    best = Math.max(best, (right - left) * Math.min(height[left], height[right]));

    if (height[left] < height[right]) left++;
    else right--;
  }

  return best;
}

console.log(maxArea([1, 8, 6, 2, 5, 4, 8, 3, 7]));   // 49
console.log(maxArea([1, 1]));                        // 1
console.log(maxArea([4, 3, 2, 1, 4]));               // 16
console.log(maxArea([1, 2, 4, 3]));                  // 4

Six lines, and there is genuinely nothing a built-in can improve here — Math.min and Math.max are the only ones that fit, and both are doing exactly the comparison you would write by hand. This is a problem where Version 1 and Version 2 are almost the same code, which is itself worth noticing: not every problem has a clever library shortcut.

a small optimisation worth knowing
// Skip lines that cannot possibly help: after moving inwards, any
// wall no taller than the one we just abandoned is useless.
function maxAreaSkipping(height) {
  let left = 0, right = height.length - 1, best = 0;

  while (left < right) {
    const h = Math.min(height[left], height[right]);
    best = Math.max(best, (right - left) * h);

    // walk past every wall that is not taller than the one we just used
    while (left < right && height[left] <= h) left++;
    while (left < right && height[right] <= h) right--;
  }

  return best;
}

console.log(maxAreaSkipping([1, 8, 6, 2, 5, 4, 8, 3, 7]));   // 49
console.log(maxAreaSkipping([4, 3, 2, 1, 4]));               // 16
console.log(maxAreaSkipping([1, 1]));                        // 1

// Still O(n) -- the pointers only move forward -- but on inputs with
// long runs of short walls it does far fewer iterations.
// Do NOT lead with this in an interview. Write the simple version,
// then offer this as a refinement.
Step 8

Complexity, in sentences

SolutionTimeSpace
Every pairO(n²)O(1)
Two pointersO(n)O(1)

O(n) because the two pointers start n - 1 apart and each iteration closes the gap by exactly one, so the loop runs at most n - 1 times. O(1) space because you hold three numbers.

The thing that makes this problem interesting rather than routine is that O(n) requires proving that discarding pairs is safe. Most O(n²)-to-O(n) improvements on this list come from remembering something (a hash map). This one comes from an argument. If you cannot give the argument, you have not solved it — you have recited it.

Say this in the interview

“Start with the widest container, one pointer at each end. The area is limited by the shorter wall, so if I keep the shorter wall and move the taller one inwards, width strictly decreases and height cannot increase — every such pair is worse than the one I just measured. So the shorter wall can be discarded. Moving one pointer per step gives O(n) time and O(1) space.”

Step 9

Mistakes people actually make

1. Moving the taller pointer

Broken — the greedy choice reversed
function broken(height) {
  let l = 0, r = height.length - 1, best = 0;
  while (l < r) {
    best = Math.max(best, (r - l) * Math.min(height[l], height[r]));
    if (height[l] > height[r]) l++;    // moving the TALLER one -- bug
    else r--;
  }
  return best;
}

console.log(broken([1, 8, 6, 2, 5, 4, 8, 3, 7]));   // 8   WRONG, should be 49
console.log(broken([1, 2, 4, 3]));                  // 3   WRONG, should be 4
console.log(broken([4, 3, 2, 1, 4]));               // 16  right, by luck

// Keeping the short wall and shrinking the width can only make things
// worse, so this walks straight past the answer. The direction of that
// single comparison IS the algorithm.

2. Using the average, or the taller wall, as the height

Broken — wrong height
function broken(height) {
  let l = 0, r = height.length - 1, best = 0;
  while (l < r) {
    best = Math.max(best, (r - l) * Math.max(height[l], height[r]));  // max -- bug
    if (height[l] < height[r]) l++; else r--;
  }
  return best;
}

console.log(broken([1, 8, 6, 2, 5, 4, 8, 3, 7]));   // 56   too big
console.log(broken([1, 1]));                        // 1

// Water does not stack above the shorter wall -- it pours out.
// The height of the container is min, never max.

3. Off-by-one in the width

The width is right - left, not right - left + 1. This is the opposite of the sliding-window rule, and it catches people who have just learned that one. The reason: you are measuring the gap between two lines, not counting how many elements are in a range. Two adjacent lines at indexes 3 and 4 have width 1.

4. Writing while (left <= right)

When the pointers meet, left === right, the width is 0, and the area is 0. Harmless for the answer, but it is one wasted iteration and it signals you have not thought about the termination condition. You need two different lines, so left < right.

5. Confusing it with Trapping Rain Water

two different problems, same picture
const h = [1, 8, 6, 2, 5, 4, 8, 3, 7];

// Container With Most Water: pick TWO lines, ignore everything between.
function maxArea(a) {
  let l = 0, r = a.length - 1, best = 0;
  while (l < r) {
    best = Math.max(best, (r - l) * Math.min(a[l], a[r]));
    if (a[l] < a[r]) l++; else r--;
  }
  return best;
}

// Trapping Rain Water: water sits in EVERY dip, and the bars have
// width. Completely different answer.
function trap(a) {
  let l = 0, r = a.length - 1, leftMax = 0, rightMax = 0, total = 0;
  while (l < r) {
    if (a[l] < a[r]) {
      leftMax = Math.max(leftMax, a[l]);
      total += leftMax - a[l];
      l++;
    } else {
      rightMax = Math.max(rightMax, a[r]);
      total += rightMax - a[r];
      r--;
    }
  }
  return total;
}

console.log('container :', maxArea(h));   // 49
console.log('trapped   :', trap(h));      // 19

// Same input, same picture, different question. Read carefully:
// "choose two lines" vs "how much rain collects".
Step 10

Practice before you move on

  1. Say the greedy argument out loud without looking. If you can only say “move the shorter one” and not why, you have memorised it.
  2. Return the two indexes as well as the area, from memory. Watch out for the same trap as Kadane’s: only freeze the indexes when a new best is confirmed.
  3. Trapping Rain Water. The version above is the two-pointer solution; there is also a prefix/suffix-max version that reuses Product of Array Except Self’s idea. Write both and compare.
  4. Largest rectangle with equal-height sides. Change the rule so the container is only valid if both lines are the same height. Does the greedy argument still hold? (It does not — work out why, and what that tells you about greedy proofs.)
  5. Three lines. If you could pick three lines and the water is limited by the shortest, does the two-pointer idea extend? Think about it before coding — the answer is instructive either way.
What to carry forward

Two pointers from the outside in. The pattern applies when you are choosing a pair and you can prove that one candidate is dominated — that no pair involving it can beat what you have already measured. Two Sum on a sorted array uses the same shape with a different argument (too small, raise the low end). Look for a comparison that lets you throw away a whole row of the pair-table in one move.
