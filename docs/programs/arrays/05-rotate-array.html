Arrays · Problem 05

Rotate Array by K

A problem with a trick so odd that it looks like a magic spell: reverse the whole array, then reverse each half. By the end of this page it will not look like magic — it will look inevitable.

Step 1

The problem

Shift every element of the array k places to the right. Anything that falls off the right-hand end wraps around and reappears at the front.

InputkAnswer
[1, 2, 3, 4, 5, 6, 7]3[5, 6, 7, 1, 2, 3, 4]
[1, 2, 3, 4, 5, 6, 7]1[7, 1, 2, 3, 4, 5, 6]
[1, 2, 3, 4]4[1, 2, 3, 4]
[1, 2, 3, 4]6[3, 4, 1, 2]

Look at rows three and four, because they carry the only real edge case in the problem. Rotating a 4-element array by 4 puts everything back exactly where it started. Rotating it by 6 is therefore the same as rotating it by 2. In general:

The first line of your solution

k = k % nums.length;

A full lap changes nothing, so only the remainder matters. Without this line, k = 1000000 either runs a million pointless laps or reads clean off the end of the array. Write it before you write anything else.

One more thing to settle before coding, and it is the kind of question interviewers want you to ask: do I modify the array in place, or return a new one? The classic version says in place. Real codebases usually prefer a new array, because silently mutating your caller’s data causes very hard bugs. Both are below.

Step 2

Think first — the obvious answer

“Rotating by 3” obviously means “rotate by 1, three times”. And rotating by 1 is easy: take the last element off the end and put it at the front.

Version 0 — one step at a time
function rotateOneAtATime(nums, k) {
  k = k % nums.length;

  for (let step = 0; step < k; step++) {
    // take the last element out
    const last = nums[nums.length - 1];

    // shift everything one place to the right, walking backwards
    // (backwards so we do not overwrite a value before we move it)
    for (let i = nums.length - 1; i > 0; i--) {
      nums[i] = nums[i - 1];
    }

    nums[0] = last;    // and the last element becomes the first
  }

  return nums;
}

console.log(rotateOneAtATime([1, 2, 3, 4, 5, 6, 7], 3));   // [5, 6, 7, 1, 2, 3, 4]
console.log(rotateOneAtATime([1, 2, 3, 4], 6));            // [3, 4, 1, 2]
console.log(rotateOneAtATime([1, 2, 3, 4], 4));            // [1, 2, 3, 4]

The inner loop walking backwards matters. Going forwards, nums[1] = nums[0] would destroy nums[1] before you had moved it, and you would end up with the first element smeared across the whole array. Try changing it and running it — the failure is instructive.

Step 3

Why it is slow

The outer loop runs k times and the inner loop runs n times, so it is O(n × k). Since k can be almost as large as n, the worst case is O(n²).

And it is a particularly silly O(n²), because every element gets picked up and put down k separate times on its way to a destination it could have jumped to directly. An element that needs to move three places is moved one place, three times.

Timing demo
const N = 20000;
const base = [];
for (let i = 0; i < N; i++) base.push(i);
const k = 9999;

function oneAtATime(a, k) {
  k %= a.length;
  for (let s = 0; s < k; s++) {
    const last = a[a.length - 1];
    for (let i = a.length - 1; i > 0; i--) a[i] = a[i - 1];
    a[0] = last;
  }
  return a;
}

function reverseTrick(a, k) {
  k %= a.length;
  const rev = (lo, hi) => {
    while (lo < hi) { const t = a[lo]; a[lo] = a[hi]; a[hi] = t; lo++; hi--; }
  };
  rev(0, a.length - 1);
  rev(0, k - 1);
  rev(k, a.length - 1);
  return a;
}

let t = performance.now();
const slow = oneAtATime(base.slice(), k);
const slowMs = performance.now() - t;

t = performance.now();
const fast = reverseTrick(base.slice(), k);
const fastMs = performance.now() - t;

console.log('one at a time : ' + slowMs.toFixed(1) + ' ms');
console.log('three reversals: ' + fastMs.toFixed(2) + ' ms');
console.log('same result:', slow[0] === fast[0] && slow[N - 1] === fast[N - 1]);
console.log('speed-up:', Math.round(slowMs / Math.max(fastMs, 0.01)) + 'x');
Step 4

The better idea — two of them

Idea A: work out where each element lands

Forget shifting. Ask directly: if the element at index i moves k places right, where does it end up? At i + k — and if that runs past the end, it wraps around, which is exactly what % does:

the whole idea in one line
newIndex = (i + k) % n

With [1,2,3,4,5,6,7] and k = 3: the 1 at index 0 goes to index 3, the 5 at index 4 goes to (4+3) % 7 = 0. Check that against the expected answer [5,6,7,1,2,3,4] — the 5 is indeed at the front and the 1 is indeed at index 3.

That gives an O(n) solution immediately, at the cost of a second array to write into. Simple, correct, and the right answer in most real code.

Idea B: the three-reversal trick

To do it in place with no extra array, there is a trick. Watch it happen rather than memorising it. Take [1,2,3,4,5,6,7], k = 3:

start                 1  2  3  4  5  6  7
                      \___________/  \____/
                      the front         the tail that
                      part              must move to the front

step 1: reverse EVERYTHING
                      7  6  5  4  3  2  1
                      \____/  \___________/
                      the 3 that     the rest,
                      belong up      also backwards
                      front -- but
                      backwards

step 2: reverse the first k = 3
                      5  6  7  4  3  2  1
                      \____/
                      fixed

step 3: reverse the rest
                      5  6  7  1  2  3  4
                               \________/
                                        fixed

done.

So why does it work? Because reversing the whole array does exactly one useful thing: it brings the last k elements to the front, which is where they need to be. It also leaves both groups backwards as a side effect — and reversing a group twice puts it back the right way round. Steps 2 and 3 undo that side effect.

The one sentence to remember

Reversing everything moves the right group to the front but scrambles the order within each group. Reversing each group afterwards unscrambles it.

Once you see it as “one move plus two repairs”, it stops being a spell.

Step 5

Dry run — trace the reversals

Reversing in place is itself two pointers walking towards each other and swapping. Trace reverse([7,6,5,4,3,2,1], 0, 2) — step 2 above:

reverse(lo = 0, hi = 2)   on   7  6  5  4  3  2  1
                               ^     ^
lo=0 hi=2   swap 7 and 5  ->   5  6  7  4  3  2  1
lo=1 hi=1   lo is not < hi     STOP

(the middle element never needs to move -- with an odd count
 the two pointers meet on it, with an even count they cross)

And the full run on [1,2,3,4,5,6,7] with k = 3:

k = 3 % 7 = 3

reverse(0, 6):
   swap idx 0,6:   7  2  3  4  5  6  1
   swap idx 1,5:   7  6  3  4  5  2  1
   swap idx 2,4:   7  6  5  4  3  2  1
   idx 3,3 meet -> stop

reverse(0, 2):
   swap idx 0,2:   5  6  7  4  3  2  1
   idx 1,1 meet -> stop

reverse(3, 6):
   swap idx 3,6:   5  6  7  1  3  2  4
   swap idx 4,5:   5  6  7  1  2  3  4
   idx 5,4 crossed -> stop

answer: [5, 6, 7, 1, 2, 3, 4]
the algorithm, narrating itself
function rotateExplained(nums, k) {

Step 6

Version 1 — without built-in methods

No reverse(), no slice, no splice. Swapping by hand with two indexes.

Version 1a — three reversals, in place
function rotateManual(nums, k) {
  const n = nums.length;
  if (n === 0) return nums;

  k = k % n;              // a full lap changes nothing
  if (k === 0) return nums;

  reverseRange(nums, 0, n - 1);   // bring the tail to the front (backwards)
  reverseRange(nums, 0, k - 1);   // repair the first group
  reverseRange(nums, k, n - 1);   // repair the second group

  return nums;
}

function reverseRange(arr, lo, hi) {
  while (lo < hi) {
    const tmp = arr[lo];    // classic three-line swap
    arr[lo] = arr[hi];
    arr[hi] = tmp;
    lo++;
    hi--;
  }
}

console.log(rotateManual([1, 2, 3, 4, 5, 6, 7], 3));   // [5, 6, 7, 1, 2, 3, 4]
console.log(rotateManual([1, 2, 3, 4, 5, 6, 7], 1));   // [7, 1, 2, 3, 4, 5, 6]
console.log(rotateManual([1, 2, 3, 4], 6));            // [3, 4, 1, 2]
console.log(rotateManual([1, 2, 3, 4], 4));            // [1, 2, 3, 4]
console.log(rotateManual([1], 5));                     // [1]
console.log(rotateManual([], 3));                      // []

The if (k === 0) return nums guard is not decoration. With k = 0 the second call would be reverseRange(nums, 0, -1) — which happens to be harmless here because 0 < -1 is false, but relying on that is luck. Handle the trivial case explicitly and you never have to reason about it.

The other approach — a second array

Version 1b — direct placement, no mutation
function rotatedCopy(nums, k) {
  const n = nums.length;
  if (n === 0) return [];

  k = k % n;
  const out = new Array(n);

  for (let i = 0; i < n; i++) {
    out[(i + k) % n] = nums[i];   // "where do I land?" -- computed, not shifted
  }

  return out;
}

const original = [1, 2, 3, 4, 5, 6, 7];
console.log(rotatedCopy(original, 3));   // [5, 6, 7, 1, 2, 3, 4]
console.log(original);                   // [1,2,3,4,5,6,7] -- untouched

// Honest comparison:
//   in place       : O(1) extra space, but mutates the caller's array
//   copy           : O(n) extra space, but the input is safe
// In application code the copy is almost always the better neighbour.
Step 7

Version 2 — with built-in methods

Version 2a — slice and spread
function rotate(nums, k) {
  const n = nums.length;
  if (n === 0) return [];
  k = k % n;
  // the last k elements, then everything before them
  return [...nums.slice(n - k), ...nums.slice(0, n - k)];
}

console.log(rotate([1, 2, 3, 4, 5, 6, 7], 3));   // [5, 6, 7, 1, 2, 3, 4]
console.log(rotate([1, 2, 3, 4], 6));            // [3, 4, 1, 2]
console.log(rotate([1, 2, 3, 4], 4));            // [1, 2, 3, 4]  needs the %
console.log(rotate([1, 2, 3, 4], 0));            // [1, 2, 3, 4]
Why the % n is doubly important here

With k = 4 on a 4-element array and no modulo, slice(n - k) is slice(0) — the whole array — and slice(0, 0) is empty, so you get the right answer by accident. But with k = 6, slice(-2) takes the last two elements (negative indexes count from the end in slice) and slice(0, -2) takes the rest, which gives [3,4,1,2] — also correct, also by accident. With k = 10 on 4 elements it breaks. Do not rely on negative-index coincidences; take the remainder first.

Version 2b — splice, in place
function rotateInPlace(nums, k) {
  const n = nums.length;
  if (n === 0) return nums;
  k = k % n;
  // cut the last k elements out, then put them back at the front
  const tail = nums.splice(n - k, k);
  nums.unshift(...tail);
  return nums;
}

console.log(rotateInPlace([1, 2, 3, 4, 5, 6, 7], 3));   // [5, 6, 7, 1, 2, 3, 4]
console.log(rotateInPlace([1, 2, 3, 4], 6));            // [3, 4, 1, 2]

// Short and readable, and genuinely fine for small arrays.
// Two caveats worth saying out loud:
//   - unshift shifts every element along, so this is O(n) per call
//     internally -- not the O(1)-space win the reversal trick gives
//   - unshift(...tail) spreads the tail into arguments; with a very
//     large k that can blow the argument limit (RangeError).
Version 2c — the built-in reverse
// The three-reversal trick, using Array.prototype.reverse.
// reverse() works on a whole array, so we reverse slices and write back.
function rotateReverse(nums, k) {
  const n = nums.length;
  if (n === 0) return nums;
  k = k % n;
  if (k === 0) return nums;

  nums.reverse();

  const front = nums.slice(0, k).reverse();
  const back  = nums.slice(k).reverse();

  for (let i = 0; i < k; i++) nums[i] = front[i];
  for (let i = k; i < n; i++) nums[i] = back[i - k];

  return nums;
}

console.log(rotateReverse([1, 2, 3, 4, 5, 6, 7], 3));   // [5, 6, 7, 1, 2, 3, 4]

// This makes the point that a built-in is not automatically better:
// slice() allocates two new arrays, so we have lost the O(1) space
// that made the manual version worth writing. Version 1a is the
// better code here, which is not something you can say very often.
Step 8

Complexity, in sentences

SolutionTimeExtra spaceMutates?
One step at a timeO(n × k)O(1)yes
Direct placementO(n)O(n)no
slice + spreadO(n)O(n)no
Three reversalsO(n)O(1)yes

Three reversals is O(n) even though it looks like three passes: the first touches all n elements, the other two touch k and n−k, which together are another n. So 2n operations total, which is O(n). Sequential passes add; they do not multiply.

It is the only version that is both linear and constant-space, which is exactly why the problem is famous. If an interviewer asks for “O(1) space, in place”, this is the answer they are waiting for.

Say this in the interview

“First, k %= n, because a full rotation is a no-op. The easy solution writes each element to (i + k) % n in a new array — O(n) time, O(n) space. For O(1) space in place, reverse the whole array, which brings the last k elements to the front but backwards, then reverse the first k and reverse the remaining n−k to repair the order. O(n) time, O(1) space.”

Step 9

Mistakes people actually make

1. Forgetting k %= n

Broken
function broken(nums, k) {
  const n = nums.length;
  // no modulo
  const rev = (a, lo, hi) => { while (lo < hi) { const t=a[lo]; a[lo]=a[hi]; a[hi]=t; lo++; hi--; } };
  rev(nums, 0, n - 1);
  rev(nums, 0, k - 1);
  rev(nums, k, n - 1);
  return nums;
}

console.log(broken([1, 2, 3, 4], 6));
// [undefined, undefined, 1, 2, 3, 4]   WRONG, should be [3, 4, 1, 2]

// Worse than wrong: the array GREW. rev(0, 5) tried to swap index 0
// with index 5, and writing to index 5 of a 4-element array simply
// creates it. JavaScript never throws for reading past the end -- it
// hands you undefined and carries on. Silent damage beats a crash
// only in the sense that it is harder to find.

2. Rotating left instead of right

the two directions, side by side
const nums = [1, 2, 3, 4, 5];
const k = 2;
const n = nums.length;

const right = [...nums.slice(n - k), ...nums.slice(0, n - k)];
const left  = [...nums.slice(k), ...nums.slice(0, k)];

console.log('rotate RIGHT by 2:', right);   // [4, 5, 1, 2, 3]
console.log('rotate LEFT  by 2:', left);    // [3, 4, 5, 1, 2]

// They are mirror images: rotating right by k is the same as
// rotating left by (n - k). If you ever get the direction wrong,
// that identity is the quickest fix.
console.log('right by 2 === left by 3:',
            JSON.stringify(right) === JSON.stringify([...nums.slice(3), ...nums.slice(0, 3)]));

3. Shifting forwards and smearing the array

Broken — overwrites before moving
function broken(nums) {   // trying to rotate right by 1
  const last = nums[nums.length - 1];
  for (let i = nums.length - 1; i > 0; i--) nums[i] = nums[i - 1];   // correct: backwards
  nums[0] = last;
  return nums;
}

function alsoBroken(nums) {
  const last = nums[nums.length - 1];
  for (let i = 1; i < nums.length; i++) nums[i] = nums[i - 1];       // forwards: BUG
  nums[0] = last;
  return nums;
}

console.log(broken([1, 2, 3, 4, 5]));       // [5, 1, 2, 3, 4]  correct
console.log(alsoBroken([1, 2, 3, 4, 5]));   // [5, 1, 1, 1, 1]  smeared

// Going forwards, nums[1] = nums[0] destroys the 2 before it has
// been copied anywhere, and then that same value propagates right.

4. Mutating the caller’s array by surprise

reverse(), splice(), sort(), push() and unshift() all change the array you pass in. slice(), map(), filter() and concat() return a new one. Rotating a config array in place because you reached for reverse() inside a helper is a genuinely nasty production bug. Decide deliberately which kind of function you are writing, and name it accordingly — rotate versus rotated.

5. Not handling empty or single-element arrays

k % 0 is NaN, and every index comparison against NaN is false, so an empty array tends to silently do nothing rather than crash. That is lucky, not correct. Guard n === 0 explicitly.

Step 10

Practice before you move on

  1. Rotate left by k, without converting it into a right rotation first. (The three reversals still work — just swap which group you cut at.)
  2. Rotate a string. Strings are immutable in JavaScript, so the in-place trick is unavailable. What is the cleanest O(n) way? (Hint: str.slice behaves like the array version.)
  3. Check whether one string is a rotation of another. isRotation("erbottlewat", "waterbottle") should be true. There is a beautiful one-line answer: (a + a).includes(b) when the lengths match. Work out why it is correct before you accept it.
  4. Rotate a matrix 90 degrees. The same “one move plus repairs” shape: transpose the matrix, then reverse each row. Trace it on a 3×3 by hand.
  5. The cyclic-replacement solution. There is a third in-place method that moves each element straight to its final home by following cycles. It is genuinely tricky — the number of cycles is gcd(n, k) — and worth reading once so the reversal trick feels as simple as it is.
What to carry forward

Two things. First, % is how you wrap around: any time a problem talks about circular arrays, clock arithmetic, or round-robin assignment, the modulo operator is doing the work. Second, reversal is a cheap, reusable building block — a surprising number of in-place rearrangement problems reduce to “reverse this range, then reverse those ranges”.
