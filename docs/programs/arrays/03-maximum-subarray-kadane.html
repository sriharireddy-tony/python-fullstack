Arrays · Problem 03

Maximum Subarray — Kadane’s Algorithm

Four lines of code that almost nobody can explain. By the end of this page you will not just be able to write it — you will be able to say why each line is there, which is the only thing an interviewer is actually testing.

Step 1

The problem

Given an array of numbers — some positive, some negative — find the contiguous run of numbers with the largest sum, and return that sum.

“Contiguous” is the whole problem. You must take a solid block, side by side, with no gaps. You cannot cherry-pick the positive numbers and skip the negative ones.

InputAnswerThe winning block
[-2, 1, -3, 4, -1, 2, 1, -5, 4]6[4, -1, 2, 1]
[1]1[1]
[5, 4, -1, 7, 8]23the whole array
[-3, -1, -7]-1[-1]

Study row one. The answer is [4, -1, 2, 1] = 6. Notice that it includes a negative number. Taking the −1 was worth it, because the 2 and the 1 sitting behind it more than paid for it. That is the tension in this problem: sometimes you push through a loss to reach a bigger gain, and sometimes you cut your losses. Kadane’s algorithm is one rule that decides which.

The row that breaks most solutions

[-3, -1, -7] answers -1, not 0. The block must be non-empty — you have to pick at least one number, so you pick the least bad one. Any solution that starts its answer at 0 returns 0 here and is wrong. Test every solution on an all-negative array. Every single one.

Why anyone cares: this is the shape of “the best week of sales in the quarter”, “the worst sustained latency window in the log”, “the most profitable stretch of the trip”. Any time you scan a timeline for its best continuous stretch, this is the algorithm.

Step 2

Think first — the obvious answer

With pen and paper you would try every block and keep the biggest total. A block is defined by where it starts and where it ends, so: two loops to choose the ends, and a third loop to add the block up.

Version 0 — three loops, O(n³)
function maxSubArrayCubic(nums) {
  let best = -Infinity;             // NOT 0 -- the answer can be negative

  for (let start = 0; start < nums.length; start++) {
    for (let end = start; end < nums.length; end++) {

      // add up the block from start to end
      let sum = 0;
      for (let k = start; k <= end; k++) {
        sum += nums[k];
      }

      if (sum > best) best = sum;
    }
  }

  return best;
}

console.log(maxSubArrayCubic([-2, 1, -3, 4, -1, 2, 1, -5, 4]));   // 6
console.log(maxSubArrayCubic([-3, -1, -7]));                      // -1

Now spot the waste, because spotting it is the first real improvement. To total the block [4, -1, 2] the inner loop adds 4, then −1, then 2. To total [4, -1, 2, 1] on the very next round it starts over and adds 4, −1, 2, 1. It just recomputed a sum it had a moment ago.

So drop the third loop and carry the running total as end moves:

Version 0b — two loops, O(n²)
function maxSubArrayQuadratic(nums) {
  let best = -Infinity;

  for (let start = 0; start < nums.length; start++) {
    let sum = 0;                       // fresh total for blocks starting here

    for (let end = start; end < nums.length; end++) {
      sum += nums[end];                // extend by one, no recomputation
      if (sum > best) best = sum;
    }
  }

  return best;
}

console.log(maxSubArrayQuadratic([-2, 1, -3, 4, -1, 2, 1, -5, 4]));   // 6
console.log(maxSubArrayQuadratic([5, 4, -1, 7, 8]));                  // 23

That is already a big win and it is a good thing to reach in an interview before going further. But it still restarts from scratch for every possible starting point, and that is the loop we are about to delete.

Step 3

Why it is slow

Read the 10,000 row across. Cubic is out of reach on any machine. Quadratic finishes but you wait for it. Linear does ten thousand additions and is done before you notice.

Press Run — 20,000 random numbers, quadratic against Kadane’s:

Timing demo
const N = 20000;
const nums = [];
for (let i = 0; i < N; i++) nums.push(Math.floor(Math.random() * 21) - 10);  // -10..10

function quadratic(a) {
  let best = -Infinity;
  for (let s = 0; s < a.length; s++) {
    let sum = 0;
    for (let e = s; e < a.length; e++) {
      sum += a[e];
      if (sum > best) best = sum;
    }
  }
  return best;
}

function kadane(a) {
  let best = a[0], current = a[0];
  for (let i = 1; i < a.length; i++) {
    current = Math.max(a[i], current + a[i]);
    best = Math.max(best, current);
  }
  return best;
}

Step 4

The better idea — derived, not memorised

Here is the move that finds Kadane’s, and it is a move you can use on many problems. Instead of asking the big question, ask a smaller question at every position:

The reframe

Do not ask “what is the best block anywhere?”
Ask, for each position i: “what is the best block that ends exactly at i?”

Why is that smaller question better? Because every block ends somewhere. If I know the best block ending at each of the n positions, the overall answer is just the biggest of those n numbers. I have turned one hard question into n easy ones.

And the easy question has a beautifully short answer. A block that ends at position i must contain nums[i]. There are only two possibilities for what comes before it:

  1. It is glued onto the best block that ended at i - 1.
  2. It is just nums[i] on its own — a fresh start.

There is no third option. So:

the entire algorithm, in one line
bestEndingHere(i) = max( nums[i] ,  nums[i] + bestEndingHere(i - 1) )
                          ^                    ^
                     start fresh          extend the previous block

Notice something: I never have to consider a block ending at i - 1 that was not the best one. If some worse block ended at i - 1, gluing nums[i] onto it gives a worse result than gluing nums[i] onto the best one. The bad options can be thrown away the moment they lose. That is why one number is enough to represent the entire past.

The same rule said in plain English

Rewrite the max slightly. Extending beats starting fresh exactly when nums[i] + previous > nums[i], which is true exactly when previous > 0. So the rule is:

Kadane’s, in one sentence

If the running total behind you is positive, carry it — it is helping. If it is negative, drop it and start fresh from where you stand.

That is genuinely intuitive once you hear it. A negative running total is dead weight: whatever comes next, you are strictly better off without it. It does not matter how negative, and it does not matter what is coming — carrying a −20 into the future can never help you. So you cut it loose.

Back to [-2, 1, -3, 4, -1, 2, 1, -5, 4] and the −1 that ended up inside the answer. When we reach it, the running total is 4 — positive, so it is helping. We carry it, giving 3. Then 2 and 1 build on that 3 and we reach 6. The −1 got included not because it was good, but because the total in front of it was still positive after paying for it.

Step 5

Dry run — trace it by hand

Two variables, and confusing them is the number one bug in this problem:

  • current — the best block ending at the position I am standing on. This goes up and down.
  • best — the best block seen anywhere so far. This never goes down.

nums = [-2, 1, -3, 4, -1, 2, 1, -5, 4]. Both start at nums[0] = -2.

start:   current = -2      best = -2

i=1  value 1
     extend: -2 + 1 = -1        start fresh: 1
     1 is bigger  ->  START FRESH        current = 1
     best = max(-2, 1) = 1               best = 1

i=2  value -3
     extend: 1 + -3 = -2        start fresh: -3
     -2 is bigger ->  EXTEND              current = -2
     best = max(1, -2) = 1               best = 1

i=3  value 4
     extend: -2 + 4 = 2         start fresh: 4
     4 is bigger  ->  START FRESH        current = 4
     best = max(1, 4) = 4                best = 4

i=4  value -1
     extend: 4 + -1 = 3         start fresh: -1
     3 is bigger  ->  EXTEND              current = 3
     best = max(4, 3) = 4                best = 4     <-- best did NOT drop

i=5  value 2
     extend: 3 + 2 = 5          start fresh: 2
     5 is bigger  ->  EXTEND              current = 5
     best = max(4, 5) = 5                best = 5

i=6  value 1
     extend: 5 + 1 = 6          start fresh: 1
     6 is bigger  ->  EXTEND              current = 6
     best = max(5, 6) = 6                best = 6     <-- the answer

i=7  value -5
     extend: 6 + -5 = 1         start fresh: -5
     1 is bigger  ->  EXTEND              current = 1
     best = max(6, 1) = 6                best = 6

i=8  value 4
     extend: 1 + 4 = 5          start fresh: 4
     5 is bigger  ->  EXTEND              current = 5
     best = max(6, 5) = 6                best = 6

answer: 6      (the block [4, -1, 2, 1], found between i=3 and i=6)

Three things to take from that trace:

  • At i=4, current fell from 4 to 3 but best stayed at 4. That is exactly why you need two variables. If you only kept one, the dip would erase the answer you had already earned.
  • At i=1 and i=3 the algorithm chose to start fresh — both times because the running total behind it was negative.
  • The tail [-5, 4] never beat 6, so the answer found at i=6 survived to the end untouched.

Now the all-negative case, nums = [-3, -1, -7]:

start:   current = -3      best = -3

i=1  value -1    extend: -4    fresh: -1    ->  fresh    current = -1   best = -1
i=2  value -7    extend: -8    fresh: -7    ->  fresh    current = -7   best = -1

answer: -1

Every step starts fresh, because the running total is always negative, and the algorithm naturally ends up returning the single largest element. It needs no special case for this — as long as you started best at nums[0] and not at 0.

Press Run and match it line by line against the first trace:

the algorithm, narrating itself
function kadaneExplained(nums) {
  if (nums.length === 0) return 0;

  let current = nums[0];
  let best = nums[0];

  console.log('nums =', nums);
  console.log('start: current = ' + current + '   best = ' + best);
  console.log('');

  for (let i = 1; i < nums.length; i++) {
    const extend = current + nums[i];
    const fresh  = nums[i];
    const choice = extend > fresh ? 'EXTEND     ' : 'START FRESH';

    current = extend > fresh ? extend : fresh;

    const improved = current > best;
    if (improved) best = current;

    console.log(
      'i=' + i + '  value ' + String(nums[i]).padStart(3) +
      '   extend ' + String(extend).padStart(3) +
      '   fresh ' + String(fresh).padStart(3) +
      '   -> ' + choice +
      '   current=' + String(current).padStart(3) +
      '   best=' + String(best).padStart(3) +
      (improved ? '   *new best*' : '')
    );
  }

  console.log('');
  return best;
}

Step 6

Version 1 — without built-in methods

No Math.max, no reduce. Just if. Written this way the two decisions are impossible to miss.

Version 1 — plain ifs
function maxSubArrayManual(nums) {
  if (nums.length === 0) return 0;      // agree with your interviewer on this

  let current = nums[0];   // best block ENDING at the current position
  let best    = nums[0];   // best block seen ANYWHERE so far

  for (let i = 1; i < nums.length; i++) {

    // decision 1: extend the block behind me, or start a new one here?
    const extended = current + nums[i];

    if (extended > nums[i]) {
      current = extended;    // the running total was helping -- keep it
    } else {
      current = nums[i];     // the running total was dead weight -- drop it
    }

    // decision 2: is the block ending here the best I have ever seen?
    if (current > best) {
      best = current;
    }
  }

  return best;
}

console.log(maxSubArrayManual([-2, 1, -3, 4, -1, 2, 1, -5, 4]));   // 6
console.log(maxSubArrayManual([1]));                               // 1
console.log(maxSubArrayManual([5, 4, -1, 7, 8]));                  // 23
console.log(maxSubArrayManual([-3, -1, -7]));                      // -1
console.log(maxSubArrayManual([-1]));                              // -1
console.log(maxSubArrayManual([0, 0, 0]));                         // 0

The if (extended > nums[i]) test can be written the other way round, and you will see both in the wild:

the same decision, said two ways
if (extended > nums[i]) current = extended; else current = nums[i];

// identical, because  current + nums[i] > nums[i]  is true
// exactly when  current > 0 :
if (current > 0) current = current + nums[i]; else current = nums[i];

The second form is the one that reads like the plain-English rule from Step 4: positive total behind me, carry it; otherwise drop it. Use whichever you can explain faster under pressure.

Returning the block itself, not just the sum

“Now tell me which numbers” is the standard follow-up, and it is a small addition: whenever you start fresh, that is a new candidate start; whenever you set a new best, freeze the current start and end.

variation — return the winning block
function maxSubArrayWithRange(nums) {
  if (nums.length === 0) return { sum: 0, start: -1, end: -1, block: [] };

  let current = nums[0];
  let best    = nums[0];

  let candidateStart = 0;   // where the CURRENT block began
  let bestStart = 0;        // where the BEST block began
  let bestEnd = 0;          // where the BEST block ended

  for (let i = 1; i < nums.length; i++) {
    if (current + nums[i] > nums[i]) {
      current = current + nums[i];       // extending: start stays put
    } else {
      current = nums[i];
      candidateStart = i;                // fresh start: the block begins here
    }

    if (current > best) {
      best = current;
      bestStart = candidateStart;        // freeze the winning range
      bestEnd = i;
    }
  }

  return {
    sum: best,
    start: bestStart,
    end: bestEnd,
    block: nums.slice(bestStart, bestEnd + 1)
  };
}

console.log(maxSubArrayWithRange([-2, 1, -3, 4, -1, 2, 1, -5, 4]));
// { sum: 6, start: 3, end: 6, block: [4, -1, 2, 1] }

console.log(maxSubArrayWithRange([-3, -1, -7]));
// { sum: -1, start: 1, end: 1, block: [-1] }

console.log(maxSubArrayWithRange([5, 4, -1, 7, 8]));
// { sum: 23, start: 0, end: 4, block: [5, 4, -1, 7, 8] }

The crucial detail is that candidateStart and bestStart are two different variables. candidateStart moves every time you start fresh, even on blocks that turn out to be rubbish. bestStart only copies it at the moment a new best is confirmed. Use one variable for both and a later fresh start will corrupt the answer you already found.

Step 7

Version 2 — with built-in methods

Version 2a — Math.max
function maxSubArray(nums) {
  let current = nums[0];
  let best    = nums[0];

  for (let i = 1; i < nums.length; i++) {
    current = Math.max(nums[i], current + nums[i]);   // extend or restart
    best    = Math.max(best, current);                // record the high-water mark
  }

  return best;
}

console.log(maxSubArray([-2, 1, -3, 4, -1, 2, 1, -5, 4]));   // 6
console.log(maxSubArray([1]));                               // 1
console.log(maxSubArray([5, 4, -1, 7, 8]));                  // 23
console.log(maxSubArray([-3, -1, -7]));                      // -1

Four lines. This is what people mean by “Kadane’s algorithm”, and it is why so many people can type it without understanding it. You now know that line 1 is the extend-or-restart decision and line 2 is the high-water mark, and that is the difference between reciting and knowing.

Version 2b — reduce
function maxSubArrayReduce(nums) {
  return nums.reduce(
    (state, n) => {
      const current = Math.max(n, state.current + n);
      return { current, best: Math.max(state.best, current) };
    },
    { current: -Infinity, best: -Infinity }
  ).best;
}

console.log(maxSubArrayReduce([-2, 1, -3, 4, -1, 2, 1, -5, 4]));   // 6
console.log(maxSubArrayReduce([-3, -1, -7]));                      // -1

// -Infinity as the seed is what makes the FIRST element behave correctly:
//   Math.max(n, -Infinity + n) = Math.max(n, -Infinity) = n
// so element 0 always starts a fresh block, exactly as it should.
// It also removes the need for a separate nums[0] initialisation.

Two things the reduce version buys you: it needs no nums[0] setup, and it is a clean example of “carry a state object through a fold”. Two things it costs you: an object allocated per element, and a colleague squinting at it. For a linear scan with two variables, the loop is better code. Know both; ship the loop.

Step 8

Complexity, in sentences

SolutionTimeSpaceIn words
Three loopsO(n³)O(1)Every block, re-added from scratch every time.
Two loopsO(n²)O(1)Every block, but the sum carried as the end moves.
Kadane’sO(n)O(1)One pass, two numbers, the past compressed into one running total.

Like the stock problem, this is O(n) time at O(1) space — the good kind of win, where you pay nothing for the speed. Both work for the same underlying reason: everything that happened before position i collapses into a single number that is all your next decision depends on.

The name for this

Kadane’s is the smallest honest example of dynamic programming. The formal version says: dp[i] = max(nums[i], nums[i] + dp[i-1]), and the answer is max(dp). That is literally the line from Step 4. The reason there is no dp array in the final code is that dp[i] only ever reads dp[i-1] — so a whole array collapses into one variable. If you can say that sentence, you can claim dynamic programming on your CV and defend it.

Say this in the interview

“Brute force is O(n²) over all start/end pairs. Instead I compute, for each index, the best subarray ending at that index — which is either the element alone or the element plus the previous best-ending-here. The overall answer is the maximum of those. Since each state only depends on the previous one, I keep two variables instead of an array: O(n) time, O(1) space. I initialise both to nums[0], not 0, so all-negative inputs return the largest element.”

Step 9

Mistakes people actually make

1. Starting at 0 — the classic

Broken
function broken(nums) {
  let current = 0, best = 0;          // bug: both should be nums[0]
  for (const n of nums) {
    current = Math.max(n, current + n);
    best = Math.max(best, current);
  }
  return best;
}

console.log(broken([-2, 1, -3, 4, -1, 2, 1, -5, 4]));   // 6   fine
console.log(broken([5, 4, -1, 7, 8]));                  // 23  fine
console.log(broken([-3, -1, -7]));                      // 0   WRONG, should be -1
console.log(broken([-1]));                              // 0   WRONG, should be -1

// Starting best at 0 secretly allows the EMPTY block, which the
// problem forbids. It passes every test with a positive number in it,
// which is why this bug survives all the way to the interview.

2. Letting best follow current down

Broken — only one variable
function broken(nums) {
  let current = nums[0];
  for (let i = 1; i < nums.length; i++) {
    current = Math.max(nums[i], current + nums[i]);
  }
  return current;                     // returns the block ending at the END
}

console.log(broken([-2, 1, -3, 4, -1, 2, 1, -5, 4]));   // 5   WRONG, should be 6

// It returns the best block ending at the LAST index, not the best
// block anywhere. The answer [4,-1,2,1] ended at index 6 and was
// then trampled by the -5. `best` exists precisely to remember it.

3. Thinking the answer cannot contain a negative number

It very often does. [5, 4, -1, 7, 8] answers 23 — the whole array, −1 included, because the 7 and 8 behind it are worth far more than the 1 it costs. Filtering out the negatives first would give 24 from a block that is not contiguous, which is not a legal answer.

4. Confusing subarray with subsequence

TermMeansFrom [1, -9, 3]
Subarray / substringcontiguous, no gaps[1], [1,-9], [-9,3], [1,-9,3]…
Subsequenceorder kept, gaps allowedalso [1, 3] — skipping the −9
Subsetorder does not matteralso [3, 1]

Maximum subsequence sum is a trivial problem — add up the positives — and if you misread the word you will solve the wrong problem confidently. When a question says “subarray”, say “contiguous” back to the interviewer to confirm.

5. Not agreeing what an empty array returns

There is no correct answer — there is no non-empty block to pick. Some codebases return 0, some return -Infinity, some throw. Ask, then write the guard you agreed on. Silently returning undefined is the only genuinely wrong choice.

Step 10

Practice before you move on

  1. Write the four-line version from memory, then say out loud what each of the two lines inside the loop decides. If you can only do one of those, you have memorised it.
  2. Minimum subarray sum. Swap both Math.max for Math.min. Check it on [2, -5, 1, -3, 4] — you should get −7.
  3. Maximum product subarray. Much harder than it looks: two negatives multiply into a big positive, so the smallest product so far can become the largest one step later. You have to carry both a running max and a running min. Try it before looking it up.
  4. Circular maximum subarray. The array wraps around, so the block may run off the end and continue at the start. Hint: the answer is either a normal Kadane result, or total sum − minimum subarray. Watch the all-negative case, which breaks the second formula.
  5. Longest subarray with sum exactly K. Kadane does not apply. This one needs prefix sums plus a hash map — the Two Sum trick, reappearing. Notice how often it does.
What to carry forward

The move that made this problem easy was not clever code, it was the reframe: replace “find the best thing anywhere” with “find the best thing ending at each position”. Whenever a problem asks for the best contiguous range, try defining the answer at index i in terms of the answer at i - 1. If it works, you get a one-pass solution and a dynamic-programming answer at the same time.
