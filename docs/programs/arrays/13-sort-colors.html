Arrays · Problem 13

Sort Colors

Sort an array containing only 0s, 1s and 2s — in one pass, in place. The solution is called the Dutch national flag algorithm, and it is the clearest example of an invariant doing all the work.

Step 1

The problem

The array contains only the values 0, 1 and 2 — red, white and blue. Sort it so all the 0s come first, then the 1s, then the 2s. Do it in place, and without calling a sort function.

InputAnswer
[2, 0, 2, 1, 1, 0][0, 0, 1, 1, 2, 2]
[2, 0, 1][0, 1, 2]
[0][0]
[2, 2, 2][2, 2, 2]

The name comes from the Dutch flag: three horizontal bands of colour. Edsger Dijkstra posed the problem of partitioning a line of mixed-colour objects into three solid bands with a single pass and no extra memory.

Why anyone cares

This is quicksort’s partition step, generalised. Standard quicksort splits into “less than pivot” and “greater than pivot”, which degrades badly when the array has many duplicates. Three-way partitioning — less, equal, greater — is exactly this algorithm, and it is why production quicksorts handle duplicate-heavy data well.

Step 2

Think first — the obvious answers

Version 0a — count, then rewrite
function sortColorsCounting(nums) {
  let zeros = 0, ones = 0, twos = 0;

  // PASS 1: count how many of each
  for (const n of nums) {
    if (n === 0) zeros++;
    else if (n === 1) ones++;
    else twos++;
  }

  // PASS 2: overwrite the array with that many of each, in order
  let i = 0;
  while (zeros-- > 0) nums[i++] = 0;
  while (ones--  > 0) nums[i++] = 1;
  while (twos--  > 0) nums[i++] = 2;

  return nums;
}

console.log(sortColorsCounting([2, 0, 2, 1, 1, 0]));   // [0,0,1,1,2,2]
console.log(sortColorsCounting([2, 0, 1]));            // [0,1,2]
console.log(sortColorsCounting([2, 2, 2]));            // [2,2,2]

// O(n) time, O(1) space, in place. This is a completely correct
// and genuinely good answer -- it just takes TWO passes.

Do not dismiss counting sort. It is simple, obviously correct, and its two passes are both O(n). The one-pass version below is only better in a narrow sense: when the array is a stream you can only read once, or when you literally cannot afford to touch each element twice.

Version 0b — the library sort
function sortColorsLibrary(nums) {
  return nums.sort((a, b) => a - b);
}

console.log(sortColorsLibrary([2, 0, 2, 1, 1, 0]));   // [0,0,1,1,2,2]

// O(n log n). Correct, and explicitly what the problem forbids.
// Worth saying out loud, then setting aside: "the built-in sort
// works but is n log n, and the problem is asking for linear."
Step 3

Why one pass is worth wanting

Counting sort touches each element twice: once to count, once to write. That is fine for an array in memory. It is not fine when the data arrives from a network socket, a database cursor, or a file you are streaming — there is no second pass to be had.

Timing demo — counting vs one pass vs library sort
const N = 2000000;
const base = [];
for (let i = 0; i < N; i++) base.push(i % 3);

function counting(a) {
  let c0 = 0, c1 = 0, c2 = 0;
  for (let i = 0; i < a.length; i++) {
    if (a[i] === 0) c0++; else if (a[i] === 1) c1++; else c2++;
  }
  let i = 0;
  while (c0-- > 0) a[i++] = 0;
  while (c1-- > 0) a[i++] = 1;
  while (c2-- > 0) a[i++] = 2;
  return a;
}

function dutchFlag(a) {
  let low = 0, mid = 0, high = a.length - 1;
  while (mid <= high) {
    if (a[mid] === 0)      { const t = a[low]; a[low] = a[mid]; a[mid] = t; low++; mid++; }
    else if (a[mid] === 2) { const t = a[high]; a[high] = a[mid]; a[mid] = t; high--; }
    else mid++;
  }
  return a;
}

let t = performance.now();
const a = base.slice().sort((x, y) => x - y);
const sortMs = performance.now() - t;

t = performance.now();
const b = counting(base.slice());
const countMs = performance.now() - t;

t = performance.now();
const c = dutchFlag(base.slice());
const dutchMs = performance.now() - t;

console.log('library sort  :', sortMs.toFixed(1) + ' ms');
console.log('counting sort :', countMs.toFixed(1) + ' ms');
console.log('dutch flag    :', dutchMs.toFixed(1) + ' ms');
console.log('all agree:', a[0] === b[0] && b[0] === c[0] &&
                          a[N-1] === b[N-1] && b[N-1] === c[N-1]);

Notice that counting sort and Dutch flag land close together — both are linear. The library sort is the outlier. That is an honest result and worth internalising: the one-pass version is elegant, not dramatically faster.

Step 4

The better idea — three regions and an invariant

Imagine the array divided into four zones as you work:

  [ 0 0 0 ][ 1 1 1 ][ ? ? ? ? ? ][ 2 2 2 ]
   settled   settled   UNKNOWN     settled
   zeros     ones                  twos
            ^        ^           ^
           low      mid         high

Three pointers hold those boundaries:

  • low — everything before it is a settled 0.
  • mid — the element being examined. Everything between low and mid is a settled 1.
  • high — everything after it is a settled 2.
The invariant — keep this true and the algorithm writes itself

[0, low) is all 0s  ·  [low, mid) is all 1s  ·  [mid, high] is unexamined  ·  (high, end] is all 2s.

Now look at nums[mid]. There are exactly three cases, and each has one forced response:

ValueDoThenWhy
0swap with nums[low]low++, mid++whatever came back from low is a 1 (or is mid itself), already settled — safe to move past
1nothingmid++it is already in the right zone
2swap with nums[high]high-- onlywhat came back from high has never been looked at — you must examine it
The one line everyone gets wrong

On a 2, you advance high but not mid. On a 0, you advance both.

Why the difference? Because low is inside territory you have already swept, so whatever it hands back is known-good. But high is at the edge of the unknown region — the value it hands back could be anything, including another 2. Advancing mid there would leave an unexamined value behind you and break the invariant.

The loop runs while mid <= high. Note the <=: when mid === high there is still one unexamined element sitting there, and skipping it leaves the array wrong.

Step 5

Dry run — trace it by hand

nums = [2, 0, 2, 1, 1, 0]. Start: low = 0, mid = 0, high = 5.

            array              low mid high   action

start   [2, 0, 2, 1, 1, 0]      0   0   5

mid=0, value 2  -> swap with high(5), high--, mid STAYS
        [0, 0, 2, 1, 1, 2]      0   0   4

mid=0, value 0  -> swap with low(0) (itself), low++, mid++
        [0, 0, 2, 1, 1, 2]      1   1   4

mid=1, value 0  -> swap with low(1) (itself), low++, mid++
        [0, 0, 2, 1, 1, 2]      2   2   4

mid=2, value 2  -> swap with high(4), high--, mid STAYS
        [0, 0, 1, 1, 2, 2]      2   2   3

mid=2, value 1  -> leave it, mid++
        [0, 0, 1, 1, 2, 2]      2   3   3

mid=3, value 1  -> leave it, mid++
        [0, 0, 1, 1, 2, 2]      2   4   3

mid(4) > high(3)  -> STOP

answer: [0, 0, 1, 1, 2, 2]

Look at the first two rows. The 2 at index 0 was swapped out, and mid stayed put — and it was right to, because the value that arrived was a 0 that still needed handling. Advancing mid there would have left that 0 stranded in the twos region.

Also count the steps: six elements, seven iterations. Every iteration either advances mid or retreats high, and they can only meet once — that is why this is one pass.

the algorithm, narrating itself
function sortColorsExplained(nums) {
  let low = 0, mid = 0, high = nums.length - 1;

  console.log('start  ' + JSON.stringify(nums) + '   low=0 mid=0 high=' + high);
  console.log('');

  while (mid <= high) {
    const value = nums[mid];

    if (value === 0) {
      const t = nums[low]; nums[low] = nums[mid]; nums[mid] = t;
      low++; mid++;
      console.log('mid value 0  -> swap with low, low++ mid++   ' +
                  JSON.stringify(nums) + '   low=' + low + ' mid=' + mid + ' high=' + high);
    } else if (value === 2) {
      const t = nums[high]; nums[high] = nums[mid]; nums[mid] = t;
      high--;
      console.log('mid value 2  -> swap with high, high-- ONLY  ' +
                  JSON.stringify(nums) + '   low=' + low + ' mid=' + mid + ' high=' + high);
    } else {
      mid++;
      console.log('mid value 1  -> leave it, mid++            ' +
                  JSON.stringify(nums) + '   low=' + low + ' mid=' + mid + ' high=' + high);
    }
  }

  console.log('');
  return nums;
}

Step 6

Version 1 — without built-in methods

Version 1 — Dutch national flag
function sortColorsManual(nums) {
  let low = 0;                    // next slot for a 0
  let mid = 0;                    // the element under inspection
  let high = nums.length - 1;     // next slot for a 2

  // <= not <, or the last unexamined element is skipped
  while (mid <= high) {

    if (nums[mid] === 0) {
      // send it to the zeros region
      const tmp = nums[low];
      nums[low] = nums[mid];
      nums[mid] = tmp;
      low++;
      mid++;              // what came back is known-good, move on

    } else if (nums[mid] === 2) {
      // send it to the twos region
      const tmp = nums[high];
      nums[high] = nums[mid];
      nums[mid] = tmp;
      high--;
      // mid does NOT advance -- the incoming value is unexamined

    } else {
      mid++;              // a 1 is already where it belongs
    }
  }

  return nums;
}

console.log(sortColorsManual([2, 0, 2, 1, 1, 0]));   // [0,0,1,1,2,2]
console.log(sortColorsManual([2, 0, 1]));            // [0,1,2]
console.log(sortColorsManual([0]));                  // [0]
console.log(sortColorsManual([2, 2, 2]));            // [2,2,2]
console.log(sortColorsManual([1, 1, 1]));            // [1,1,1]
console.log(sortColorsManual([2, 1, 0]));            // [0,1,2]
console.log(sortColorsManual([]));                   // []
console.log(sortColorsManual([1, 2, 0, 2, 0, 1, 1, 0, 2]));   // [0,0,0,1,1,1,2,2,2]

Why low can never overtake mid

the invariant, checked at every step
// Assert the four regions after every single iteration.
// If the algorithm is right, this never throws.
function sortColorsChecked(nums) {
  let low = 0, mid = 0, high = nums.length - 1;

  const check = () => {
    for (let i = 0; i < low; i++)
      if (nums[i] !== 0) throw new Error('region [0,low) should be all 0s');
    for (let i = low; i < mid; i++)
      if (nums[i] !== 1) throw new Error('region [low,mid) should be all 1s');
    for (let i = high + 1; i < nums.length; i++)
      if (nums[i] !== 2) throw new Error('region (high,end] should be all 2s');
    if (low > mid) throw new Error('low overtook mid');
  };

  while (mid <= high) {
    if (nums[mid] === 0)      { const t=nums[low]; nums[low]=nums[mid]; nums[mid]=t; low++; mid++; }
    else if (nums[mid] === 2) { const t=nums[high]; nums[high]=nums[mid]; nums[mid]=t; high--; }
    else mid++;
    check();
  }

  return nums;
}

// Try a few hundred random arrays -- the invariant must hold every time
let ok = 0;
for (let trial = 0; trial < 300; trial++) {
  const a = [];
  const len = Math.floor(Math.random() * 12);
  for (let i = 0; i < len; i++) a.push(Math.floor(Math.random() * 3));

  const sorted = sortColorsChecked(a.slice());
  const expected = a.slice().sort((x, y) => x - y);
  if (JSON.stringify(sorted) === JSON.stringify(expected)) ok++;
}

console.log('300 random arrays, invariant held and result correct:', ok + '/300');

Writing the invariant as an assertion and hammering it with random inputs is a genuinely useful habit. It turns “I think this is right” into evidence, and it is how you would debug this algorithm if it were wrong.

Step 7

Version 2 — with built-in methods

Version 2 — destructuring swap
function sortColors(nums) {
  let low = 0, mid = 0, high = nums.length - 1;

  while (mid <= high) {
    if (nums[mid] === 0) {
      [nums[low], nums[mid]] = [nums[mid], nums[low]];   // swap, one line
      low++;
      mid++;
    } else if (nums[mid] === 2) {
      [nums[high], nums[mid]] = [nums[mid], nums[high]];
      high--;
    } else {
      mid++;
    }
  }

  return nums;
}

console.log(sortColors([2, 0, 2, 1, 1, 0]));   // [0,0,1,1,2,2]
console.log(sortColors([2, 0, 1]));            // [0,1,2]
console.log(sortColors([1, 2, 0]));            // [0,1,2]

[a, b] = [b, a] is the array-destructuring swap. It builds a temporary array, so it is very slightly slower than the three-line version with a tmp variable — but it reads better and the difference does not matter outside a hot loop.

The general version: any three-way partition

the pattern, generalised
// Partition around a pivot into less / equal / greater.
// This IS the quicksort partition that handles duplicates well.
function threeWayPartition(arr, pivot, compare = (a, b) => a - b) {
  let low = 0, mid = 0, high = arr.length - 1;

  while (mid <= high) {
    const c = compare(arr[mid], pivot);

    if (c < 0)      { [arr[low], arr[mid]] = [arr[mid], arr[low]]; low++; mid++; }
    else if (c > 0) { [arr[high], arr[mid]] = [arr[mid], arr[high]]; high--; }
    else            { mid++; }
  }

  return { lessEnd: low, greaterStart: high + 1 };
}

const nums = [5, 3, 8, 5, 1, 9, 5, 2];
const bounds = threeWayPartition(nums, 5);
console.log(nums, bounds);
// everything before lessEnd is < 5, everything from greaterStart is > 5

// It also works on objects with a custom comparator:
const people = [
  { name: 'ana', age: 30 }, { name: 'bo', age: 25 },
  { name: 'cy', age: 30 },  { name: 'di', age: 41 }
];
threeWayPartition(people, { age: 30 }, (a, b) => a.age - b.age);
console.log(people.map(p => p.name + ':' + p.age).join('  '));
Step 8

Complexity, in sentences

SolutionTimeSpacePasses
Library sortO(n log n)O(n)—
Counting sortO(n)O(1)two
Dutch flagO(n)O(1)one

Why is one pass O(n) when the loop has no obvious bound? Because the gap high - mid shrinks by exactly one on every single iteration: either mid goes up or high goes down. It starts at n - 1 and the loop stops when it goes negative, so there can be at most n iterations. That is the argument to give — not “it looks linear”.

Counting sort beats it in one respect worth mentioning: it generalises to k distinct values with a counter array, while Dutch flag is specific to three. For four values you would need four pointers and the case analysis gets ugly fast.

Say this in the interview

“Counting sort does it in two passes: count the 0s, 1s and 2s, then overwrite. For one pass I use three pointers — low, mid and high — maintaining the invariant that everything before low is 0, between low and mid is 1, and after high is 2. On a 0 I swap with low and advance both low and mid; on a 2 I swap with high and only decrement high, because the incoming value has not been examined; on a 1 I just advance mid. Each iteration shrinks the unknown region by one, so it is O(n) time and O(1) space.”

Step 9

Mistakes people actually make

1. Advancing mid after swapping with high

Broken — skips an unexamined value
function broken(nums) {
  let low = 0, mid = 0, high = nums.length - 1;
  while (mid <= high) {
    if (nums[mid] === 0)      { [nums[low],nums[mid]]=[nums[mid],nums[low]]; low++; mid++; }
    else if (nums[mid] === 2) { [nums[high],nums[mid]]=[nums[mid],nums[high]]; high--; mid++; }  // mid++ -- bug
    else mid++;
  }
  return nums;
}

console.log(broken([2, 0, 2, 1, 1, 0]));   // [0,0,1,1,2,2]  right, by luck
console.log(broken([2, 2, 0, 1]));         // [1,0,2,2]      WRONG
console.log(broken([2, 0, 2, 0]));         // [0,0,2,2]      right again

// On [2,2,0,1]: mid=0 sees a 2, swaps in the 1 from the end, then
// SKIPS it. That 1 is never examined and stays at index 0.
// A value arriving from the `high` side has never been looked at.

2. Writing while (mid < high)

Broken — misses the last element
function broken(nums) {
  let low = 0, mid = 0, high = nums.length - 1;
  while (mid < high) {          // should be <=
    if (nums[mid] === 0)      { [nums[low],nums[mid]]=[nums[mid],nums[low]]; low++; mid++; }
    else if (nums[mid] === 2) { [nums[high],nums[mid]]=[nums[mid],nums[high]]; high--; }
    else mid++;
  }
  return nums;
}

console.log(broken([2, 0, 2, 1, 1, 0]));   // [0,0,1,1,2,2]  right
console.log(broken([1, 0]));               // [1,0]          WRONG, should be [0,1]
console.log(broken([2, 0]));               // [0,2]          right

// When mid === high there is still ONE unexamined element sitting
// there. Stopping early leaves it wherever it happened to be.

3. Swapping with low but forgetting to advance it

Without low++, the zeros region never grows, so the next 0 swaps into the same slot and overwrites the one before it. The array ends up with the wrong counts entirely — a bug that is obvious the moment you print the array, and invisible if you only check the first element.

4. Assuming the values are always exactly 0, 1, 2

The algorithm has no else for “something else” — a stray 3 would be treated as a 1 and left in the middle. That is correct for this problem’s guarantees, but if you generalise it, use the three-way comparison version from Step 7 rather than equality checks.

5. Returning a new array

The problem says in place. nums.filter(n => n === 0).concat(...) gives the right values in a new array and fails the requirement. If the signature returns void, that is your hint.

Step 10

Practice before you move on

  1. Write both versions from memory — counting sort and Dutch flag — then say which you would ship and why. (Counting sort, usually. It is easier to read and just as fast.)
  2. Sort an array of 0s and 1s only. Two pointers is enough. It is the same algorithm with the middle region deleted, and it is literally Move Zeroes.
  3. Sort by a boolean property. Given objects, move everything where isActive is true to the front, in place. Same partition, different test.
  4. Three-way quicksort. Use the Step 7 partition as the core of a quicksort and compare it against a two-way partition on an array of a million values drawn from ten distinct numbers. The difference is dramatic.
  5. Prove the termination. Write down why the loop cannot run forever, in one sentence, without looking at Step 8. This is the kind of thing an interviewer follows up with.
What to carry forward

State the invariant before you write the loop. This algorithm is almost impossible to derive by guessing at pointer movements, and almost trivial once you have written down what each region is supposed to contain. When a problem involves partitioning an array in place, draw the regions first, decide what must be true of each, and then every branch of the loop body is forced by the requirement to keep that true.
