Arrays · Problem 10

Find the Duplicate Number

Finding the duplicate is easy. The problem is famous because of its constraints: no extra memory, no modifying the array. Those two rules force one of the most surprising tricks in the whole subject — treating the array as a linked list and looking for a loop.

Step 1

The problem

You have n + 1 numbers, and every number is somewhere between 1 and n. So by the pigeonhole principle at least one number must repeat. Find it.

InputnAnswer
[1, 3, 4, 2, 2]42
[3, 1, 3, 4, 2]43
[2, 2, 2, 2, 2]42
[1, 1]11

The three rules that make it interesting:

  • You may not modify the array. So no sorting, no marking visited slots.
  • You may use only O(1) extra space. So no Set, no counting array.
  • There is exactly one repeated value, but it may appear many times — see row three.
Pigeonhole, in one sentence

Five slots, four possible values — at least two slots must hold the same value. That is why the problem can promise a duplicate exists without telling you anything else. It is also the key to the binary-search solution later on.

Be honest about which constraints you are given. In a real codebase you would use a Set and move on. The version below builds up from that, and only pays the price of cleverness once the constraints demand it.

Step 2

Think first — the obvious answers

Version 0a — compare everything to everything
function findDuplicateBrute(nums) {
  for (let i = 0; i < nums.length; i++) {
    for (let j = i + 1; j < nums.length; j++) {
      if (nums[i] === nums[j]) return nums[i];
    }
  }
  return -1;
}

console.log(findDuplicateBrute([1, 3, 4, 2, 2]));   // 2
console.log(findDuplicateBrute([3, 1, 3, 4, 2]));   // 3

// O(n^2) time, O(1) space, does not modify the array.
// It satisfies the constraints! It is just slow.
Version 0b — a Set
function findDuplicateSet(nums) {
  const seen = new Set();
  for (const n of nums) {
    if (seen.has(n)) return n;    // the first value we meet twice
    seen.add(n);
  }
  return -1;
}

console.log(findDuplicateSet([1, 3, 4, 2, 2]));   // 2
console.log(findDuplicateSet([3, 1, 3, 4, 2]));   // 3
console.log(findDuplicateSet([2, 2, 2, 2, 2]));   // 2

// O(n) time -- but O(n) space. This is the version you write at
// work, and the version the constraints are designed to forbid.
Version 0c — sort first
function findDuplicateSort(nums) {
  const s = [...nums].sort((a, b) => a - b);
  for (let i = 1; i < s.length; i++) {
    if (s[i] === s[i - 1]) return s[i];   // duplicates become neighbours
  }
  return -1;
}

console.log(findDuplicateSort([3, 1, 3, 4, 2]));   // 3

// O(n log n) time. Sorting a COPY keeps the original intact, but
// the copy costs O(n) space. Sorting in place would be O(1) space
// but breaks the "do not modify" rule. Either way, one rule loses.

Say all three of these out loud in an interview before reaching for the clever answer. Naming the trade each one makes — time, space, or mutation — is most of the mark.

Timing demo
const N = 20000;
const nums = [];

function brute(a) {
  for (let i = 0; i < a.length; i++)
    for (let j = i + 1; j < a.length; j++)
      if (a[i] === a[j]) return a[i];
  return -1;
}

function floyd(a) {
  let slow = a[0], fast = a[0];
  do { slow = a[slow]; fast = a[a[fast]]; } while (slow !== fast);
  slow = a[0];
  while (slow !== fast) { slow = a[slow]; fast = a[fast]; }
  return slow;
}

Step 4

The better idea — the array is secretly a linked list

Here is the leap. Stop reading the array as a list of values. Read it as a set of arrows: from index i, jump to index nums[i].

The unlock

Every value is between 1 and n, and every index is between 0 and n. So nums[i] is always a valid index. That means you can follow arrows forever without ever falling off the array — you are walking a linked list where nums[i] is the next pointer.

Take [1, 3, 4, 2, 2] and follow the arrows from index 0:

index:  0   1   2   3   4
value:  1   3   4   2   2

start at index 0
  index 0 holds 1  ->  go to index 1
  index 1 holds 3  ->  go to index 3
  index 3 holds 2  ->  go to index 2
  index 2 holds 4  ->  go to index 4
  index 4 holds 2  ->  go to index 2      <-- been here before!
  index 2 holds 4  ->  go to index 4
  index 4 holds 2  ->  go to index 2      round and round

path:   0 -> 1 -> 3 -> 2 -> 4 -> 2 -> 4 -> 2 -> ...
                          \____________/
                           the loop

The walk enters a loop. Why must there be one? Because you can never stop — every step lands on a valid index — and there are only finitely many indexes, so eventually you revisit one. That is a loop, guaranteed.

Now the important part. Where does the loop begin? A loop entrance is an index that two different arrows point at. Two arrows pointing at index d means two positions in the array both hold the value d — which is precisely what “d is the duplicate” means.

The whole reduction

The duplicate value = the index where the cycle starts.

In the trace above the cycle starts at index 2, and 2 is indeed the duplicate. Starting at index 0 is safe, by the way, because no value can ever be 0 — values are 1 to n — so no arrow points back to index 0, and index 0 can never be part of the loop.

Floyd’s tortoise and hare

Finding a cycle’s start with no extra memory is a solved problem. Two walkers:

  1. Phase 1 — meet. slow takes one step at a time, fast takes two. If there is a loop, the fast one laps the slow one and they land on the same index. (They meet somewhere in the loop — not necessarily at its start.)
  2. Phase 2 — find the entrance. Put one walker back at the beginning and leave the other at the meeting point. Now move both one step at a time. Where they meet is the start of the loop.

Phase 2 looks like magic. It is arithmetic. Call the distance from the start to the loop entrance a, the distance from the entrance to the meeting point b, and the remaining loop length c. When they meet, slow has walked a + b and fast has walked exactly twice that. Fast has also gone round the loop some whole number of times, so:

why phase 2 works
2(a + b) = a + b + k(b + c)        k = laps fast made
     a + b = k(b + c)
         a = k(b + c) - b
         a = (k-1)(b + c) + c

read that last line as:
  "walking a steps from the START" lands in the same place as
  "walking c steps from the MEETING POINT, after some whole laps"

which is exactly the loop entrance.

You do not have to reproduce that derivation under pressure. You do have to be able to say “the distance from the head to the entrance equals the distance from the meeting point to the entrance, so two one-step walkers converge there”.

Step 6

Version 1 — without built-in methods

Version 1 — Floyd’s cycle detection
function findDuplicateManual(nums) {
  // Index 0 is the head of the list. Both walkers start there.
  let slow = 0;
  let fast = 0;

  // PHASE 1: take a step BEFORE testing (do/while), otherwise the
  // test slow !== fast is false immediately and the loop never runs.
  do {
    slow = nums[slow];          // one step
    fast = nums[nums[fast]];    // two steps
  } while (slow !== fast);

  // PHASE 2: one walker back to the head, both now move ONE step.
  // Where they meet is the entrance of the cycle.
  slow = 0;

  while (slow !== fast) {
    slow = nums[slow];
    fast = nums[fast];
  }

  return slow;
}

console.log(findDuplicateManual([1, 3, 4, 2, 2]));      // 2
console.log(findDuplicateManual([3, 1, 3, 4, 2]));      // 3
console.log(findDuplicateManual([2, 2, 2, 2, 2]));      // 2
console.log(findDuplicateManual([1, 1]));               // 1
console.log(findDuplicateManual([1, 4, 6, 6, 6, 2, 3]));// 6

// The array is never touched, and we hold exactly two numbers.
// O(n) time, O(1) space, no mutation -- all three rules satisfied.
Why the loop starts after one step

Both walkers start at index 0, which means they are already equal — so a plain while (slow !== fast) would never run even once. That is why phase 1 is a do ... while: it takes a step before testing. The alternative is to pre-advance them by hand, but then you must advance them by exactly one and two steps respectively, keeping fast at precisely double slow’s distance from the head. Get that wrong and phase 2 never converges — it spins forever. The do ... while is safer because it makes the two speeds impossible to desynchronise.

The binary-search alternative

There is a second solution that satisfies the same constraints and is much easier to justify on the spot. It binary-searches over the value range, not the array.

Version 1b — binary search on the answer
function findDuplicateBinary(nums) {
  let low = 1;
  let high = nums.length - 1;      // values run 1..n

  while (low < high) {
    const mid = Math.floor((low + high) / 2);

    // how many values are <= mid?
    let count = 0;
    for (let i = 0; i < nums.length; i++) {
      if (nums[i] <= mid) count++;
    }

    // If there are more than `mid` values in the range 1..mid,
    // pigeonhole says the duplicate is in 1..mid.
    if (count > mid) {
      high = mid;
    } else {
      low = mid + 1;
    }
  }

  return low;
}

console.log(findDuplicateBinary([1, 3, 4, 2, 2]));       // 2
console.log(findDuplicateBinary([3, 1, 3, 4, 2]));       // 3
console.log(findDuplicateBinary([2, 2, 2, 2, 2]));       // 2
console.log(findDuplicateBinary([1, 4, 6, 6, 6, 2, 3])); // 6

// O(n log n) time, O(1) space, no mutation.
// Slower than Floyd's, but you can EXPLAIN it in one sentence:
// "count how many values fall in the lower half; if that count
//  exceeds the size of the half, the duplicate is in there."

If you can only remember one, remember this one. It is a genuinely good answer, and being able to derive it beats half-remembering Floyd’s and getting phase 2 wrong.

Step 7

Version 2 — with built-in methods

Version 2 — when the constraints are lifted
// The honest production answer, if nobody forbids extra memory.
function findDuplicate(nums) {
  const seen = new Set();
  for (const n of nums) {
    if (seen.has(n)) return n;
    seen.add(n);
  }
  return -1;
}

console.log(findDuplicate([1, 3, 4, 2, 2]));   // 2

// Find EVERY duplicate, not just one:
function allDuplicates(nums) {
  const counts = new Map();
  for (const n of nums) counts.set(n, (counts.get(n) || 0) + 1);
  return [...counts].filter(([, c]) => c > 1).map(([v]) => v);
}

console.log(allDuplicates([1, 2, 2, 3, 3, 3, 4]));   // [2, 3]

// The shortest possible check for "does this array have duplicates?"
function hasDuplicates(nums) {
  return new Set(nums).size !== nums.length;
}

console.log(hasDuplicates([1, 2, 3]));      // false
console.log(hasDuplicates([1, 2, 2]));      // true
Do not skip the easy answer to look clever

If an interviewer does not state the O(1)-space rule, write the Set version, say “O(n) time, O(n) space”, and then offer: “if you want constant space without modifying the array, I can do binary search on the value range, or Floyd’s cycle detection”. Leading with the clever version and fumbling it is a much worse outcome than leading with the simple one.

The solution that breaks the rules — and is fine when it does not

index marking — O(1) space, but mutates
// If you ARE allowed to modify the array, this is the neatest trick:
// use the sign of nums[v] as a "have I seen value v?" flag.
function findDuplicateMarking(nums) {
  for (let i = 0; i < nums.length; i++) {
    const value = Math.abs(nums[i]);

    if (nums[value] < 0) {
      return value;            // already flagged -> we have seen it before
    }

    nums[value] = -nums[value];  // flag it by flipping the sign
  }
  return -1;
}

const arr = [1, 3, 4, 2, 2];
console.log(findDuplicateMarking(arr));   // 2
console.log('array afterwards:', arr);    // signs flipped -- destroyed

// O(n) time, O(1) space -- but the input is wrecked. You can restore
// it with a second pass of Math.abs, which is a good thing to offer.
Step 8

Complexity, in sentences

SolutionTimeSpaceModifies?
Nested loopsO(n²)O(1)no
SetO(n)O(n)no
Binary search on valueO(n log n)O(1)no
Sign markingO(n)O(1)yes
Floyd’s cycleO(n)O(1)no

Only the last row hits all three targets at once, which is why it is the “official” answer. But look at the table honestly: binary search is O(n log n) with the same guarantees and is far easier to derive on the spot. On any realistic input size the difference is invisible.

Floyd’s is O(n) because each phase walks at most a constant multiple of the list length, and the two phases run one after the other — sequential passes add.

Say this in the interview

“Since every value is a valid index, I can read the array as a linked list where nums[i] points to index nums[i]. A duplicate value means two indexes point at the same place, so the list has a cycle, and the cycle’s entrance is the duplicate. Floyd’s algorithm finds it: move a slow and a fast pointer until they meet, then restart one from the head and advance both by one until they meet again. O(n) time, O(1) space, and the array is untouched.”

Step 9

Mistakes people actually make

1. Returning the meeting point from phase 1

Broken — stops halfway
function broken(nums) {
  let slow = 0, fast = 0;
  do {
    slow = nums[slow];
    fast = nums[nums[fast]];
  } while (slow !== fast);
  return slow;          // phase 2 missing -- bug
}

console.log(broken([1, 3, 4, 2, 2]));   // 4   WRONG, should be 2
console.log(broken([3, 1, 3, 4, 2]));   // 2   WRONG, should be 3

// Phase 1 only proves a cycle EXISTS and finds SOME point inside it.
// The entrance -- the duplicate -- needs phase 2.

2. Starting both pointers at the same place with a plain while

Broken — the loop never runs
function broken(nums) {
  let slow = 0, fast = 0;
  while (slow !== fast) {        // 0 !== 0 is false -- never entered
    slow = nums[slow];
    fast = nums[nums[fast]];
  }
  slow = 0;
  while (slow !== fast) { slow = nums[slow]; fast = nums[fast]; }
  return slow;
}

console.log(broken([1, 3, 4, 2, 2]));   // 0   WRONG

// Fix it either by taking one step before the test:
function fixed(nums) {
  let slow = 0, fast = 0;
  do { slow = nums[slow]; fast = nums[nums[fast]]; } while (slow !== fast);
  slow = 0;
  while (slow !== fast) { slow = nums[slow]; fast = nums[fast]; }
  return slow;
}
console.log(fixed([1, 3, 4, 2, 2]));    // 2

3. Moving both pointers at two steps in phase 2

Phase 2 requires both walkers to move one step. The whole arithmetic in Step 4 depends on equal speeds. Keeping fast = nums[nums[fast]] in phase 2 is a copy-paste slip that produces a wrong answer on most inputs.

4. Confusing indexes with values

In this problem the two are deliberately blurred, which is exactly what makes it confusing. Say it slowly: slow holds an index; the step slow = nums[slow] reads the value there and uses it as the next index; and the final answer is an index that happens to equal the duplicate value. Writing nums[slow] at the end instead of slow gives a plausible wrong number.

5. Assuming the duplicate appears exactly twice

[2,2,2,2,2] is legal. Solutions that count occurrences and look for exactly 2 fail here. All the solutions on this page handle it, but check any solution you write against this input.

Step 10

Practice before you move on

  1. Write the binary-search version from memory. It is the one you are most likely to be able to reconstruct under pressure, and it is a complete answer.
  2. Find the missing number. An array of n distinct numbers from 0 to n with one missing. Sum 0..n and subtract the actual sum — O(n) time, O(1) space, one line. Then do it again with XOR and explain why that avoids overflow.
  3. Find both the duplicate and the missing number. Numbers 1..n where one value replaced another. Two equations, two unknowns — or the sign-marking trick.
  4. Set Mismatch and First Missing Positive. Both use index marking, and First Missing Positive is the hardest of this family: put each value at its own index by swapping, then scan for the first index that is wrong.
  5. Linked List Cycle II. Floyd’s on an actual linked list. Once you have seen it there, this page’s trick looks obvious, because it is that problem in disguise.
What to carry forward

Two ideas. First, an array of valid indexes is a graph — when values happen to be in the range of the indexes, following them is a legal walk, and graph tools like cycle detection become available. Second, you can binary-search the answer, not just the array: if you can cheaply test “is the answer at most X?”, you can halve the range of possible answers. That trick shows up in a lot of hard problems.
