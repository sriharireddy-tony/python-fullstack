Searching & sorting · Problem 06

Merge Sort & Quick Sort

Two divide-and-conquer sorts that split the work in opposite orders. Merge sort splits blindly and does the work while combining. Quick sort does the work while splitting and combines for free. That one sentence explains every difference between them.

Step 1

The problem

Sort an array, from scratch, in O(n log n). Two classic algorithms, both recursive, both divide and conquer.

Merge sortQuick sort
Splitalways down the middlearound a pivot value
Combinemerge two sorted halvesnothing to do
TimeO(n log n) alwaysO(n log n) average, O(n²) worst
SpaceO(n)O(log n) stack
Stableyesno
The one-sentence difference

Merge sort splits the array in half without looking at the values — so the split is free, and all the real work happens in the merge.

Quick sort partitions so that everything on the left is smaller than everything on the right — so the split does all the work, and once both sides are sorted there is nothing left to combine.

Every trade-off in the table follows from that.

Why write them by hand when .sort() exists? Because the two techniques — recursive halving, and partitioning — reappear constantly. Quickselect is quick sort’s partition. Counting inversions is merge sort’s merge. The sorts are the clearest place to learn both.

Step 2

Think first — the sorts you can derive yourself

Version 0 — the O(n²) sorts
// Bubble sort: repeatedly swap neighbours that are out of order.
function bubbleSort(a) {
  const arr = [...a];
  for (let pass = 0; pass < arr.length - 1; pass++) {
    let swapped = false;
    // after `pass` rounds the last `pass` elements are settled
    for (let i = 0; i < arr.length - 1 - pass; i++) {
      if (arr[i] > arr[i + 1]) {
        [arr[i], arr[i + 1]] = [arr[i + 1], arr[i]];
        swapped = true;
      }
    }
    if (!swapped) break;          // already sorted -- stop early
  }
  return arr;
}

// Selection sort: find the smallest remaining, swap it into place.
function selectionSort(a) {
  const arr = [...a];
  for (let i = 0; i < arr.length - 1; i++) {
    let min = i;
    for (let j = i + 1; j < arr.length; j++) {
      if (arr[j] < arr[min]) min = j;
    }
    if (min !== i) [arr[i], arr[min]] = [arr[min], arr[i]];
  }
  return arr;
}

// Insertion sort: take each element and slide it back into place.
function insertionSort(a) {
  const arr = [...a];
  for (let i = 1; i < arr.length; i++) {
    const value = arr[i];
    let j = i - 1;
    while (j >= 0 && arr[j] > value) {
      arr[j + 1] = arr[j];
      j--;
    }
    arr[j + 1] = value;
  }
  return arr;
}

All three are O(n²), and insertion sort deserves respect: it is O(n) on already-sorted input, and it is genuinely the fastest option for small arrays. Real library sorts use it for subarrays under about sixteen elements.

function insertionSort(a) {
  const arr = [...a];
  for (let i = 1; i < arr.length; i++) {
    const v = arr[i];
    let j = i - 1;
    while (j >= 0 && arr[j] > v) { arr[j + 1] = arr[j]; j--; }
    arr[j + 1] = v;

function mergeSort(a) {
  if (a.length <= 1) return a;
  const mid = a.length >> 1;
  const left = mergeSort(a.slice(0, mid));
  const right = mergeSort(a.slice(mid));
  const out = [];
  let i = 0, j = 0;
  while (i < left.length && j < right.length) {
    out.push(left[i] <= right[j] ? left[i++] : right[j++]);
  }
  while (i < left.length) out.push(left[i++]);
  while (j < right.length) out.push(right[j++]);
  return out;
}

function quickSort(a, lo = 0, hi = a.length - 1) {
  if (lo >= hi) return a;
  const pivot = a[lo + ((Math.random() * (hi - lo + 1)) | 0)];
  let i = lo, m = lo, j = hi;
  while (m <= j) {
    if (a[m] < pivot) { [a[i], a[m]] = [a[m], a[i]]; i++; m++; }
    else if (a[m] > pivot) { [a[j], a[m]] = [a[m], a[j]]; j--; }
    else m++;
  }
  quickSort(a, lo, i - 1);
  quickSort(a, j + 1, hi);
  return a;
}

Step 4

The better ideas — two shapes of divide and conquer

Merge sort: split blindly, work on the way up

The unlock

An array of one element is already sorted. So: split in half, sort each half recursively, then merge the two sorted halves — which is the linear two-pointer merge from the previous page.

              [5, 2, 9, 1]
             /            \
        [5, 2]            [9, 1]        split -- no comparisons
        /    \            /    \
     [5]     [2]       [9]     [1]      base case: length 1
        \    /            \    /
        [2, 5]            [1, 9]        merge
             \            /
              [1, 2, 5, 9]              merge

  log n levels of splitting, and each level merges n elements.
  n per level x log n levels = O(n log n).

Quick sort: work on the way down, nothing on the way up

The unlock

Pick a pivot and partition: rearrange so everything smaller sits left of it and everything larger sits right. The pivot is now in its final position. Sort each side recursively — and there is no combine step, because the sides are already in the right places.

  [5, 2, 9, 1]     pivot 5

  partition:  [2, 1 | 5 | 9]
               \___/       \_/
             sort these   sort this
             recursively  recursively

  [2, 1]  pivot 2  ->  [1 | 2]
  [9]     already done

  result: [1, 2, 5, 9]     no merging anywhere
The pivot decides everything

A pivot near the median splits the array in half: log n levels, O(n log n).

A pivot that is the smallest or largest element peels off one element per level: n levels, O(n²). And with a fixed pivot such as “the last element”, an already-sorted array hits that worst case every single time — which is the input you are most likely to be handed in practice.

Pick the pivot at random. It is not an optimisation.

The trade-off, stated plainly

Merge sortQuick sort
Worst caseO(n log n) — guaranteedO(n²) — rare with a random pivot
Extra memoryO(n) for the merge buffersO(log n) for the call stack
Stabilitystable — ties keep their ordernot stable — swaps move ties
Cache behaviourworse — copies between arraysbetter — swaps in place
Good forlinked lists, external sorting, stabilityarrays in memory, speed

function mergeSortManual(input) {
  // copy so the caller's array is untouched
  const a = [];
  for (let i = 0; i < input.length; i++) a[i] = input[i];

  // a scratch buffer, allocated ONCE and reused at every level
  const buffer = [];
  for (let i = 0; i < a.length; i++) buffer[i] = 0;

  function sortRange(lo, hi) {
    if (hi - lo < 1) return;                 // 0 or 1 element: sorted

    const mid = lo + ((hi - lo) - ((hi - lo) % 2)) / 2;

    sortRange(lo, mid);
    sortRange(mid + 1, hi);
    mergeRange(lo, mid, hi);
  }

  function mergeRange(lo, mid, hi) {
    let i = lo;          // walks the left half
    let j = mid + 1;     // walks the right half
    let k = lo;          // walks the buffer

    while (i <= mid && j <= hi) {
      if (a[i] <= a[j]) {        // <= keeps it STABLE
        buffer[k] = a[i];
        i = i + 1;
      } else {
        buffer[k] = a[j];
        j = j + 1;
      }
      k = k + 1;
    }

    while (i <= mid) { buffer[k] = a[i]; i = i + 1; k = k + 1; }
    while (j <= hi)  { buffer[k] = a[j]; j = j + 1; k = k + 1; }

    // copy the merged range back
    for (let x = lo; x <= hi; x++) a[x] = buffer[x];
  }

  sortRange(0, a.length - 1);
  return a;
}

Version 1b — quick sort, in place
function quickSortManual(input) {
  const a = [];
  for (let i = 0; i < input.length; i++) a[i] = input[i];

  function swap(x, y) {
    const t = a[x]; a[x] = a[y]; a[y] = t;
  }

  function sortRange(lo, hi) {
    // insertion sort is faster on tiny ranges -- what real
    // libraries do, and it also caps the recursion depth
    if (hi - lo < 10) {
      for (let i = lo + 1; i <= hi; i++) {
        const v = a[i];
        let j = i - 1;
        while (j >= lo && a[j] > v) { a[j + 1] = a[j]; j = j - 1; }
        a[j + 1] = v;
      }
      return;
    }

    // RANDOM pivot -- a fixed one is O(n^2) on sorted input
    const pivotIndex = lo + ((Math.random() * (hi - lo + 1)) | 0);
    const pivot = a[pivotIndex];

    // three-way partition: less | equal | greater
    let i = lo;      // end of the "less" block
    let m = lo;      // the scanner
    let j = hi;      // start of the "greater" block

    while (m <= j) {
      if (a[m] < pivot)      { swap(i, m); i = i + 1; m = m + 1; }
      else if (a[m] > pivot) { swap(j, m); j = j - 1; }
      else                   { m = m + 1; }
    }

    // [lo..i-1] < pivot,  [i..j] === pivot,  [j+1..hi] > pivot
    // the equal block is already final -- never recurse into it
    sortRange(lo, i - 1);
    sortRange(j + 1, hi);
  }

  sortRange(0, a.length - 1);
  return a;
}

// Merge sort: the shortest correct version.
function mergeSort(a) {
  if (a.length <= 1) return a;

  const mid = Math.floor(a.length / 2);
  const left = mergeSort(a.slice(0, mid));
  const right = mergeSort(a.slice(mid));

  const out = [];
  let i = 0, j = 0;
  while (i < left.length && j < right.length) {
    out.push(left[i] <= right[j] ? left[i++] : right[j++]);
  }

  return out.concat(left.slice(i), right.slice(j));
}

what the merge step buys you elsewhere
// Counting inversions: how many pairs are out of order?
// Brute force is O(n^2). Merge sort counts them for free, because
// every time you take from the RIGHT half, it jumps over everything
// left in the LEFT half -- and each of those is an inversion.
function countInversions(a) {
  let inversions = 0;

  function sort(arr) {
    if (arr.length <= 1) return arr;
    const mid = arr.length >> 1;
    const l = sort(arr.slice(0, mid));
    const r = sort(arr.slice(mid));

    const out = [];
    let i = 0, j = 0;
    while (i < l.length && j < r.length) {
      if (l[i] <= r[j]) {
        out.push(l[i++]);
      } else {
        inversions += l.length - i;      // the whole rest of the left half
        out.push(r[j++]);
      }
    }
    return out.concat(l.slice(i), r.slice(j));
  }

  sort(a);
  return inversions;
}

function countBrute(a) {
  let n = 0;
  for (let i = 0; i < a.length; i++)
    for (let j = i + 1; j < a.length; j++)
      if (a[i] > a[j]) n++;
  return n;
}

const t = [2, 4, 1, 3, 5];
console.log('inversions (merge):', countInversions(t));   // 3
console.log('inversions (brute):', countBrute(t));        // 3

const sortedAsc = [1,2,3,4,5];
console.log('sorted ascending  :', countInversions(sortedAsc));    // 0
const reversed = [5,4,3,2,1];
console.log('fully reversed    :', countInversions(reversed));     // 10

Step 8

Complexity, in sentences

AlgorithmBestAverageWorstSpaceStable
BubbleO(n)O(n²)O(n²)O(1)yes
SelectionO(n²)O(n²)O(n²)O(1)no
InsertionO(n)O(n²)O(n²)O(1)yes
MergeO(n log n)O(n log n)O(n log n)O(n)yes
QuickO(n log n)O(n log n)O(n²)O(log n)no

Why merge sort is always O(n log n): the split is blind, so the depth is always exactly log n regardless of the data, and each level merges every element once. There is no bad input.

Why quick sort can be O(n²): the depth depends on the pivots. Good pivots halve the range and give log n levels; a worst-case pivot removes one element and gives n levels. Random pivoting makes a bad run astronomically unlikely, but the bound is still there.

The O(n log n) floor. Any sort that only compares elements needs at least about n log n comparisons — there are n! possible orderings and each comparison at best halves the possibilities. That is why counting sort and bucket sort can beat it: they do not compare, they index.

Say this in the interview

“Merge sort splits blindly in half, recurses, then merges two sorted halves with two pointers — guaranteed O(n log n) and stable, at the cost of O(n) buffer space. Quick sort partitions around a pivot so the pivot lands in its final position, then recurses into each side with nothing to combine — O(n log n) average, in place, but O(n²) if the pivots are consistently bad, so I choose the pivot randomly. I would use a three-way partition so duplicate-heavy input does not degrade, and switch to insertion sort on small subarrays.”

1. Quick sort with a fixed pivot

let depth = 0, maxDepth = 0;

function fixedPivotQuickSort(a, lo = 0, hi = a.length - 1) {
  if (lo >= hi) return a;

  depth++;
  if (depth > maxDepth) maxDepth = depth;

  const pivot = a[hi];                 // ALWAYS the last element
  let i = lo;
  for (let j = lo; j < hi; j++) {
    if (a[j] < pivot) { [a[i], a[j]] = [a[j], a[i]]; i++; }
  }
  [a[i], a[hi]] = [a[hi], a[i]];

  fixedPivotQuickSort(a, lo, i - 1);
  fixedPivotQuickSort(a, i + 1, hi);
  depth--;
  return a;
}

for (let i = 0; i < N; i++) sorted.push(i);
depth = 0; maxDepth = 0;

3. Losing stability in merge sort with <

Broken — one character breaks stability
function stableMerge(a, keyOf) {
  if (a.length <= 1) return a;
  const mid = a.length >> 1;
  const l = stableMerge(a.slice(0, mid), keyOf), r = stableMerge(a.slice(mid), keyOf);
  const out = [];
  let i = 0, j = 0;
  while (i < l.length && j < r.length) {
    out.push(keyOf(l[i]) <= keyOf(r[j]) ? l[i++] : r[j++]);   // <=
  }
  return out.concat(l.slice(i), r.slice(j));
}

function unstableMerge(a, keyOf) {
  if (a.length <= 1) return a;
  const mid = a.length >> 1;
  const l = unstableMerge(a.slice(0, mid), keyOf), r = unstableMerge(a.slice(mid), keyOf);
  const out = [];
  let i = 0, j = 0;

4. Two-way partition on duplicate-heavy data

Broken — all-equal values degrade
let twoWayDepth = 0, twoWayMax = 0;

function twoWayQuickSort(a, lo = 0, hi = a.length - 1) {
  if (lo >= hi) return a;
  twoWayDepth++;
  if (twoWayDepth > twoWayMax) twoWayMax = twoWayDepth;

  const pivot = a[lo + ((Math.random() * (hi - lo + 1)) | 0)];
  let i = lo, j = hi;
  while (i <= j) {
    while (a[i] < pivot) i++;
    while (a[j] > pivot) j--;
    if (i <= j) { [a[i], a[j]] = [a[j], a[i]]; i++; j--; }
  }
  twoWayQuickSort(a, lo, j);
  twoWayQuickSort(a, i, hi);
  twoWayDepth--;
  return a;
}

function threeWayQuickSort(a, lo = 0, hi = a.length - 1) {
  if (lo >= hi) return a;
  const pivot = a[lo + ((Math.random() * (hi - lo + 1)) | 0)];
  let i = lo, m = lo, j = hi;
  while (m <= j) {
    if (a[m] < pivot) { [a[i],a[m]]=[a[m],a[i]]; i++; m++; }
    else if (a[m] > pivot) { [a[j],a[m]]=[a[m],a[j]]; j--; }
    else m++;
  }
  threeWayQuickSort(a, lo, i - 1);
  threeWayQuickSort(a, j + 1, hi);
  return a;
}

// only THREE distinct values, repeated many times
const N = 200000;
const dup = [];
for (let i = 0; i < N; i++) dup.push(i % 3);

twoWayDepth = 0; twoWayMax = 0;
let t = performance.now();
twoWayQuickSort([...dup]);
console.log('two-way   : ' + (performance.now() - t).toFixed(1) +
            ' ms,  depth ' + twoWayMax);

t = performance.now();
threeWayQuickSort([...dup]);
console.log('three-way : ' + (performance.now() - t).toFixed(1) + ' ms');

console.log('values. Three-way puts them all in the middle and never');

5. Claiming merge sort is O(1) space

It is not. The merge needs somewhere to build the combined result, and that is O(n). There are in-place merge sorts, but they are complicated and slower in practice — nobody uses them. If you are asked for a sort with O(1) extra space and a guaranteed O(n log n), the answer is heap sort, not merge sort.

Step 10

Practice before you move on

  1. Write merge sort from memory, base case first. Then say why it is always O(n log n) and always stable.
  2. Write quick sort from memory with a random pivot and a three-way partition. Then say what happens with a fixed pivot on sorted input.
  3. Count inversions. In Step 7 — one extra line inside the merge, and it turns an O(n²) problem into O(n log n).
  4. Heap sort. The third O(n log n) sort: build a max-heap, then repeatedly swap the root to the end and sift down. O(1) extra space, not stable. You already wrote the heap in the Kth Largest page.
  5. Sort a linked list. Merge sort is the natural choice, because splitting and merging need no random access — and quick sort’s partition does. That is the clearest illustration of why both algorithms still exist.
What to carry forward

Divide and conquer has two shapes, and you choose where the work goes. Split cheaply and pay on the way up (merge sort), or pay on the way down and get the combine for free (quick sort). Recognising which shape a problem wants is worth more than either algorithm: the merge step gives you inversion counting and k-way merging, and the partition step gives you quickselect and the Dutch national flag.
