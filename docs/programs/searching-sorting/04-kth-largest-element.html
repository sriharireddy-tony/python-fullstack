Searching & sorting · Problem 04

Kth Largest Element

Three genuinely different answers, and the interview is mostly about choosing between them: sort it (simplest), a size-k heap (best for streams), or quickselect (best average time). Knowing when each wins matters more than any one of them.

Step 1

The problem

Return the kth largest element in an unsorted array. Note: the kth largest value by position in sorted order, not the kth distinct value.

InputkAnswerSorted descending
[3,2,1,5,6,4]256,5,4,3,2,1
[3,2,3,1,2,4,5,5,6]446,5,5,4,3,...
[1]11
[7,7,7]277,7,7
Duplicates count — ask about this

In row two the two 5s occupy positions 2 and 3, so the 4th largest is 4. If the question wanted the 4th distinct value it would be 3. These are different problems and the wording is often ambiguous — clarify before coding.

Row four makes it stark: the 2nd largest of [7,7,7] is 7. There is no 2nd distinct value at all.

Step 2

Think first — sort it

Version 0 — sort and index
function kthLargestSort(nums, k) {
  const sorted = [...nums].sort((a, b) => b - a);   // descending
  return sorted[k - 1];
}

console.log(kthLargestSort([3,2,1,5,6,4], 2));          // 5
console.log(kthLargestSort([3,2,3,1,2,4,5,5,6], 4));    // 4
console.log(kthLargestSort([1], 1));                    // 1
console.log(kthLargestSort([7,7,7], 2));                // 7

// Or ascending, and index from the other end -- same thing:
const kthAsc = (nums, k) =>
  [...nums].sort((a, b) => a - b)[nums.length - k];

console.log('');
console.log(kthAsc([3,2,1,5,6,4], 2));                  // 5
console.log(kthAsc([3,2,3,1,2,4,5,5,6], 4));            // 4

// Two lines, O(n log n), impossible to get wrong.
// This is the right answer most of the time. Say it first.

Do not apologise for this solution. It is two lines, it is obviously correct, and on any array small enough to fit in memory it is fast. The interview question is what to do when n is huge or the data is a stream.

The off-by-one, both ways

Descending: the kth largest is at index k - 1.
Ascending: it is at index n - k.

Check both on k = 1: descending gives index 0 (the maximum), ascending gives index n - 1 (also the maximum). Verifying with k = 1 takes two seconds and catches the mistake.

Step 3

Why sorting can be more than you need

Sorting produces a total order over all n elements. You asked for one element. Everything below position k is ordered for nothing.

Two situations where that matters:

  • k is small and n is huge. Finding the top 10 of a hundred million values does not require ordering the other 99,999,990.
  • The data is a stream. You cannot sort what you cannot hold.

function bySorting(a, k) {
  return [...a].sort((x, y) => y - x)[k - 1];
}

// a size-k min-heap: the smallest of the k largest sits on top
function byHeap(a, k) {
  const heap = [];
  const up = (i) => {
    while (i > 0) {
      const p = (i - 1) >> 1;
      if (heap[p] <= heap[i]) break;
      [heap[p], heap[i]] = [heap[i], heap[p]];
      i = p;
    }
  };
  const down = () => {
    let i = 0;
    for (;;) {
      const l = 2 * i + 1, r = 2 * i + 2;
      let s = i;
      if (l < heap.length && heap[l] < heap[s]) s = l;
      if (r < heap.length && heap[r] < heap[s]) s = r;
      if (s === i) break;
      [heap[i], heap[s]] = [heap[s], heap[i]];
      i = s;
    }
  };

  for (const v of a) {
    if (heap.length < k) { heap.push(v); up(heap.length - 1); }
    else if (v > heap[0]) { heap[0] = v; down(); }
  }
  return heap[0];
}

function byQuickselect(a, k) {
  const arr = [...a];
  let target = arr.length - k;      // the index in ASCENDING order
  let lo = 0, hi = arr.length - 1;

  while (lo < hi) {
    const pivot = arr[lo + Math.floor(Math.random() * (hi - lo + 1))];
    let i = lo, j = hi, m = lo;
    while (m <= j) {
      if (arr[m] < pivot) { [arr[i], arr[m]] = [arr[m], arr[i]]; i++; m++; }
      else if (arr[m] > pivot) { [arr[j], arr[m]] = [arr[m], arr[j]]; j--; }
      else m++;
    }
    if (target < i) hi = i - 1;
    else if (target > j) lo = j + 1;
    else return pivot;              // target landed in the equal block
  }
  return arr[lo];
}

Step 4

The better ideas — two of them

Idea A: a min-heap of size k

The unlock

Keep only the k largest values seen so far, in a min-heap. The smallest of those k sits on top — and that top element is the kth largest.

For each new value: if the heap is not full, push it. Otherwise, if the value beats the top, replace the top. Anything smaller than the top can never be in the top k, so discard it immediately.

Why a min-heap when we want the largest? Because the thing you need cheap access to is the weakest member of the winning group — the one to evict. A max-heap would give you the strongest, which you never need to remove.

  nums = [3, 2, 1, 5, 6, 4]     k = 2

  3    heap not full  ->  [3]
  2    heap not full  ->  [2, 3]         (min on top)
  1    1 > 2?  no     ->  discard
  5    5 > 2?  yes    ->  replace top    [3, 5]
  6    6 > 3?  yes    ->  replace top    [5, 6]
  4    4 > 5?  no     ->  discard

  heap = [5, 6],  top = 5   ->  the 2nd largest

Idea B: quickselect

The unlock

Partition around a pivot, exactly as quicksort does. Now you know the pivot’s final position. If that position is the one you want, you are done. Otherwise recurse into only the side that contains your target — never both.

Quicksort recurses into both halves, giving O(n log n). Quickselect recurses into one, and the work halves each time: n + n/2 + n/4 + … which sums to 2n. So O(n) on average.

  looking for the 2nd largest of [3,2,1,5,6,4]
  = the element at ASCENDING index 6 - 2 = 4

  partition around 3:   [2, 1 | 3 | 5, 6, 4]
                                     indexes 0 1  2  3 4 5
  the pivot 3 landed at index 2.  We want index 4.
  4 > 2  ->  recurse RIGHT only: [5, 6, 4]

  partition around 5:   [4 | 5 | 6]  within indexes 3..5
  the pivot 5 landed at index 4.  That is our target  ->  answer 5
Quickselect’s two hazards

Worst case O(n²). Always picking the smallest element as pivot removes one element per pass. A random pivot makes that astronomically unlikely, and picking one is not optional — a fixed pivot on already-sorted input hits the worst case every time.

It mutates the array and produces a partially-sorted mess. Copy first if the caller cares.

Notice the heap arrays above are shown as heap-ordered, not sorted — only the top is guaranteed to be the minimum. That is all you need.

the heap, narrating itself
class MinHeap {
  constructor() { this.a = []; }
  get size() { return this.a.length; }
  peek() { return this.a[0]; }

  push(v) {
    this.a.push(v);
    let i = this.a.length - 1;
    while (i > 0) {
      const p = (i - 1) >> 1;
      if (this.a[p] <= this.a[i]) break;
      [this.a[p], this.a[i]] = [this.a[i], this.a[p]];
      i = p;
    }
  }

  pop() {
    const top = this.a[0];
    const last = this.a.pop();
    if (this.a.length) {
      this.a[0] = last;
      let i = 0;
      for (;;) {
        const l = 2 * i + 1, r = 2 * i + 2;
        let s = i;
        if (l < this.a.length && this.a[l] < this.a[s]) s = l;
        if (r < this.a.length && this.a[r] < this.a[s]) s = r;
        if (s === i) break;
        [this.a[i], this.a[s]] = [this.a[s], this.a[i]];
        i = s;
      }
    }
    return top;
  }
}

Version 1 — without built-in methods

Version 1a — a min-heap, written out
function kthLargestHeapManual(nums, k) {
  const heap = [];       // a binary min-heap stored in an array
  let size = 0;

  function siftUp(i) {
    while (i > 0) {
      const parent = (i - 1 - ((i - 1) % 2)) / 2;
      if (heap[parent] <= heap[i]) break;
      const t = heap[parent]; heap[parent] = heap[i]; heap[i] = t;
      i = parent;
    }
  }

  function siftDown(i) {
    for (;;) {
      const left = 2 * i + 1;
      const right = 2 * i + 2;
      let smallest = i;

      if (left < size && heap[left] < heap[smallest]) smallest = left;
      if (right < size && heap[right] < heap[smallest]) smallest = right;
      if (smallest === i) break;

      const t = heap[i]; heap[i] = heap[smallest]; heap[smallest] = t;
      i = smallest;
    }
  }

  for (let idx = 0; idx < nums.length; idx++) {
    const v = nums[idx];

    if (size < k) {
      heap[size] = v;
      size = size + 1;
      siftUp(size - 1);
    } else if (v > heap[0]) {
      heap[0] = v;          // overwrite the weakest survivor
      siftDown(0);
    }
    // anything <= heap[0] can never be in the top k
  }

  return heap[0];
}

Version 1b — quickselect, written out
function kthLargestQuickselectManual(nums, k) {
  // work on a copy: quickselect reorders the array
  const a = [];
  for (let i = 0; i < nums.length; i++) a[i] = nums[i];

  // the kth LARGEST is at ascending index length - k
  const target = a.length - k;

  let lo = 0;
  let hi = a.length - 1;

  while (lo < hi) {
    // RANDOM pivot -- a fixed one hits O(n^2) on sorted input
    const pivotIndex = lo + ((Math.random() * (hi - lo + 1)) | 0);
    const pivot = a[pivotIndex];

    // three-way partition: less | equal | greater  (Dutch flag)
    let i = lo;      // end of the "less" block
    let m = lo;      // scanner
    let j = hi;      // start of the "greater" block

    while (m <= j) {
      if (a[m] < pivot) {
        const t = a[i]; a[i] = a[m]; a[m] = t;
        i = i + 1; m = m + 1;
      } else if (a[m] > pivot) {
        const t = a[j]; a[j] = a[m]; a[m] = t;
        j = j - 1;
      } else {
        m = m + 1;
      }
    }

    // now: [lo..i-1] < pivot,  [i..j] === pivot,  [j+1..hi] > pivot
    if (target < i) {
      hi = i - 1;              // the target is in the "less" block
    } else if (target > j) {
      lo = j + 1;              // the target is in the "greater" block
    } else {
      return pivot;            // the target is inside the equal block
    }
  }

  return a[lo];
}

the streaming version — where the heap is essential
// "KthLargest" as a class: values arrive over time and after each
// one you report the current kth largest. You cannot sort a stream.
class KthLargest {
  constructor(k, initial = []) {
    this.k = k;
    this.h = [];
    for (const v of initial) this.add(v);
  }

  _up(i) {
    while (i > 0) {
      const p = (i - 1) >> 1;
      if (this.h[p] <= this.h[i]) break;
      [this.h[p], this.h[i]] = [this.h[i], this.h[p]];
      i = p;
    }
  }

  _down() {
    let i = 0;
    for (;;) {
      const l = 2 * i + 1, r = 2 * i + 2;
      let s = i;
      if (l < this.h.length && this.h[l] < this.h[s]) s = l;
      if (r < this.h.length && this.h[r] < this.h[s]) s = r;
      if (s === i) break;
      [this.h[i], this.h[s]] = [this.h[s], this.h[i]];
      i = s;
    }
  }

  add(v) {
    if (this.h.length < this.k) { this.h.push(v); this._up(this.h.length - 1); }
    else if (v > this.h[0]) { this.h[0] = v; this._down(); }
    return this.h.length < this.k ? null : this.h[0];
  }
}

Step 8

Complexity, in sentences

SolutionTimeSpaceBest when
Sort and indexO(n log n)O(n)almost always, in real code
Size-k min-heapO(n log k)O(k)streams, or k much smaller than n
QuickselectO(n) average, O(n²) worstO(1) extraone-off query, array in memory

Why the heap is O(n log k): each of the n values does at most one heap operation, and the heap never holds more than k items, so each operation is log k. When k is 10 and n is a million, log k is about 3 — effectively linear.

Why quickselect is O(n) on average: a random pivot splits the range roughly in half, and you only recurse into one side. The work is n + n/2 + n/4 + … = 2n. The worst case is O(n²) when every pivot is extreme, which random pivoting makes vanishingly unlikely.

Say this in the interview

“Sorting and indexing is O(n log n) and two lines — I would ship that. If k is much smaller than n, a min-heap of size k gives O(n log k) and only O(k) memory, which also works on a stream. If the whole array is in memory and I want the best average time, quickselect partitions around a random pivot and recurses into only the side containing the target, giving O(n) average and O(1) extra space, with an O(n²) worst case that random pivoting makes negligible. I would use a three-way partition so arrays of equal values do not degrade.”

3. Using a max-heap for “kth largest”

why min-heap is the right choice
// A max-heap of ALL n values also works: push everything, pop k times.
function byMaxHeap(nums, k) {
  const h = [...nums];
  // build a max-heap in place
  const down = (i, n) => {
    for (;;) {
      const l = 2*i+1, r = 2*i+2;
      let big = i;
      if (l < n && h[l] > h[big]) big = l;
      if (r < n && h[r] > h[big]) big = r;
      if (big === i) break;
      [h[i], h[big]] = [h[big], h[i]];
      i = big;
    }
  };
  for (let i = (h.length >> 1) - 1; i >= 0; i--) down(i, h.length);

  let n = h.length;
  for (let popped = 0; popped < k - 1; popped++) {
    [h[0], h[n - 1]] = [h[n - 1], h[0]];
    n--;
    down(0, n);
  }
  return h[0];
}

console.log(byMaxHeap([3,2,1,5,6,4], 2));         // 5
console.log(byMaxHeap([3,2,3,1,2,4,5,5,6], 4));   // 4

// Correct, and O(n + k log n) time with O(n) SPACE -- it holds the
// whole array. The size-k MIN-heap holds only k. When k is 10 and
// n is a billion, that is the difference between 10 slots and a
// billion. Pick the heap by what you need to EVICT.

4. Quickselect with a fixed pivot

Broken — O(n²) on sorted input
function fixedPivot(nums, k) {
  const a = [...nums];
  const target = a.length - k;
  let lo = 0, hi = a.length - 1, comparisons = 0;

  while (lo < hi) {
    const pivot = a[hi];                  // ALWAYS the last element
    let i = lo;
    for (let j = lo; j < hi; j++) {
      comparisons++;
      if (a[j] < pivot) { [a[i], a[j]] = [a[j], a[i]]; i++; }
    }
    [a[i], a[hi]] = [a[hi], a[i]];
    if (i === target) return { value: a[i], comparisons };
    if (i < target) lo = i + 1; else hi = i - 1;
  }
  return { value: a[lo], comparisons };
}

const N = 4000;
const sorted = [];
for (let i = 0; i < N; i++) sorted.push(i);

// ask for the SMALLEST (k = N). With the pivot always taken from
// the end of a sorted range, each pass peels off exactly one element.
console.log('sorted input, fixed pivot:', fixedPivot(sorted, N));
// note the comparison count: about N^2 / 2

const shuffled = [...sorted];
for (let i = shuffled.length - 1; i > 0; i--) {
  const j = Math.floor(Math.random() * (i + 1));
  [shuffled[i], shuffled[j]] = [shuffled[j], shuffled[i]];
}
console.log('shuffled input, same code:', fixedPivot(shuffled, N));
// far fewer comparisons -- the input order was the whole problem

function quickselectInPlace(a, k) {
  const target = a.length - k;
  let lo = 0, hi = a.length - 1;
  while (lo < hi) {
    const pivot = a[lo + ((Math.random() * (hi - lo + 1)) | 0)];
    let i = lo, m = lo, j = hi;
    while (m <= j) {
      if (a[m] < pivot) { [a[i],a[m]]=[a[m],a[i]]; i++; m++; }
      else if (a[m] > pivot) { [a[j],a[m]]=[a[m],a[j]]; j--; }
      else m++;
    }
    if (target < i) hi = i - 1;
    else if (target > j) lo = j + 1;
    else return pivot;
  }
  return a[lo];
}

Step 10

Practice before you move on

  1. Write the two-line sort version and verify the index with k = 1. Then say the three options and their trade-offs out loud — that summary is the interview answer.
  2. Write the min-heap from scratch. About 25 lines, and JavaScript has no built-in one, so it is genuinely worth being able to produce.
  3. Kth smallest. Flip the comparator, or use a max-heap of size k. Both; then say which you prefer.
  4. Top K Frequent Elements. Already in the hashmap topic — and it is “kth largest” applied to counts rather than values. Notice the bucket-sort answer beats both the heap and the sort there, because counts are bounded.
  5. Median of an unsorted array. Quickselect for position n/2 — O(n) average instead of sorting. For an even-length array you need two selects, or one select plus a scan.
What to carry forward

“Find the kth best” almost never needs a full sort. Three tools cover it: sort when simplicity wins, a size-k heap when memory or streaming matters, quickselect when average speed matters. And the general lesson from the heap: choose the data structure by what you need cheap access to. Here that is the weakest member of the winning group, which is why a min-heap answers a question about the largest values.
