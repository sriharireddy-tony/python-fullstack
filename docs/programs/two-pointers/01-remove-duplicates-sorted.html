Two pointers · Problem 01

Remove Duplicates from Sorted Array

The read/write pointer from Move Zeroes, with one change to the test. And the reason it is easy: in a sorted array, every duplicate is standing right next to its twin, so you never have to look further than one step back.

Step 1

The problem

Given a sorted array, remove the duplicates in place so each value appears once. Return the new length. Whatever sits beyond that length does not matter.

InputReturnsArray becomes
[1, 1, 2]2[1, 2, _]
[0,0,1,1,1,2,2,3,3,4]5[0,1,2,3,4, _ _ _ _ _]
[1, 2, 3]3[1, 2, 3]
[7]1[7]
[]0[]

The underscores are leftover junk. The contract is only that the first k slots hold the distinct values in order.

What “sorted” buys you

In an unsorted array, a duplicate of nums[i] could be anywhere, so you would need a Set to remember everything seen. Sorted, equal values are adjacent. So the entire memory you need is the last value you kept — one variable instead of a whole set.

This is the same reason sorting helped in Three Sum and Merge Intervals: it converts “compare against everything” into “compare against your neighbour”.

Step 2

Think first — the obvious answers

Version 0a — splice out the duplicates
function removeDuplicatesSplice(nums) {
  for (let i = 1; i < nums.length; ) {
    if (nums[i] === nums[i - 1]) {
      nums.splice(i, 1);      // cut it out; everything after shifts left
      // do NOT advance i -- a new value slid into this slot
    } else {
      i++;
    }
  }
  return nums.length;
}

const a = [0,0,1,1,1,2,2,3,3,4];
console.log(removeDuplicatesSplice(a), a);   // 5 [0,1,2,3,4]

const b = [1, 1, 2];
console.log(removeDuplicatesSplice(b), b);   // 2 [1,2]

// Correct, and genuinely shortens the array. But splice shifts
// every later element, so it is O(n) per removal -- O(n^2) overall.
Version 0b — build a new array
function removeDuplicatesCopy(nums) {
  const out = [];
  for (const n of nums) {
    if (out.length === 0 || out[out.length - 1] !== n) out.push(n);
  }
  return out;
}

console.log(removeDuplicatesCopy([0,0,1,1,1,2,2,3,3,4]));   // [0,1,2,3,4]
console.log(removeDuplicatesCopy([1, 1, 2]));               // [1,2]

// O(n) time -- but O(n) space, and it does not modify the input,
// so it fails the "in place" requirement.

// The one-liner people reach for, which is also a copy:
console.log([...new Set([0,0,1,1,1,2,2,3,3,4])]);           // [0,1,2,3,4]

The Set one-liner is worth knowing and worth saying out loud — and then setting aside, because it allocates and because it does not need the array to be sorted, which means it is not using the gift the problem gave you.

Step 3

Why splice is slow

Removing from the middle of an array shifts every element after it. Do that once per duplicate and you have O(n²) hidden inside a method call that looks like one step.

Timing demo
// Mostly duplicates: the worst case for splice.
const N = 40000;
const base = [];
for (let i = 0; i < N; i++) base.push(Math.floor(i / 20));   // each value 20 times

function bySplice(nums) {
  for (let i = 1; i < nums.length; ) {
    if (nums[i] === nums[i - 1]) nums.splice(i, 1);
    else i++;
  }
  return nums.length;
}

function byPointers(nums) {
  if (nums.length === 0) return 0;
  let write = 1;
  for (let read = 1; read < nums.length; read++) {
    if (nums[read] !== nums[write - 1]) {
      nums[write] = nums[read];
      write++;
    }
  }
  return write;
}

let t = performance.now();
const x = bySplice(base.slice());
const spliceMs = performance.now() - t;

t = performance.now();
const y = byPointers(base.slice());
const ptrMs = performance.now() - t;

console.log('splice each duplicate :', x, 'in', spliceMs.toFixed(1) + ' ms');
console.log('read/write pointers   :', y, 'in', ptrMs.toFixed(2) + ' ms');
console.log('same length:', x === y);
console.log('speed-up:', Math.round(spliceMs / Math.max(ptrMs, 0.01)) + 'x');
Step 4

The better idea — read and write pointers

Stop removing. Start overwriting, exactly as in Move Zeroes.

The unlock

read visits every element. write marks the next slot for a distinct value. Copy nums[read] forward only when it differs from nums[write - 1] — the last value you actually kept.

Note carefully what you compare against. Not nums[read - 1], the previous element you looked at — nums[write - 1], the last one you committed. In this problem the two happen to be equal, because the array is sorted and you keep the first of every run. But writing nums[write - 1] states the real invariant, and it generalises to problems where they differ.

       0  0  1  1  1  2
       w  r                    write starts at 1, read at 1
                               (the first element is always kept)

  r=1  value 0,  nums[w-1] = nums[0] = 0    same -> skip
  r=2  value 1,  nums[w-1] = 0              different -> nums[1] = 1, w=2

       0  1  1  1  1  2
          w     r

  r=3  value 1,  nums[w-1] = nums[1] = 1    same -> skip
  r=4  value 1,  same -> skip
  r=5  value 2,  nums[w-1] = 1              different -> nums[2] = 2, w=3

       0  1  2  1  1  2
             w

  new length: 3       first three slots: 0, 1, 2

write starts at 1, not 0. The first element can never be a duplicate of anything before it, so it is always kept — and starting at 1 means nums[write - 1] is always a real value, never index −1.

function removeDuplicatesExplained(nums) {
  if (nums.length === 0) { console.log('empty -> 0'); return 0; }

Step 6

Version 1 — without built-in methods

Version 1 — read and write pointers
function removeDuplicatesManual(nums) {
  if (nums.length === 0) return 0;

  let write = 1;      // index 0 is always a keeper

  for (let read = 1; read < nums.length; read++) {
    // compare with the last value we COMMITTED, not the previous read
    if (nums[read] !== nums[write - 1]) {
      nums[write] = nums[read];
      write = write + 1;
    }
  }

  return write;
}

function show(arr) {
  const copy = [...arr];
  const k = removeDuplicatesManual(copy);
  return { length: k, kept: copy.slice(0, k) };
}

console.log(show([1, 1, 2]));                     // 2, [1,2]
console.log(show([0,0,1,1,1,2,2,3,3,4]));         // 5, [0,1,2,3,4]
console.log(show([1, 2, 3]));                     // 3, [1,2,3]
console.log(show([7]));                           // 1, [7]
console.log(show([]));                            // 0, []
console.log(show([5, 5, 5, 5]));                  // 1, [5]
console.log(show([-2, -2, 0, 0, 1]));             // 3, [-2,0,1]

The follow-up: allow each value at most twice

variation — keep up to two of each
function removeDuplicatesTwice(nums) {
  if (nums.length <= 2) return nums.length;

  let write = 2;      // the first two are always keepers

  for (let read = 2; read < nums.length; read++) {
    // compare with the value TWO slots back among the kept ones.
    // If they differ, this value has appeared at most once so far.
    if (nums[read] !== nums[write - 2]) {
      nums[write] = nums[read];
      write++;
    }
  }

  return write;
}

function show2(arr) {
  const copy = [...arr];
  const k = removeDuplicatesTwice(copy);
  return { length: k, kept: copy.slice(0, k) };
}

console.log(show2([1,1,1,2,2,3]));          // 5, [1,1,2,2,3]
console.log(show2([0,0,1,1,1,1,2,3,3]));    // 7, [0,0,1,1,2,3,3]
console.log(show2([1,1]));                  // 2, [1,1]
console.log(show2([1,2,3]));                // 3, [1,2,3]

// The generalisation: "at most k copies" compares with
// nums[write - k]. Once you see that, the whole family is one
// parameter.
function removeDuplicatesAtMost(nums, k) {
  if (nums.length <= k) return nums.length;
  let write = k;
  for (let read = k; read < nums.length; read++) {
    if (nums[read] !== nums[write - k]) nums[write++] = nums[read];
  }
  return write;
}

const t = [1,1,1,1,2,2,2,3];
const n = removeDuplicatesAtMost(t, 3);
console.log(n, t.slice(0, n));              // 7, [1,1,1,2,2,2,3]

Version 2 — the interview answer

the versions you would actually ship
// Truncate the array too, so the caller does not have to track k:
function dedupeInPlace(nums) {
  if (nums.length === 0) return nums;
  let write = 1;
  for (let read = 1; read < nums.length; read++) {
    if (nums[read] !== nums[write - 1]) nums[write++] = nums[read];
  }
  nums.length = write;          // assigning to .length truncates
  return nums;
}

const c = [0,0,1,1,1,2,2,3,3,4];
console.log(dedupeInPlace(c));     // [0,1,2,3,4] -- actually shortened

// Not in place, unsorted input welcome, one line:
console.log([...new Set([3,1,3,2,1])]);          // [3,1,2]

// Sorted input, non-mutating, keeps the "neighbour" idea:
const dedupeSorted = arr => arr.filter((v, i) => i === 0 || v !== arr[i - 1]);
console.log(dedupeSorted([0,0,1,1,1,2,2,3,3,4]));  // [0,1,2,3,4]

// Dedupe objects by a key -- the version you write most often at work:
function uniqueBy(items, keyOf) {
  const seen = new Set();
  return items.filter(item => {
    const key = keyOf(item);
    if (seen.has(key)) return false;
    seen.add(key);
    return true;
  });
}

console.log(uniqueBy(
  [{id:1,n:'a'}, {id:2,n:'b'}, {id:1,n:'c'}],
  o => o.id
));   // keeps the FIRST of each id
new Set(...) does not need a sorted array — and that is the point

The Set version works on any input and is what you write at work. It is not the answer to this problem, because it allocates O(n) and does not modify the input. When an interviewer specifies “sorted” and “in place”, both words are requirements — and the first one is a hint that O(1) space is achievable.

Step 8

Complexity, in sentences

SolutionTimeSpaceIn place?
splice per duplicateO(n²)O(1)yes
Set / filterO(n)O(n)no
Read/write pointersO(n)O(1)yes

One pass, one comparison and at most one assignment per element. O(n) time. Two integers of state, whatever the input size — O(1) space, and this time genuinely O(1), because there is no output array to excuse.

Worth noting: the number of writes equals the number of distinct values. On an array with no duplicates, every write is nums[i] = nums[i]. Some implementations add if (write !== read) to skip those; it changes nothing asymptotically and rarely matters.

Say this in the interview

“Because the array is sorted, duplicates are adjacent, so I only need to compare each element with the last one I kept — no Set required. I keep a write pointer at the next slot for a distinct value, starting at 1 since the first element is always kept, and copy forward only when nums[read] !== nums[write - 1]. O(n) time, O(1) space, and I return the write pointer as the new length.”

Step 9

Mistakes people actually make

1. Comparing with nums[read - 1] after writing

Broken — compares against overwritten data
function broken(nums) {
  if (nums.length === 0) return 0;
  let write = 1;
  for (let read = 1; read < nums.length; read++) {
    if (nums[read] !== nums[read - 1]) {     // reads a slot we may have overwritten
      nums[write] = nums[read];
      write++;
    }
  }
  return write;
}

const a = [0,0,1,1,1,2,2,3,3,4];
console.log(broken(a), a.slice(0, 5));   // 5 [0,1,2,3,4]  -- correct here!

// On a SORTED array this happens to be safe, because write never
// catches up to read and the value at read-1 is still the original.
// It is right by circumstance rather than by design. Comparing with
// nums[write - 1] says what you actually mean -- "the last value I
// committed" -- and stays correct if the algorithm ever changes.

2. Starting write at 0

Broken — index -1
function broken(nums) {
  let write = 0;                             // should be 1
  for (let read = 0; read < nums.length; read++) {
    if (nums[read] !== nums[write - 1]) {    // nums[-1] on the first step
      nums[write] = nums[read];
      write++;
    }
  }
  return write;
}

const a = [1, 1, 2];
console.log(broken(a), a.slice(0, 2));

// nums[-1] is undefined, which is never equal to a real value, so
// the first element is written and it works -- again by accident.
// Being explicit that index 0 is always kept, and starting write
// at 1, removes the reliance on undefined comparing unequal.

3. Assuming the array is sorted when it is not

Broken — on unsorted input
function neighbourOnly(nums) {
  if (nums.length === 0) return 0;
  let write = 1;
  for (let read = 1; read < nums.length; read++) {
    if (nums[read] !== nums[write - 1]) nums[write++] = nums[read];
  }
  return write;
}

const sorted = [1,1,2,2,3];
console.log(neighbourOnly(sorted), sorted.slice(0, 3));   // 3 [1,2,3]  correct

const unsorted = [1,2,1,2,1];
const k = neighbourOnly(unsorted);
console.log(k, unsorted.slice(0, k));   // 5 [1,2,1,2,1]  nothing removed

// Every neighbour differs, so nothing is a "duplicate" by the
// adjacency test. For unsorted input you need a Set -- which means
// O(n) space. The sorted guarantee is what buys the O(1).

4. Returning the array instead of the length

The signature returns a number, and the array still contains junk past index k. Returning nums hands the caller data that looks wrong. If you want to return an array, truncate first with nums.length = write.

5. Advancing read after a splice

If you do use splice, you must not increment the index in the same step — a different element has just slid into that slot. It is the same trap as Move Zeroes, and it is one more reason to avoid splice in a loop entirely.

Step 10

Practice before you move on

  1. Write the five-line version from memory, then say why write starts at 1.
  2. Allow at most two of each. In Step 6 — write it from memory and work out why the comparison becomes nums[write - 2].
  3. Remove Element. Delete every occurrence of a given value in place and return the new length. The same skeleton with a different keep-test — and the array need not be sorted, because the test does not involve neighbours.
  4. Count the distinct values without modifying the array. One pass, one counter, comparing with the previous element. Two lines.
  5. Merge two sorted arrays, removing duplicates. Two read pointers and one write pointer — the natural next step, and it is the merge step of merge sort with a dedupe.
What to carry forward

Two ideas, both already familiar. Read pointer, write pointer for any in-place filter that must preserve order. And sorted means adjacent: whenever a problem hands you a sorted array, the first question is what “compare against everything” can be downgraded to “compare against my neighbour”. That downgrade is usually worth a whole complexity class, or a whole data structure.
