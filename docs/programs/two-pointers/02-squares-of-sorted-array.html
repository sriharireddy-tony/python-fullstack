Two pointers · Problem 02

Squares of a Sorted Array

Squaring a sorted array un-sorts it, because negatives flip to the front. Re-sorting costs O(n log n). The O(n) fix is to notice that the largest square is always at one end or the other — so build the answer backwards.

Step 1

The problem

Given a sorted array of integers (which may include negatives), return an array of their squares, also sorted.

InputSquares, in orderSorted answer
[-4,-1,0,3,10][16,1,0,9,100][0,1,9,16,100]
[-7,-3,2,3,11][49,9,4,9,121][4,9,9,49,121]
[1,2,3][1,4,9][1,4,9]
[-3,-2,-1][9,4,1][1,4,9]
Why the order breaks

Sorting orders by value; squaring orders by distance from zero. For all positives those agree, so nothing changes. For all negatives they are exactly reversed. For a mixed array you get a V shape — the squares fall to a minimum near zero and rise again.

  input:    -4   -1    0    3   10
  squares:  16    1    0    9  100

             \          /
              \        /            a V: descending, then ascending
               \      /
                \    /
                 \  /
                  \/
                  0

That V is the whole structure of the problem. The two ends hold the biggest squares; the middle holds the smallest.

Step 2

Think first — square then sort

Version 0 — map and sort
function sortedSquaresSimple(nums) {
  return nums.map(n => n * n).sort((a, b) => a - b);
}

console.log(sortedSquaresSimple([-4,-1,0,3,10]));   // [0,1,9,16,100]
console.log(sortedSquaresSimple([-7,-3,2,3,11]));   // [4,9,9,49,121]
console.log(sortedSquaresSimple([1,2,3]));          // [1,4,9]
console.log(sortedSquaresSimple([-3,-2,-1]));       // [1,4,9]
console.log(sortedSquaresSimple([]));               // []

// One line, obviously correct, O(n log n). Say it out loud, then
// offer the linear version.

Do not skip past this. It is a genuinely good answer, and in a real codebase it is the one to ship unless profiling says otherwise. The interview question is whether you can do better given that the input is already sorted.

Step 3

Why sorting is more than you need

The input arrives sorted. Sorting again throws that away and rediscovers an order you were handed most of.

Timing demo
const N = 2000000;
const nums = [];
for (let i = -N / 2; i < N / 2; i++) nums.push(i);   // sorted, half negative

function mapSort(a) {
  return a.map(n => n * n).sort((x, y) => x - y);
}

function twoPointer(a) {
  const out = new Array(a.length);
  let left = 0, right = a.length - 1;
  for (let pos = a.length - 1; pos >= 0; pos--) {
    const l = a[left] * a[left];
    const r = a[right] * a[right];
    if (l > r) { out[pos] = l; left++; }
    else { out[pos] = r; right--; }
  }
  return out;
}

let t = performance.now();
const a = mapSort(nums);
const sortMs = performance.now() - t;

t = performance.now();
const b = twoPointer(nums);
const ptrMs = performance.now() - t;

console.log('map + sort   : ' + sortMs.toFixed(1) + ' ms');
console.log('two pointers : ' + ptrMs.toFixed(1) + ' ms');
console.log('same answer  :', a[0] === b[0] && a[N - 1] === b[N - 1] &&
                              a[N >> 1] === b[N >> 1]);
console.log('speed-up:', Math.round(sortMs / Math.max(ptrMs, 0.01)) + 'x');
Step 4

The better idea — fill backwards from both ends

Look at the V again. The smallest square is somewhere in the middle, and you do not know where without searching. But the largest square is trivially easy: it is at one of the two ends, because the ends are the values furthest from zero.

The unlock

Put a pointer at each end. Compare the two squares; the bigger one is the largest square left. Write it into the last unfilled slot of the output and move that pointer inwards. Repeat, filling the output right to left.

Why is the maximum always at an end? Because the array is sorted, so nums[left] is the most negative value remaining and nums[right] the most positive. Everything between them is closer to zero, so every square between them is smaller than the larger of those two. Nothing in the middle can win.

  nums = [-4, -1, 0, 3, 10]
          L                R

  squares at the ends: 16 and 100.  100 wins.
     -> out[4] = 100,  right moves in

  nums = [-4, -1, 0, 3]
          L           R
  squares: 16 and 9.  16 wins.
     -> out[3] = 16,  left moves in

  nums = [-1, 0, 3]
          L      R
  squares: 1 and 9.  9 wins.
     -> out[2] = 9,   right moves in

  nums = [-1, 0]
          L   R
  squares: 1 and 0.  1 wins.
     -> out[1] = 1,   left moves in

  nums = [0]
          LR
  squares: 0 and 0.  either.
     -> out[0] = 0

  out = [0, 1, 9, 16, 100]

Filling backwards is the key detail. Going forwards you would need the smallest square first, which requires finding the V’s bottom. Going backwards, the answer is always sitting at one of two places you are already looking at.

The general lesson

When the easy thing to find is the maximum rather than the minimum, build the output from the end. The same instinct solves Merge Sorted Array in place — merging backwards avoids overwriting data you still need.

Step 5

Dry run — trace it by hand

nums = [-7,-3,2,3,11].

out = [_, _, _, _, _]    left=0  right=4  pos=4

pos=4  nums[0]=-7 -> 49    nums[4]=11 -> 121
       121 wins   out[4] = 121   right=3
       out = [_,_,_,_,121]

pos=3  nums[0]=-7 -> 49    nums[3]=3 -> 9
       49 wins    out[3] = 49    left=1
       out = [_,_,_,49,121]

pos=2  nums[1]=-3 -> 9     nums[3]=3 -> 9
       tie -- take the right one   out[2] = 9    right=2
       out = [_,_,9,49,121]

pos=1  nums[1]=-3 -> 9     nums[2]=2 -> 4
       9 wins     out[1] = 9     left=2
       out = [_,9,9,49,121]

pos=0  nums[2]=2 -> 4      nums[2]=2 -> 4
       left === right, one element left   out[0] = 4
       out = [4,9,9,49,121]

Note the tie at pos=2. When the two squares are equal it does not matter which you take — both are correct, and both eventually get written. Using if (l > r) versus if (l >= r) changes which pointer moves first and nothing else.

And note the last step: left === right, both pointers on the same element. The loop still runs because there is still one slot to fill. That is why the loop is driven by pos, not by left < right.

the algorithm, narrating itself
function squaresExplained(nums) {
  const n = nums.length;
  const out = new Array(n).fill(null);
  let left = 0, right = n - 1;

  console.log('nums =', nums);
  console.log('');

  for (let pos = n - 1; pos >= 0; pos--) {
    const l = nums[left] * nums[left];
    const r = nums[right] * nums[right];

    if (l > r) {
      out[pos] = l;
      console.log('pos=' + pos + '   left ' + nums[left] + '^2=' + l +
                  '  vs  right ' + nums[right] + '^2=' + r +
                  '   -> take LEFT ' + l + '   left becomes ' + (left + 1));
      left++;
    } else {
      out[pos] = r;
      console.log('pos=' + pos + '   left ' + nums[left] + '^2=' + l +
                  '  vs  right ' + nums[right] + '^2=' + r +
                  '   -> take RIGHT ' + r + '   right becomes ' + (right - 1));
      right--;
    }

    console.log('          out = [' + out.map(v => v === null ? '_' : v).join(', ') + ']');
  }

  console.log('');
  return out;
}

Step 6

Version 1 — without built-in methods

Version 1 — two pointers, loops only
function sortedSquaresManual(nums) {
  const n = nums.length;
  const out = [];

  let left = 0;
  let right = n - 1;

  // fill the output from the LAST slot backwards
  for (let pos = n - 1; pos >= 0; pos--) {
    const leftSquare = nums[left] * nums[left];
    const rightSquare = nums[right] * nums[right];

    if (leftSquare > rightSquare) {
      out[pos] = leftSquare;
      left = left + 1;
    } else {
      out[pos] = rightSquare;
      right = right - 1;
    }
  }

  return out;
}

console.log(sortedSquaresManual([-4,-1,0,3,10]));    // [0,1,9,16,100]
console.log(sortedSquaresManual([-7,-3,2,3,11]));    // [4,9,9,49,121]
console.log(sortedSquaresManual([1,2,3]));           // [1,4,9]
console.log(sortedSquaresManual([-3,-2,-1]));        // [1,4,9]
console.log(sortedSquaresManual([0]));               // [0]
console.log(sortedSquaresManual([]));                // []
console.log(sortedSquaresManual([-5, 5]));           // [25,25]
console.log(sortedSquaresManual([-1, 0, 1]));        // [0,1,1]
Why the loop is driven by pos

Writing while (left <= right) also works, but then you need a separate pos counter and two places to keep in sync. Driving the loop by the output position guarantees exactly n iterations and exactly n writes — every slot filled once. Fewer moving parts, fewer off-by-ones.

the alternative: find the pivot, then merge
// A different linear solution: find where the sign changes, then
// merge the two halves outwards from that point.
function squaresByMerge(nums) {
  const n = nums.length;
  if (n === 0) return [];

  // find the first non-negative index
  let split = 0;
  while (split < n && nums[split] < 0) split++;

  let neg = split - 1;    // walks leftwards through the negatives
  let pos = split;        // walks rightwards through the non-negatives
  const out = [];

  // merge, taking the smaller square each time -- forwards this time
  while (neg >= 0 && pos < n) {
    const a = nums[neg] * nums[neg];
    const b = nums[pos] * nums[pos];
    if (a < b) { out.push(a); neg--; }
    else { out.push(b); pos++; }
  }
  while (neg >= 0) { out.push(nums[neg] * nums[neg]); neg--; }
  while (pos < n)  { out.push(nums[pos] * nums[pos]); pos++; }

  return out;
}

console.log(squaresByMerge([-4,-1,0,3,10]));   // [0,1,9,16,100]
console.log(squaresByMerge([-7,-3,2,3,11]));   // [4,9,9,49,121]
console.log(squaresByMerge([1,2,3]));          // [1,4,9]
console.log(squaresByMerge([-3,-2,-1]));       // [1,4,9]
console.log(squaresByMerge([]));               // []

// Also O(n), and it makes the structure explicit: the array is two
// sorted sequences glued together, so this is the merge step of
// merge sort. More code, more edge cases -- the backwards fill is
// the one to write.
Step 7

Version 2 — with built-in methods

Version 2 — the interview answer
function sortedSquares(nums) {
  const n = nums.length;
  const out = new Array(n);

  let left = 0;
  let right = n - 1;

  for (let pos = n - 1; pos >= 0; pos--) {
    const l = nums[left] ** 2;
    const r = nums[right] ** 2;

    if (l > r) { out[pos] = l; left++; }
    else       { out[pos] = r; right--; }
  }

  return out;
}

console.log(sortedSquares([-4,-1,0,3,10]));   // [0,1,9,16,100]
console.log(sortedSquares([-7,-3,2,3,11]));   // [4,9,9,49,121]
console.log(sortedSquares([-5]));             // [25]
console.log(sortedSquares([]));               // []

** is the exponent operator, so x ** 2 is x * x. For squaring specifically, x * x is marginally faster and reads just as well — use whichever your codebase prefers. Math.abs would also work for the comparison, since comparing absolute values gives the same ordering as comparing squares.

comparing by absolute value instead
function sortedSquaresAbs(nums) {
  const n = nums.length;
  const out = new Array(n);
  let left = 0, right = n - 1;

  for (let pos = n - 1; pos >= 0; pos--) {
    // |a| > |b|  is equivalent to  a^2 > b^2, and avoids the multiply
    if (Math.abs(nums[left]) > Math.abs(nums[right])) {
      out[pos] = nums[left] * nums[left];
      left++;
    } else {
      out[pos] = nums[right] * nums[right];
      right--;
    }
  }

  return out;
}

console.log(sortedSquaresAbs([-4,-1,0,3,10]));   // [0,1,9,16,100]
console.log(sortedSquaresAbs([-7,-3,2,3,11]));   // [4,9,9,49,121]

// Worth knowing for a different reason: with very large numbers,
// squaring can overflow into imprecise floating point, while
// comparing magnitudes cannot. In JavaScript, integers above
// 2^53 lose precision:
console.log(Number.MAX_SAFE_INTEGER);              // 9007199254740991
console.log(3037000500 ** 2 === 3037000499 ** 2);  // false, still fine
console.log((2 ** 53) === (2 ** 53) + 1);          // true -- precision lost
a non-mutating check that both agree
function mapSort(nums) {
  return nums.map(n => n * n).sort((a, b) => a - b);
}

function twoPointer(nums) {
  const out = new Array(nums.length);
  let l = 0, r = nums.length - 1;
  for (let p = nums.length - 1; p >= 0; p--) {
    const a = nums[l] * nums[l], b = nums[r] * nums[r];
    if (a > b) { out[p] = a; l++; } else { out[p] = b; r--; }
  }
  return out;
}

// random sorted arrays, both methods, 300 trials
let ok = 0;
for (let trial = 0; trial < 300; trial++) {
  const len = Math.floor(Math.random() * 12);
  const arr = [];
  for (let i = 0; i < len; i++) arr.push(Math.floor(Math.random() * 21) - 10);
  arr.sort((a, b) => a - b);

  if (JSON.stringify(mapSort(arr)) === JSON.stringify(twoPointer(arr))) ok++;
}

console.log('300 random sorted arrays, both methods agree:', ok + '/300');
Step 8

Complexity, in sentences

SolutionTimeSpace
Map then sortO(n log n)O(n)
Two pointers, backwardsO(n)O(n)

Exactly n iterations, each doing two multiplications, one comparison and one write. O(n) — and O(n) is optimal, since the output alone has n entries.

Space is O(n) for the output, which does not count against you by convention. The scratch space is three integers. If you were allowed to overwrite the input you could not do better anyway — there is nowhere to put the answer without either an output array or destroying values you still need.

Say this in the interview

“Squaring reverses the order of the negatives, so the squares form a V — the largest values are at the two ends. I put a pointer at each end and fill the output array from the back: at each step the larger of the two end squares is the largest remaining, so it goes in the last empty slot and that pointer moves inwards. Exactly n steps, O(n) time and O(n) output space, and it uses the fact that the input is already sorted rather than re-sorting.”

Step 9

Mistakes people actually make

1. Filling the output forwards

Broken — takes the max but writes it first
function broken(nums) {
  const out = [];
  let left = 0, right = nums.length - 1;
  while (left <= right) {
    const l = nums[left] * nums[left];
    const r = nums[right] * nums[right];
    if (l > r) { out.push(l); left++; }      // push = forwards -- bug
    else { out.push(r); right--; }
  }
  return out;
}

console.log(broken([-4,-1,0,3,10]));   // [100,16,9,1,0]  -- reversed
console.log(broken([1,2,3]));          // [9,4,1]         -- reversed

// The values are right and the order is exactly backwards, because
// we are producing them largest-first and appending. Either fill
// backwards by index, or push and then reverse at the end.
console.log(broken([-4,-1,0,3,10]).reverse());   // [0,1,9,16,100]

2. Trying to take the minimum from the ends

Broken — the minimum is not at an end
function broken(nums) {
  const out = [];
  let left = 0, right = nums.length - 1;
  while (left <= right) {
    const l = nums[left] * nums[left];
    const r = nums[right] * nums[right];
    if (l < r) { out.push(l); left++; }      // taking the SMALLER -- bug
    else { out.push(r); right--; }
  }
  return out;
}

console.log(broken([-4,-1,0,3,10]));   // [1,0,9,16,100]  WRONG
console.log(broken([-7,-3,2,3,11]));   // [9,4,9,49,121]  WRONG

// The smallest square is somewhere in the MIDDLE of the V, not at
// an end. Comparing the two ends and taking the smaller does not
// find it. The maximum is the one guaranteed to be at an end.

3. Assuming the array has no negatives

Broken — just squares in place
const broken = nums => nums.map(n => n * n);

console.log(broken([1,2,3]));          // [1,4,9]      correct
console.log(broken([-4,-1,0,3,10]));   // [16,1,0,9,100]  NOT sorted

// If the input were guaranteed non-negative there would be no
// problem to solve. The negatives are the entire question -- which
// is why the first thing to check is whether any exist.

4. Off-by-one in the starting position

pos starts at n - 1, the last index, not at n. Writing out[n] grows the array to length n + 1 with an undefined at the front. And right starts at n - 1 for the same reason.

5. Forgetting the empty array

With n === 0, the loop for (pos = -1; pos >= 0; ...) never runs and new Array(0) is [] — so the two-pointer version handles it for free. Confirm that rather than assuming it; a version that reads nums[left] before the loop would throw.

Step 10

Practice before you move on

  1. Write the seven-line version from memory, then say why the maximum is guaranteed to be at an end and the minimum is not.
  2. Merge Sorted Array in place. nums1 has spare room at the end; merge nums2 into it. Fill backwards for exactly the same reason — it avoids overwriting values you have not read yet. It is in the searching topic here.
  3. Absolute values, sorted. Same problem without the squaring. Confirm your solution does not depend on squares specifically.
  4. Cubes of a sorted array. A trick question: cubes preserve sign, so the array is already sorted after cubing. Work out why, and notice that the V does not form.
  5. Find the closest value to zero. The bottom of the V. Binary search finds it in O(log n) — a good warm-up for the searching topic.
What to carry forward

If the maximum is easy to find but the minimum is not, build the answer from the back. Filling an output in reverse is a small habit that solves this problem, in-place merging, and several array-shifting problems. The general question to ask is: which end of my answer can I determine right now with certainty? Start there, whichever end it is.
