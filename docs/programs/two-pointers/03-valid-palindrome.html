Two pointers · Problem 03

Valid Palindrome With Skips

Two pointers walking towards each other — the simplest two-pointer shape there is. The interesting part is doing it without building a cleaned copy of the string, which is what takes it from O(n) space to O(1).

Step 1

The problem

Is the string a palindrome, ignoring case, and ignoring everything that is not a letter or a digit?

InputAnswerWhat it reduces to
"A man, a plan, a canal: Panama"true"amanaplanacanalpanama"
"race a car"false"raceacar"
" "true"" — empty is a palindrome
"0P"false"0p" — digits are kept
".,"true""
The two rows that catch people

" " is true. After removing the space nothing is left, and an empty string reads the same forwards and backwards.

"0P" is false. Both characters are alphanumeric, so both are kept; lowercased that is "0p", and 0 !== p. A solution that only accepts letters would drop the 0 and wrongly answer true.

Step 2

Think first — clean it, then reverse it

Version 0 — clean and compare with the reverse
function isPalindromeClean(s) {
  const cleaned = s.toLowerCase().replace(/[^a-z0-9]/g, '');
  const reversed = [...cleaned].reverse().join('');
  return cleaned === reversed;
}

console.log(isPalindromeClean('A man, a plan, a canal: Panama'));   // true
console.log(isPalindromeClean('race a car'));                       // false
console.log(isPalindromeClean(' '));                                // true
console.log(isPalindromeClean('0P'));                               // false
console.log(isPalindromeClean('.,'));                               // true
console.log(isPalindromeClean('ab_a'));                             // true

Three lines, obviously correct, and the one you would write at work. Its cost is three extra strings: the lowercased copy, the cleaned copy and the reversed copy. That is O(n) space for a question that can be answered with two integers.

The regex, read aloud

/[^a-z0-9]/g — the [^...] means “any character not in this set”, and g means “every occurrence”. So: replace every character that is not a lowercase letter or a digit with nothing. It runs after toLowerCase(), which is why uppercase letters do not need to be in the set.

Step 3

Why building copies costs

Both approaches are O(n) time. The difference is memory and allocations — and, on a long string that fails early, wasted work: the cleaning version processes the entire string before discovering a mismatch at position 1.

Timing demo
// A long string that is NOT a palindrome, and fails at the very
// first comparison.
const N = 2000000;
const s = 'a' + 'x'.repeat(N) + 'b';

function cleanAndReverse(str) {
  const c = str.toLowerCase().replace(/[^a-z0-9]/g, '');
  return c === [...c].reverse().join('');
}

function twoPointers(str) {
  const ok = ch => (ch >= 'a' && ch <= 'z') ||
                   (ch >= 'A' && ch <= 'Z') ||
                   (ch >= '0' && ch <= '9');
  let lo = 0, hi = str.length - 1;
  while (lo < hi) {
    while (lo < hi && !ok(str[lo])) lo++;
    while (lo < hi && !ok(str[hi])) hi--;
    if (str[lo].toLowerCase() !== str[hi].toLowerCase()) return false;
    lo++; hi--;
  }
  return true;
}

let t = performance.now();
const a = cleanAndReverse(s);
const cleanMs = performance.now() - t;

t = performance.now();
const b = twoPointers(s);
const ptrMs = performance.now() - t;

console.log('clean + reverse :', a, 'in', cleanMs.toFixed(1) + ' ms');
console.log('two pointers    :', b, 'in', ptrMs.toFixed(3) + ' ms');
console.log('same answer:', a === b);
console.log('');
console.log('The two-pointer version compared ONE pair and stopped.');
console.log('The cleaning version built three 2,000,002-character');
console.log('strings first.');
Step 4

The better idea — walk inwards, skipping as you go

The unlock

Put one pointer at each end. Before comparing, advance each pointer past anything that is not alphanumeric. Then compare the two characters, lowercased. If they differ, it is not a palindrome. If they match, step both inwards and repeat.

No copies, no allocations, and it stops the instant it finds a mismatch.

  "A man, a plan, a canal: Panama"
   ^                            ^
   lo                           hi

  'A' vs 'a'  ->  lowercase both  ->  'a' === 'a'   match, step in

  "A man, a plan, a canal: Panama"
     ^                        ^
     lo is on a space -> skip
     hi is on 'm'

  ' ' is not alphanumeric  ->  lo++
  now lo is on 'm', hi is on 'm'   match, step in

  ...and so on, with the commas and colon skipped silently.

The three inner conditions

Each skip loop needs lo < hi in its own condition, not just the outer loop:

the guard that prevents running off the end
while (lo < hi && !isAlphanumeric(s[lo])) lo++;
             ^^^
             without this, a string of pure punctuation walks
             lo past hi and past the end of the string, and
             s[lo] becomes undefined

Try it on ".,": the first skip loop would advance lo forever without the guard. With the guard it stops at lo === hi, the outer loop condition fails, and the function correctly returns true.

the algorithm, narrating itself
function isAlnum(ch) {
  return (ch >= 'a' && ch <= 'z') ||
         (ch >= 'A' && ch <= 'Z') ||
         (ch >= '0' && ch <= '9');
}

function palindromeExplained(s) {
  console.log('s = "' + s + '"');
  let lo = 0, hi = s.length - 1;

  while (lo < hi) {
    while (lo < hi && !isAlnum(s[lo])) {
      console.log("  lo=" + lo + " is '" + s[lo] + "' -- skip");
      lo++;
    }
    while (lo < hi && !isAlnum(s[hi])) {
      console.log("  hi=" + hi + " is '" + s[hi] + "' -- skip");
      hi--;
    }

    if (lo >= hi) break;

    const a = s[lo].toLowerCase();
    const b = s[hi].toLowerCase();
    console.log("  compare lo=" + lo + " '" + s[lo] + "' with hi=" + hi +
                " '" + s[hi] + "'   ->  '" + a + "' vs '" + b + "'   " +
                (a === b ? 'match' : 'MISMATCH'));

    if (a !== b) {
      console.log('  -> FALSE');
      console.log('');
      return false;
    }

    lo++;
    hi--;
  }

  console.log('  pointers met -> TRUE');
  console.log('');
  return true;
}

console.log('==========================================');
console.log('ANSWER:', palindromeExplained('ab_a'));
console.log('==========================================');
console.log('ANSWER:', palindromeExplained('A man, a plan, a canal: Panama'));
Step 6

Version 1 — without built-in methods

Version 1 — no regex, no toLowerCase
function isAlphanumeric(code) {
  return (code >= 48 && code <= 57) ||     // 0-9
         (code >= 65 && code <= 90) ||     // A-Z
         (code >= 97 && code <= 122);      // a-z
}

function toLower(code) {
  // uppercase letters are exactly 32 below their lowercase twins
  if (code >= 65 && code <= 90) return code + 32;
  return code;
}

function isPalindromeManual(s) {
  let lo = 0;
  let hi = s.length - 1;

  while (lo < hi) {
    // walk lo forward past anything we ignore
    while (lo < hi && !isAlphanumeric(s.charCodeAt(lo))) lo = lo + 1;

    // walk hi backward past anything we ignore
    while (lo < hi && !isAlphanumeric(s.charCodeAt(hi))) hi = hi - 1;

    if (lo >= hi) break;

    if (toLower(s.charCodeAt(lo)) !== toLower(s.charCodeAt(hi))) {
      return false;
    }

    lo = lo + 1;
    hi = hi - 1;
  }

  return true;
}

console.log(isPalindromeManual('A man, a plan, a canal: Panama'));   // true
console.log(isPalindromeManual('race a car'));                       // false
console.log(isPalindromeManual(' '));                                // true
console.log(isPalindromeManual('0P'));                               // false
console.log(isPalindromeManual('.,'));                               // true
console.log(isPalindromeManual(''));                                 // true
console.log(isPalindromeManual('a'));                                // true
console.log(isPalindromeManual('ab_a'));                             // true
console.log(isPalindromeManual('12321'));                            // true
console.log(isPalindromeManual('Was it a car or a cat I saw?'));      // true
The 32 trick, and why to be careful with it

'A' is 65 and 'a' is 97 — exactly 32 apart, for every letter. So code + 32 lowercases, and code | 32 does it with one bit operation. It is correct for ASCII letters and wrong for everything else: applied to a digit or punctuation it produces a different character entirely. That is why the guard checks the range first. In real code, use toLowerCase(), which also handles accented letters and other scripts.

Step 7

Version 2 — with built-in methods

Version 2 — the interview answer
function isPalindrome(s) {
  const isAlnum = ch => /[a-z0-9]/i.test(ch);

  let lo = 0;
  let hi = s.length - 1;

  while (lo < hi) {
    while (lo < hi && !isAlnum(s[lo])) lo++;
    while (lo < hi && !isAlnum(s[hi])) hi--;

    if (s[lo].toLowerCase() !== s[hi].toLowerCase()) return false;

    lo++;
    hi--;
  }

  return true;
}

console.log(isPalindrome('A man, a plan, a canal: Panama'));   // true
console.log(isPalindrome('race a car'));                       // false
console.log(isPalindrome(' '));                                // true
console.log(isPalindrome('0P'));                               // false
console.log(isPalindrome('.,'));                               // true
console.log(isPalindrome('Madam, I am Adam'));                  // false
console.log(isPalindrome('Never odd or even'));                 // true
Why there is no if (lo >= hi) break; here

When the skip loops leave lo === hi, the comparison s[lo] !== s[hi] compares a character with itself — always equal, always harmless. So the check can be omitted safely in this version. The Step 6 version keeps it explicit because it is clearer about intent, and because a solution that manipulates indexes further would need it. Either is fine; know which one you wrote and why.

the follow-up: allow one deletion
// "Valid Palindrome II": you may remove at most ONE character.
// When the pointers disagree, try skipping either side and see if
// the rest is a palindrome.
function isPalindromeRange(s, lo, hi) {
  while (lo < hi) {
    if (s[lo] !== s[hi]) return false;
    lo++; hi--;
  }
  return true;
}

function validPalindromeOneDeletion(s) {
  let lo = 0, hi = s.length - 1;

  while (lo < hi) {
    if (s[lo] !== s[hi]) {
      // spend our one deletion on the left OR on the right
      return isPalindromeRange(s, lo + 1, hi) ||
             isPalindromeRange(s, lo, hi - 1);
    }
    lo++;
    hi--;
  }

  return true;
}

console.log(validPalindromeOneDeletion('aba'));      // true  -- no deletion needed
console.log(validPalindromeOneDeletion('abca'));     // true  -- delete 'b' or 'c'
console.log(validPalindromeOneDeletion('abc'));      // false -- one deletion is not enough
console.log(validPalindromeOneDeletion('deeee'));    // true  -- delete 'd'
console.log(validPalindromeOneDeletion('eeccccbebaeeabebccceea'));   // false

// Still O(n): the outer walk is one pass, and when it finds the
// single mismatch it does at most two more linear checks.
checking the two approaches agree
function clean(s) {
  const c = s.toLowerCase().replace(/[^a-z0-9]/g, '');
  return c === [...c].reverse().join('');
}

function pointers(s) {
  const ok = ch => /[a-z0-9]/i.test(ch);
  let lo = 0, hi = s.length - 1;
  while (lo < hi) {
    while (lo < hi && !ok(s[lo])) lo++;
    while (lo < hi && !ok(s[hi])) hi--;
    if (s[lo].toLowerCase() !== s[hi].toLowerCase()) return false;
    lo++; hi--;
  }
  return true;
}

const alphabet = 'aabbAB01 ,.!_-';
let agree = 0;

for (let trial = 0; trial < 500; trial++) {
  const len = Math.floor(Math.random() * 10);
  let s = '';
  for (let i = 0; i < len; i++) {
    s += alphabet[Math.floor(Math.random() * alphabet.length)];
  }
  if (clean(s) === pointers(s)) agree++;
  else console.log('DISAGREE on', JSON.stringify(s));
}

console.log('500 random strings, both methods agree:', agree + '/500');
Step 8

Complexity, in sentences

SolutionTimeSpace
Clean + reverse + compareO(n)O(n)
Two pointers with skipsO(n)O(1)

Why the nested while loops are still O(n). Same argument as every two-pointer solution: lo only increases, hi only decreases, and they meet in the middle. Across the whole run they take at most n steps between them, however those steps are distributed between the skip loops and the outer loop.

The real win is space: three integers instead of three copies of the string. And on a long string that fails early, the two-pointer version stops at the first mismatch while the cleaning version has already processed everything.

Say this in the interview

“Cleaning the string and comparing it with its reverse is O(n) time but O(n) space. Instead I walk two pointers inwards from the ends, skipping any character that is not alphanumeric before each comparison, and comparing lowercased. O(n) time, O(1) space, and it returns as soon as it finds a mismatch. The skip loops need their own lo < hi guard so a string of pure punctuation does not run off the end.”

Step 9

Mistakes people actually make

1. Omitting lo < hi inside the skip loops

Broken — runs off the end
function broken(s) {
  const ok = ch => /[a-z0-9]/i.test(ch);
  let lo = 0, hi = s.length - 1;
  while (lo < hi) {
    while (!ok(s[lo])) lo++;        // no lo < hi guard -- bug
    while (!ok(s[hi])) hi--;
    if (s[lo].toLowerCase() !== s[hi].toLowerCase()) return false;
    lo++; hi--;
  }
  return true;
}

console.log(broken('abba'));    // true   fine
try {
  console.log(broken('.,'));
} catch (err) {
  console.log('threw:', err.message);
}

// On ".," nothing is alphanumeric, so lo runs past the end.
// s[lo] becomes undefined, ok(undefined) is false, and it keeps
// going forever -- until it throws on undefined.toLowerCase().

2. Forgetting to lowercase

Broken — case-sensitive
function broken(s) {
  const ok = ch => /[a-z0-9]/i.test(ch);
  let lo = 0, hi = s.length - 1;
  while (lo < hi) {
    while (lo < hi && !ok(s[lo])) lo++;
    while (lo < hi && !ok(s[hi])) hi--;
    if (s[lo] !== s[hi]) return false;        // no toLowerCase -- bug
    lo++; hi--;
  }
  return true;
}

console.log(broken('aba'));                             // true   fine
console.log(broken('A man, a plan, a canal: Panama'));  // false  WRONG

// 'A' !== 'a'. The very first comparison fails. Lowercase BOTH
// characters, not just one.

3. Only allowing letters, not digits

Broken — digits silently dropped
function broken(s) {
  const ok = ch => /[a-z]/i.test(ch);        // letters only -- bug
  let lo = 0, hi = s.length - 1;
  while (lo < hi) {
    while (lo < hi && !ok(s[lo])) lo++;
    while (lo < hi && !ok(s[hi])) hi--;
    if (s[lo].toLowerCase() !== s[hi].toLowerCase()) return false;
    lo++; hi--;
  }
  return true;
}

console.log(broken('0P'));       // TRUE   WRONG, should be false
console.log(broken('12321'));    // TRUE   right, but by accident --
                                 // every digit was skipped, leaving ""
console.log(broken('1a2'));      // TRUE   WRONG -- only 'a' survived

// "Alphanumeric" includes digits. Read the requirement literally:
// [a-z0-9], not [a-z].

4. Using reverse() on the original string

s === [...s].reverse().join('') without cleaning first answers a different question — “is the raw string, punctuation and all, a palindrome?”. For "A man, a plan, a canal: Panama" that is false. Either clean first, or use pointers and skip.

5. Building the cleaned string and then still using two pointers

Not wrong, just pointless — you have already paid the O(n) space, so cleaned === reversed is simpler. Pick one approach and commit to it. Mixing them gets you the cost of both and the benefit of neither.

Step 10

Practice before you move on

  1. Write the pointer version from memory, then test it on ".," and " ". Those two catch the missing guard.
  2. Valid Palindrome II — one deletion allowed. It is in Step 7; write it from memory and explain why it is still O(n) despite the two extra checks.
  3. Two deletions allowed. The same idea does not extend cleanly — work out why, and what it would cost to allow k deletions.
  4. Longest palindromic substring, ignoring punctuation. Combine this page’s skipping with the expand-around-centre technique from the strings topic.
  5. Palindrome number. Is 121 a palindrome without converting it to a string? Peel digits off both ends with % 10 and division — the same two pointers, in arithmetic.
What to carry forward

Skip in place instead of building a filtered copy. Whenever you find yourself writing input.filter(...) and then walking the result, ask whether the walk could just skip the unwanted items itself. It saves the allocation, it preserves the original indexes (often useful), and it lets you exit early instead of processing everything first.
