Two pointers · Problem 04

Sort 0s, 1s and 2s

The same problem as Sort Colors, approached from the two-pointer side. This page focuses on the part that page did not: the honest comparison between counting sort and the one-pass Dutch flag, and how to generalise both.

Step 1

The problem

An array contains only 0, 1 and 2. Sort it in place without calling a sort function.

InputAnswer
[0, 1, 2, 0, 1, 2][0, 0, 1, 1, 2, 2]
[2, 2, 1, 1, 0, 0][0, 0, 1, 1, 2, 2]
[1][1]
[0, 0, 0][0, 0, 0]
Why a general sort is overkill

A comparison sort has to be O(n log n) in the worst case — that is a proven lower bound. But that bound only applies when all you can do is compare. Here you know something stronger: there are exactly three possible values. Knowledge about the data beats a general-purpose algorithm, and it is what lets you get to O(n).

Step 2

Think first — count them

Version 0 — counting sort, two passes
function sortByCounting(nums) {
  let zeros = 0, ones = 0, twos = 0;

  // PASS 1: how many of each?
  for (let i = 0; i < nums.length; i++) {
    if (nums[i] === 0) zeros++;
    else if (nums[i] === 1) ones++;
    else twos++;
  }

  // PASS 2: write them back in order
  let i = 0;
  for (let k = 0; k < zeros; k++) nums[i++] = 0;
  for (let k = 0; k < ones;  k++) nums[i++] = 1;
  for (let k = 0; k < twos;  k++) nums[i++] = 2;

  return nums;
}

console.log(sortByCounting([0,1,2,0,1,2]));   // [0,0,1,1,2,2]
console.log(sortByCounting([2,2,1,1,0,0]));   // [0,0,1,1,2,2]
console.log(sortByCounting([1]));             // [1]
console.log(sortByCounting([]));              // []
console.log(sortByCounting([2,0,1]));         // [0,1,2]

// O(n) time, O(1) space, in place, two passes.
// This is a completely correct answer. Do not let anyone tell you
// otherwise -- the one-pass version is more elegant, not more correct.

Counting sort is the answer most people give and it deserves respect: it is short, obviously right, and impossible to get subtly wrong. The interview question is usually “can you do it in one pass?”, which is a different question from “can you do it faster?”.

Step 3

Why one pass, honestly

Both are O(n). Both are O(1) space. So what does one pass actually buy?

  • Streams. If the data arrives once and cannot be re-read, two passes is not an option.
  • Cache behaviour. One walk over a very large array beats two, because the second walk has to pull everything back from memory again.
  • Stability of the technique. The three-way partition generalises to a pivot (see Step 7); counting does not.
Timing demo — and a fair comparison
const N = 5000000;
const base = [];
for (let i = 0; i < N; i++) base.push(i % 3);

function counting(a) {
  let c0 = 0, c1 = 0, c2 = 0;
  for (let i = 0; i < a.length; i++) {
    if (a[i] === 0) c0++; else if (a[i] === 1) c1++; else c2++;
  }
  let i = 0;
  while (c0-- > 0) a[i++] = 0;
  while (c1-- > 0) a[i++] = 1;
  while (c2-- > 0) a[i++] = 2;
  return a;
}

function dutchFlag(a) {
  let low = 0, mid = 0, high = a.length - 1;
  while (mid <= high) {
    if (a[mid] === 0)      { const t = a[low];  a[low]  = a[mid]; a[mid] = t; low++; mid++; }
    else if (a[mid] === 2) { const t = a[high]; a[high] = a[mid]; a[mid] = t; high--; }
    else mid++;
  }
  return a;
}

function librarySort(a) { return a.sort((x, y) => x - y); }

Step 4

The better idea — three regions

Keep three pointers describing four zones of the array:

  [ 0 0 0 ][ 1 1 1 ][ ? ? ? ? ? ][ 2 2 2 ]
            ^        ^           ^
           low      mid         high

  before low   : settled 0s
  low to mid   : settled 1s
  mid to high  : not yet examined
  after high   : settled 2s
The unlock

Look at nums[mid]. There are exactly three cases and each forces one action:

  • 0 — swap with low, then low++ and mid++.
  • 1 — already correct, just mid++.
  • 2 — swap with high, then high-- only.
The asymmetry, one more time

On a 0 you advance mid; on a 2 you do not.

low sits inside territory you have already swept, so whatever it hands back is known — a 1, or the element itself. high sits at the edge of the unexamined region, so whatever it hands back could be anything, including another 2. You must look at it.

The loop condition is mid <= high, with <=: when they are equal there is still one unexamined element sitting there.

Step 5

Dry run — trace it by hand

nums = [2, 0, 1, 2, 1, 0]. Start low=0 mid=0 high=5.

          array               low mid high    action

start   [2,0,1,2,1,0]          0   0   5

mid=0 value 2  -> swap with high(5), high--, mid STAYS
        [0,0,1,2,1,2]          0   0   4

mid=0 value 0  -> swap with low(0) (itself), low++ mid++
        [0,0,1,2,1,2]          1   1   4

mid=1 value 0  -> swap with low(1) (itself), low++ mid++
        [0,0,1,2,1,2]          2   2   4

mid=2 value 1  -> leave it, mid++
        [0,0,1,2,1,2]          2   3   4

mid=3 value 2  -> swap with high(4), high--, mid STAYS
        [0,0,1,1,2,2]          2   3   3

mid=3 value 1  -> leave it, mid++
        [0,0,1,1,2,2]          2   4   3

mid(4) > high(3)  ->  STOP

answer: [0,0,1,1,2,2]

Six elements, seven iterations. Each iteration either advances mid or retreats high, so the unexamined gap shrinks by exactly one every time — that is the termination proof and the O(n) proof at once.

the algorithm, narrating itself
function sortExplained(nums) {
  let low = 0, mid = 0, high = nums.length - 1;

  console.log('start  [' + nums.join(',') + ']   low=0 mid=0 high=' + high);
  console.log('');

  let steps = 0;

  while (mid <= high) {
    steps++;
    const v = nums[mid];

    if (v === 0) {
      [nums[low], nums[mid]] = [nums[mid], nums[low]];
      low++; mid++;
      console.log('value 0 -> swap with low, low++ mid++   [' + nums.join(',') +
                  ']   low=' + low + ' mid=' + mid + ' high=' + high);
    } else if (v === 2) {
      [nums[high], nums[mid]] = [nums[mid], nums[high]];
      high--;
      console.log('value 2 -> swap with high, high-- ONLY  [' + nums.join(',') +
                  ']   low=' + low + ' mid=' + mid + ' high=' + high);
    } else {
      mid++;
      console.log('value 1 -> leave it, mid++             [' + nums.join(',') +
                  ']   low=' + low + ' mid=' + mid + ' high=' + high);
    }
  }

  console.log('');
  console.log(steps + ' iterations for ' + nums.length + ' elements');
  console.log('');
  return nums;
}

Step 6

Version 1 — without built-in methods

Version 1 — three pointers, manual swaps
function sortColorsManual(nums) {
  let low = 0;                    // next slot for a 0
  let mid = 0;                    // the element being examined
  let high = nums.length - 1;     // next slot for a 2

  while (mid <= high) {

    if (nums[mid] === 0) {
      const tmp = nums[low];
      nums[low] = nums[mid];
      nums[mid] = tmp;
      low = low + 1;
      mid = mid + 1;              // the incoming value is known-good

    } else if (nums[mid] === 2) {
      const tmp = nums[high];
      nums[high] = nums[mid];
      nums[mid] = tmp;
      high = high - 1;
      // mid does NOT move -- the incoming value is unexamined

    } else {
      mid = mid + 1;
    }
  }

  return nums;
}

console.log(sortColorsManual([2,2,1,1,0,0]));       // [0,0,1,1,2,2]
console.log(sortColorsManual([1]));                 // [1]
console.log(sortColorsManual([]));                  // []

console.log(sortColorsManual([1,0,2,1,0,2,1,0,2])); // [0,0,0,1,1,1,2,2,2]
counting the work: swaps vs writes
// A fair comparison people rarely make: counting sort does 2n
// reads/writes; Dutch flag does n reads plus up to n swaps, and a
// swap is three assignments.
function countingInstrumented(nums) {
  let ops = 0;
  let c0 = 0, c1 = 0, c2 = 0;
  for (let i = 0; i < nums.length; i++) { ops++; if (nums[i]===0) c0++; else if (nums[i]===1) c1++; else c2++; }
  let i = 0;
  while (c0-- > 0) { nums[i++] = 0; ops++; }
  while (c1-- > 0) { nums[i++] = 1; ops++; }
  while (c2-- > 0) { nums[i++] = 2; ops++; }
  return ops;
}

function dutchInstrumented(nums) {
  let ops = 0;
  let low = 0, mid = 0, high = nums.length - 1;
  while (mid <= high) {
    ops++;                                    // the read
    if (nums[mid] === 0) {
      const t = nums[low]; nums[low] = nums[mid]; nums[mid] = t;
      ops += 3;                               // the swap
      low++; mid++;
    } else if (nums[mid] === 2) {
      const t = nums[high]; nums[high] = nums[mid]; nums[mid] = t;
      ops += 3;
      high--;
    } else mid++;
  }
  return ops;
}

  return a;
};

Step 7

Version 2 — with built-in methods

Version 2 — destructuring swap
function sortColors(nums) {
  let low = 0, mid = 0, high = nums.length - 1;

  while (mid <= high) {
    if (nums[mid] === 0) {
      [nums[low], nums[mid]] = [nums[mid], nums[low]];
      low++;
      mid++;
    } else if (nums[mid] === 2) {
      [nums[high], nums[mid]] = [nums[mid], nums[high]];
      high--;
    } else {
      mid++;
    }
  }

  return nums;
}

console.log(sortColors([0,1,2,0,1,2]));   // [0,0,1,1,2,2]
console.log(sortColors([2,0,1]));         // [0,1,2]
console.log(sortColors([1,2,0]));         // [0,1,2]
generalising: counting sort for k values
// Counting sort extends to any small set of values; Dutch flag
// does not extend past three without getting ugly.
function countingSortSmallRange(nums, maxValue) {
  const counts = new Array(maxValue + 1).fill(0);
  for (const n of nums) counts[n]++;

  let i = 0;
  for (let value = 0; value <= maxValue; value++) {
    for (let k = 0; k < counts[value]; k++) nums[i++] = value;
  }
  return nums;
}

console.log(countingSortSmallRange([3,1,4,1,5,9,2,6,5,3,5], 9));
console.log(countingSortSmallRange([2,0,1,2,0,1], 2));
console.log(countingSortSmallRange([0,0,0], 2));

// O(n + k). Beats n log n whenever k is small relative to n --
// grades, ages, priorities, small enum values. It is the same
// "index by the key" idea as bucket sort in Top K Frequent.
generalising: three-way partition around a pivot
// This is where Dutch flag earns its place: partition into
// less / equal / greater around any pivot. It is the partition step
// of a quicksort that handles duplicates well.
function partitionThreeWay(arr, pivot, compare = (a, b) => a - b) {
  let low = 0, mid = 0, high = arr.length - 1;

  while (mid <= high) {
    const c = compare(arr[mid], pivot);
    if (c < 0)      { [arr[low], arr[mid]] = [arr[mid], arr[low]]; low++; mid++; }
    else if (c > 0) { [arr[high], arr[mid]] = [arr[mid], arr[high]]; high--; }
    else            { mid++; }
  }

  return { lessEnd: low, greaterStart: high + 1 };
}

const nums = [5, 3, 8, 5, 1, 9, 5, 2];
console.log('bounds:', partitionThreeWay(nums, 5), nums);
// everything before lessEnd is < 5, from greaterStart onwards is > 5

// And a quicksort built on it -- notice the recursion skips the
// whole EQUAL block, which is why duplicate-heavy arrays are fast.
function quickSort3(arr, lo = 0, hi = arr.length - 1) {
  if (lo >= hi) return arr;

  const pivot = arr[Math.floor((lo + hi) / 2)];
  let i = lo, mid = lo, j = hi;

  while (mid <= j) {
    if (arr[mid] < pivot)      { [arr[i], arr[mid]] = [arr[mid], arr[i]]; i++; mid++; }
    else if (arr[mid] > pivot) { [arr[j], arr[mid]] = [arr[mid], arr[j]]; j--; }
    else mid++;
  }

  quickSort3(arr, lo, i - 1);
  quickSort3(arr, j + 1, hi);
  return arr;
}

console.log(quickSort3([5,3,8,5,1,9,5,2,7,5]));
console.log(quickSort3([3,3,3,3,3]));            // the case two-way quicksort hates
console.log(quickSort3([]));
Step 8

Complexity, in sentences

SolutionTimeSpacePassesGeneralises to
Library sortO(n log n)O(n)—anything
Counting sortO(n + k)O(k)twoany small k
Dutch flagO(n)O(1)onethree-way partition

Why the Dutch flag terminates and is linear: every iteration either increments mid or decrements high, so the size of the unexamined region high - mid shrinks by exactly one each time. It starts at n - 1 and the loop ends when it goes negative — at most n iterations.

Say that argument rather than “it looks linear”. It is the difference between having reasoned about the algorithm and having recognised it.

Say this in the interview

“With only three values I do not need a comparison sort. Counting sort is two passes: count each value, then rewrite. For one pass I use three pointers — low, mid and high — with the invariant that everything before low is 0, between low and mid is 1, and after high is 2. On a 0 I swap with low and advance both; on a 2 I swap with high and only move high, because the incoming value has not been examined; on a 1 I advance mid. Each iteration shrinks the unknown region by one, so O(n) time, O(1) space.”

Step 9

Mistakes people actually make

1. Advancing mid after swapping with high

Broken — skips an unexamined value
function broken(nums) {
  let low = 0, mid = 0, high = nums.length - 1;
  while (mid <= high) {
    if (nums[mid] === 0)      { [nums[low],nums[mid]]=[nums[mid],nums[low]]; low++; mid++; }
    else if (nums[mid] === 2) { [nums[high],nums[mid]]=[nums[mid],nums[high]]; high--; mid++; }
    else mid++;
  }
  return nums;
}

console.log(broken([0,1,2,0,1,2]));   // [0,0,1,1,2,2]  right, by luck
console.log(broken([2,2,0,1]));       // [1,0,2,2]      WRONG
console.log(broken([2,0,0,1]));       // [1,0,0,2]      WRONG

// On [2,2,0,1]: mid=0 sees a 2, swaps the 1 in from the end, then
// skips past it. That 1 sits at index 0 forever.

2. Using mid < high instead of <=

Broken — misses the last element
function broken(nums) {
  let low = 0, mid = 0, high = nums.length - 1;
  while (mid < high) {          // should be <=
    if (nums[mid] === 0)      { [nums[low],nums[mid]]=[nums[mid],nums[low]]; low++; mid++; }
    else if (nums[mid] === 2) { [nums[high],nums[mid]]=[nums[mid],nums[high]]; high--; }
    else mid++;
  }
  return nums;
}

console.log(broken([0,1,2,0,1,2]));   // [0,0,1,1,2,2]  right
console.log(broken([1,0]));           // [1,0]          WRONG
console.log(broken([2,1]));           // [1,2]          right

// When mid === high there is still one element nobody has looked at.
// The bug only shows on tiny arrays and on inputs where the final
// element is out of place -- so test [1,0] every time.

3. Forgetting low++

Without it, the zeros region never grows, so the next 0 swaps into the same slot and overwrites the previous one. The result has the wrong counts entirely — obvious the moment you print the array, invisible if you only check that it is sorted at the front.

4. Reaching for a sort function

and the numeric-comparator reminder
// The problem forbids it, but know the trap anyway:
console.log([2,0,1,10].sort());                  // [0,1,10,2]  string order
console.log([2,0,1,10].sort((a,b) => a - b));    // [0,1,2,10]  numeric

// Also: sort() MUTATES and returns the same array.
const a = [2,0,1];
const b = a.sort((x,y) => x - y);
console.log(a, b, a === b);                      // both sorted, same object

// The non-mutating version, in newer runtimes:
if (Array.prototype.toSorted) {
  const c = [2,0,1];
  console.log(c.toSorted((x,y) => x - y), c);    // sorted copy, c untouched
}

5. Assuming the values are exactly 0, 1, 2

The algorithm has no branch for anything else — a stray 3 would be treated as a 1 and left stranded in the middle. Correct for this problem’s guarantees. If you generalise, use the three-way comparison version from Step 7 rather than equality tests.

Step 10

Practice before you move on

  1. Write both versions from memory, then say which you would ship and why. (Counting sort, most days. Say so — being able to defend the simpler choice is a senior signal.)
  2. Sort 0s and 1s only. Two pointers, no middle region — and notice it is exactly Move Zeroes.
  3. Sort by a boolean property, in place. Move every object where isActive is true to the front. Same partition, different test.
  4. Three-way quicksort. In Step 7 — write it from memory, then race it against a two-way quicksort on an array of a million values drawn from five distinct numbers.
  5. Prove the termination in one sentence without looking at Step 8. Interviewers ask this exact follow-up.
What to carry forward

Knowing something about your data beats a general algorithm. The O(n log n) lower bound applies to comparison sorts; the moment you know the values come from a small fixed set, you can index by them instead of comparing them, and linear becomes possible. The same reasoning gives you bucket sort, counting sort and radix sort. Whenever a sort feels expensive, ask: what do I know about these values that a general sort does not?
