Object & data shaping · Problem 05

Flat List With parentId → Nested Tree

Every database gives you a flat table; every UI wants a tree. The good answer is one pass with a lookup map — and the reason it works in one pass is a trick worth understanding, because it does not depend on the rows being in any order.

Version 0 — the ten-line answer
function listToTree(items, { idKey = 'id', parentKey = 'parentId' } = {}) {
  const byId = new Map();
  const roots = [];

  // pass 1: put every node in the map, with an empty children array
  for (const item of items) {
    byId.set(item[idKey], { ...item, children: [] });
  }

  // pass 2: attach each node to its parent, or to roots
  for (const item of items) {
    const node = byId.get(item[idKey]);
    const parent = byId.get(item[parentKey]);
    if (parent) parent.children.push(node);
    else roots.push(node);
  }

  return roots;
}

Why two passes, and why one is not enough

In one pass, a child that appears before its parent has nowhere to go — the parent's node does not exist yet.

Two passes fixes that: create every node first, then wire them up. And because the second pass only looks up parents rather than searching for them, the whole thing is O(n).

You can do it in one pass if you are willing to create placeholder parents on demand — shown in Step 7 — but two passes is clearer and the same complexity.

function buildWithMap(items) {
  let ops = 0;
  const byId = new Map();
  for (const item of items) { ops++; byId.set(item.id, { ...item, children: [] }); }
  const roots = [];
  for (const item of items) {
    ops++;
    const node = byId.get(item.id);
    const parent = byId.get(item.parentId);
    if (parent) parent.children.push(node);
    else roots.push(node);
  }
  return { roots, ops };
}

  const byId = new Map();
  for (const item of items) byId.set(item.id, { ...item, children: [] });
  const roots = [];
  for (const item of items) {

Step 4

The better idea — the trick that makes one pass possible

  Two passes:

    PASS 1   id -> node, with children: []

      1 -> { id: 1, children: [] }
      2 -> { id: 2, children: [] }
      3 -> { id: 3, children: [] }
      4 -> { id: 4, children: [] }

    PASS 2   for each row, look up its parent and push

      row 4 (parent 2)   byId.get(2).children.push(node4)
      row 1 (parent null) no parent  ->  roots.push(node1)
      row 3 (parent 1)   byId.get(1).children.push(node3)
      row 2 (parent 1)   byId.get(1).children.push(node2)


  The crucial detail: `node2` was ALREADY in the map when row 4
  attached to it, and node4 was already attached when node2 was
  pushed into node1.

  Objects are references. Attaching a child to a node that is
  itself not yet attached anywhere still works -- when the parent
  is finally attached, its whole subtree comes with it.

  That is why the row ORDER does not matter, and why you never
  have to sort the input or do multiple sweeps.

The four questions to settle before writing it

Orphans — a row whose parentId points at nothing. Treat as a root, drop, or throw?

Cycles — A's parent is B and B's parent is A. Neither ever becomes a root, so both silently disappear from the output.

Multiple roots — a forest, not a tree. Very common, and the reason the function returns an array.

Order — children come out in row order. If the UI needs alphabetical or by a sortOrder column, sort each children array afterwards.

function listToTreeManual(items, idKey, parentKey) {
  if (idKey === undefined) idKey = 'id';
  if (parentKey === undefined) parentKey = 'parentId';

  // Object.create(null) so an id of "__proto__" or "constructor"
  // is just an id
  const byId = Object.create(null);
  const roots = [];
  let rootCount = 0;

  for (let i = 0; i < items.length; i++) {
    const item = items[i];
    const copy = {};
    for (const k in item) {
      if (Object.prototype.hasOwnProperty.call(item, k)) copy[k] = item[k];
    }
    copy.children = [];
    byId[item[idKey]] = copy;
  }

  for (let i = 0; i < items.length; i++) {
    const item = items[i];
    const node = byId[item[idKey]];
    const parentId = item[parentKey];
    const parent = (parentId === null || parentId === undefined)
      ? undefined
      : byId[parentId];

    if (parent !== undefined) {
      parent.children[parent.children.length] = node;
    } else {
      roots[rootCount] = node;
      rootCount = rootCount + 1;
    }
  }

  return roots;
}

function listToTree(items, options = {}) {
  const {
    idKey = 'id',
    parentKey = 'parentId',
    childrenKey = 'children',
    rootValues = [null, undefined, 0, ''],   // what counts as "no parent"
    orphans = 'root',                        // 'root' | 'drop' | 'throw'
    sortBy = null,
    addDepth = false,
  } = options;

  const isRoot = (v) => rootValues.includes(v);

  const byId = new Map();
  for (const item of items) {
    byId.set(item[idKey], { ...item, [childrenKey]: [] });
  }

  const roots = [];
  const orphaned = [];

  for (const item of items) {
    const node = byId.get(item[idKey]);
    const parentId = item[parentKey];

    if (isRoot(parentId)) { roots.push(node); continue; }

    const parent = byId.get(parentId);
    if (parent) {
      if (parent === node) {                 // self-parent
        orphaned.push(node);
        continue;
      }
      parent[childrenKey].push(node);
    } else {
      orphaned.push(node);
    }
  }

  if (orphaned.length) {
    if (orphans === 'throw') {
      throw new Error('orphaned nodes: ' +
        orphaned.map((n) => n[idKey]).join(', '));
    }
    if (orphans === 'root') roots.push(...orphaned);
    // 'drop' -> do nothing
  }

  // a node that is in a cycle is never reachable from any root
  const reachable = new Set();
  (function mark(nodes, depth) {
    for (const n of nodes) {
      if (reachable.has(n)) continue;        // guards a cycle in the tree itself
      reachable.add(n);
      if (addDepth) n.depth = depth;
      if (sortBy) n[childrenKey].sort(sortBy);
      mark(n[childrenKey], depth + 1);
    }
  })(roots, 0);

  const lost = [...byId.values()].filter((n) => !reachable.has(n));

  return { tree: roots, orphaned, unreachable: lost };
}

the one-pass version, and when it is worth it
// Create placeholder parents on demand, so a single pass suffices.
function listToTreeOnePass(items, idKey = 'id', parentKey = 'parentId') {
  const byId = new Map();
  const roots = [];

  const ensure = (id) => {
    if (!byId.has(id)) byId.set(id, { children: [], __placeholder: true });
    return byId.get(id);
  };

  for (const item of items) {
    const node = ensure(item[idKey]);
    Object.assign(node, item);           // fill in the real fields
    delete node.__placeholder;

    const parentId = item[parentKey];
    if (parentId === null || parentId === undefined) roots.push(node);
    else ensure(parentId).children.push(node);
  }

  // any node still marked as a placeholder was referenced as a
  // parent but never appeared as a row -- so its children are
  // orphans
  const orphaned = [];
  for (const [id, node] of byId) {
    if (node.__placeholder) {
      orphaned.push(...node.children);
      byId.delete(id);
    }
  }
  roots.push(...orphaned);

  return roots;
}

function listToTreeTwoPass(items) {
  const byId = new Map();
  for (const item of items) byId.set(item.id, { ...item, children: [] });
  const roots = [];
  for (const item of items) {
    const node = byId.get(item.id);
    const parent = byId.get(item.parentId);
    (parent ? parent.children : roots).push(node);
  }
  return roots;
}

// 1. the PATH to every node -- for breadcrumbs and permalinks
function withPaths(nodes, prefix = []) {
  const out = [];
  for (const n of nodes) {
    const path = [...prefix, n.name];
    out.push({ id: n.id, path: path.join('/'), depth: path.length - 1 });
    out.push(...withPaths(n.children, path));
  }
  return out;
}

function findWithAncestors(nodes, id, trail = []) {
  for (const n of nodes) {
    if (n.id === id) return [...trail, n];
    const found = findWithAncestors(n.children, id, [...trail, n]);
    if (found) return found;
  }
  return null;
}

// 3. filter the tree, KEEPING ancestors of anything that matches
function filterTree(nodes, predicate) {
  const out = [];
  for (const n of nodes) {
    const children = filterTree(n.children, predicate);
    if (predicate(n) || children.length) out.push({ ...n, children });
  }
  return out;
}

function withCounts(nodes) {
  return nodes.map((n) => {
    const children = withCounts(n.children);

Step 8

Complexity, in sentences

ApproachTimeSpace
recursive filterO(n2)O(n)
two passes with a mapO(n)O(n)
one pass with placeholdersO(n)O(n)
with a sort per nodeO(n log n)O(n)

The two-pass version does n map inserts and n map lookups, both O(1) amortised, so O(n) total. Space is one map entry and one node object per row — and note the nodes are shared between the map and the tree, so it is O(n) objects, not 2n.

The last row is worth flagging: sorting each children array is O(n log n) overall (the sum of k log k over all sibling groups is bounded by n log n), which is fine — but doing it inside a recursive traversal that also rebuilds nodes with spread is how a linear algorithm quietly becomes something worse.

Say this in the interview

“Two passes and a Map from id to node. First pass creates every node with an empty children array; second pass looks up each row's parent and pushes the node into it, or into the roots list if there is no parent. It is O(n) because the second pass looks parents up rather than searching for them, and it works regardless of row order because after pass one every node exists — attaching a child to a not-yet-attached parent is fine, since these are references and the whole subtree travels with the parent when it is finally attached. The cases to handle are orphans, whose parent id points at nothing, and cycles, where two nodes point at each other and silently never appear in the output at all.”

function listToTreeChecked(items) {
  const byId = new Map();
  for (const item of items) byId.set(item.id, { ...item, children: [] });
  const roots = [];
  for (const item of items) {
    const node = byId.get(item.id);
    if (item.parentId === item.id) {
      throw new Error('node ' + item.id + ' is its own parent');
    }
    const parent = byId.get(item.parentId);
    (parent ? parent.children : roots).push(node);
  }

  const reachable = new Set();
  (function mark(nodes) {
    for (const n of nodes) {
      if (reachable.has(n)) continue;
      reachable.add(n);
      mark(n.children);
    }
  })(roots);

  const lost = [...byId.values()].filter((n) => !reachable.has(n));
  if (lost.length) {
    throw new Error('unreachable nodes (a cycle?): ' +
      lost.map((n) => n.id).join(', '));
  }
  return roots;
}

Step 10

Practice before you move on

  1. Write the two-pass version from memory, then explain why row order does not matter — the reference argument in Step 4 is the answer.
  2. Handle orphans and cycles. Step 7 — and say what a cycle does if you do not handle it.
  3. Write the one-pass version so you can answer the follow-up, then say why you would still ship two passes.
  4. Write filterTree keeping ancestors. Step 7 — it is what every searchable tree UI needs and it is four lines.
  5. Tree back to a flat list. The next page — the same trip in reverse.
What to carry forward

Build an index, then use it. That is the same move as Two Sum, groupBy and keyBy: replace “search the collection again” with “look it up”. The part specific to trees is the reference insight — attaching a child to a parent that is not yet attached anywhere works, so you never need to sort the input or sweep repeatedly. And always ask what happens to rows that are unreachable, because the default answer is that they disappear without a word.
