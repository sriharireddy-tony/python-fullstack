Object & data shaping · Problem 01

Group an Array of Objects by Key

Four lines, and you will write it every week of your working life. The interesting parts are the ones that bite in production: keys that are not strings, the spread that turns it quadratic, and the built-in that finally landed.

Step 1

The problem

Version 0 — the four-line answer
function groupBy(items, keyOf) {
  return items.reduce((acc, item) => {
    const key = typeof keyOf === 'function' ? keyOf(item) : item[keyOf];
    (acc[key] ||= []).push(item);
    return acc;
  }, {});
}

const people = [
  { name: 'Ada', city: 'London', age: 36 },
  { name: 'Grace', city: 'New York', age: 45 },
  { name: 'Alan', city: 'London', age: 41 },
  { name: 'Edsger', city: 'Amsterdam', age: 42 },
];

}

  console.log('  ' + decade.padEnd(10) + group.map((p) => p.name).join(', '));

console.log('  create the bucket if it does not exist, then push.');
console.log('');

console.log('  acc[key].push(item);');
One thing that version gets wrong

(acc[key] ||= []) reads acc[key] first — and a plain {} inherits toString, constructor, valueOf and the rest from Object.prototype. Group by a key called "toString" and the read finds a function, ||= leaves it alone, and .push throws.

Fine when the keys are yours. A real bug when they come from data. Step 9 shows it failing, and the two fixes: Object.create(null) or a Map.

Two things to be deliberate about

The key becomes a string. Object keys always do. Group by an object, a Date or a boolean and you get "[object Object]", "Mon Jan..." or "true" — sometimes fine, often a collision.

The groups hold references, not copies. Mutating a grouped item mutates the original. Usually what you want; occasionally a surprise.

Step 2

Think first — the nested-loop version

Version 0a — filter once per distinct key
function groupByFilter(items, key) {
  const keys = [...new Set(items.map((i) => i[key]))];
  const out = {};
  let comparisons = 0;
  for (const k of keys) {
    out[k] = items.filter((i) => { comparisons++; return i[key] === k; });
  }
  return { out, comparisons };
}

function groupByReduce(items, key) {
  let comparisons = 0;
  const out = items.reduce((acc, item) => {
    comparisons++;
    (acc[item[key]] ||= []).push(item);
    return acc;
  }, {});
  return { out, comparisons };
}

Step 3

Why the spread version is the one to watch for

The “functional” grouping that spreads the accumulator looks elegant and is quadratic. This is the single most common performance bug in data-shaping code.

Timing demo — spread versus mutate
const N = 4000;
const records = [];
for (let i = 0; i < N; i++) records.push({ id: i, group: 'g' + (i % 200) });

// spreads the whole accumulator on every item
const withSpread = (items) => items.reduce((acc, item) => ({
  ...acc,
  [item.group]: [...(acc[item.group] || []), item],
}), {});

// mutates the accumulator it already owns
const withMutation = (items) => items.reduce((acc, item) => {
  (acc[item.group] ||= []).push(item);
  return acc;
}, {});

let t = performance.now();
const a = withSpread(records);
const spreadMs = performance.now() - t;

t = performance.now();
const b = withMutation(records);
const mutateMs = performance.now() - t;

console.log(N.toLocaleString('en-US') + ' records into 200 groups');
console.log('  spread the accumulator: ' + spreadMs.toFixed(1) + ' ms');
console.log('  mutate the accumulator: ' + mutateMs.toFixed(1) + ' ms');
console.log('  ratio                 : ' +
            Math.round(spreadMs / Math.max(mutateMs, 0.01)) + 'x');
console.log('  identical result      :',
            JSON.stringify(Object.keys(a).sort()) === JSON.stringify(Object.keys(b).sort()) &&
            Object.keys(a).every((k) => a[k].length === b[k].length));

console.log('');
console.log('The spread copies every key of the accumulator on every');
console.log('single item -- and the accumulator grows. It also copies');

Step 4

The better idea — one pass, and choose your container

  for each item:
      key = keyOf(item)
      bucket = out[key]  or  a new []
      bucket.push(item)

  Three decisions, and each has a right answer for a given case:

  1. WHAT IS THE KEY?
        a property name          groupBy(items, 'city')
        a computed value         groupBy(items, p => p.age > 40)
        several properties       groupBy(items, p => p.city + '|' + p.role)

  2. WHAT GOES IN THE BUCKET?
        the whole item           the default
        one field                groupBy(items, 'city', p => p.name)
        a count                  countBy
        a single item            keyBy / indexBy (last one wins)

  3. OBJECT OR MAP?
        object   keys are strings, JSON-friendly, integer keys reorder
        Map      any key type, insertion-ordered, no prototype
When to reach for a Map

Use a plain object when the keys are strings you will serialise. Use a Map when the keys are objects or dates, when insertion order matters and the keys look numeric, or when the keys come from user data — because "__proto__" as an object key is a real problem, shown in Step 9.

function groupByLoud(items, keyOf) {
  const acc = {};

  items.forEach((item, i) => {
    const key = typeof keyOf === 'function' ? keyOf(item) : item[keyOf];
    const existed = Object.prototype.hasOwnProperty.call(acc, key);

    if (!existed) acc[key] = [];
    acc[key].push(item);

    console.log('item ' + (i + 1) + ': ' + JSON.stringify(item));
    console.log('  key ' + JSON.stringify(key) +
                (existed ? '  -- bucket exists, pushing' : '  -- NEW bucket'));
    console.log('  acc: ' + JSON.stringify(
      Object.fromEntries(Object.entries(acc).map(([k, v]) =>
        [k, v.map((x) => x.name)]))));
  });

  return acc;
}

Version 1 — without built-in methods

Version 1 — index loops, no reduce, no spread
function groupByManual(items, keyOf) {
  // no prototype at all, so "__proto__", "toString" and
  // "constructor" are ordinary keys
  const out = Object.create(null);

  for (let i = 0; i < items.length; i++) {
    const item = items[i];
    const key = typeof keyOf === 'function' ? keyOf(item, i) : item[keyOf];

    let bucket = out[key];
    if (bucket === undefined) {
      bucket = [];
      out[key] = bucket;
    }
    bucket[bucket.length] = item;
  }

  return out;
}

Version 2 — the family

groupBy, countBy, keyBy, partition
const iterate = (keyOf) => (item, i) =>
  typeof keyOf === 'function' ? keyOf(item, i) : item[keyOf];

// every item that shares a key, in a list
function groupBy(items, keyOf, valueOf = (x) => x) {
  const get = iterate(keyOf);
  const out = {};
  items.forEach((item, i) => {
    (out[get(item, i)] ||= []).push(valueOf(item, i));
  });
  return out;
}

// how many share each key
function countBy(items, keyOf) {
  const get = iterate(keyOf);
  const out = {};
  items.forEach((item, i) => {
    const k = get(item, i);
    out[k] = (out[k] || 0) + 1;
  });
  return out;
}

// ONE item per key -- last one wins. For building a lookup table.
function keyBy(items, keyOf) {
  const get = iterate(keyOf);
  const out = {};
  items.forEach((item, i) => { out[get(item, i)] = item; });
  return out;
}

// exactly two groups, from a predicate
function partition(items, predicate) {
  const pass = [], fail = [];
  items.forEach((item, i) => (predicate(item, i) ? pass : fail).push(item));
  return [pass, fail];
}

// sum / average per key -- the reporting shape
function aggregateBy(items, keyOf, valueOf) {
  const get = iterate(keyOf);
  const acc = {};
  for (const item of items) {
    const k = get(item);
    acc[k] ||= { count: 0, total: 0 };
    acc[k].count++;
    acc[k].total += valueOf(item);
  }
  return Object.fromEntries(Object.entries(acc).map(([k, v]) => [k, {
    count: v.count, total: v.total, average: +(v.total / v.count).toFixed(2),
  }]));
}

// 1. a COMPOSITE key -- flat result, one level
function groupByComposite(items, keys, sep = '|') {
  const out = {};
  for (const item of items) {
    (out[keys.map((k) => item[k]).join(sep)] ||= []).push(item);

// 2. NESTED grouping -- a tree, one level per key
function groupByNested(items, keys) {
  if (keys.length === 0) return items;
  const [first, ...rest] = keys;
  const out = {};
  for (const item of items) (out[item[first]] ||= []).push(item);
  for (const k of Object.keys(out)) out[k] = groupByNested(out[k], rest);
  return out;
}

Step 8

Complexity, in sentences

ApproachTimeSpace
filter once per keyO(n · k)O(n)
one pass, mutating the accumulatorO(n)O(n)
one pass, spreading the accumulatorO(n · k)O(n · k) allocated
sort then chunkO(n log n)O(n)

n is the number of items, k the number of distinct keys. The one-pass version does one hash insert per item, so O(n) — and the space is O(n) because every item ends up in exactly one bucket. Nothing is duplicated; the buckets hold references.

The last row is worth knowing about: sorting by the key and then walking the sorted array gives you groups in sorted key order for free, at O(n log n). If the caller wants the groups ordered, that can be cheaper than grouping and then sorting the keys.

Say this in the interview

“One reduce, one pass. For each item I compute the key, create the bucket if it is missing, and push. I mutate the accumulator rather than spreading it — spreading copies the whole accumulator per item and makes it O(n·k), and the accumulator is private to the reduce so there is nothing to protect. The thing to flag is that object keys are strings: grouping by a boolean, a date or an object collapses values, and "__proto__" as a key silently fails, so I would use Object.create(null) or a Map when the keys come from user data. Object.groupBy does this natively now, with a null prototype.”

console.log('the operator.');

// __proto__ fails differently, and more quietly
console.log('');
const proto = (() => {
  const acc = {};
  for (const item of [{ tag: '__proto__' }, { tag: 'ok' }]) {
    if (!Object.prototype.hasOwnProperty.call(acc, item.tag)) acc[item.tag] = [];
    acc[item.tag].push(item);
  }
  return acc;
})();
console.log('with a "__proto__" group, using hasOwnProperty:');
console.log('  Object.keys :', JSON.stringify(Object.keys(proto)));
console.log('  reading it  :', JSON.stringify(proto['__proto__']));
console.log('  is it an own property?',
            Object.prototype.hasOwnProperty.call(proto, '__proto__'));
console.log('');
console.log('  Strange, and worth following: no error, and the value');
console.log('  reads back. But it is not a KEY. `acc.__proto__ = []`');
console.log('  invoked the setter and made that array the OBJECT PROTOTYPE.');
console.log('  Reading __proto__ then returns that prototype,');
console.log('  which is that same array -- so .push worked, and the');
console.log('  items went into the prototype.');
console.log('');
console.log('  Object.keys does not see it, JSON.stringify drops it,');
console.log('  and Object.entries misses it -- so any code that');
console.log('  iterates the groups loses that one silently.');
console.log('  prototype is now an Array?', Array.isArray(Object.getPrototypeOf(proto)));

// both problems disappear with a null prototype
const safeGroupBy = (items, key) => {
  const acc = Object.create(null);
  for (const item of items) (acc[item[key]] ||= []).push(item);
  return acc;
};
const safe = safeGroupBy(
  [{ tag: 'toString' }, { tag: '__proto__' }, { tag: 'ok' }], 'tag');
console.log('');
console.log('with Object.create(null):');
console.log('  keys:', JSON.stringify(Object.keys(safe)));
console.log('  every group present, no inherited anything.');

// or a Map, where a key is only ever a key
const mapGroupBy = (items, key) => {
  const m = new Map();
  for (const item of items) {
    if (!m.has(item[key])) m.set(item[key], []);
    m.get(item[key]).push(item);
  }
  return m;
};
console.log('');
console.log('with a Map:', JSON.stringify([...mapGroupBy(
  [{ tag: 'toString' }, { tag: '__proto__' }, { tag: 'ok' }], 'tag').keys()]));

Step 10

Practice before you move on

  1. Write groupBy from memory, then say why the accumulator is mutated rather than spread.
  2. Write countBy, keyBy and partition. Step 7 — each is three lines and each answers a different question.
  3. List the three object-key traps. Stringification, integer reordering, and __proto__. Then say when you would use a Map.
  4. Write the nested version. Step 7 — and be able to say why you would usually prefer a composite key.
  5. Write aggregateBy that returns count, sum and average per key. That is the shape of nearly every real reporting endpoint.
What to carry forward

One pass, one lookup, mutate what you own. That is the whole pattern, and it is the same one behind Two Sum, Top K Frequent and every “count the things” problem. The part specific to this page is the container: an object's keys are strings with rules of their own, and the moment those keys come from data rather than from you, a Map or a null-prototype object is the safer default.
