Object & data shaping · Problem 08

Remove Duplicates by Object Key

Three lines with a Map, and the version everyone writes instead — filter plus findIndex — is quadratic. The interesting question underneath is one nobody asks explicitly: when two rows collide, which one wins?

Step 1

The problem

Version 0 — three lines, and the two policies
// LAST wins: a later row overwrites an earlier one
const dedupeLast = (items, keyOf) =>
  [...new Map(items.map((item) => [keyOf(item), item])).values()];

// FIRST wins: keep the earliest, ignore later collisions
const dedupeFirst = (items, keyOf) => {
  const seen = new Map();
  for (const item of items) {
    const key = keyOf(item);
    if (!seen.has(key)) seen.set(key, item);
  }
  return [...seen.values()];
};

Why new Map(pairs) works

new Map([[k, v], ...]) takes an iterable of pairs, and a later pair with the same key overwrites the earlier one — while keeping the earlier one's position in the iteration order.

So [...new Map(items.map(item => [key(item), item])).values()] is a complete last-wins dedupe in one expression, and it is O(n).

Step 4

The better idea — and the three questions

  seen = new Map()

  for each item:
      key = keyOf(item)

      FIRST WINS:   if not seen.has(key):  seen.set(key, item)
      LAST WINS:    seen.set(key, item)                 always
      MERGE:        seen.set(key, combine(seen.get(key), item))
      BEST:         if better(item, seen.get(key)):  seen.set(key, item)

  return [...seen.values()]


  One loop, one hash operation per item. O(n).

  And the iteration ORDER of the result is the position of the
  first time each key was seen -- because Map.set on an existing
  key updates the value and leaves the position alone.
The three questions, in order

1. What is the key? A field, a composite of fields, or a normalised form (lower-cased, trimmed). The Group By page's key traps all apply here too.

2. Who wins a collision? First, last, the newest by timestamp, or a merge of both. There is no safe default — make it explicit.

3. What order comes out? Insertion order of first appearance, by default. If you need something else, sort afterwards.

Step 5

Dry run — first, last and merge side by side

  rows:
      #1 Ada,   updated Jan
      #2 Grace, updated Jan
      #1 Ada L, updated Jun
      #2 Grace H, updated May

  FIRST WINS                          LAST WINS
  ----------                          ---------
  #1 not seen -> set Ada              #1 -> set Ada
  #2 not seen -> set Grace            #2 -> set Grace
  #1 SEEN     -> skip                 #1 -> set Ada L      (overwrite)
  #2 SEEN     -> skip                 #2 -> set Grace H    (overwrite)

  [Ada, Grace]                        [Ada L, Grace H]

  In BOTH cases the output order is #1 then #2, because the
  positions were fixed on the first insert.


  MERGE
  -----
  #1 -> set Ada
  #2 -> set Grace
  #1 -> set combine(Ada, Ada L)
  #2 -> set combine(Grace, Grace H)

  combine can be anything: newest-wins per field, sum the
  amounts, concatenate the tags, keep the first non-null.
the four policies, narrating themselves
function dedupeLoud(items, keyOf, policy, combine) {
  const seen = new Map();

  for (const item of items) {
    const key = keyOf(item);
    const existing = seen.get(key);
    const had = seen.has(key);

    if (!had) {
      seen.set(key, item);
      console.log('  ' + JSON.stringify(key) + ' NEW      -> keep ' + item.name);
      continue;
    }

    if (policy === 'first') {
      console.log('  ' + JSON.stringify(key) + ' seen     -> skip ' + item.name);
    } else if (policy === 'last') {
      seen.set(key, item);
      console.log('  ' + JSON.stringify(key) + ' seen     -> replace ' +
                  existing.name + ' with ' + item.name);
    } else if (policy === 'merge') {
      const merged = combine(existing, item);
      seen.set(key, merged);
      console.log('  ' + JSON.stringify(key) + ' seen     -> merge -> ' + merged.name);
    } else if (policy === 'best') {
      if (combine(item, existing)) {
        seen.set(key, item);
        console.log('  ' + JSON.stringify(key) + ' seen     -> ' + item.name +
                    ' is better than ' + existing.name);
      } else {
        console.log('  ' + JSON.stringify(key) + ' seen     -> keeping ' + existing.name);
      }
    }
  }

  return [...seen.values()];
}

function dedupeManual(items, keyOf, lastWins) {
  // Object.create(null) so a key of "__proto__" or "toString" is
  // just a key
  const index = Object.create(null);
  const order = [];
  let orderCount = 0;

  for (let i = 0; i < items.length; i++) {
    const item = items[i];
    const key = String(keyOf(item));

    if (index[key] === undefined) {
      index[key] = { position: orderCount, value: item };
      order[orderCount] = key;
      orderCount = orderCount + 1;
    } else if (lastWins) {
      index[key].value = item;              // same position, new value
    }
  }

  const out = [];
  for (let i = 0; i < orderCount; i++) out[i] = index[order[i]].value;
  return out;
}

function dedupeBy(items, keyOf, options = {}) {
  const {
    keep = 'first',        // 'first' | 'last' | a (a, b) => winner
    onCollision = null,    // (existing, incoming, key) => void
  } = options;

  const seen = new Map();
  let collisions = 0;

  const getKey = typeof keyOf === 'function' ? keyOf : (item) => item[keyOf];

  for (const item of items) {
    const key = getKey(item);

    if (!seen.has(key)) { seen.set(key, item); continue; }

    collisions++;
    const existing = seen.get(key);
    if (onCollision) onCollision(existing, item, key);

    if (keep === 'last') seen.set(key, item);
    else if (typeof keep === 'function') seen.set(key, keep(existing, item));
    // 'first' -> leave it alone
  }

  const result = [...seen.values()];
  result.collisions = collisions;
  return result;
}

// 1. find the duplicates, rather than removing them
function findDuplicates(items, keyOf) {
  const groups = new Map();
  for (const item of items) {
    const k = keyOf(item);
    if (!groups.has(k)) groups.set(k, []);
    groups.get(k).push(item);
  }
  return [...groups.entries()].filter(([, list]) => list.length > 1);
}

// 2. partition into unique and duplicate
function partitionDuplicates(items, keyOf) {
  const seen = new Set();
  const unique = [], duplicates = [];
  for (const item of items) {
    const k = keyOf(item);
    if (seen.has(k)) duplicates.push(item);
    else { seen.add(k); unique.push(item); }
  }
  return { unique, duplicates };
}

function dedupeStructural(items) {
  const seen = new Map();          // canonical string -> item
  const canonical = (v) => {
    if (v === null || typeof v !== 'object') return JSON.stringify(v);
    if (Array.isArray(v)) return '[' + v.map(canonical).join(',') + ']';
    return '{' + Object.keys(v).sort()
      .map((k) => JSON.stringify(k) + ':' + canonical(v[k])).join(',') + '}';
  };
  for (const item of items) {
    const k = canonical(item);
    if (!seen.has(k)) seen.set(k, item);
  }
  return [...seen.values()];
};

// 5. dedupe a stream, with a bounded memory footprint
function makeStreamDeduper(limit = 1000) {
  const seen = new Set();
  return (key) => {
    if (seen.has(key)) return false;
    seen.add(key);
    if (seen.size > limit) {
      // evict the oldest -- a Set iterates in insertion order
      seen.delete(seen.values().next().value);
    }
    return true;
  };
}

Step 8

Complexity, in sentences

ApproachTimeSpace
filter + findIndexO(n2)O(k)
filter + indexOfO(n2)O(k)
reduce + spreadO(n2)O(n2) allocated
Map or SetO(n)O(k)
structural, with a canonical keyO(n · size)O(n · size)

n is the number of items and k the number of distinct keys. The Map version does one hash operation per item, so O(n), and holds one entry per distinct key, so O(k) — which is why deduplicating a million rows down to a thousand costs a thousand entries, not a million.

The last row is the one to be careful about: a canonical-string key costs the size of each object to build, on every item, and stores that string. For deduplicating large objects by structure that can dominate everything else.

Say this in the interview

“A Map from key to item, one pass. First-wins is if (!seen.has(key)) seen.set(key, item); last-wins is an unconditional set, which also happens to be the one-line [...new Map(items.map(i => [key(i), i])).values()]. Either way it is O(n), and the output is in order of first appearance because Map.set on an existing key updates the value without moving it. The version to avoid is filter with findIndex — a fresh scan per element, so O(n²). And the question worth asking back is which row should win: if the input order is arbitrary, 'last' is not a policy, so I would take an explicit comparator or a merge function, and report the collisions rather than silently dropping rows.”

function assertUnique(items, keyOf, label) {
  const seen = new Map();
  const clashes = [];
  for (const item of items) {
    const k = keyOf(item);
    if (seen.has(k)) clashes.push({ key: k, a: seen.get(k), b: item });

      clashes.map((c) => JSON.stringify(c.key)).join(', '));
  }
  return items;
}

What to carry forward

Build an index instead of rescanning — and decide who wins. The first half is the same lesson as Two Sum, groupBy, keyBy and list-to-tree: a hash lookup turns O(n²) into O(n). The second half is the part specific to real data: deduplication deletes rows, so the collision policy is a data decision, it should be deterministic under reordering, and what it removed is worth reporting.
