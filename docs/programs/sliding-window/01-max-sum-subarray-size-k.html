Sliding window · Problem 01

Maximum Sum Subarray of Size K

The simplest window there is: it never changes size. Slide it one step and the sum updates with one addition and one subtraction — not a fresh loop. Learn this shape first; the variable-size windows are built on it.

Step 1

The problem

Find the largest sum of any k consecutive elements.

InputkAnswerThe window
[2, 1, 5, 1, 3, 2]39[5, 1, 3]
[2, 3, 4, 1, 5]27[3, 4]
[-1, -2, -3]2-3[-1, -2]
[1, 2]5nullk is larger than the array

Two things that separate this from Maximum Subarray (Kadane’s):

  • The size is fixed. Exactly k elements, no more, no fewer. Kadane chooses its own length.
  • Negatives are fine. Because the window size never changes, there is no “should I extend?” decision, so no monotonicity is needed. Row three is a normal case, not an edge case.
Why the fixed size makes this easy

Every variable-size window has to decide when to shrink, and that decision needs the quantity to behave predictably. A fixed window shrinks on every step, by exactly one, unconditionally. There is no decision at all — which is why this version works with any values.

Step 2

Think first — sum every window

Version 0 — recompute each window
function maxSumBrute(nums, k) {
  if (k > nums.length || k <= 0) return null;

  let best = -Infinity;

  for (let start = 0; start + k <= nums.length; start++) {
    let sum = 0;

    for (let i = start; i < start + k; i++) {
      sum += nums[i];              // re-adds k values every time
    }

    if (sum > best) best = sum;
  }

  return best;
}

console.log(maxSumBrute([2,1,5,1,3,2], 3));   // 9
console.log(maxSumBrute([2,3,4,1,5], 2));     // 7
console.log(maxSumBrute([-1,-2,-3], 2));      // -3
console.log(maxSumBrute([1,2], 5));           // null
console.log(maxSumBrute([5], 1));             // 5

Note best = -Infinity, not 0. With all-negative input, 0 is not achievable by any window, and starting there would return 0 — a sum no window actually has.

And note the loop bound: start + k <= nums.length. The last valid window starts at nums.length - k. Writing start < nums.length would read past the end.

Step 3

Why it is slow — and what it repeats

There are about n windows and each costs k additions: O(n × k). But look at what two neighbouring windows share:

  nums = [2, 1, 5, 1, 3, 2]     k = 3

  window at 0:  2 + 1 + 5
  window at 1:      1 + 5 + 1
                    \___/
                these two were just added, and are added again

  The windows overlap in k-1 elements. Only ONE element leaves and
  ONE element joins. Everything else is unchanged.
Timing demo
const N = 200000;
const K = 1000;
const nums = [];
for (let i = 0; i < N; i++) nums.push(Math.floor(Math.random() * 100));

function brute(a, k) {
  let best = -Infinity;
  for (let s = 0; s + k <= a.length; s++) {
    let sum = 0;
    for (let i = s; i < s + k; i++) sum += a[i];
    if (sum > best) best = sum;
  }
  return best;
}

function window(a, k) {
  let sum = 0;
  for (let i = 0; i < k; i++) sum += a[i];
  let best = sum;
  for (let i = k; i < a.length; i++) {
    sum += a[i] - a[i - k];
    if (sum > best) best = sum;
  }
  return best;
}

Step 4

The better idea — add one, remove one

The unlock

Compute the first window’s sum the slow way, once. Then to move the window one step: add the element joining on the right and subtract the element leaving on the left.

sum += nums[i] - nums[i - k];

Which element leaves? If the window now ends at i, it covers i - k + 1 through i. The element that just fell out is the one before that range: i - k.

  nums = [2, 1, 5, 1, 3, 2]     k = 3

  i=2   the first window, summed the slow way: 2+1+5 = 8
        [2 1 5] 1 3 2                          best = 8

  i=3   joining: nums[3] = 1     leaving: nums[3-3] = nums[0] = 2
        sum = 8 + 1 - 2 = 7
        2 [1 5 1] 3 2                          best = 8

  i=4   joining: nums[4] = 3     leaving: nums[1] = 1
        sum = 7 + 3 - 1 = 9
        2 1 [5 1 3] 2                          best = 9

  i=5   joining: nums[5] = 2     leaving: nums[2] = 5
        sum = 9 + 2 - 5 = 6
        2 1 5 [1 3 2]                          best = 9

  answer: 9

Each step is two array reads and two arithmetic operations, regardless of how big k is. A window of a million elements slides just as cheaply as a window of three.

The index that gets fumbled

It is nums[i - k], not nums[i - k + 1] and not nums[i - k - 1]. Check it on the first slide: with k = 3 and i = 3, the window becomes indexes 1, 2, 3, so the element that left is index 0 — and 3 - 3 = 0. Verifying that one case by hand takes ten seconds and saves the bug.

Step 6

Version 1 — without built-in methods

Version 1 — fixed window, loops only
function maxSumManual(nums, k) {
  if (k <= 0 || k > nums.length) return null;

  // sum the first window the slow way -- once
  let sum = 0;
  for (let i = 0; i < k; i++) {
    sum = sum + nums[i];
  }

  let best = sum;

  // slide: one joins on the right, one leaves on the left
  for (let i = k; i < nums.length; i++) {
    sum = sum + nums[i] - nums[i - k];

    if (sum > best) {
      best = sum;
    }
  }

  return best;
}

console.log(maxSumManual([2,1,5,1,3,2], 3));    // 9
console.log(maxSumManual([2,3,4,1,5], 2));      // 7
console.log(maxSumManual([-1,-2,-3], 2));       // -3
console.log(maxSumManual([1,2], 5));            // null
console.log(maxSumManual([5], 1));              // 5
console.log(maxSumManual([1,2,3], 3));          // 6
console.log(maxSumManual([], 1));               // null

variation — report the window, and every window sum
function bestWindow(nums, k) {
  if (k <= 0 || k > nums.length) return null;

  let sum = 0;
  for (let i = 0; i < k; i++) sum += nums[i];

  let best = sum, bestStart = 0;

  for (let i = k; i < nums.length; i++) {
    sum += nums[i] - nums[i - k];
    if (sum > best) {
      best = sum;
      bestStart = i - k + 1;         // freeze only on a new best
    }
  }

  return { sum: best, from: bestStart, to: bestStart + k - 1,
           values: nums.slice(bestStart, bestStart + k) };
}

console.log(bestWindow([2,1,5,1,3,2], 3));
// { sum: 9, from: 2, to: 4, values: [5,1,3] }

// Every window's sum, in one pass -- useful for moving averages
function windowSums(nums, k) {
  if (k <= 0 || k > nums.length) return [];
  const out = [];
  let sum = 0;
  for (let i = 0; i < k; i++) sum += nums[i];
  out.push(sum);
  for (let i = k; i < nums.length; i++) {
    sum += nums[i] - nums[i - k];
    out.push(sum);
  }
  return out;
}

console.log(windowSums([2,1,5,1,3,2], 3));      // [8, 7, 9, 6]
console.log(windowSums([1,2,3,4,5], 2));        // [3, 5, 7, 9]

// Moving average -- the same thing, divided
const movingAverage = (nums, k) => windowSums(nums, k).map(s => s / k);
console.log(movingAverage([1,2,3,4,5], 3));     // [2, 3, 4]
Step 7

Version 2 — with built-in methods

Version 2 — the interview answer
function maxSumSubarray(nums, k) {
  if (k <= 0 || k > nums.length) return null;

  let sum = nums.slice(0, k).reduce((a, b) => a + b, 0);
  let best = sum;

  for (let i = k; i < nums.length; i++) {
    sum += nums[i] - nums[i - k];
    best = Math.max(best, sum);
  }

  return best;
}

console.log(maxSumSubarray([2,1,5,1,3,2], 3));   // 9
console.log(maxSumSubarray([2,3,4,1,5], 2));     // 7
console.log(maxSumSubarray([-1,-2,-3], 2));      // -3
console.log(maxSumSubarray([1,2], 5));           // null
the version that looks clean and is O(n×k)
function tempting(nums, k) {
  if (k > nums.length) return null;

  let best = -Infinity;
  for (let i = 0; i + k <= nums.length; i++) {
    // slice allocates, reduce re-adds all k values
    const sum = nums.slice(i, i + k).reduce((a, b) => a + b, 0);
    best = Math.max(best, sum);
  }
  return best;
}

console.log(tempting([2,1,5,1,3,2], 3));   // 9   correct

// Maximum average
function maxAverage(nums, k) {
  let sum = 0;
  for (let i = 0; i < k; i++) sum += nums[i];
  let best = sum;
  for (let i = k; i < nums.length; i++) {
    sum += nums[i] - nums[i - k];
    best = Math.max(best, sum);
  }
  return best / k;
}
console.log('max average:', maxAverage([1,12,-5,-6,50,3], 4));   // 12.75

// Count how many windows of size k contain no duplicates
function windowsWithAllDistinct(nums, k) {
  const counts = new Map();
  let distinct = 0, found = 0;

  const add = v => {
    const n = (counts.get(v) || 0) + 1;
    counts.set(v, n);
    if (n === 1) distinct++;
  };
  const remove = v => {
    const n = counts.get(v) - 1;
    counts.set(v, n);
    if (n === 0) distinct--;
  };

  for (let i = 0; i < k; i++) add(nums[i]);
  if (distinct === k) found++;

  for (let i = k; i < nums.length; i++) {
    add(nums[i]);
    remove(nums[i - k]);
    if (distinct === k) found++;
  }

  return found;
}

console.log('all-distinct windows:', windowsWithAllDistinct([1,2,3,1,2], 3));   // 3
console.log('all-distinct windows:', windowsWithAllDistinct([1,1,1,1], 2));     // 0

// Note the add/remove pair keeping `distinct` in sync -- the same
// incremental-invariant trick as `formed` in Minimum Window Substring.
Step 8

Complexity, in sentences

SolutionTimeSpace
Recompute each windowO(n · k)O(1)
slice + reduce per windowO(n · k)O(k)
Slide the windowO(n)O(1)

The first window costs k additions; every slide after that costs exactly two operations, and there are n - k slides. Total k + 2(n - k), which is O(n). Notice that k disappears from the complexity entirely — the window size stops mattering, which is the whole point.

O(1) space: one running sum and one best. No matter how large the window is, you never store its contents.

Say this in the interview

“Recomputing each window is O(n·k), and neighbouring windows share k−1 elements. So I sum the first window once, then slide: each step adds the entering element and subtracts the leaving one, sum += nums[i] - nums[i - k]. O(n) time, O(1) space, and the running time is independent of k. It works with negative numbers because the window size is fixed — there is no shrink decision to justify.”

Step 9

Mistakes people actually make

1. Subtracting the wrong element

Broken — off by one on the leaving index
function broken(nums, k) {
  let sum = 0;
  for (let i = 0; i < k; i++) sum += nums[i];
  let best = sum;
  for (let i = k; i < nums.length; i++) {
    sum += nums[i] - nums[i - k + 1];      // should be nums[i - k]
    best = Math.max(best, sum);
  }
  return best;
}

console.log(broken([2,1,5,1,3,2], 3));   // 10  WRONG, should be 9
console.log(broken([2,3,4,1,5], 2));     // 8   WRONG, should be 7

// It subtracts an element that is still INSIDE the window, and
// leaves the one that should have left. Check it on the first slide
// by hand: with k=3 and i=3 the window is indexes 1..3, so index 0
// is what left.

2. Starting best at 0

Broken — all-negative input
function broken(nums, k) {
  let sum = 0;
  for (let i = 0; i < k; i++) sum += nums[i];
  let best = 0;                            // should be sum
  for (let i = k; i < nums.length; i++) {
    sum += nums[i] - nums[i - k];
    best = Math.max(best, sum);
  }
  return best;
}

console.log(broken([2,1,5,1,3,2], 3));   // 9    fine
console.log(broken([-1,-2,-3], 2));      // 0    WRONG, should be -3
console.log(broken([-5,-1,-8], 1));      // 0    WRONG, should be -1

// Zero is not achievable by any window here. Seed `best` with the
// FIRST window's actual sum -- that is guaranteed to be a real
// answer. Same lesson as Kadane's nums[0] initialisation.

3. Forgetting to record the first window

Broken — the first window never counts
function broken(nums, k) {
  let sum = 0;
  for (let i = 0; i < k; i++) sum += nums[i];
  let best = -Infinity;                    // never seeded with sum
  for (let i = k; i < nums.length; i++) {
    sum += nums[i] - nums[i - k];
    best = Math.max(best, sum);            // only slid windows are checked
  }
  return best;
}

console.log(broken([5,1,1,1], 2));   // 2    WRONG, should be 6
console.log(broken([1,2,3], 3));     // -Infinity   WRONG, should be 6

// The best window can be the very first one. Either seed
// best = sum before the loop, or check inside the loop starting
// at i = k - 1 rather than i = k.

4. Not validating k

k > nums.length means no window exists. Without a guard, the first loop reads undefined and the sum becomes NaN — which then compares false against everything and silently returns -Infinity or NaN. Decide what an impossible k should return (null, 0, or a thrown error) and say so.

5. Confusing it with Kadane’s

two different questions
const nums = [2, 1, 5, 1, 3, 2];

// Fixed size: exactly 3 elements
function fixedK(a, k) {
  let s = 0;
  for (let i = 0; i < k; i++) s += a[i];
  let best = s;
  for (let i = k; i < a.length; i++) { s += a[i] - a[i - k]; best = Math.max(best, s); }
  return best;
}

// Any size: Kadane chooses the length itself
function kadane(a) {
  let cur = a[0], best = a[0];
  for (let i = 1; i < a.length; i++) {
    cur = Math.max(a[i], cur + a[i]);
    best = Math.max(best, cur);
  }
  return best;
}

console.log('best window of exactly 3 :', fixedK(nums, 3));   // 9
console.log('best window of any size  :', kadane(nums));      // 14 (the whole array)

// "Subarray of size k" versus "maximum subarray" are different
// problems. The word "size k" is the whole difference, and it is
// easy to skim past.
Step 10

Practice before you move on

  1. Write the six-line version from memory, then verify the nums[i - k] index by hand on the first slide.
  2. Return the window, not just the sum. In Step 6 — and remember to freeze the start only when a new best is confirmed.
  3. Minimum sum window of size k. One comparison flips. Then find both in a single pass.
  4. Moving average of a stream. Values arrive one at a time and you report the average of the last k. You need a queue to know what is leaving — and that is the real-world version of this problem.
  5. Maximum in every window of size k. Much harder: the maximum cannot be updated with an add and a subtract, because removing the maximum leaves you not knowing the next one. The answer is a monotonic deque. Try it, fail, then look it up — the failure is the lesson.
What to carry forward

Update the aggregate incrementally instead of recomputing it. Sums, counts and products all support “add the newcomer, remove the leaver”, which makes the window size irrelevant to the running time. Aggregates that do not support it — maximum, minimum, median — need a different structure, and recognising which kind you have is what tells you whether a simple sliding window will work at all.
