Sliding window · Problem 02

Longest Repeating Character Replacement

You may change up to k characters. How long can you make a run of identical letters? The entire problem collapses into one formula: replacements needed = window length − count of the most frequent character.

Step 1

The problem

Given a string of uppercase letters and a number k, you may replace at most k characters with any letters you like. Return the length of the longest run of the same letter you can produce.

skAnswerHow
"ABAB"24change both B’s to A
"AABABBA"14"AABA" → change the B
"AAAA"04nothing to change
"ABCDE"12any two adjacent
"AAAB"03the run of A’s
The reframe that makes it tractable

Do not think about which characters to replace. Think about a window and ask: could this window be made uniform with at most k changes?

The cheapest way to make any window uniform is to keep the character that already appears most often and change everything else. So the cost is:

windowLength − countOfMostFrequentCharacter

If that is at most k, the window is achievable. The answer is the longest achievable window.

  window "AABABB"    length 6
  counts:  A x3   B x3
  most frequent: 3

  replacements needed = 6 - 3 = 3

  so this window works if k >= 3
Step 2

Think first — test every window

Version 0 — brute force
function costToMakeUniform(s, start, end) {
  const counts = new Map();
  let most = 0;

  for (let i = start; i <= end; i++) {
    const n = (counts.get(s[i]) || 0) + 1;
    counts.set(s[i], n);
    if (n > most) most = n;
  }

  const length = end - start + 1;
  return length - most;
}

function longestBrute(s, k) {
  let best = 0;

  for (let start = 0; start < s.length; start++) {
    for (let end = start; end < s.length; end++) {
      if (costToMakeUniform(s, start, end) <= k) {
        best = Math.max(best, end - start + 1);
      }
    }
  }

  return best;
}

console.log(longestBrute('ABAB', 2));      // 4
console.log(longestBrute('AABABBA', 1));   // 4
console.log(longestBrute('AAAA', 0));      // 4
console.log(longestBrute('ABCDE', 1));     // 2
console.log(longestBrute('AAAB', 0));      // 3
console.log(longestBrute('', 2));          // 0

Every substring, and counting the characters of each one from scratch: O(n³) in the worst case. Correct, and a fine starting point to say out loud.

Step 3

Why it is slow

Timing demo
const N = 700;
let s = '';
for (let i = 0; i < N; i++) s += 'AB'[i % 2];
const k = 3;

function cost(str, a, b) {
  const c = new Map();
  let most = 0;
  for (let i = a; i <= b; i++) {
    const n = (c.get(str[i]) || 0) + 1;
    c.set(str[i], n);
    if (n > most) most = n;
  }
  return (b - a + 1) - most;
}

function brute(str, k) {
  let best = 0;
  for (let a = 0; a < str.length; a++)
    for (let b = a; b < str.length; b++)
      if (cost(str, a, b) <= k) best = Math.max(best, b - a + 1);
  return best;
}

function windowed(str, k) {
  const counts = new Array(26).fill(0);
  let left = 0, most = 0, best = 0;
  for (let right = 0; right < str.length; right++) {
    const idx = str.charCodeAt(right) - 65;
    counts[idx]++;
    most = Math.max(most, counts[idx]);

    while ((right - left + 1) - most > k) {
      counts[str.charCodeAt(left) - 65]--;
      left++;
    }

    best = Math.max(best, right - left + 1);
  }
  return best;
}

Step 4

The better idea — grow, shrink while invalid

This is the longest shape of sliding window, the same as Longest Substring Without Repeating Characters: grow on the right, shrink from the left while the window is invalid, record the length afterwards.

The unlock

A window is valid when (right - left + 1) - mostFrequentCount <= k.

Extend right by one, updating the character counts. While the window is invalid, drop characters from the left. Then record the length — it is now valid.

The part that looks like a bug and is not

Here is the detail that makes this problem famous. Most solutions track most as a running maximum and never decrease it, even when characters leave the window on the left. That means most can be stale — larger than any character’s actual count in the current window.

It still gives the right answer, and the reason is worth understanding:

Why a stale maximum is harmless

We only care about the longest window ever seen. The window only grows when a genuinely better most is found; a stale most makes the validity test too permissive, so the window never shrinks below the best length already achieved — it just slides along at that width. Since a too-small window can never become the answer, and the width only increases when a real improvement happens, the maximum recorded length is correct.

Put differently: the window size becomes a high-water mark. It never shrinks, and it only grows when justified.

You can also recompute the true maximum each time. It is O(26) per step — still linear overall — and it is much easier to defend. Both are below; write whichever you can explain.

Step 6

Version 1 — without built-in methods

Version 1a — recompute the true maximum
function longestManual(s, k) {
  const counts = [];
  for (let i = 0; i < 26; i++) counts[i] = 0;

  let left = 0;
  let best = 0;

  for (let right = 0; right < s.length; right++) {
    counts[s.charCodeAt(right) - 65] = counts[s.charCodeAt(right) - 65] + 1;

    // the TRUE most frequent count in the current window
    let most = 0;
    for (let i = 0; i < 26; i++) {
      if (counts[i] > most) most = counts[i];
    }

    // shrink while the window would need more than k replacements
    while ((right - left + 1) - most > k) {
      counts[s.charCodeAt(left) - 65] = counts[s.charCodeAt(left) - 65] - 1;
      left = left + 1;

      // recompute, because a character just left
      most = 0;
      for (let i = 0; i < 26; i++) {
        if (counts[i] > most) most = counts[i];
      }
    }

    const length = right - left + 1;
    if (length > best) best = length;
  }

  return best;
}

console.log(longestManual('ABCDE', 1));      // 2
console.log(longestManual('AAAB', 0));       // 3
console.log(longestManual('', 2));           // 0
console.log(longestManual('ABBB', 2));       // 4

This version is obviously correct: the validity test always uses the real maximum. Recomputing over 26 slots is a constant, so it is still O(26n) = O(n). Unless the interviewer specifically asks you to avoid the inner scan, this is the version to write.

Version 1b — the stale maximum
function longestStaleMax(s, k) {
  const counts = [];
  for (let i = 0; i < 26; i++) counts[i] = 0;

  let left = 0;
  let most = 0;      // a HIGH-WATER MARK, never decreased
  let best = 0;

  for (let right = 0; right < s.length; right++) {
    const idx = s.charCodeAt(right) - 65;
    counts[idx] = counts[idx] + 1;
    if (counts[idx] > most) most = counts[idx];

    // note: `most` may be larger than any count in the CURRENT window
    if ((right - left + 1) - most > k) {
      counts[s.charCodeAt(left) - 65] = counts[s.charCodeAt(left) - 65] - 1;
      left = left + 1;
      // the window slides by exactly one; it never gets smaller
    }

    const length = right - left + 1;
    if (length > best) best = length;
  }

  return best;
}

console.log(longestStaleMax('AAAB', 0));       // 3

function reference(s, k) {          // the obviously-correct brute force
  const cost = (a, b) => {
    const c = new Map();
    let m = 0;
    for (let i = a; i <= b; i++) {
      const n = (c.get(s[i]) || 0) + 1;
      c.set(s[i], n);
      if (n > m) m = n;
    }
    return (b - a + 1) - m;
  };
  let best = 0;
  for (let a = 0; a < s.length; a++)
    for (let b = a; b < s.length; b++)
      if (cost(a, b) <= k) best = Math.max(best, b - a + 1);
  return best;
}

function trueMax(s, k) {
  const counts = new Array(26).fill(0);
  let left = 0, best = 0;
  for (let right = 0; right < s.length; right++) {
    counts[s.charCodeAt(right) - 65]++;
    let most = Math.max(...counts);
    while ((right - left + 1) - most > k) {
      counts[s.charCodeAt(left) - 65]--;
      left++;
      most = Math.max(...counts);
    }
    best = Math.max(best, right - left + 1);
  }
  return best;
}

function staleMax(s, k) {
  const counts = new Array(26).fill(0);
  let left = 0, most = 0, best = 0;
  for (let right = 0; right < s.length; right++) {
    const i = s.charCodeAt(right) - 65;
    most = Math.max(most, ++counts[i]);
    if ((right - left + 1) - most > k) counts[s.charCodeAt(left++) - 65]--;
    best = Math.max(best, right - left + 1);
  }
  return best;
}

Step 7

Version 2 — with built-in methods

Version 2 — the interview answer
function characterReplacement(s, k) {
  const counts = new Map();
  let left = 0;
  let most = 0;
  let best = 0;

  for (let right = 0; right < s.length; right++) {
    const c = s[right];
    counts.set(c, (counts.get(c) || 0) + 1);
    most = Math.max(most, counts.get(c));

    // shrink while more than k replacements would be needed
    while ((right - left + 1) - most > k) {
      const gone = s[left];
      counts.set(gone, counts.get(gone) - 1);
      left++;
    }

    best = Math.max(best, right - left + 1);
  }

  return best;
}

console.log(characterReplacement('ABCDE', 1));     // 2
console.log(characterReplacement('AAAB', 0));      // 3

console.log(characterReplacement('ABBB', 2));      // 4
Why a while is safe here even with the stale maximum

With most stale, the condition can only be true at most once per step — the window grew by one, so at most one character needs to leave. So the while behaves like an if. Using while costs nothing and keeps the code readable as a standard sliding window. If you also recompute most after each removal, the while becomes genuinely necessary.

returning the window, and the letter to keep
function bestReplacement(s, k) {
  const counts = new Map();
  let left = 0, most = 0, best = 0, bestStart = 0;

  for (let right = 0; right < s.length; right++) {
    counts.set(s[right], (counts.get(s[right]) || 0) + 1);
    most = Math.max(most, counts.get(s[right]));

    while ((right - left + 1) - most > k) {
      counts.set(s[left], counts.get(s[left]) - 1);
      left++;
    }

    if (right - left + 1 > best) {
      best = right - left + 1;
      bestStart = left;
    }
  }

  if (best === 0) return { length: 0, window: '', keep: null, changes: 0 };

  // which letter should we keep in the winning window?
  const win = s.slice(bestStart, bestStart + best);
  const winCounts = new Map();
  for (const c of win) winCounts.set(c, (winCounts.get(c) || 0) + 1);

  let keep = null, keepCount = 0;
  for (const [c, n] of winCounts) if (n > keepCount) { keep = c; keepCount = n; }

  return { length: best, window: win, keep, changes: best - keepCount };
}

console.log(bestReplacement('AABABBA', 1));
// { length: 4, window: 'AABA', keep: 'A', changes: 1 }

console.log(bestReplacement('ABAB', 2));
console.log(bestReplacement('ABCDE', 1));
console.log(bestReplacement('AAAB', 0));
Step 8

Complexity, in sentences

SolutionTimeSpace
Every substring, counted freshO(n³)O(1)
Window, true max recomputedO(26n) = O(n)O(1)
Window, stale maxO(n)O(1)

Both window versions are linear. Recomputing the maximum scans 26 counters per step, which is a constant factor, not a complexity change — say “O(26n), which is O(n)” rather than pretending the scan is free.

Space is O(26) — one counter per uppercase letter — which is O(1) for a fixed alphabet. If the input could be any Unicode character, it becomes O(k) for the distinct characters in the window.

Say this in the interview

“For any window, the cheapest way to make it uniform is to keep the most frequent character and replace the rest, so the cost is length - maxCount. I slide a window, extending right and shrinking left while that cost exceeds k, recording the longest valid window. Recomputing the max over the 26 counters keeps it O(26n) = O(n) and is easy to justify. There is a variant that never decreases the max, which is also correct because the window then acts as a high-water mark — it only grows when a genuinely better count appears — but I would only use it if asked.”

Step 9

Mistakes people actually make

1. Counting the wrong thing as the cost

Broken — counts distinct characters instead
function broken(s, k) {
  const counts = new Map();
  let left = 0, best = 0;

  for (let right = 0; right < s.length; right++) {
    counts.set(s[right], (counts.get(s[right]) || 0) + 1);

    // "at most k+1 distinct characters" -- wrong measure
    while (counts.size > k + 1) {
      const gone = s[left];
      const n = counts.get(gone) - 1;
      if (n === 0) counts.delete(gone); else counts.set(gone, n);
      left++;
    }

    best = Math.max(best, right - left + 1);
  }
  return best;
}

console.log(broken('ABAB', 2));      // 4   right, by luck
console.log(broken('AABABBA', 1));   // 7   WRONG, should be 4

// "AABABBA" has only two distinct characters, so this never shrinks
// and reports the whole string. But making it uniform needs three
// replacements, not one. The cost is about COUNTS, not about how
// many distinct characters are present.

2. Forgetting to decrement when a character leaves

Broken — counts never come back down
function broken(s, k) {
  const counts = new Map();
  let left = 0, most = 0, best = 0;

  for (let right = 0; right < s.length; right++) {
    counts.set(s[right], (counts.get(s[right]) || 0) + 1);
    most = Math.max(most, counts.get(s[right]));

    while ((right - left + 1) - most > k) {
      left++;                       // moved, but the count was not decremented
    }

    best = Math.max(best, right - left + 1);
  }
  return best;
}

console.log(broken('AABABBA', 1));    // 5   WRONG, should be 4
console.log(broken('CABCBCC', 0));    // 4   WRONG, should be 2
console.log(broken('CBCACA', 1));     // 4   WRONG, should be 3

// left is still counted, so `most` stays inflated and the validity
// test passes windows that are not actually achievable.
// It survives many inputs, which is exactly what makes it dangerous.
// Every character that leaves the window must be decremented.

3. Using counts.size or the maximum over the whole string

The maximum must be over the current window. Computing it once over the whole string, or using the size of the map (the number of distinct characters), both answer different questions. The formula needs the largest count inside the window.

4. Recording the length before shrinking

Broken — measures an invalid window
function broken(s, k) {
  const counts = new Map();
  let left = 0, most = 0, best = 0;

  for (let right = 0; right < s.length; right++) {
    counts.set(s[right], (counts.get(s[right]) || 0) + 1);
    most = Math.max(most, counts.get(s[right]));

    best = Math.max(best, right - left + 1);    // recorded BEFORE shrinking

    while ((right - left + 1) - most > k) {
      counts.set(s[left], counts.get(s[left]) - 1);
      left++;
    }
  }
  return best;
}

// In the LONGEST shape, shrink FIRST so the window is valid, THEN
// record. (In the SHORTEST shape -- Minimum Window Substring -- you
// record first and then shrink. Know which shape you are in.)

5. Assuming uppercase A–Z

charCodeAt(i) - 65 maps 'A' to 0. On lowercase input every index is negative and the 26-slot array silently breaks. If the alphabet is not guaranteed, use a Map — and then “recompute the max” means iterating the map’s values, which is O(distinct) rather than O(26).

Step 10

Practice before you move on

  1. Say the cost formula out loud — window length minus the most frequent count — and why it is the cheapest way to make a window uniform. Everything else follows.
  2. Write the recompute-the-max version from memory. It is the one you can defend, and O(26n) is still linear.
  3. Max Consecutive Ones III. A binary array where you may flip up to k zeros. It is the same window, with the cost being simply the number of zeros inside — and it is the next page here.
  4. Return the actual modified string, not just the length. You have the window and the letter to keep; the rest is a replace.
  5. Explain the stale-maximum argument to someone else. If you can convince them, you understand it. If you cannot, write the recompute version and say why.
What to carry forward

Turn “what should I change?” into “what would this cost?” Searching over which characters to replace is hopeless; computing the cost of a candidate window is one subtraction. That reframe — from choosing actions to evaluating candidates — is what makes a sliding window possible here, and it is the same move that turned Trapping Rain Water from “find the pools” into “how deep above this bar?”.
