Sliding window · Problem 03

Permutation in String

Does any rearrangement of t appear inside s? Two ideas combine here: the fixed-size window and the frequency map. The refinement is keeping a single counter that says whether they currently match.

Step 1

The problem

Given two strings, return true if s contains a substring that is a permutation of t — the same characters, the same counts, in any order.

tsAnswerWhy
"ab""eidbaooo"true"ba" at index 3
"ab""eidboaoo"falseno window is a rearrangement
"adc""dcda"true"dcd"? no — "cda" at index 1
"abc""ab"falses is shorter than t
"aa""aba"falseno two adjacent a’s
The realisation that makes this easy

Every permutation of t has exactly the same length as t. So you are not searching for a variable-length window at all — you are checking every window of a fixed size, and asking whether its character counts equal t’s.

That is the fixed-size window from problem 01, carrying a frequency map instead of a sum.

Row five is worth checking: "aba" contains two a’s, but never side by side. The window must be contiguous, so the answer is false.

Step 2

Think first — check every window from scratch

Version 0 — count every window
function sameCounts(a, b) {
  if (a.size !== b.size) return false;
  for (const [k, v] of a) if (b.get(k) !== v) return false;
  return true;
}

function countsOf(str, from, to) {
  const m = new Map();
  for (let i = from; i < to; i++) m.set(str[i], (m.get(str[i]) || 0) + 1);
  return m;
}

function checkInclusionBrute(t, s) {
  const k = t.length;
  if (k > s.length) return false;

  const need = countsOf(t, 0, k);

  for (let start = 0; start + k <= s.length; start++) {
    if (sameCounts(need, countsOf(s, start, start + k))) return true;
  }

  return false;
}

console.log(checkInclusionBrute('ab', 'eidbaooo'));   // true
console.log(checkInclusionBrute('ab', 'eidboaoo'));   // false
console.log(checkInclusionBrute('adc', 'dcda'));      // true
console.log(checkInclusionBrute('abc', 'ab'));        // false
console.log(checkInclusionBrute('aa', 'aba'));        // false
console.log(checkInclusionBrute('a', 'a'));           // true

Correct, and it rebuilds a whole frequency map for every window. With n windows and k characters each, that is O(n × k) — plus a full map comparison per window.

Step 3

Why it is slow

Same waste as the fixed window in problem 01: neighbouring windows share k - 1 characters, and we throw all that away and recount.

function same(a, b) {
  if (a.size !== b.size) return false;
  for (const [k, v] of a) if (b.get(k) !== v) return false;
  return true;
}

function brute(pat, str) {
  const k = pat.length;
  const need = countsOf(pat, 0, k);
  for (let i = 0; i + k <= str.length; i++) {
    if (same(need, countsOf(str, i, i + k))) return true;
  }
  return false;
}

function windowed(pat, str) {
  const k = pat.length;
  if (k > str.length) return false;

  const need = new Array(26).fill(0);
  const have = new Array(26).fill(0);
  for (let i = 0; i < k; i++) {
    need[pat.charCodeAt(i) - 97]++;
    have[str.charCodeAt(i) - 97]++;
  }

  let matches = 0;
  for (let i = 0; i < 26; i++) if (need[i] === have[i]) matches++;

  for (let i = k; i < str.length; i++) {
    if (matches === 26) return true;

    const enter = str.charCodeAt(i) - 97;
    const leave = str.charCodeAt(i - k) - 97;

    have[enter]++;
    if (have[enter] === need[enter]) matches++;
    else if (have[enter] === need[enter] + 1) matches--;

    have[leave]--;
    if (have[leave] === need[leave]) matches++;
    else if (have[leave] === need[leave] - 1) matches--;
  }

  return matches === 26;
}

Step 4

The better idea — slide the counts, track one number

Two improvements stack here.

Improvement one: slide the counts

Move the window by one: increment the count of the character entering on the right, decrement the one leaving on the left. Two operations per step, regardless of k — the same idea as sum += nums[i] - nums[i - k], applied to a frequency table.

Improvement two: do not compare the maps

Comparing two 26-slot tables every step is O(26) — a constant, but a fat one. Instead maintain a single number.

The unlock

Track matches: how many of the 26 letters currently have have[c] === need[c]. When matches === 26, the window is a permutation.

Each count change affects exactly one letter, so matches can be repaired in O(1).

the four lines that keep matches honest
// a character ENTERS
have[c]++;
if (have[c] === need[c])      matches++;   // just became correct
else if (have[c] === need[c] + 1) matches--;   // just went one over

// a character LEAVES
have[c]--;
if (have[c] === need[c])      matches++;   // just became correct
else if (have[c] === need[c] - 1) matches--;   // just went one under

Read those conditions carefully. A letter only changes status when it crosses the boundary. Going from correct to one-too-many loses a match; going from one-too-few to correct gains one. Any other movement — from three-too-many to two-too-many — changes nothing.

This is exactly the formed counter from Minimum Window Substring, and it is the same general trick: when a predicate is checked in a loop, maintain its answer incrementally instead of recomputing it.

Why 26 and not need.size

matches counts letters where the two tables agree, and that includes letters where both are zero. If t has no z, then need['z'] is 0 and the window must also contain no z — that agreement counts. So the target is all 26 letters, not just the ones in t. Getting this wrong lets windows with extra characters slip through.

Step 6

Version 1 — without built-in methods

Version 1a — compare the tables each step
function checkInclusionSimple(t, s) {
  const k = t.length;
  if (k > s.length) return false;

  const need = [];
  const have = [];
  for (let i = 0; i < 26; i++) { need[i] = 0; have[i] = 0; }

  // build the pattern counts and the first window
  for (let i = 0; i < k; i++) {
    need[t.charCodeAt(i) - 97] = need[t.charCodeAt(i) - 97] + 1;
    have[s.charCodeAt(i) - 97] = have[s.charCodeAt(i) - 97] + 1;
  }

  function tablesMatch() {
    for (let i = 0; i < 26; i++) {
      if (need[i] !== have[i]) return false;
    }
    return true;
  }

  if (tablesMatch()) return true;

  for (let i = k; i < s.length; i++) {
    have[s.charCodeAt(i) - 97] = have[s.charCodeAt(i) - 97] + 1;       // enters
    have[s.charCodeAt(i - k) - 97] = have[s.charCodeAt(i - k) - 97] - 1; // leaves

    if (tablesMatch()) return true;
  }

  return false;
}

console.log(checkInclusionSimple('ab', 'eidboaoo'));   // false
console.log(checkInclusionSimple('adc', 'dcda'));      // true
console.log(checkInclusionSimple('abc', 'ab'));        // false
console.log(checkInclusionSimple('aa', 'aba'));        // false
console.log(checkInclusionSimple('a', 'a'));           // true
console.log(checkInclusionSimple('abc', 'ccccbbbbaaaa'));   // false
console.log(checkInclusionSimple('abc', 'cbabcacab'));      // true

O(26n), which is O(n). This is the version to write in an interview — it is obviously correct, and the 26-slot comparison is a constant. Offer the matches refinement afterwards.

Version 1b — the matches counter
function checkInclusionManual(t, s) {
  const k = t.length;
  if (k > s.length) return false;

  const need = [];
  const have = [];
  for (let i = 0; i < 26; i++) { need[i] = 0; have[i] = 0; }

  for (let i = 0; i < k; i++) {
    need[t.charCodeAt(i) - 97] = need[t.charCodeAt(i) - 97] + 1;
    have[s.charCodeAt(i) - 97] = have[s.charCodeAt(i) - 97] + 1;
  }

  // how many of the 26 letters currently agree?
  let matches = 0;
  for (let i = 0; i < 26; i++) {
    if (need[i] === have[i]) matches = matches + 1;
  }

  for (let i = k; i < s.length; i++) {
    if (matches === 26) return true;

    const enter = s.charCodeAt(i) - 97;
    const leave = s.charCodeAt(i - k) - 97;

    // one character joins
    have[enter] = have[enter] + 1;
    if (have[enter] === need[enter]) matches = matches + 1;
    else if (have[enter] === need[enter] + 1) matches = matches - 1;

    // one character leaves
    have[leave] = have[leave] - 1;
    if (have[leave] === need[leave]) matches = matches + 1;
    else if (have[leave] === need[leave] - 1) matches = matches - 1;
  }

  return matches === 26;
}

console.log(checkInclusionManual('ab', 'eidboaoo'));   // false
console.log(checkInclusionManual('adc', 'dcda'));      // true
console.log(checkInclusionManual('abc', 'ab'));        // false
console.log(checkInclusionManual('aa', 'aba'));        // false
console.log(checkInclusionManual('a', 'a'));           // true
console.log(checkInclusionManual('abc', 'cbabcacab')); // true
console.log(checkInclusionManual('hello', 'ooolleoooleh'));  // false
The order matters when the same letter enters and leaves

If the entering and leaving characters are the same letter, the have count goes up then straight back down — and matches is adjusted twice, once each way, cancelling out. That is correct, but only because each adjustment is written as a pair of transition checks rather than a recount. Handle enter and leave as two separate, complete steps and this case takes care of itself.

Version 2 — with built-in methods

Version 2 — the interview answer
function checkInclusion(t, s) {
  const k = t.length;
  if (k > s.length) return false;

  const need = new Array(26).fill(0);
  const have = new Array(26).fill(0);
  const idx = c => c.charCodeAt(0) - 97;

  for (let i = 0; i < k; i++) {
    need[idx(t[i])]++;
    have[idx(s[i])]++;
  }

  const same = () => need.every((n, i) => n === have[i]);

  if (same()) return true;

  for (let i = k; i < s.length; i++) {
    have[idx(s[i])]++;
    have[idx(s[i - k])]--;
    if (same()) return true;
  }

  return false;
}

// "Find All Anagrams in a String" -- the same window, collecting
// every match instead of stopping at the first.
function findAnagrams(s, t) {
  const k = t.length;
  const out = [];
  if (k > s.length) return out;

  const need = new Array(26).fill(0);
  const have = new Array(26).fill(0);
  const idx = c => c.charCodeAt(0) - 97;

  for (let i = 0; i < k; i++) {
    need[idx(t[i])]++;
    have[idx(s[i])]++;
  }

  let matches = 0;
  for (let i = 0; i < 26; i++) if (need[i] === have[i]) matches++;

  if (matches === 26) out.push(0);

  for (let i = k; i < s.length; i++) {
    const enter = idx(s[i]);
    const leave = idx(s[i - k]);

    have[enter]++;
    if (have[enter] === need[enter]) matches++;
    else if (have[enter] === need[enter] + 1) matches--;

    have[leave]--;
    if (have[leave] === need[leave]) matches++;
    else if (have[leave] === need[leave] - 1) matches--;

    if (matches === 26) out.push(i - k + 1);
  }

  return out;
}

console.log(findAnagrams('cbaebabacd', 'abc'));   // [0, 6]
console.log(findAnagrams('abab', 'ab'));          // [0, 1, 2]
console.log(findAnagrams('aaaaa', 'aa'));         // [0, 1, 2, 3]
console.log(findAnagrams('af', 'be'));            // []
a Map version, for arbitrary characters
// The 26-slot array assumes lowercase a-z. For any characters,
// use Maps and count how many keys currently agree.
function checkInclusionAny(t, s) {
  const k = [...t].length;
  const chars = [...s];
  if (k > chars.length) return false;

  const need = new Map();
  for (const c of t) need.set(c, (need.get(c) || 0) + 1);

  const have = new Map();
  const bump = (c, by) => {
    const n = (have.get(c) || 0) + by;
    if (n === 0) have.delete(c); else have.set(c, n);
  };

  for (let i = 0; i < k; i++) bump(chars[i], 1);

  const same = () => {
    if (have.size !== need.size) return false;
    for (const [c, n] of need) if (have.get(c) !== n) return false;
    return true;
  };

  if (same()) return true;

  for (let i = k; i < chars.length; i++) {
    bump(chars[i], 1);
    bump(chars[i - k], -1);
    if (same()) return true;
  }

  return false;
}

console.log(checkInclusionAny('ab', 'eidbaooo'));       // true
console.log(checkInclusionAny('!A', 'xxA!yy'));         // true
console.log(checkInclusionAny('😀a', 'zza😀z'));         // true
console.log(checkInclusionAny('aa', 'aba'));            // false

// Note `if (n === 0) have.delete(c)` -- without it, a key with a
// count of zero stays in the map and `have.size !== need.size`
// rejects a window that is actually correct.
Step 8

Complexity, in sentences

SolutionTimeSpace
Recount every windowO(n · k)O(k)
Slide + compare 26 slotsO(26n) = O(n)O(1)
Slide + matches counterO(n)O(1)

Building the initial tables is O(k). Each of the n - k slides is two count updates and, in the refined version, four comparisons — all constant. So O(n + k), which is O(n) for the usual case where k ≤ n.

Space is two 26-element arrays: O(1) for a fixed alphabet, O(distinct characters) if you use Maps.

Say this in the interview

“Every permutation of t has the same length as t, so I only need to check windows of that fixed size. I build a frequency table for t and for the first window, then slide: increment the entering character, decrement the leaving one. Comparing the two 26-slot tables each step is O(26), so O(n) overall. To avoid even that, I keep a matches counter of how many letters currently agree and update it on the two transitions — then a window is a permutation exactly when matches === 26.”

Step 9

Mistakes people actually make

1. Counting matches only over the letters in t

Broken — extra characters slip through
function broken(t, s) {
  const k = t.length;
  if (k > s.length) return false;

  const need = new Map();
  for (const c of t) need.set(c, (need.get(c) || 0) + 1);

  const have = new Map();
  for (let i = 0; i < k; i++) have.set(s[i], (have.get(s[i]) || 0) + 1);

  // only checks the letters t cares about -- bug
  const ok = () => {
    for (const [c, n] of need) if (have.get(c) !== n) return false;
    return true;
  };

  if (ok()) return true;

  for (let i = k; i < s.length; i++) {
    have.set(s[i], (have.get(s[i]) || 0) + 1);
    have.set(s[i - k], have.get(s[i - k]) - 1);
    if (ok()) return true;
  }
  return false;
}

console.log(broken('ab', 'eidbaooo'));   // true   fine
console.log(broken('ab', 'ba'));         // true   fine
console.log(broken('a', 'ab'));          // true   fine

// It happens to survive here because the window length forces the
// totals to line up. But the reasoning is wrong: checking only t's
// letters ignores whether the window contains anything ELSE. It
// only works because the window is exactly k long, so any extra
// character means one of t's letters must be short. Rely on that
// and you will get it wrong the moment the window size varies.
// Count agreement across the WHOLE alphabet -- it costs nothing
// and the reasoning is then airtight.

2. Getting the transition conditions backwards

Broken — matches drifts
function broken(t, s) {
  const k = t.length;
  if (k > s.length) return false;
  const need = new Array(26).fill(0), have = new Array(26).fill(0);
  const idx = c => c.charCodeAt(0) - 97;
  for (let i = 0; i < k; i++) { need[idx(t[i])]++; have[idx(s[i])]++; }

  let matches = 0;
  for (let i = 0; i < 26; i++) if (need[i] === have[i]) matches++;

  for (let i = k; i < s.length; i++) {
    if (matches === 26) return true;
    const e = idx(s[i]), l = idx(s[i - k]);

    have[e]++;
    if (have[e] >= need[e]) matches++;        // >= instead of === -- bug

    have[l]--;
    if (have[l] <= need[l]) matches++;        // also wrong
  }
  return matches === 26;
}

// matches only counts up, so it sails past 26 and every window
// looks like a match. The conditions must fire ONLY on the exact
// transition into or out of agreement.

4. Comparing sorted substrings

[...s.slice(i, i+k)].sort().join('') === sortedT is correct and is O(n · k log k) — worse than the brute force with counts. Sorting computes an ordering the question does not need, exactly as in Valid Anagram.

5. Not handling t longer than s

Without the guard, the initial loop reads past the end of s, charCodeAt returns NaN, and NaN - 97 is NaN — which as an array index silently creates a property named "NaN". No crash, no correct answer. One guard line.

Step 10

Practice before you move on

  1. Write Version 1a from memory — the one that compares the 26 slots. It is obviously correct and still linear, and that is the answer to give first.
  2. Find All Anagrams in a String. In Step 7 — the same window, collecting every index. Write it from memory.
  3. Return the matching substring, not just true. You have the index; it is one slice.
  4. Permutation with at most one mismatch. The window may differ from t in one character. What does that do to the matches test? (Hint: think about the total absolute difference between the tables, not the count of agreeing letters.)
  5. Minimum Window Substring. The variable-size cousin, where the window may contain extras. Compare its formed counter with this page’s matches — same trick, different definition of valid.
What to carry forward

Two techniques compose. This problem is the fixed-size window from problem 01 carrying the frequency map from Valid Anagram, with the incremental-invariant trick from Minimum Window Substring on top. None of the three is new; recognising that a problem is a combination rather than something novel is most of what makes hard problems feel easy.
